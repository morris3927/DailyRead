# 2026-05-08 - Agent Memory

## 今日領域觀察

Agent memory 今天的搜尋結果比另外兩個領域更像典型 paper stream：survey、method paper、system paper 都很多。整體趨勢很明顯：這個領域正在從「把歷史對話丟進向量資料庫」往更完整的 memory architecture 前進。

今天值得注意的三個方向是：第一，survey 類 paper 開始整理 agent memory 的分類與設計模式；第二，A-MEM 這類方法開始強調記憶之間的動態連結與演化；第三，Mem0 這類系統開始把 long-term memory 推向 production-ready，關心 latency、token cost 與多 session 對話的一致性。

## 1. A-MEM: Agentic Memory for LLM Agents

- Link: https://arxiv.org/abs/2502.12110
- Type: paper / method

### 這篇在說什麼

這篇的出發點是：LLM agents 如果要處理長期任務，就不能只依賴當前 context window。它們需要某種 memory system 來保存歷史經驗，並在未來任務中取用。但作者認為，現有 memory system 大多只做到基本的 storage 和 retrieval，就算加入 graph database，也常常是固定結構、固定操作，缺乏跨任務的適應性。

A-MEM 想解決的是「記憶如何自己組織起來」。作者把 Zettelkasten 筆記法的概念帶進 agent memory：新記憶不是孤立存進資料庫，而是會被寫成包含上下文描述、關鍵字、tag 等屬性的 structured note，然後系統會主動尋找它和過去記憶的關聯，建立連結，甚至更新舊記憶的描述。

### 主要貢獻

- 提出 agentic memory system，讓 agent 可以動態組織記憶。
- 把 Zettelkasten 的 linked notes 思想轉成 LLM agent memory 機制。
- 新記憶寫入時不只存內容，還會產生 context、keywords、tags 等結構化屬性。
- 記憶會和歷史記憶建立連結，並觸發 memory evolution，更新既有記憶的表示。
- 在六個 foundation models 上做實驗，摘要稱相對於既有 SOTA baselines 有更好表現。

### 方法

A-MEM 的 pipeline 大致可以理解成三步：

第一，新 memory 進來時，系統先把它整理成比較完整的 note，而不是只存原文。這個 note 會包含描述、關鍵字、tag 等 metadata。

第二，系統把新 note 和歷史 memories 比對，找出語意或情境上相關的記憶，並建立連結。這讓 memory 變成一個 interconnected knowledge network，而不是一堆扁平文件。

第三，新記憶可能反過來改變舊記憶的 contextual representation。也就是說，memory system 不是 append-only，而是會隨著新資訊進來持續演化。

### 實驗設計

摘要提到作者在六個 foundation models 上做 empirical experiments，並與既有 SOTA baselines 比較。雖然光看 abstract 還看不到完整 benchmark 細節，但實驗目的應該是驗證：動態組織與連結記憶，是否比單純 storage / retrieval 或固定 graph 結構更能提升 agent 任務表現。

它想證明的不是「有記憶比沒記憶好」這種基本命題，而是「記憶的組織方式會影響 agent 使用歷史經驗的能力」。

### かに讀後判斷

這篇很值得看，因為它把 agent memory 從 RAG 式檢索推進到「記憶管理」本身。特別是 memory evolution 這個概念很重要：如果 agent 的記憶只會增加、不會重組，那長期下來很容易變成雜訊倉庫。A-MEM 代表的是更主動、更結構化的 memory design。

## 2. A Survey on the Memory Mechanism of Large Language Model based Agents

- Link: https://arxiv.org/abs/2404.13501
- Type: survey

### 這篇在說什麼

這篇是 agent memory 的 survey。它的動機很直接：LLM-based agents 越來越多，但 memory mechanism 分散在很多不同 paper 裡，缺少一個整體整理。作者想回答幾個基本問題：agent memory 是什麼、為什麼需要、有哪些設計方式、怎麼評估、以及 memory 在不同 agent applications 裡扮演什麼角色。

這類 survey 的價值不是提出新方法，而是幫你建立地圖。因為 agent memory 很容易混在 RAG、long context、reflection、tool use、personalization 裡面，如果沒有 taxonomy，會很難判斷每篇 paper 到底是在改哪一層。

### 主要貢獻

- 系統性整理 LLM-based agents 的 memory mechanisms。
- 討論 memory 在 agent 裡的定義與必要性。
- 整理 memory module 的設計與 evaluation 方法。
- 蒐集 memory 在不同 agent applications 中的角色。
- 提出現有工作的限制與未來方向，並維護相關 paper repository。

### 方法

這是一篇 survey，所以方法不是實作模型，而是文獻整理。它會從「what is memory」和「why memory is needed」開始，再分類不同 memory design，例如短期記憶、長期記憶、檢索機制、更新機制、應用場景與評估方法。

對 DailyRead 來說，這篇比較像 background map。後續看到 A-MEM、Mem0、MemOS、Memory-R1 之類 paper 時，可以回到這篇的分類架構裡定位它們。

### 實驗設計

Survey 本身通常不做新實驗，而是比較既有研究的 evaluation setup。這篇的重點應該會在於整理 memory module 如何被評估：例如任務成功率、長期一致性、多輪對話 QA、agent-environment interaction performance 等。

### かに讀後判斷

這篇適合收藏，不一定要一次讀完。建議先看 taxonomy、tables 和 future directions。之後如果你看到某篇 memory paper 很有興趣，可以用這篇來判斷它是 episodic memory、semantic memory、reflection、retrieval 還是 memory consolidation 的路線。

## 3. Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory

- Link: https://arxiv.org/abs/2504.19413
- Type: paper / system

### 這篇在說什麼

這篇處理的是更產品化的 agent memory 問題：LLM 的固定 context window 讓它很難在長時間、多 session 的對話裡維持一致性，所以需要一個可以動態萃取、整合、檢索重要資訊的長期記憶架構。

Mem0 的定位不是只做學術概念展示，而是要做 production-ready memory。它關心的不只是回答準不準，還包括 latency、token cost，以及和 full-context method 相比能不能更有效率地支援長期對話。

### 主要貢獻

- 提出 Mem0，一個 scalable memory-centric architecture。
- 從 ongoing conversations 中動態萃取、整合與檢索 salient information。
- 提出 graph-based memory variant，用圖結構表示對話元素之間的關係。
- 在 LOCOMO benchmark 上和多種 baseline 比較。
- 摘要宣稱在 LLM-as-a-Judge metric 上相對 OpenAI 有 26% improvement，同時 p95 latency 降低 91%，token cost 省超過 90%。

### 方法

Mem0 的核心做法是不要把整段歷史對話都塞進 context，也不要只做粗糙 chunk retrieval。它會從互動中抽取重要資訊，將其整理成可長期保存的 memory，之後根據當前問題檢索相關記憶。

進階版本加入 graph memory，用圖表示不同記憶元素之間的關係。這讓系統不只記得單點事實，也能保留人物、事件、時間、偏好等資訊之間的連結。

### 實驗設計

這篇用 LOCOMO benchmark 評估長期記憶能力，並比較六類 baseline：既有 memory-augmented systems、不同 chunk size 和 k 值的 RAG、full-context method、open-source memory solution、proprietary model system，以及專門的 memory management platform。

評估問題類型包含 single-hop、temporal、multi-hop 和 open-domain。這點重要，因為 agent memory 不只是問「以前說過什麼」，還包含時間順序、跨資訊整合與開放式回憶。

除了準確率，這篇也把 latency 和 token cost 放進比較。這讓它比一般 memory method paper 更接近真實部署場景。

### かに讀後判斷

這篇很值得追，因為它代表 agent memory 的工程化方向。A-MEM 比較像研究型 memory organization，Mem0 則比較像 production memory layer。這兩種路線未來可能會合流：一邊重視記憶結構，一邊重視成本、延遲與穩定性。

## 明天可延伸方向

- 看 Memory-R1、SimpleMem、HiMem 和 MemOS，判斷 agent memory 是否正在形成幾個固定架構派別。
- 補查 memory security / memory poisoning，因為長期記憶一旦進 production，安全問題會變重要。
