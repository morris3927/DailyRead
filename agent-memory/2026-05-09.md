# Agent Memory — 2026-05-09

## 今日篩選判斷

今天 Agent Memory 的主線是「memory 從外掛模組變成 agent policy 的一部分」。一篇 survey 把 memory 整理成 write–manage–read loop，另一篇 AgeMem 則直接把長期記憶與短期記憶的操作變成 tool actions，並用 RL 學什麼時候存、取、更新、摘要、丟棄。這代表 agent memory 正從 RAG / vector store 工程，走向可訓練的 memory control policy。

## 1. Memory for Autonomous LLM Agents: Mechanisms, Evaluation, and Emerging Frontiers

- URL: https://arxiv.org/abs/2603.07670
- Authors: Eric Du
- Date: 2026-03-08
- Source type: survey

### 這篇在說什麼

這篇 survey 的切入點很清楚：context window 再大，也不足以保存 agent 在多次互動中學到的事情、犯過的錯、使用者偏好、任務狀態與長期知識。memory 是把 stateless text generator 變成 adaptive agent 的關鍵能力。

作者把 agent memory 形式化成 write–manage–read loop，並把它和 perception / action 綁在一起看。也就是說，memory 不只是「查資料再塞回 prompt」，而是 agent 在行動過程中決定寫入、整理、取回、壓縮、反思、忘記的一整套控制迴路。

### 主要貢獻

survey 提出三維 taxonomy：temporal scope、representational substrate、control policy。它也整理五種 mechanism families：context-resident compression、retrieval-augmented stores、reflective self-improvement、hierarchical virtual context、policy-learned management。

這個分類很適合幫 Morris 對齊不同 memory paper 的位置：有些 paper 其實是在做短期 context compression，有些是在做外部 store + retrieval，有些是在做 reflection / self-improvement，有些是在做 hierarchy，有些則真的在學 memory management policy。

### 方法 / pipeline

因為是 survey，它不是提出單一系統，而是整理 2022 到 2026 early 的 LLM agent memory 研究。它把 memory design、implementation、evaluation 放在一起談，並特別指出 evaluation 正從 static recall benchmarks 走向 multi-session agentic tests：也就是測 agent 能否在跨 session、跨 decision 的任務中真正用到 memory，而不是只問它能不能背出某個事實。

### 實驗設計 / evaluation 討論

這篇本身沒有做新實驗；它分析了近期 benchmarks 顯示 current systems 仍有 gap。摘要提到 evaluation 方向包含四個近期 benchmark，重點是把 memory 和 decision-making interleave 起來。它也點出工程現實：write-path filtering、contradiction handling、latency budgets、privacy governance。這幾個點非常 production：memory 不是存越多越好，還要處理錯誤記憶、衝突記憶、成本與隱私。

### かに讀後判斷

值得點開，尤其適合當 agent memory 的總覽地圖。若 Morris 今天只想快速更新領域全貌，這篇比單一系統 paper 更有效；但如果想看新方法與實驗，下面 AgeMem 更具體。

## 2. Agentic Memory: Learning Unified Long-Term and Short-Term Memory Management for Large Language Model Agents

- URL: https://arxiv.org/abs/2601.01885
- HTML: https://arxiv.org/html/2601.01885v2
- Code: https://github.com/y1y5/AgeMem
- Authors: Yi Yu, Liuyi Yao, Yuexiang Xie, Qingquan Tan, Jiaqi Feng, Yaliang Li, Libing Wu
- First version: 2026-01-05; v2: 2026-04-30

### 這篇在說什麼

AgeMem 的主張是：現有 agent memory 常把 long-term memory 與 short-term memory 分開處理，長期記憶靠 trigger 或 memory manager，短期記憶靠 RAG / summarization / context selection。這樣雖然可行，但兩個系統常常是 heuristic 拼在一起，沒有端到端學到什麼時候該寫、該取、該更新、該摘要、該忘記。

這篇把記憶管理直接放進 agent policy。memory operations 被暴露成 tool actions，讓 LLM agent 自己決定何時 Add / Update / Delete 長期記憶，何時 Retrieve / Summary / Filter 短期上下文。換句話說，memory 不再只是旁邊的資料庫，而是 agent 可學習的行動空間。

### 主要貢獻

第一，AgeMem 統一管理 LTM 和 STM，不再把兩者當作分離模組。第二，它用三階段 progressive reinforcement learning 訓練 memory behavior：先學 LTM storage，再學 STM context management，最後在完整任務中協調兩種 memory。第三，它設計 step-wise GRPO，把稀疏、延遲的 task reward 回傳到先前的 memory decisions，處理 memory operation 造成的 fragmented / discontinuous trajectory。

這篇相對於 A-Mem、Mem0、Zep、ReSum 這類方法的位置很明確：不是只提出新的 memory structure，而是把 memory control policy 學出來。

### 方法 / pipeline / 架構

AgeMem 的 state 包含 conversation context、long-term memory store、task specification。action space 同時包含 language generation 與 memory operations。LTM tools 包括 Add、Update、Delete；STM tools 包括 Retrieve、Summary、Filter。Reward 結合 task performance、memory quality，以及避免 redundant storage、excessive tool usage、context expansion 的 penalty。

訓練 trajectory 被分成三段：Stage 1 讓 agent 在 casual interactions 中決定哪些資訊要存入 LTM；Stage 2 加入 distractors / irrelevant content，逼 agent 管理 STM；Stage 3 給一個需要結合先前 LTM 與當前 context 的任務。這個設計的關鍵是讓早期 memory decision 真的影響後面能不能解任務。

### 實驗設計

摘要說 AgeMem 在五個 long-horizon benchmarks 上評估，跨多個 LLM backbones，並且 consistently outperform strong memory-augmented baselines；效果包含 task performance、long-term memory quality、context usage efficiency。這次我讀到 abstract、introduction、method 開頭與 problem formulation，還沒完整核對五個 benchmark 名稱、每個 baseline、metric 與數字，所以先不寫具體分數。

比較能確定的是它的 evaluation framing：不是只測 retrieval accuracy，而是把 memory operation 放在長程任務裡，用最終任務 reward 與 memory quality 一起看。這比單純「存了什麼、搜到什麼」更接近 agent memory 的真問題。

### かに讀後判斷

今天 Agent Memory 最推薦點開這篇。它把 memory 做成可學的 policy，方向比傳統 RAG memory 更進一步。如果 Morris 關心 OpenClaw / agent 長期工作狀態，這篇值得細讀，尤其是 tool-based memory operations 與 step-wise credit assignment 的設計。
