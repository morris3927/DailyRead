# Agent Memory — 2026-05-10

## 今日篩選判斷

今天 Agent Memory 的主線從「要不要有長期記憶」轉到三個更工程化的問題：記憶系統要多快、多省、多可治理。LightMem / SimpleMem 代表效率派：不要每次都靠大模型重新整理歷史，而要把記憶壓成高密度、可檢索、可離線整合的結構。Long-term memory security survey 則提醒另一面：一旦記憶是 persistent、writable、shared，它就不只是功能模組，而是新的攻擊面與治理問題。

## 1. Lightweight LLM Agent Memory with Small Language Models

- URL: https://arxiv.org/abs/2604.07798
- HTML: https://arxiv.org/html/2604.07798v3
- Authors: Jiaquan Zhang et al.
- First version: 2026-04-09; v3: 2026-04-22
- Status: ACL 2026 main

### 這篇在說什麼

LightMem 的問題意識很實際：agent 需要跨 turn、跨 session 的記憶，但記憶操作不能每次都靠昂貴的大模型 call。傳統 retrieval-based external memory 線上成本低，但 accuracy 不穩，因為 query construction 和 candidate filtering 容易出錯；反過來，如果每次寫入、整理、判斷都叫大模型，長互動裡 latency 和成本會快速累積。

作者的解法是用 Small Language Models（SLMs）驅動 memory retrieval、writing、long-term consolidation，把線上處理和離線整合分開。也就是說，agent 當下要快，先在固定 budget 內找出可用記憶；比較重的抽象、整合、長期更新則移到 offline consolidation。

### 主要貢獻

LightMem 把 memory 分成三層：short-term memory（STM）保存 immediate conversational context；mid-term memory（MTM）保存 reusable interaction summaries；long-term memory（LTM）保存 consolidated knowledge。它也用 user identifiers 支援多使用者情境下的獨立檢索與增量維護。

最實用的貢獻是 bounded compute 的 retrieval pipeline：online 時先做 vector-based coarse retrieval，再做 semantic consistency re-ranking；offline 時再把互動 evidence 抽象化並整合到 LTM。這個設計避免把所有 intelligence 都塞在 online retrieval 這一步。

### 方法 / pipeline / 架構

online path 是效率導向：固定 retrieval budget，先從記憶庫抓候選，再用語意一致性重排，盡量在低延遲下把有用記憶送回 agent context。offline path 則負責整理：從互動中抽出可重用 evidence，更新 mid-term / long-term memory，降低下次 retrieval 的負擔。

這和昨天讀到的 AgeMem 不同。AgeMem 是讓 agent policy 學 memory operations；LightMem 則更像 production memory system：把記憶操作拆成可低成本運行的模組，並用小模型降低線上成本。

### 實驗設計

摘要說 LightMem 在多個 model scales 上都有一致增益，在 LoCoMo 上平均 F1 比 A-MEM 高約 2.5，同時維持高效率：retrieval median latency 83 ms，end-to-end median latency 581 ms。這次我主要讀 abstract / landing page，還沒逐表核對每個 baseline 與 metric，因此具體數字先以摘要為準。

### かに讀後判斷

今天 Agent Memory 最推薦點開這篇。它很適合 Morris 關心的長期 agent 系統：不是只追求更會記，而是把記憶做成低延遲、可增量維護、可多使用者隔離的工程系統。

## 2. A Survey on the Security of Long-Term Memory in LLM Agents: Toward Mnemonic Sovereignty

- URL: https://arxiv.org/abs/2604.16548
- HTML: https://arxiv.org/html/2604.16548v1
- Authors: Zehao Lin et al.
- Date: 2026-04-17
- Source type: survey preprint

### 這篇在說什麼

這篇把 agent memory security 的問題講得很尖銳：LLM security 正從「模型會不會洩漏 training data」轉向「有持久記憶的 agent 能不能被跨 session 塑形、污染、未授權讀取，甚至把錯誤記憶傳播到組織共享狀態」。只要 agent memory 是 persistent、writable、retrievable、shareable，它就不是一般 RAG index，而是一個會影響未來行為的狀態層。

作者提出 mnemonic sovereignty 這個概念：使用者或組織需要可驗證、可恢復的記憶治理能力，能控制什麼可以寫入、誰能讀取、何時允許更新、哪些狀態可以被忘記或 rollback。

### 主要貢獻

survey 用六個 lifecycle phases 組織記憶安全：Write、Store、Retrieve、Execute、Share、Forget/Rollback，並和四個 security objectives cross-tab：integrity、confidentiality、availability、governance。這個矩陣很有用，因為它把 memory attack 從單點 prompt injection 擴展成完整生命週期問題。

摘要列出三個 findings。第一，現有文獻集中在 write-time / retrieve-time integrity attacks，其他面向如 confidentiality、availability、store / forget、benign-persistence failures 研究較少。第二，沒有既有架構覆蓋作者提出的九個 governance primitives。第三，用 LLM 自身協助 memory security 的工作仍少，但未來可能不可避免。

### 方法 / pipeline

這是 63 頁 survey，不是單一系統。它從認知神經科學與記憶哲學借概念，把 agent memory 描述成 malleable、rewritable、socially propagating，再回到 LLM agent 的工程架構，討論 memory poisoning、extraction、retrieval corruption、control-flow hijacking、cross-agent propagation、rollback 與治理。

### 實驗設計 / evaluation 討論

因為是 survey，沒有新實驗。它比較適合當 design review checklist：如果一個 agent 平台要上長期記憶，至少要問 write authorization、retrieval permission、memory provenance、conflict handling、rollback / forgetting、shared-state propagation、audit trail 這幾件事是否有明確設計。

### かに讀後判斷

值得收藏。它不會直接告訴你怎麼提升 memory benchmark 分數，但很適合提醒我們：agent memory 進 production 後，真正難的可能不是 recall，而是治理、隔離、復原與審計。

## 3. SimpleMem: Efficient Lifelong Memory for LLM Agents

- URL: https://arxiv.org/abs/2601.02553
- HTML: https://arxiv.org/html/2601.02553v3
- Authors: Jiaqi Liu et al.
- First version: 2026-01-05; v3: 2026-01-29
- Code: https://github.com/aiming-lab/SimpleMem

### 這篇在說什麼

SimpleMem 也在處理 memory efficiency，但它的關鍵詞是 semantic lossless compression。作者認為長期互動會產生大量冗餘歷史；如果直接保留完整 transcript，token 成本高且容易讓 agent 被舊資訊干擾；如果用反覆推理來過濾噪音，又會增加推理成本。

### 主要貢獻與方法

SimpleMem 提出三階段 pipeline。第一是 Semantic Structured Compression，把非結構化互動壓成 compact、multi-view indexed memory units。第二是 Online Semantic Synthesis，在同一 session 中即時整合相關 context，消除冗餘。第三是 Intent-Aware Retrieval Planning，先推斷當前 search intent，再動態決定 retrieval scope，避免把不必要的歷史塞回上下文。

### 實驗設計

摘要說 SimpleMem 在 benchmark datasets 上提升 accuracy、retrieval efficiency 與 inference cost；在 LoCoMo 上平均 F1 improvement 26.4%，同時 inference-time token consumption 最多降低 30 倍。這次只讀 abstract / landing page，尚未核對 baseline 細節，因此不過度解讀數字。

### かに讀後判斷

值得作為 LightMem 的對照閱讀。LightMem 強調 SLM + online/offline 分工；SimpleMem 強調壓縮與 intent-aware retrieval。兩篇合起來看，agent memory 的工程方向很清楚：未來不是存更多 transcript，而是把可用資訊整理成高密度、低延遲、可控制的記憶層。
