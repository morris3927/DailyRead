# Agent Memory — 2026-05-11

## 今日篩選判斷

今天 Agent Memory 的主線是 evaluation 變得更嚴格。前幾天看到的 LightMem / SimpleMem 主要問「記憶系統怎麼更快、更省、更可部署」；今天的 MemoryArena / Memora 則提醒：只會 recall 過去事實還不夠，agent memory 必須在多 session、會變動、會失效、需要行動決策的情境下被評估。Mem0 的 2026 landscape blog 則補上產業側訊號：memory 已經從 RAG-like feature 變成有 benchmark、latency budget、integration ecosystem 的工程層。

## 1. MemoryArena: Benchmarking Agent Memory in Interdependent Multi-Session Agentic Tasks

- URL: https://arxiv.org/abs/2602.16313
- HTML: https://arxiv.org/html/2602.16313v1
- Authors: Zexue He, Yu Wang, Churan Zhi, Yuanzhe Hu, Tzu-Ping Chen, Lang Yin, Ze Chen, Tong Arthur Wu, Siru Ouyang, Zihan Wang, Jiaxin Pei, Julian McAuley, Yejin Choi, Alex Pentland
- Date: 2026-02-18
- Source type: arXiv preprint / benchmark
- Project: https://memoryarena.github.io/

### 這篇在說什麼

MemoryArena 抓到 agent memory evaluation 的一個根本問題：很多 benchmark 只測「能不能從過去對話裡答出某個事實」，但真實 agent 需要的是「先互動、從回饋中形成記憶，之後再用這些記憶做更好的行動」。也就是說，memory 不能和 action 分開評估。

作者把這件事稱為 Memory-Agent-Environment loop。agent 在前幾個 session 裡採取行動、收到環境回饋、把有用經驗蒸餾成記憶；後面 session 的成功則依賴它能不能把早先記住的 constraints、preferences、compatibility、intermediate reasoning state 拿出來用。

### 主要貢獻

MemoryArena 的貢獻是把 memory benchmark 從 static recall 推向 multi-session agentic tasks。它包含人工設計的 interdependent subtasks，後續任務如果沒有正確保存前面獲得的資訊，就會變成 underspecified 或做錯。

它支援四類 / 多個場景：bundled web shopping、preference-constrained group travel planning、progressive information search、sequential formal reasoning（數學與物理）。這些場景都不是單純問答，而是需要 agent 在多次行動中維持 latent task state。

### 方法 / pipeline

以 bundled web shopping 為例，agent 不是一次買完所有東西，而是跨 session 購買相容的商品。後續選擇要記得前面買過什麼、尺寸 / 類別 / 相容條件是什麼，還要避開 distractors。group travel planning 則要求保留偏好與限制；progressive search 逐步增加條件；formal reasoning 則讓後面問題依賴前面累積出的中間結果或技巧。

這比 LoCoMo 類長對話 QA 更接近實際 agent memory，因為成功不是答出「某人生日是什麼」，而是用先前經驗改變後續 action selection。

### 實驗設計

論文比較了現有 memory / agent benchmarks 的維度，指出很多 benchmark 有 memory 但沒有 agentic actions，或有 actions 但沒有 multi-session memory dependence。MemoryArena 規模上包含 766 tasks、平均 6.9 subtasks、平均 57 action steps；其中 progressive search trace 可超過 100k tokens。作者評估 long-context agents、RAG-augmented agents、external-memory agents，結果顯示即使在 LoCoMo 等 memory benchmark 接近飽和的 agent，在 MemoryArena 的 agentic setting 仍表現不佳。

這次我讀到 abstract、introduction、benchmark construction 與部分 table，還沒有逐項核對每個 agent 的完整成績，因此不細報單一系統分數。

### かに讀後判斷

今天 Agent Memory 最推薦點開這篇。它給了一個很好的判準：agent memory benchmark 應該測「記憶是否改善未來行動」，而不是只測「記得多少」。如果 Morris 關心長期 agent / personal assistant / research agent，MemoryArena 比純 recall benchmark 更接近真正痛點。

## 2. From Recall to Forgetting: Benchmarking Long-Term Memory for Personalized Agents

- URL: https://arxiv.org/abs/2604.20006
- Authors: Md Nayem Uddin et al.
- Date: 2026-04-21
- Status: ACL 2026 Findings
- Source type: arXiv preprint / benchmark

### 這篇在說什麼

這篇提出 Memora，重點是 personalized agents 的長期記憶不能只會「記得」，還要會「忘記」或至少不再使用失效記憶。長期互動裡，使用者偏好、狀態、限制常會改變；如果 agent 一直引用舊偏好或被撤銷的資訊，memory 反而會傷害 personalization。

### 主要貢獻

Memora 橫跨 weeks to months 的 user conversations，評估三種 memory-grounded tasks：remembering、reasoning、recommending。作者也提出 Forgetting-Aware Memory Accuracy（FAMA），用來懲罰 agent 依賴 obsolete / invalidated memory 的情況。

這個 metric 很重要，因為傳統 accuracy 很容易獎勵「把任何曾經出現過的事都拿出來」。但 personalized memory 的難點常常是 conflict resolution：哪個版本比較新？哪個偏好已經被更新？哪些記憶應該降權、撤回或刪除？

### 實驗設計

摘要說作者評估四個 LLMs 與六種 memory agents，發現 memory agents 只有 marginal improvements，而且常常重用 invalid memories，無法 reconcile evolving memories。這次我只讀 arXiv abstract / landing page，還沒讀完整 HTML 與表格，所以先保守記錄結論，不展開 baseline 細節。

### かに讀後判斷

值得接在 MemoryArena 後面讀。MemoryArena 說 memory 要能支撐 action；Memora 說 memory 還要知道何時不該再被使用。這對 personal agents 非常關鍵，因為「記錯舊偏好」比「不記得」更容易讓使用者失去信任。

## 3. State of AI Agent Memory 2026 — Mem0

- URL: https://mem0.ai/blog/state-of-ai-agent-memory-2026
- Author: Mem0 Engineering Team
- Published: 2026-04-01（頁面 metadata 顯示 2026-05-09 重新發布 / 更新）
- Source type: engineering blog / ecosystem report

### 這篇在說什麼

這篇是 Mem0 對 AI agent memory landscape 的工程整理。它的立場很明確：agent memory 在 2026 已經不是「把聊天紀錄塞進 context」的小功能，而是有 benchmark、latency / token cost trade-off、graph memory、multi-scope API、framework integrations、vector store backends 的一個工程 discipline。

### 工程設計 / 架構重點

文章用 LoCoMo benchmark 說明為什麼 memory evaluation 需要同時看 accuracy、latency、token consumption。它列出的 Mem0 benchmark 數字裡，full-context accuracy 最高，但 median latency 約 9.87s、p95 約 17.12s，token 成本也高；selective memory pipeline 犧牲一些 accuracy，換來更低 latency 與更少 token。這個 trade-off 很 production-oriented：一個記憶系統如果每次都等十幾秒，即使答得準也很難用。

它也整理了幾個 2026 很清楚的工程方向：graph memory 從 experimental 走向 production；memory scope model 需要 user_id、agent_id、run/session_id、app/org_id；多 agent 系統需要 actor-aware memory，否則不知道一段記憶到底是誰說的、誰推論的、誰產生的中間狀態。

### 對 agent memory 的意義

這篇不是中立 survey，因為它來自 Mem0；但作為工程趨勢整理仍有用。它提醒我們 agent memory 不只是 retrieval quality，而是 API design、identity scoping、metadata filtering、privacy isolation、graph/vector backend choice、voice latency、framework integration 的組合問題。

### かに讀後判斷

適合收藏作為產業側 checklist，但研究優先度低於 MemoryArena / Memora。若 Morris 想看「memory system 真正進 production 要考慮哪些面」，這篇比單篇 benchmark 更直觀。
