# Agent Memory — 2026-05-14

## 1. HiAgent: Hierarchical Working Memory Management for Solving Long-Horizon Agent Tasks

- **Venue**: ACL 2025
- **Link**: https://aclanthology.org/2025.acl-long.1575/

**📌 今日推薦點開**

HiAgent 解決了一個很實際的問題：長任務中 working memory 太長、太冗餘，LLM 被歷史 action-observation pair 淹沒。

方法很直覺但有效：把 working memory 用 subgoal 當 chunk 來做層級管理。具體來說：
1. LLM 先在生成 action 之前規劃 subgoal
2. 每個 subgoal 下的 action-observation pair 是一個 chunk
3. 當 LLM 切換到新 subgoal 時，主動決定是否用摘要觀察替換前一個 subgoal 的詳細記錄
4. 只保留與當前 subgoal 相關的 action-observation

實驗在 5 個 long-horizon 任務上測試，成功率翻倍，平均步數減少 3.8 步。而且不同步數下表現穩定提升，顯示方法有好的泛化性。

**閱讀判斷**：這篇的方法簡潔、直覺、效果明確。對於做 coding agent 或任何 long-horizon planning agent 的人來說，HiAgent 的 subgoal-chunking 思路可以直接借鑑。值得點開看實驗細節。

## 2. MemoryOS: Memory Operating System for AI Agents

- **Venue**: EMNLP 2025
- **Link**: https://aclanthology.org/2025.emnlp-main.1318/

MemoryOS 把作業系統的記憶體管理概念搬到了 agent memory 上。

架構是三層儲存：short-term → mid-term → long-term personal memory。
- Short-term 到 mid-term：遵循 dialogue-chain-based FIFO 原則
- Mid-term 到 long-term：用 segmented page organization 策略

四個模組：Storage、Updating、Retrieval、Generation。

在 LoCoMo benchmark 上，用 GPT-4o-mini 測試，F1 平均提升 48.36%，BLEU-1 提升 46.18%。這個數字很驚人，但要注意是相對於 baseline（沒有 memory management），不是相對於其他 memory 方法。

**閱讀判斷**：如果你在設計 agent 的記憶架構，MemoryOS 的三層遷移機制和 page organization 思路可以參考。但它和 HiAgent 的層級管理邏輯不同——MemoryOS 更偏 dialogue/personalization，HiAgent 更偏 task planning。看你的場景需求。

## 3. RMM: Reflective Memory Management for Long-term Personalized Dialogue Agents

- **Venue**: ACL 2025
- **Link**: https://aclanthology.org/2025.acl-long.413/

RMM 提出了一個雙向反思的記憶管理機制：

1. **Prospective Reflection**（前瞻）：在對話進行中，跨不同粒度（utterance → turn → session）動態摘要，建立 personalized memory bank 供未來檢索
2. **Retrospective Reflection**（回顧）：用 online RL 迭代改進檢索策略，根據 LLM 引用的證據來優化什麼該存、什麼該取

在 LongMemEval 上比無 memory 管理的 baseline 準確率提升超過 10%。

**閱讀判斷**：RMM 的雙向反思設計比單純的摘要+檢索更深一層，尤其是 retrospective 用 RL 來學 retrieval policy 這一點。但從方法複雜度來看，HiAgent 的 subgoal-chunking 更容易實際落地。如果你在做對話式 agent 的長期記憶，RMM 值得細看。
