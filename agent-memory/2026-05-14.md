# Agent Memory — 2026-05-14

## 1. HiAgent: Hierarchical Working Memory Management for Solving Long-Horizon Agent Tasks

- **Venue**: ACL 2025
- **Link**: https://aclanthology.org/2025.acl-long.1575/

**📌 今日推薦點開**

HiAgent 解決了一個很實際的問題：長任務中 working memory 太長、太冗餘，LLM 被歷史 action-observation pair 淹沒。

方法很直覺但有效：把 working memory 用 subgoal 當 chunk 來做層級管理。具體來說：
1. LLM 先在生成 action 之前規劃 subgoal
2. 每個 subgoal 下的 action-observation pair 是一個 chunk
3. 當 LLM 切換到新 subgoal 時，主動決定是否用摘要觀察替換前一個 subgoal 的詳細記錄
4. 只保留與當前 subgoal 相關的 action-observation

實驗在 5 個 long-horizon 任務上測試，成功率翻倍，平均步數減少 3.8 步。而且不同步數下表現穩定提升，顯示方法有好的泛化性。

**閱讀判斷**：這篇的方法簡潔、直覺、效果明確。對於做 coding agent 或任何 long-horizon planning agent 的人來說，HiAgent 的 subgoal-chunking 思路可以直接借鑑。值得點開看實驗細節。

## 2. MemoryOS: Memory Operating System for AI Agents

- **Venue**: EMNLP 2025
- **Link**: https://aclanthology.org/2025.emnlp-main.1318/

MemoryOS 把作業系統的記憶體管理概念搬到了 agent memory 上。

架構是三層儲存：short-term → mid-term → long-term personal memory。
- Short-term 到 mid-term：遵循 dialogue-chain-based FIFO 原則
- Mid-term 到 long-term：用 segmented page organization 策略

四個模組：Storage、Updating、Retrieval、Generation。

在 LoCoMo benchmark 上，用 GPT-4o-mini 測試，F1 平均提升 48.36%，BLEU-1 提升 46.18%。這個數字很驚人，但要注意是相對於 baseline（沒有 memory management），不是相對於其他 memory 方法。

**閱讀判斷**：如果你在設計 agent 的記憶架構，MemoryOS 的三層遷移機制和 page organization 思路可以參考。但它和 HiAgent 的層級管理邏輯不同——MemoryOS 更偏 dialogue/personalization，HiAgent 更偏 task planning。看你的場景需求。

## 3. RMM: Reflective Memory Management for Long-term Personalized Dialogue Agents

- **Venue**: ACL 2025
- **Link**: https://aclanthology.org/2025.acl-long.413/

RMM 提出了一個雙向反思的記憶管理機制：

1. **Prospective Reflection**（前瞻）：在對話進行中，跨不同粒度（utterance → turn → session）動態摘要，建立 personalized memory bank 供未來檢索
2. **Retrospective Reflection**（回顧）：用 online RL 迭代改進檢索策略，根據 LLM 引用的證據來優化什麼該存、什麼該取

在 LongMemEval 上比無 memory 管理的 baseline 準確率提升超過 10%。

**閱讀判斷**：RMM 的雙向反思設計比單純的摘要+檢索更深一層，尤其是 retrospective 用 RL 來學 retrieval policy 這一點。但從方法複雜度來看，HiAgent 的 subgoal-chunking 更容易實際落地。如果你在做對話式 agent 的長期記憶，RMM 值得細看。

## 4. Human-Inspired Memory Architecture for LLM Agents

- **arXiv**: 2605.08538
- **Link**: https://arxiv.org/abs/2605.08538
- **Authors**: Doga Kerestecioglu, Alexei Robsky, Clemens Vasters, Anshul Sharma, Yitzhak Kesselman (Microsoft)

**📌 今日推薦點開**

這篇是 Microsoft 提出的一套完整生物學啟發的 agent memory 架構，做工程落地做得非常紮實。核心主張很明確：現在 LLM agent 的記憶管理太陽春——不是無狀態就是暴力塞 context window 或單純 RAG，都缺少「遺忘」、「成熟」、「重新整合」這些人類記憶的關鍵機制。

架構映射六個認知機制到系統元件：
1. **Sleep-phase consolidation**（睡眠整合）：每 6 小時批次執行，識別重複記憶、合併、提升到長期知識圖譜。Dedup-based consolidation 在 VSCode issue-tracking dataset 上達到 97.2% retention precision，同時減少 58% 儲存量（比 baseline 高出 21.8 pp）。
2. **Interference-based forgetting**（干擾遺忘）：用 Ebbinghaus 曲線的被動衰減 + 記憶間相似度計算干擾分數，選擇性遺忘高干擾低價值的記憶。衰減半衰期約 29 天。
3. **Engram maturation**（記憶成熟）：新整合的記憶初始 activation_strength=0.0（沉默狀態），用 sigmoid 函數逐步提升，約一週後達到可檢索閾值，兩週後完全成熟。這模仿了神經科學中 engram 形成「先沉默後活化」的發現。
4. **Reconsolidation upon retrieval**（提取後重新整合）：被檢索的記憶進入 60 分鐘的 lability window，新資訊可以修正舊記憶。
5. **Entity knowledge graphs**（實體知識圖譜）：長期語義儲存，支援 multi-hop traversal。
6. **Hybrid multi-cue retrieval**（混合多線索檢索）：優先從短期 hot cache（毫秒級）→ 溫 episodic store → 知識圖譜逐層檢索。

方法論上最值得注意的是他們引入了 **synthetic calibration methodology**——用 LLM 生成的合成語料來推導所有 pipeline 閾值，完全避免接觸 benchmark 資料，消除評估洩漏。這在 memory 研究中非常少見。

實驗在兩個 benchmark 上：
- VSCode issue-tracking dataset（13K issues, 120K events）：dedup consolidation 達到 97.2% retention precision / 58% store reduction
- LongMemEval personal-chat benchmark（475 sessions, ~540K turns）：首次做 streaming M-tier evaluation，在 200K token context budget 下匹配 raw retrieval accuracy（70.1% vs. 71.2%，CI 重疊），同時提供可調的 accuracy/store-size operating curve。在 S-tier（50 sessions）上 dedup consolidation 比 baseline 高出 +13.3 pp。

四個機制有 ablation（consolidation, forgetting, graph retrieval, importance scoring），兩個（maturation, reconsolidation）因為 benchmark 限制只實作未 ablation——maturation 需要數週的反覆檢索才能觸發，reconsolidation 需要跨 session 矛盾，而 LongMemEval 的設計不包含這些場景。

**閱讀判斷**：這篇是目前看過最完整的工程落地型 agent memory 論文。方法不是純概念映射，每個機制都有對應的系統設計（TTL、decay rate、sigmoid 參數），而且 synthetic calibration 和 streaming evaluation 都是方法論上的創新。和早上看的 HiAgent 比：HiAgent 側重 task planning 的 working memory 管理，這篇側重長期記憶的保存/遺忘/成熟——兩者互補。如果你在做 production agent 的記憶系統，這篇的架構可以直接參考。建議優先看 §3-6（架構、consolidation、forgetting、maturation）和 Table 2（importance scoring factors）。

## 5. From Storage to Experience: A Survey on the Evolution of LLM Agent Memory Mechanisms

- **arXiv**: 2605.06716
- **Link**: https://arxiv.org/abs/2605.06716
- **Venue**: ACL 2026 Findings
- **Authors**: Jinghao Luo, Yuchen Tian, Chuxue Cao, Ziyang Luo, Hongzhan Lin, Kaixin Li, Chuyi Kong, Ruichao Yang, Jing Ma

這篇 survey 提出了一個演化框架來理解 LLM agent 記憶機制的發展，把記憶分為三個階段：

1. **Storage**（軌跡保存）：最基礎的層級，忠實記錄 interaction trajectory，不做轉換。形式化為累積軌跡集合 ℳ_raw = {τ_i}。
2. **Reflection**（軌跡提煉）：引入語義轉換映射 F_ref: T → S，對已完成軌跡做品質篩選和反思，注入提煉後的洞察回記憶庫。
3. **Experience**（軌跡抽象）：最高層級，跨軌跡壓縮成通用策略規則。滿足 Minimum Description Length（MDL）原則——把冗餘軌跡壓縮成通用 schema，|K| ≪ Σ|τ|。

三個演化驅動力：
- Long-range consistency（長程一致性）：解決 LLM 的狀態和目標一致性問題
- Dynamic environment（動態環境）：適應環境變化需要記憶的動態管理
- Continual learning（持續學習）：最終目標是讓 agent 從經驗中持續學習

特別值得注意的是 Experience 階段的兩個前沿機制：
- **Proactive exploration**（主動探索）：讓 agent 從被動記錄者變成目標驅動的經驗收集者
- **Cross-trajectory abstraction**（跨軌跡抽象）：把孤立的互動軌跡壓縮成通用策略模式

**閱讀判斷**：這篇 survey 的 Storage → Reflection → Experience 演化框架有清晰的邏輯，把 OS 工程派和認知科學派兩條研究路線統一起來了。如果你需要一張全局地圖來理解 agent memory 領域，這是目前最完整的框架之一。不過作為 survey 它更多是分類和整合，沒有新的實驗。建議搭配 2605.08538（Human-Inspired Memory）一起看——那篇是工程落地，這篇是理論框架。
