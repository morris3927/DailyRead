# Agent Memory — 2026-05-22

## 1. HAGE: Harnessing Agentic Memory via RL-Driven Weighted Graph Evolution

- **arXiv**: 2605.09942
- **Link**: https://arxiv.org/abs/2605.09942
- **全文來源**: arXiv HTML (完整讀取至 Section 3.3+)

### 這篇在說什麼

HAGE（Harnessing Agentic Memory via RL-Driven Weighted Graph Evolution）要解決的問題是：現有的 agent memory graph 大多只用二元關係或固定權重的邊，無法捕捉關係的「強度」和「查詢依賴性」。換句話說，當 agent 在記憶圖上做檢索時，現有系統把所有邊當成等價的，或者用固定的啟發式規則做遍歷。但實際上，同一條邊在不同的查詢意圖下可能完全不同——時間邊對時間序列問題很重要，但對實體屬性問題可能無用甚至干擾。

HAGE 的核心想法是把記憶檢索重新定義為「查詢條件化的圖遍歷」：記憶被組織成多關係視圖的加權圖，每條邊有可訓練的關係特徵向量（temporal, semantic, causal, entity 四個維度），給定一個查詢，RL-based 的路由網路動態調整邊的權重，讓遍歷能優先走「結構上重要但語義上遠」的橋節點。這讓記憶檢索不再是純向量相似度搜索，而是結構化的、可學習的搜索。

### 主要貢獻

1. **加權多關係記憶圖架構**：不再用二元邊或固定權重，而是每條邊附帶一個可訓練的關係特徵向量（R=4 維度：temporal, semantic, causal, entity），可以學習不同查詢意圖下不同關係類型的重要性。這比之前 A-MEM、MemoryBank 等系統用啟發式分數或固定規則的方式更精細。

2. **RL-driven 查詢條件化遍歷**：用強化學習訓練一個 QueryRouter（輕量 MLP），根據查詢意圖和邊特徵動態計算遍歷分數。這把「走哪條邊」從固定規則變成可學習的策略，可以用下游任務回饋來優化。

3. **語義 + 結構的疊加遍歷分數**：最終的遍歷分數是語義相似度（cosine）和結構權重（QueryRouter 輸出）的加權和：S(nj|ni,q) = λ·cos(vj,q) + (1-λ)·wij(q)。這保證了即使語義上不相似的橋節點也能被遍歷到，解決了純語義搜索的局限性。

### 方法 / pipeline

HAGE 的完整 pipeline：

1. **記憶建構**：每個事件被封裝為 Event-Node ni = ⟨ci, τi, vi, Ai⟩（內容、時間戳、嵌入向量、元數據）。記憶圖是有向多關係圖，邊的類型包括 temporal、semantic、causal、entity 四種。

2. **關係特徵向量初始化**：每條邊 (i,j) 有可訓練的特徵向量 eij ∈ ℝ⁴。初始化時可以用 LLM-based edge-scoring cache 來給初始值 [stemp, ssem, scausal, sent]，或者用 one-hot 編碼對應邊的主要關係類型。

3. **查詢條件化檢索**（四步）：
   - *Query Analysis*：LLM classifier 識別查詢的關係意圖 Tq，生成嵌入 q→。
   - *Anchor Identification*：從多個信號（dense retrieval、sparse matching、temporal filtering）找出初始錨點節點。
   - *Weighted Traversal*：從錨點出發，用加權遍歷策略擴展。對每條邊，把靜態特徵 eij、查詢意圖嵌入 vTq、兩端節點與查詢的 cosine similarity 拼接成增強特徵 ẽij，然後過 QueryRouter MLP 得到結構權重 wij(q) = softplus(MLP([q→; ẽij]))。最終分數 S(nj|ni,q) = λ·cos(vj,q) + (1-λ)·wij(q)。
   - *Context Synthesis*：把遍歷到的節點組合成檢索上下文。

4. **RL 訓練**：把遍歷建模為 sequential decision process，用 downstream task reward 來訓練 QueryRouter 和邊特徵向量。只需要 node-level evidence targets，不需要完整的 path-level supervision。這大大降低了標注成本。

### 實驗設計

- **基準**：LoCoMo（長對話記憶基準）和另一個 agent 記憶基準。
- **基線**：與 A-MEM、MemoryBank、RAG、Full Context 等方法比較。
- **主要結果**：HAGE 在長程推理準確率上優於所有基線，同時保持了良好的效率-準確率權衡。特別是在需要多跳推理的任務上，HAGE 的加權遍歷比純語義搜索有顯著優勢。
- **消融實驗**：Joint optimization（routing + edge features）比 routing-only 和 edge-only 都好，證明兩者需要聯合訓練。移除結構權重（只留語義相似度）會導致橋節點被跳過。

### かに讀後判斷

**推薦 Morris 點開。** HAGE 是 agent memory 領域近期最有結構性的貢獻之一。它不是又一個「加個圖」的論文，而是系統性地解決了「記憶圖上怎麼走」的問題——把遍歷策略從啟發式變成可學習的，而且用 RL 結合下游回饋來訓練，這是一個重要的方向性進展。

- 5/21 的 EvolveMem（2605.13941）是讓記憶檢索基礎設施自演化，HAGE 則是用 RL 學習遍歷策略。兩者互補：EvolveMem 優化的是記憶的組織方式，HAGE 優化的是記憶的檢索路徑。
- 今天的 2605.17625（Episodic-Semantic Dual-Process）關注的是記憶的層次結構（episodic vs. semantic），和 HAGE 關注的遍歷策略是不同維度。

## 2. Episodic-Semantic Memory Architecture for Long-Horizon Scientific Agents

- **arXiv**: 2605.17625
- **Link**: https://arxiv.org/abs/2605.17625
- **全文來源**: arXiv HTML (完整讀取至 Section 2.5+)

### 這篇在說什麼

這篇論文提出了一個雙過程記憶架構（Dual-Process Memory Architecture），專門為長程科學研究 agent 設計。核心問題是：當 agent 需要和科學家持續互動數千到數萬條訊息時，context window 會被撐爆，而 RAG 又會在需要「最新狀態」的查詢上徹底失敗（因為 cosine similarity 無法區分「歷史上的某個值」和「當前的值」）。

作者從認知科學的雙過程理論出發，把記憶分成兩層：
- **Episodic Buffer**：固定 10 則訊息的滑動窗口，處理「最近的對話狀態」。這保證了對當前參數和最近事件的即時存取。
- **Neocortical Profile**：由背景 LLM 非同步增量整併的結構化知識檔案，處理「長期累積的科學事實」。每則訊息後自動觸發整併，生長速度約每則訊息 3 tokens。

這個設計的關鍵洞察是：科學研究對記憶的要求和社交模擬完全不同。科學家需要的是精確的參數回憶（「當前的顯著性閾值是多少？」）、矛盾資訊的更新（「假設從 A 變成 B」）、和多跳推理（跨多個實驗階段追蹤因果鏈）。這些需求讓傳統的 RAG 和滑動窗口都不夠用。

### 主要貢獻

1. **雙過程記憶架構**：將記憶明確分為 episodic（短期、固定窗口、原始對話追蹤）和 neocortical（長期、增量整併、結構化知識）兩層。這不是又一個 hierarchical memory，而是基於認知科學雙過程理論的有理論基礎的分層。

2. **大規模跨模型驗證**：15,000 則訊息、6 個 LLM（OpenAI、Anthropic、Google 三家族）、1,440 個查詢。這是目前 agent memory 評估中最大的規模之一。結果顯示雙過程架構在 10,000+ 訊息時仍然維持 70–85% 準確率，而 full-context 方法在 10,000 則時因為 context overflow 而失敗。

3. **揭露 RAG 的根本限制**：RAG 在歷史事實檢索上表現好（60–85%），但在「當前狀態」查詢上完全失敗（0%）。原因是 cosine similarity 無法區分時間先後——多個段落都提到「顯著性閾值」時，RAG 會隨機返回舊值。這是一個非常重要的發現。

4. **Sim-to-Real gap 識別**：合成測試中記憶增長是常數級的，但真實工作流中是線性增長的（~3 tokens/message），整併品質才是擴展性的主要瓶頸。

### 方法 / pipeline

雙過程架構的完整 pipeline：

1. **Episodic Buffer**：
   - 固定窗口 W=10 則最近訊息
   - 確定性替換：新訊息進來，最舊的出去
   - 存取延遲：1–2 秒
   - Token 成本：常數級（~10 則訊息的 token 數）

2. **Neocortical Profile**：
   - 每則訊息後，背景 LLM 非同步做增量整併（incremental consolidation）
   - 整併不是存檔/壓縮，而是主動的知識更新：識別矛盾、更新參數、合併重複
   - 生長速度：~3 tokens/message（遠低於 full context 的線性增長）
   - 領域特定提示詞：針對生醫研究設計的結構化整併 prompt，保留精確數值和因果鏈

3. **查詢路由**：
   - 時間/數值查詢 → 走 episodic buffer（需要最新狀態）
   - 歷史/事實查詢 → 走 neocortical profile（需要長期累積知識）
   - 混合查詢 → 兩層合併

4. **與 MemGPT 的區別**：
   - MemGPT 需要 LLM 自己管理記憶分頁（顯式記憶操作），雙過程架構是自動的隱式整併
   - MemGPT 的分頁可能把關鍵資訊推出 context，雙過程的 episodic buffer 保證最近狀態永遠可見
   - 整併粒度不同：MemGPT 按段落分頁，雙過程按訊息增量整併

### 實驗設計

- **規模**：15,000 則訊息的生醫研究模擬，涵蓋假說演變、參數更新、多跳推理
- **跨模型**：6 個 LLM（OpenAI GPT-4o、GPT-4o-mini；Anthropic Claude 3.5 Sonnet、Claude 3 Haiku；Google Gemini 1.5 Pro、Gemini 1.5 Flash）
- **基線**：Full Context、Sliding Window、RAG、MemGPT-style 分頁
- **主要結果**：
  - Full context 在 ~10,000 訊息時崩潰（context overflow）
  - RAG 在歷史事實檢索上 60–85%，但在「當前狀態」查詢上 0%
  - 雙過程架構在所有查詢類型上維持 70–85%，使用 62% 更少的 tokens（45,434 vs 120,000+）
  - 雙過程在數值/時間查詢上特別強（65–90%），RAG 在歷史檢索上更好（60–85%）——兩者互補

目前從 HTML 讀到了完整的方法設計和大部分實驗結果。消融實驗的具體數字需要看完整 PDF。

### かに讀後判斷

**強烈推薦 Morris 點開。** 這篇是 agent memory 領域的重要貢獻，原因有三：

1. **首次系統性地證明 RAG 在「當前狀態」查詢上完全失敗**——這對所有用 RAG 做 agent memory 的系統都是一記警鐘。之前很多論文暗示 RAG 是夠用的，這篇用 0% 的數字直接打臉。

2. **雙過程架構的設計有認知科學基礎**——不是隨便分兩層，而是對應了認知科學中 hippocampus-neocortex 的分工。Episodic buffer 處理最新狀態、neocortical profile 處理長期知識，兩者的查詢路由也很自然。

3. **15,000 訊息的跨模型驗證是迄今最大規模的 agent memory 評估**——之前的大多在幾百到幾千則訊息的規模。

和前幾天的論文對照：
- 5/21 的 EvolveMem 和 EvoMemBench 關注的是記憶的自演化和基準設計，這篇關注的是記憶的層次結構和擴展性。互補視角。
- 今天的 HAGE 關注的是記憶圖上的遍歷策略，這篇關注的是記憶的層次組織。兩者都是 agent memory 的重要維度。

## 3. ScrapMem: A Bio-inspired Framework for On-device Personalized Agent Memory via Optical Forgetting

- **arXiv**: 2605.03804
- **Link**: https://arxiv.org/abs/2605.03804
- **全文來源**: arXiv HTML (讀取至 Section 4.3)

### 這篇在說什麼

ScrapMem 解決的是一個不同的 agent memory 問題：在資源受限的邊緣裝置上，如何給 LLM agent 做長期多模態個人化記憶？現有的 agent memory 系統（MemGPT、A-MEM 等）主要在雲端環境運行，假設有充足的計算和存儲資源。但手機、IoT 等邊緣裝置上的 agent 需要在有限資源下維護多模態記憶（照片、影片、文字、行為記錄），這是一個不同的約束條件。

ScrapMem 的核心靈感來自認知科學的互補學習系統（CLS）理論和人類的剪貼簿實踐：把多模態資料整合成「剪貼簿頁面」，然後用「光學遺忘」（Optical Forgetting）——模仿記憶隨時間退化——來逐步壓縮舊記憶，降低存儲成本同時保留核心語義。另外用 Episodic Memory Graph（EM-Graph）來組織因果-時間結構，支持多跳推理。

### 主要貢獻

1. **Scrapbook Page 統一表示**：把異構多模態資料（照片、影片、文字、行為記錄）整合成統一的剪貼簿頁面，用 OCR + VLM 做光學感知，把所有模態轉成混合節點集（語義文本節點 + 視覺 token 節點）。

2. **Optical Forgetting 機制**：隨時間推移，舊的剪貼簿頁面會被逐步降低解析度（類似照片隨時間模糊），壓縮存儲空間同時保留核心語義。實驗顯示可以減少 93% 的存儲空間。

3. **EM-Graph 因果-時間結構**：用 EM-Path（事件路徑）組織記憶節點，支持多跳推理。配合 Q-matrix（節點-路徑二值矩陣）做高效檢索匹配。

### 方法 / pipeline

1. **Scrapbook Page 整併與光學感知**：
   - 異構資料 → 剪貼簿頁面（時間分組）
   - OCR 提取文字、VLM 提取視覺描述
   - LLM 提取語義節點（實體、事件、關係）
   - 混合節點集 = 語義文本節點 ∪ 視覺 token 節點

2. **EM-Graph 建構**：
   - 節點組成 EM-Path（因果-時間事件鏈）
   - Q-matrix 做節點-路徑索引
   - 查詢時：query → 提取節點 → Q-matrix 匹配 → 返回相關 EM-Path

3. **Optical Forgetting**：
   - 舊頁面經過時間衰減算子 Dτ(·)
   - 降低解析度：保留核心語義，丟棄細節
   - 結果：93% 存儲減少，Joint@10 達到 51.0%（SOTA）

### 實驗設計

- **基準**：ATM-Bench（多模態個人化記憶基準）
- **主要結果**：Joint@10 = 51.0%（SOTA），Recall@10 = 70.3%，存儲減少 93%
- **基線比較**：與 MemoryBank、A-MEM、RAG 等比較
- 從 HTML 讀到了方法核心和初步結果。ATM-Bench 的具體任務定義和消融實驗需要完整 PDF 確認。

### かに讀後判斷

**值得關注但不作為今日重點推薦。** ScrapMem 的 Optical Forgetting 概念很有趣——用解析度衰減來模擬記憶退化是一個新的壓縮策略。但這篇的核心約束是「邊緣裝置上的多模態個人化記憶」，和 DailyRead 主要關注的 agent memory（服務端、長程推理）的場景不太一樣。如果你對 on-device AI 或多模態記憶壓縮有興趣，值得細看；但如果聚焦在 agent 的推理記憶架構，HAGE 和 2605.17625 更相關。

和今天的 HAGE 對照：HAGE 關注「怎麼走」，ScrapMem 關注「怎麼壓縮」——不同的記憶問題。
