# Agent Memory — 2026-05-28

## 1. Causal Memory Intervention (CMI): Causal Intervention-Based Memory Selection for Long-Horizon LLM Agents

- **arXiv**: 2605.17641
- **Link**: https://arxiv.org/abs/2605.17641
- **Authors**: Saksham Srivastava, He
- **Submitted**: 2026-05-17

### 這篇在說什麼

Long-horizon LLM agents 仰賴 persistent memory 來維持跨 session 的知識延續，但現有 memory 系統幾乎全用 semantic similarity 做 retrieval，把「retrieved memory」當成「useful memory」。這個假設非常脆弱：一條 memory 可能主題相關但實際上已過時、無關甚至有害（adversarial / poisoned），而 LLM 卻會高信心地把它塞進回答裡。這篇論文的核心洞察是：**memory selection 不是 retrieval problem，而是 intervention problem**。CMI 把每條 candidate memory 當成一個「intervention」——加入它到底會不會讓回答變好？如果不會，或者加入後模型回答不穩定，就不該選它。

這和之前 DailyRead 看過的 A-Mem (Zettelkasten 動態索引)、ActMem (causal + semantic graph)、MemTier (tripartite + attribution) 走的方向不同：A-Mem 和 ActMem 都是在 memory 的組織方式上做改變，MemTier 是在 retrieval signal 的設計上做改變，而 CMI 直接在「要不要用這條 memory」這個 decision 上引入因果推論框架。

### 主要貢獻

1. **Causal Memory Intervention (CMI) 框架**：把 memory selection 從 similarity-based retrieval 重構為 intervention-based decision problem。對每條 candidate memory，用三個條件 (no-memory / with-memory / perturbed-memory) 比較模型輸出，估計該 memory 的 causal effect。
2. **Causal-LoCoMo benchmark**：從 LoCoMo 長對話資料衍生的 causally annotated memory-selection benchmark。每個 example 包含 user request、structured memory bank（useful memories + irrelevant distractors + synthetic harmful memories），用來測試 agent 在有干擾記憶下的選擇能力。87 個 filtered examples。
3. **全面 baseline 比較**：CMI 對比 vector、graph、reflection、summary、full-history、no-memory 六種策略，在 task score、success rate、useful-memory F1、harmful-memory rejection 四個維度上都取得最強 balance。
4. **Zero poisoned-memory adoption**：CMI 是所有方法中唯一做到有害記憶零採用的，這對 LLM agent 的安全性非常關鍵（之前 MemoryGraft 等工作已經顯示 poisoned experience retrieval 可以持續影響 agent 行為）。

### 方法 / pipeline

CMI 的 pipeline 分三步：

1. **Candidate Proposal**：用 hybrid retriever（BM25 + dense embedding）從 memory bank 中取出小量 candidates（top-k）。
2. **Intervention Scoring**：對每條 candidate memory $m_i$，比較模型在三種條件下的輸出：
   - **No-memory condition**：prompt 不含 $m_i$，得到 baseline answer $y_\emptyset$
   - **With-memory condition**：prompt 加入 $m_i$，得到 answer $y_{m_i}$
   - **Perturbed-memory condition**：把 $m_i$ 中的關鍵實體替換成同義但矛盾的版本，得到 answer $y_{m_i'}$
   
   計算 causal effect：$\Delta_{\text{useful}} = \text{score}(y_{m_i}) - \text{score}(y_\emptyset)$；計算 stability：$\text{sim}(y_{m_i}, y_{m_i'})$。
3. **Memory Selection**：選擇滿足兩個條件的 memory：
   - Causal improvement：$\Delta_{\text{useful}} > 0$（加入後比不加好）
   - Stability：perturbed version 下的輸出與 with-memory 版本差異夠大（確認模型確實在使用 memory 中的資訊，而非隨意改變）

這個設計的精妙之處在於：它不只看「memory 有沒有用」，還看「模型是不是真的在用這條 memory 的資訊」——perturbed condition 確認了因果鏈。

### 實驗設計

- **Benchmark**：Causal-LoCoMo，從 LoCoMo (Maharana et al., 2024) 衍生，87 個 filtered examples。包含 temporal reasoning、multi-evidence questions、factual memory questions、inferential memory questions 四類。
- **Baselines**：Vector memory (dense retrieval)、Graph memory、Reflection memory (Shinn et al., 2023)、Summary memory、Full-history prompting、No-memory。
- **Main results**：
  - CMI：task score 0.846, success rate 0.816, useful-memory F1 0.875
  - Harmful-memory rejection 0.990, zero poisoned-memory adoption
  - 相比之下，full-history 的 harmful-memory adoption 很高（把所有記憶都塞進 prompt）
  - Vector / graph 方法在 semantic similarity 上表現尚可，但無法區分 useful vs. harmful memories
- **Limitations**：目前只在 87 個 filtered examples 上評估（Causal-LoCoMo 的規模相對小）。每條 memory 需要 3 次 LLM inference（no-memory / with / perturbed），計算成本是 baseline 的 3×。論文沒有在真正的 long-horizon agent deployment（如 OpenClaw 跨天對話）上測試，而是在單次 QA setting 下模擬。

### かに讀後判斷

CMI 的核心 idea 非常清晰：memory selection 應該基於 causal effect 而非 semantic similarity。這和 MemTier 的 attribution loop 有精神上的呼應（都用「outcome 來判斷記憶價值」），但 CMI 走得更遠——它不只是更新 weight，而是直接用 counterfactual 來決定要不要採用。不過有三個限制值得深讀時注意：

1. **3× inference 成本**：每條 candidate 需要 3 次 LLM call。在 real-time agent 系統中（如 OpenClaw 每次 prompt 都要檢索 memory），這個成本可能不 practical。論文有沒有討論 amortization 或 caching 策略？
2. **Benchmark 規模**：87 examples 偏小。需要看 CMI 在更大規模的 long-horizon setting（如 LongMemEval 的 500 題）下是否仍然有效。
3. **和 MemTier 的關係**：CMI 做的是「selection」，MemTier 做的是「retrieval + attribution」。兩者是互補而非衝突——CMI 可以接在 MemTier 的 retrieval 結果之後做二次過濾。

值得 Morris 點開深讀。重點看 Section 3（CMI method）和 Section 4（experimental results 和 ablation），特別是 ablation 中 perturbed condition 的消融實驗，確認 stability constraint 是否真的關鍵。

## 2. MemTier: Tiered Memory Architecture and Retrieval Bottleneck Analysis for Long-Running LLM Agents

- **arXiv**: 2605.03675
- **Link**: https://arxiv.org/abs/2605.03675
- **Authors**: Bronislav Sidik, Prof. Lior Rokach (Ben-Gurion University of the Negev)
- **Submitted**: 2026-05-05, v3 updated 2026-05-25

### 這篇在說什麼

MemTier 針對一個非常具體、非常實際的問題：OpenClaw agent 在長時間運行（72 小時）後，tool-execution success rate 下降 14 個百分點，原因是現有的 flat-file memory 系統（20KB MEMORY.md + append-only daily logs）有四個 compounding failure modes：context collapse（截斷）、compaction discontinuity（62% compaction 事件造成行為斷裂）、structural blindness（flat text 無法區分 entity 關係 vs. 偶然共現）、no attribution loop（tool outcome 不反饋到 memory quality）。這不是一個抽象的研究問題，而是 OpenClaw 社區 Issue #33406 和 #62488 的真實用戶反饋。

MemTier 的定位很清楚：它是一個 OpenClaw plugin，targeting edge hardware（6GB GPU 上的 Qwen2.5-7B），不是追求 SOTA accuracy，而是要在受限環境下做出可用的 long-running memory。

### 主要貢獻

1. **Tripartite memory architecture**：Episodic JSONL store（daily entries，agent-private）→ 5-signal weighted retrieval engine → Asynchronous consolidation daemon（promoting episodic facts to semantic tier，project-shared）。三層之間有明確的 data flow 和 isolation boundary。
2. **5-signal weighted retrieval**：BM25 + time decay + cognitive weight + tier boost + semantic scoping（2-stage: semantic→episodic）。認知權重來自 tool-outcome attribution，不是 LLM 自己判斷，而是看這條 memory 在過去 tool call 中是否帶來成功。
3. **Diagnostic analysis of PPO weight learning**：這是論文最有趣的發現之一——PPO 適配 retrieval weights 完全無效。原因是 BM25 的 raw score 是 unbounded 的，會壓過所有 bounded signals（time decay, cognitive weight, tier boost），無論怎麼調 weight 都一樣。作者診斷出三個 failure modes：BM25 dominance、zero-variance advantage under uninitialised cognitive weight、以及 linear combination 下的 signal swamping。
4. **Consumer-grade performance**：在 LongMemEval-S (N=500) 上，Qwen2.5-7B on 6GB GPU 達到 Acc=0.382, F1=0.412（比 no-retrieval baseline 的 0.050 提升 33 個百分點）。加上 DeepSeek-V4-Flash fact pre-population，single-session recall 達到 0.686–0.732，方向性超過 RAG BM25 GPT-4o baseline (0.560)。
5. **Token efficiency finding**：LLM-extracted facts（~3.1/question）比 heuristic extraction（~509/question）在 F1 上好 2.9×。Precision beats coverage。

### 方法 / pipeline

MemTier 的架構分四個 Phase：

- **Phase 1a — Episodic JSONL Store**：每個 agent session 寫入 `~/.openclaw/workspace/memory/episodic/YYYY-MM-DD.jsonl`，entry schema 包含 id, timestamp, session_id, project, content, tokens, promoted (Boolean), cognitive_weight ∈ [-1,1]。Cognitive weight 初始為 0，由 attribution loop 更新。
- **Phase 1b — Weighted Retrieval Engine**：Score function $S(q, m_i) = \mathbf{w}^\top \boldsymbol{\phi}(q, m_i)$，where $\boldsymbol{\phi} = [\phi_{\text{sem}}, \phi_{\text{bm25}}, \phi_{\text{decay}}, \phi_{\text{cw}}, \phi_{\text{tier}}]$。Default weights: $\mathbf{w}_0 = [0, 0.35, 0.25, 0.25, 0.15]$。注意 $w_{\text{sem}} = 0$ 因為 semantic info 透過 Stage 1 scoping 進入，而非在 Stage 2 linear combination 中。
  - BM25：unbounded raw score，這是後來 PPO 失敗的根源。
  - Time decay：$e^{-\lambda \Delta t}$，$\lambda = 0.05$（half-life ≈ 14 days）。有 bypass rule：BM25 > 2.0 或 semantic scoping 命中時不衰減。
  - Cognitive weight：$(\text{CW} + 1) / 2$，從 $[-1,1]$ 映射到 $[0,1]$。
  - Tier boost：semantic tier 的 entries 得到 boost。
- **Phase 1c — Attribution Loop**：Tool call 結束後，根據 outcome reward $r \in \{-0.5, 0, +1\}$ 和 attribution proxy $a_i$（Jaccard similarity between memory content and tool call context）更新 CW：$\text{CW}_i \leftarrow \text{clip}(\text{CW}_i + \alpha \cdot r \cdot \hat{a}_i, -1, 1)$。
- **Phase 2a — Asynchronous Consolidation Daemon**：Promote episodic entries to semantic tier。Semantic tier 是 project-shared 的（不是 agent-private），讓多個 agent 可以共享提煉後的事實。
- **Phase 2b — PPO Weight Learning**（**失敗的診斷同樣重要**）：嘗試用 PPO 學習 retrieval weights，但發現完全無效。原因分析是這篇論文的亮點之一。

### 實驗設計

- **Primary benchmark**：LongMemEval-S (N=500)，5 個 ability types：single-session recall, multi-session synthesis, temporal reasoning, knowledge update, abstention。和 LoCoMo 不同，LongMemEval-S 要求 storage 和 retrieval，conversations 不在 context 中可用。
- **模型**：Qwen2.5-7B（6GB GPU），DeepSeek-V4-Flash 用於 fact pre-population。
- **Main results**：
  - No-retrieval baseline: Acc=0.050, F1=0.050
  - Full system (5-signal + attribution): Acc=0.382, F1=0.412
  - With DeepSeek-V4-Flash pre-population: single-session recall 0.686–0.732, temporal reasoning 0.316, multi-session synthesis 0.180
  - PPO weight adaptation: **no measurable gain** — BM25 dominance kills all other signals
- **Ablation**：
  - 移除 attribution loop：F1 下降
  - 移除 consolidation daemon：multi-session synthesis 受損
  - BM25-only retrieval：比 full system 差但不是最差
  - LLM-extracted facts vs. heuristic extraction：3.1 tokens vs. 509 tokens, F1 差 2.9×
- **Limitations**：
  - 診斷了 PPO 失敗但沒有完全解決（提出 score normalisation 和 recall-first dense retrieval 作為未來方向）
  - 沒有和 ProMem 等高 accuracy 系統做 controlled comparison（定位不同）
  - LongMemEval-S 的 evaluation protocol 和 LoCoMo 不一樣，不能直接跨 benchmark 比較

### かに讀後判斷

MemTier 是一篇非常務實的系統論文。它不是追求 SOTA accuracy，而是回答一個非常具體的問題：在 edge hardware 上，OpenClaw 的 flat-file memory 為什麼會爛掉，以及怎麼修。診斷部分（4 failure modes + PPO failure analysis）比解決方案本身更有價值——它告訴我們 BM25 的 unbounded score 是 retrieval bottleneck 的根源。

和之前 DailyRead 看過的幾篇有明確的對話關係：
- **vs. AgentIR**（2026-05-27 推薦）：AgentIR 用 cascade routing 跳過 63% dense queries，MemTier 用 5-signal weighted scoring 但發現 BM25 dominance 是瓶頸。兩者互補——AgentIR 解決的是「什麼時候不需要 dense retrieval」，MemTier 解決的是「在 retrieval 做 ranking 時怎麼組合多個 signal」。
- **vs. CMI**（今天另一篇推薦）：CMI 用 causal intervention 做二次 selection，MemTier 用 weighted scoring 做初次 retrieval。CMI 可以接在 MemTier 的 retrieval 結果之後。
- **vs. ActMem**（之前看過）：ActMem 用 causal + semantic graph，MemTier 用 linear combination of 5 signals。兩者都試圖超越 pure similarity，但路徑不同。

值得 Morris 點開深讀。重點看 Section 4 的 ablation（特別是 PPO 失敗的診斷）和 Section 5 的 invariance analysis（generator scale 和 retrieval weights 都不改善 → bottleneck 在 BM25-based retrieval architecture）。
