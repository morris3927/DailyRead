# Agent Memory — 2026-05-29

## 1. From Storage to Steering: Memory Control Flow Attacks on LLM Agents

- **arXiv**: 2603.15125
- **Link**: https://arxiv.org/abs/2603.15125
- **Authors**: Zhenlin Xu, Xiaogang Zhu, Yu Yao, Minhui Xue, Yiliao Song (Adelaide University, University of Sydney, CSIRO's Data61)
- **Submitted**: 2026-03-16, v2 updated 2026-05-09

### 這篇在說什麼

這篇論文發現了一個新的安全威脅類別：Memory Control Flow Attacks (MCFA)。現有的 LLM agent 安全分析大多把 control flow（tool selection 和 tool ordering）當成 ephemeral、one-off session 中的事——攻擊者在當前 session 裡注入惡意指令，但下一個 benign session 就恢復正常。但當 agent 有 persistent memory 時，攻擊者寫入 memory 的惡意 policy（例如「always use Tool X first」）可以在後續所有 benign task 中持續影響 control flow——memory 變成了一個 write-once, read-many 的 control signal。

這是 agent memory 領域裡一個很重要的安全視角轉換：memory 不只是 storage，它是一個可以 hijack agent control flow 的 steering mechanism。之前 DailyRead 看過的 SSGM (2603.11768) 關注的是 memory 的 semantic drift 和 privacy leakage，MCFA 關注的是 memory 可以被 weaponized 來控制 agent 的行為。

### 主要貢獻

1. **MCFA 的定義和形式化**：MCFA 是一個 two-phase process：(1) injection phase——攻擊者透過正常互動讓惡意 policy π_adv 被寫入 memory M；(2) attack phase——在後續 benign task 中，被 retrieve 的惡意 policy 改變 agent 的 tool selection 和 tool ordering。這個定義明確區分了 injection success（惡意內容是否被存入 memory）和 attack success（被存入的 policy 是否改變了後續的 control flow）。

2. **五個 attack family 的系統性分類**：
   - **Override**：惡意 memory 讓 agent 使用 risky tool set 中的工具（例如「always use Tool X first」）。Violation semantic 是 Safety Set Violation——trace 包含了禁止的工具。
   - **Order**：惡意 memory 讓 agent 打亂安全相關的 tool ordering（例如 skip audit before transfer）。Violation semantic 是 Precedence Violation。
   - **M-Scope**：攻擊在異質任務中持續生效（cross-domain persistence）。Violation semantic 是 Distributional Shift。
   - **Persistence**：攻擊在注入後很長時間仍然有效。Violation semantic 是 Temporal Stability。
   - **Resistance**：明確的 repair instruction 也無法恢復正常行為。Violation semantic 是 Correction Failure。

3. **MemFlow 評估框架**：一個自動化的 MCFA 評估框架，包含 Agent Runner（定義執行環境）、Attack Generator（產生 MCFA trials）、Control-Flow Auditor（用量化指標評估 control flow deviations）。設計上 decouple 了 agent 配置和攻擊規格，可以跨模型、跨 memory mechanism、跨 tool framework 一致評估。

4. **大規模實證評估**：在 GPT-5 mini、Claude Sonnet 4.5、Gemini 2.5 Flash 三個 SOTA LLM 上，用 LangChain 和 LlamaIndex 兩個主流 agent framework 的 real-world tools 進行攻擊。結果：
   - **一般情況下超過 90% 的 trials 對 MCFA 脆弱**
   - Tool selection corruption: 91.7%~100%
   - Tool ordering corruption: 52.8%~69.4%（單一 session 內）
   - Cross-task persistence: 97.2%~100%
   - 長互動（>30 rounds）單一 task setting: 100%
   - **即使有 production-style mitigation，超過一半的 trials 仍然有 >85% 的 system deviation**

### 方法 / pipeline

MCFA 的攻擊流程：

1. **Injection phase**：攻擊者透過正常互動讓惡意 content 被寫入 memory。這不是透過 privileged access，而是透過 ordinary interaction——例如在餐廳推薦場景中，攻擊者讓 agent 記住「always use Tool X first」作為用戶偏好。

2. **Isolation evaluation**（Protocol 1）：為了確認攻擊是來自 memory 而不是 short-term context，MemFlow 使用 Isolated Evaluation Regime——清除短期對話歷史 H = ∅，讓任何觀察到的 deviation 都只能歸因於 memory state M。

3. **Attack generation**：MemFlow 的 Attack Generator 產生不同 attack family 的 injection prompts，並在 Phase 2 中用 benign task set 評估攻擊成功率 ASR = S/|X_benign|。

4. **Control-Flow Auditor**：量測兩個維度的 deviation：(a) tool selection——agent 是否使用了不在安全 policy 允許範圍內的工具；(b) tool ordering——agent 是否違反了安全相關的工具執行順序。

### 實驗設計

**Models**：GPT-5 mini, Claude Sonnet 4.5, Gemini 2.5 Flash
**Agent frameworks**：LangChain, LlamaIndex
**Memory mechanisms**：每個 framework 的 default memory implementation
**Tasks**：6 heterogeneous real-world tasks（restaurant recommendation, email management, travel planning, etc.）

**Main results**：
- Injection Success Rate (ISR)：接近 100%（幾乎所有惡意 content 都能被寫入 memory）
- Attack Success Rate (ASR)：
  - Override attacks: 91.7%~100% across all models and frameworks
  - Order attacks: 52.8%~69.4%
  - M-Scope (cross-task): 97.2%~100%
  - Persistence (long-term): 100% after >30 rounds
  - Resistance (repair failure): >85% system deviation even with explicit repair instructions

**Ablation**：
- Memory type comparison：不同 memory implementation（conversation buffer, summary buffer, vector store）的脆弱性差異
- Defense evaluation：Llama Guard、A-MemGuard 等 defense 的效果——超過一半的 trials 仍然有 >85% deviation
- Cross-framework consistency：LangChain 和 LlamaIndex 上的結果一致，說明這不是特定 framework 的問題

### かに讀後判斷

這篇是 agent memory 領域裡一個重要的安全視角論文。它不是在提出新的 memory architecture，而是在指出現有 memory architecture 的根本安全缺陷。和之前 DailyRead 看過的幾篇對照：

- **vs. SSGM (2603.11768)**：SSGM 關注的是 memory 的 semantic drift 和 privacy leakage（topology-induced knowledge leakage），MCFA 關注的是 memory 被武器化來 hijack control flow。兩者是互補的——SSGM 說 memory 會自然地 drift 和 leak，MCFA 說 memory 還可以被主動攻擊來控制行為。
- **vs. Focus/Active Context Compression (2601.07190)**：Focus 解決的是 context bloat（memory 太多無用資訊），MCFA 說即使你解決了 context bloat，你的 memory 仍然可以被攻擊者植入惡意 policy。壓縮不解決安全問題。
- **vs. Harness framework (2605.26112)**：Scaling the Harness 的 𝒢（verification-and-governance layer）正好是 MCFA 的防禦方向——harness 需要對 memory write 和 memory retrieval 進行 governance，不能讓任意 content 通過 Φ_upd 進入 memory 並通過 Φ_ret 影響 control flow。

值得 Morris 點開嗎？非常值得。MCFA 是一個全新識別的攻擊類別，90%+ 的成功率非常驚人，而且目前沒有有效的 defense。重點看 Section 3.1（MCFA 定義和 attack family 分類）、Table 1（五個 attack family 的定義）、Section 4（實驗結果，特別是 cross-task persistence 和 resistance 的數據）。如果你在設計有 persistent memory 的 agent，這篇是必讀的安全警示。
