# Agent Memory — 2026-06-01

## 1. Is Agent Memory a Database? Rethinking Data Foundations for Long-Term AI Agent Memory (GEM)

- **arXiv / Venue / 類型**: arXiv 2605.26252 (cs.AI, cs.DB), 2026-05-25
- **Link**: https://arxiv.org/abs/2605.26252

### 這篇在說什麼

當前所有 agent memory 系統——不論是 MemGPT 的 tiered memory、Mem0 的 fact extraction、Zep 的 graph memory、還是各種 RL-driven memory——都犯了一個根本性的設計錯誤：它們把記憶當成資料庫在管。資料庫的 CRUD 操作是 record-level 的（create、read、update、delete），但 agent memory 需要的是 state-level 的演化語義——ingestion、revision、forgetting、retrieval。

這篇論文指出四個 recurring failure modes：（1）unregulated growth——記憶只增不減，重複和低相關 entry 累積；（2）missing semantic revision——更新是 append 而非整合，過時和新版並存導致 retrieval 時可能取到舊值；（3）absence of selective forgetting——eviction 靠年齡或容量而非相關性，重要事實和無關閒聊同時被淘汰；（4）read-only retrieval——讀取不影響狀態，頻繁存取的事實得不到 reinforcement，和過時內容競爭時沒有優勢。

### 主要貢獻

1. **四能力分析框架（Four-Capability Analytical Lens）**：用 relevance-driven retention、dependency-aware propagation、graded attenuation、state-modifying retrieval 四個能力軸分析所有主流 database paradigms（relational、key-value/document、RDF/property graph、temporal DB、vector DB）和五類 agent memory 系統（tiered、fact-extraction、graph-structured、consolidation-based、RL-driven），證明沒有任何一個涵蓋全部四個能力。

2. **Governed Evolving Memory (GEM) 抽象**：把 memory 定義為全局狀態 M_t = (D_t, S_t, P_t)——semantic units、structural organization、declarative evolution policies。四個 state-level operators 取代 CRUD：ingestion（合併而非 append）、revision（dependency-aware propagation）、forgetting（graded attenuation 而非 binary delete）、retrieval（state-modifying read）。六個 correctness conditions 管制狀態演化。

3. **三個結構性觀察（Structural Observations）**：證明沒有任何 record-level system（不論 storage model）能滿足 GEM 的正確性條件。這是理論上的 impossibility result，不只是「目前做不好」。

4. **MemState 原型**：在 property-graph backend 上實作 GEM，用 topic-based storage、typed dependencies、declarative policies。驗證可行性同時暴露原生引擎需要的 gap。

### 方法 / pipeline

GEM 的核心設計：

- **Memory State M_t = (D_t, S_t, P_t)**：D_t 是 semantic units（帶 value history 和 salience signal），S_t 是 structural organization（entity graph、dependency links），P_t 是 declarative evolution policies（何時 merge、何時 forget、何時 revise）。

- **四個 operators**：
  - **Ingestion**：新資訊進入時，不是 append 一筆 record，而是判斷是否 merge 到已有的 semantic unit、是否建立新的 dependency link。
  - **Revision**：當一個 unit 更新時，沿著 dependency graph propagation 到所有相關的 units（不是只更新一個 node 的 edge）。
  - **Forgetting**：不是 binary delete 或 FIFO eviction，而是 graded attenuation——降低 salience signal 但保留 audit trail。
  - **Retrieval**：讀取同時更新 salience，讓頻繁存取的內容保持突出。

- **六個 Correctness Conditions**：（論文定義了正式的條件，包括 consistency of propagation、bounded growth、graded attenuation bounds、retrieval salience monotonicity 等——具體條文在 Section 3.2-3.3，我已讀到框架描述但完整 formal conditions 需要讀完 Section 3。）

- **三個結構性觀察**：
  1. Record-level CRUD 無法表達 dependency-aware propagation（update 只改一筆，不會 cascade）。
  2. Record-level delete 無法做到 graded attenuation（binary 的，沒有「降級但保留」）。
  3. Record-level read 無法做到 state-modifying retrieval（read 不改 state）。

- **MemState 原型**：基於 property-graph（Neo4j-style），用 topic partition 做 storage unit、typed edges 做 dependencies、declarative policies 做 evolution rules。實驗驗證了 GEM 的可行性，但暴露了 property-graph backend 的效能瓶頸（特別是在 propagation 和 salience update 的 write amplification）。

### 實驗設計

這篇是 vision + prototype 論文，不是大規模 benchmark 論文。MemState 的驗證主要在可行性層面：

- **Table 1**：Systematic comparison of 5 database paradigms × 6 agent memory systems × 1 generative agents approach，沿四個能力軸打分。每個 cell 都有文字說明該 family 如何（不）address 那個能力。這是目前最完整的 agent memory 系統分類分析之一。

- **MemState prototype**：在 property-graph 上實作 GEM operators，驗證四個 operators 的可行性。暴露的 gap 包括：propagation 的 write amplification、salience update 的 transaction cost、和宣告式 policy 的語義覆蓋度。

- **三個研究方向**：(1) native engine（專為 GEM 設計的 storage 和 query engine），(2) trajectory-level correctness（不是 record-level ACID，而是 state trajectory 的 correctness），(3) privacy under multi-tenant memory。

- **資訊不足的部分**：我已讀完 abstract、introduction、Section 2 的四能力分析、和 Section 3 GEM 定義的前半段。MemState 的具體實驗數據和 benchmark 比較在 Section 4，三個研究方向的詳細論述在 Section 5，這些需要讀全文確認。但目前的核心論點——record-level CRUD 無法滿足 agent memory 的需求——已經從 Section 2 的分析清楚建立。

### かに讀後判斷

這篇是一個重要的 position + vision paper。它不是提出一個新 benchmark 或新 system 來打榜，而是從理論層面重新框架了整個 agent memory 的問題空間。

和之前追蹤的 STALE（2605.06527，處理 stale memory 問題）和 EvoMemBench（2605.18421，self-evolving memory benchmark）相比，GEM 的視角更高：STALE 問的是「agent 能不能辨識過時記憶」，EvoMemBench 問的是「memory 能不能自我演化」，GEM 問的是「為什麼所有現有 memory 系統都沒有正確的演化語義」。

和今天同時追蹤的 DeMem（2605.10870）相比：DeMem 從 decision theory 的角度重新定義「什麼值得記住」（preserve decision-relevant distinctions），GEM 從 data management 的角度重新定義「記憶應該怎麼演化」（state-level operators 取代 CRUD）。兩者互補：DeMem 回答「記什麼」，GEM 回答「怎麼管」。

## 2. Remember the Decision, Not the Description: A Rate-Distortion Framework for Agent Memory (DeMem)

- **arXiv / Venue / 類型**: arXiv 2605.10870 (cs.AI), 2026-05-11
- **Link**: https://arxiv.org/abs/2605.10870

### 這篇在說什麼

目前 agent memory 的主流設計邏輯是「記住過去發生了什麼」——用 relevance、salience、summary quality 這些描述性標準來決定存什麼、取什麼、壓縮什麼。但這篇論文指出一個根本問題：對 agent 來說，記憶的價值不在於它多準確地描述過去，而在於它能不能在有限 budget 下保留對決策有用的區分。

作者用 rate-distortion theory 重新框架 agent memory：記憶壓縮的 distortion 不是「描述失真」，而是「決策品質下降」。這給出一個 exact forgetting boundary——什麼可以安全忘記，什麼不能——和一個 memory-distortion frontier——memory budget 和決策品質之間的最優 tradeoff。

### 主要貢獻

1. **Decision-centric forgetting theory**：把 agent memory 正式框架為 rate-distortion 問題，distortion measure 是「compression 後決策品質的損失」。給出 exact forgetting boundary（安全合併的條件）和 memory-distortion frontier（最優 budget-quality tradeoff）。

2. **DeMem: Online memory learner with certified refinement**：一個 K-slot online memory 方法，只在資料證明「shared state 會導致 decision conflict」時才 refine partition。有 near-minimax regret 保證。

3. **LoCoMo benchmark 上的實驗驗證**：在描述性相似度只能 weak 預測 evidence compatibility（ρ=0.103, AUC=0.548）的情況下，DeMem 在相同 budget 下 recover 83% 的 gold evidence（vs. description-based 的 66%）。

### 方法 / pipeline

DeMem 的核心邏輯：

- **K runtime slots**：agent 有 K 個記憶 slot（不是無限的），每個 slot 對應一個 internal state。

- **Slot routing**：每個 (history, query) pair 被路由到一個 slot。如果兩個 history 被路由到同一個 slot，表示它們被視為「可以合併」。

- **Certified refinement**：不是一開始就分很多 slot，而是從粗 partition 開始，只在資料證明「當前 slot 會導致 decision conflict」時才 split。這是 online 的——每次收到新 data point，check 是否現有 partition 會讓這個 point 做出錯誤的決策。

- **Exact forgetting boundary**：理論上，兩個 history 可以安全合併（共享一個 memory slot）的條件是：在任何可能的 decision context 下，合併後的決策和分開的決策相同。如果不能保證，就必須分開存。

- **Near-minimax regret guarantee**：DeMem 的 online refinement 保證 regret 相對於最優 static partition 是 near-minimax 的。

### 實驗設計

- **Synthetic diagnostics**：控制環境下驗證 forgetting boundary 和 memory-distortion frontier 的理論預測。

- **LoCoMo benchmark**：長對話記憶 benchmark。在相同 K-slot budget 下比較 DeMem 和 description-based retrieval（用 semantic similarity 做 retrieval）。

- **主要結果**：
  - Description-based retrieval 的 Spearman correlation with evidence compatibility 只有 ρ=0.103（AUC=0.548），確認「描述相似 ≠ 決策相容」。
  - DeMem 在相同 budget 下 recover 83% gold evidence，description-based 只 recover 66%。
  - 在 85% 的 description-based failure cases 中，錯誤可以直接追溯到 evidence miss 或 dilution caused by description-based memory。

- **資訊不足的部分**：我已讀完 abstract、introduction、和 related work。DeMem 的具體演算法細節（slot routing 的實作、certified refinement 的計算成本）在 Section 3，LoCoMo 的完整實驗設定和 baselines 在 Section 4-5，需要讀全文確認。

### かに讀後判斷

DeMem 提出了一個非常乾淨的理論框架。它的核心 insight——「記憶應該保留決策相關的區分而非描述性內容」——簡單但深遠。這和 GEM（2605.26252）形成有趣的對照：GEM 問「memory 的正確演化語義是什麼」，DeMem 問「memory 該保留什麼區分」。

和之前追蹤的 STALE（過時記憶偵測）相比，DeMem 提供了一個更根本的理論基礎：STALE 在偵測「哪些記憶過時了」，DeMem 在定義「什麼情況下可以安全忘記」。STALE 是啟發式的，DeMem 有理論保證。

值得點開，特別看：
- Section 3 DeMem 演算法的完整描述
- Section 4-5 的實驗結果和 LoCoMo 詳細設定

## 3. SMMBench: A Benchmark for Source-Distributed Multimodal Agent Memory

- **arXiv / Venue / 類型**: arXiv 2605.15710 (cs.CL), 2026-05-15
- **Link**: https://arxiv.org/abs/2605.15710
- **HuggingFace**: https://huggingface.co/datasets/HuacanChai/SMMBench

### 這篇在說什麼

現有多模態記憶 benchmark 大多在 pre-assembled context 裡評估——所有資訊已經整理好放在一個 context 裡，agent 只需要 retrieve 和 reason。但真實世界裡，agent 的記憶是 source-distributed 的：相關證據散落在不同來源（conversations、profiles、screenshots、tables、images、documents），agent 需要先從多個來源 retrieve、align、再 compose。

SMMBench 是第一個專門測試 source-distributed multimodal memory 的 benchmark。

### 主要貢獻

1. **Source-distributed 評估框架**：把 multimodal memory 從「single curated context」推進到「multiple heterogeneous sources」，測試 agent 能不能 retrieve、align、compose 來自不同來源的 multimodal evidence。

2. **四個核心能力**：(1) cross-source multimodal reasoning、(2) conflict resolution、(3) preference reasoning、(4) memory-grounded action prediction。

3. **1877 個 samples，264 個 sources**：每個 sample 都 grounded 在多個真實或半真實的 heterogeneous sources 上。

### 方法 / pipeline

SMMBench 的設計：

- **Sources**：conversations、user profiles、screenshots、tables、images、documents 等多模態來源。
- **Tasks**：四類任務對應四個核心能力。每個 task 需要跨來源的 multimodal evidence alignment 和 composition。
- **Evaluation**：比對 agent 的回答和 ground truth，測試跨來源的 retrieve、align、compose 能力。

### 實驗設計

- 測試了 representative memory-style 和 retrieval-based baselines。
- 結果顯示 current systems 在 source-distributed multimodal memory 上仍然 struggle，特別是 conflict resolution 和 preference reasoning。
- 1877 samples，264 sources。

- **資訊不足的部分**：目前只從 abstract 和搜尋結果確認了框架設計和核心結果。具體的 baseline 名稱、per-capability 分數、和 failure analysis 需要讀全文確認。此篇標記為「僅 abstract 層級快速掃描」。

### かに讀後判斷

SMMBench 填補了一個重要的評估缺口：source-distributed multimodal memory。和之前追蹤的 WorldMemArena（action-world interaction loop）相比，WorldMemArena 測的是 memory 在行動中的生命週期，SMMBench 測的是 memory 在多來源情境下的 retrieve-align-compose 能力。兩者互補。

和今天同時追蹤的 GEM 及 DeMem 相比，SMMBench 是純 benchmark 論文，不提出新的 memory 架構，但提供了一個 GEM 和 DeMem 都還沒有被測試過的評估維度：source distribution。
