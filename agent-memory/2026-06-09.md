# Agent Memory — 2026-06-09

## 1. HiMem: Hierarchical Long-Term Memory for LLM Long-Horizon Agents

- **arXiv**: 2601.06377
- **Link**: https://arxiv.org/abs/2601.06377
- **Authors**: Xingxing Yang, Zhizhong Tan, Weiping Deng, Wenyong Wang (Macau University of Science and Technology)
- **Code**: https://github.com/jojopdq/HiMem

### 這篇在說什麼

現有的 LLM 長期記憶系統有三個結構性缺陷：(1) 語意錯位——提取出的記憶脫離原始對話脈絡，解析時間指涉與共指會出錯；(2) 單層結構——要嘛保存太多原始對話（高檢索成本），要嘛過度抽象（損失關鍵細節）；(3) 靜態更新——缺乏衝突偵測機制，新舊記憶矛盾時無法自我修正。HiMem 從認知科學出發，設計了一個雙層記憶架構：Episode Memory 保存細粒度的互動事件，Note Memory 保存穩定的知識單元，兩者透過語意連結形成層級結構，支援從抽象到具體的高效檢索，並有衝突感知的記憶再鞏固機制。

### 主要貢獻

1. **雙層記憶架構 Episode Memory + Note Memory**：Episode Memory 用 Topic-Aware Event–Surprise 雙通道分段策略，讓記憶邊界同時對齊主題轉換與認知突變；Note Memory 透過多階段知識抽取管線，獨立提取事實、偏好、使用者畫像三類知識。兩層透過語意連結形成層級，而不是單一扁平存儲。

2. **Topic-Aware Event–Surprise Dual-Channel Segmentation**：不只用主題轉換切分對話，還用認知突變（意圖、情感狀態的急遽變化）作為第二個分段信號，兩者用 OR 規則融合。單次掃描即完成分段，不需要多輪處理。

3. **衝突感知的記憶再鞏固（Memory Reconsolidation）**：檢索失敗時不是直接跳過，而是作為學習信號——從 Episode Memory 補充缺失知識、修正既有 Note Memory 中的矛盾。這讓記憶系統能在長期使用中自我演化。

4. **Hybrid 與 Best-effort 雙重檢索策略**：hybrid 同時查兩層最大化召回；best-effort 先查 Note Memory，只在證據不足時降階到 Episode Memory，用 LLM 判斷證據充分性。

### 方法 / pipeline

HiMem 的三個核心模組：

1. **記憶建構模組**：
   - Episode Memory：對話序列透過 LLM 聯合評估主題與驚訝信號，一次性輸出分段結果。每個 episode 包含 ID、時間戳、主題、摘要、元資料和原始對話段。
   - Note Memory：三階段抽取——Stage 1 抽取獨立可解釋的事實單元；Stage 2 從隱含資訊推論偏好與畫像（不引入新事實）；Stage 3 做去重、共指解析與時間正規化。每條知識以結構化記錄儲存。
   - 知識對齊：時間正規化、共指解析、隱含語意提取——Episode 優先保留原文脈絡，Note 優先抽象與正規化。

2. **記憶檢索模組**：
   - Hybrid 檢索：同時查 Episode + Note，最大化召回。
   - Best-effort 檢索：先查 Note Memory，LLM 評估證據充分性；不足時降階查 Episode Memory。無法回答的問題明確標記。

3. **記憶更新與自我演化模組**：
   - 固定 LLM 自評提示詞（temperature=0），二元判斷證據是否充分。
   - 證據不足時從 Episode 補充 + 衝突偵測 → 更新 Note Memory。
   - 這與迭代自精修不同：自評只作控制信號，不修改記憶內容。

### 實驗設計

- **Benchmark**: 長期對話基準測試（論文全文中應有具體名稱，目前從 HTML 確認為 long-horizon dialogue benchmarks）
- **Baseline**: 代表性長期記憶方法（具體名稱需看全文）
- **Metrics**: 準確率、一致性、長期推理能力、效率
- **Main results**: HiMem 在準確率、一致性與長期推理上穩定優於所有 baseline，同時維持有利的效率
- **Ablation**: 論文聲稱有 extensive ablation studies 驗證層級結構、語意對齊與衝突感知更新的必要性

**注意**：實驗細節（具體 benchmark 名稱、baseline 清單、數值結果）需看 PDF 全文才能完整確認。

### かに讀後判斷

HiMem 是近期 agent memory 設計中架構最完整的工作之一。它跟之前讀過的 DimMem（2605.15759，關注維度結構化記憶）和 Memory for Autonomous LLM Agents（2603.07670，機制與評估綜述）形成對話：DimMem 側重記憶的維度組織，HiMem 則用認知理論的雙層架構解決三個具體問題（語意錯位、單層瓶頸、靜態更新）。衝突感知再鞏固這個設計特別值得注意——它把檢索失敗當成學習機會，而不是錯誤。

## 2. CraniMem: Cranial Inspired Gated and Bounded Memory for Agentic Systems

- **arXiv**: 2603.15642
- **Link**: https://arxiv.org/abs/2603.15642
- **Authors**: Pearl Mody et al.
- **Code**: https://github.com/PearlMody05/Cranimem (PyPI: cranimem)

### 這篇在說什麼

目前 LLM agent 的記憶系統大多把記憶當外部資料庫，用 ad hoc 的讀寫規則，導致三個問題：不穩定的保留（重要事件被噪音覆蓋）、薄弱的跨時間整合、多 agent 間的信念同步困難。CraniMem 從神經認知科學出發，設計了一個有門控、有界的多階段記憶架構：短期用有界 episode buffer，長期用結構化知識圖譜，中間有排程的鞏固迴圈把高效用軌跡重播進圖譜並修剪低效用項目，控制記憶增長。

### 主要貢獻

1. **門控 + 有界 + 多階段記憶架構**：不是無限增長的向量庫，而是有明確的輸入門控、episode buffer、鞏固排程、知識圖譜四個階段。

2. **Goal-conditioned gating + utility tagging**：用 RAS（Reticular Activating System）啟發的門控機制過濾低顯著性輸入，只讓與目標相關的資訊進入記憶。

3. **Dual-store + scheduled consolidation**：episode buffer 存近期高保真軌跡，知識圖譜存穩定語意結構。鞏固排程把高效用 episode 重播進圖譜、修剪低效用項目。

4. **在 clean 和 noisy 設定下都優於 Vanilla RAG 和 Mem0**：特別是 noise drop 更小，顯示門控機制有效阻擋干擾。

### 方法 / pipeline

CraniMem 的架構如 Figure 1：

1. **Ingestion**：輸入經 RAS 啟發的門控模組，用目標條件判斷是否值得存入，同時標記效用值。

2. **Short-term storage**：通過門控的項目進入有界 episodic buffer，支援短期連續性。buffer 有容量上限，超出時按效用值與時間衰減淘汰。

3. **Consolidation loop**：定期從 buffer 中選擇高效用軌跡，透過 linkage engine 整合進知識圖譜。低效用軌跡被丟棄（Trash）。

4. **Dual-path retrieval**：查詢時可走 buffer 或知識圖譜，或兩條路徑同時查。

### 實驗設計

- **Benchmark**: HotpotQA 多跳問答（clean + noisy 設定）
- **Baselines**: Vanilla RAG、Mem0
- **Models**: Qwen2.5-7B-Instruct（主實驗）、Gemma-2-9B-IT、Qwen2.5-Coder-7B-Instruct、Mistral-7B-Instruct-v0.3（跨模型泛化）
- **Metrics**: F1 score、noise drop（clean vs noisy 的效能差距）
- **Main results**：
  - Qwen2.5-7B 上：CraniMem 在 clean 和 noisy 設定下整體優於 Vanilla RAG 和 Mem0，noise drop 最小
  - Gemma-2-9B-IT：noisy F1=0.323，noise drop=0.015（Vanilla RAG drop=0.160）
  - Qwen2.5-Coder-7B：noise drop=0.004（Vanilla RAG=0.079）
- **Tradeoff**：CraniMem 延遲較高（因為鞏固階段 + 知識圖譜存取），但換來更好的噪音抗性

### かに讀後判斷

CraniMem 的門控 + 有界設計解決了 agent memory 的實際痛點——噪音干擾和無限增長。跟 HiMem 的認知啟發雙層架構相比，CraniMem 更偏工程導向（門控、排程、圖譜都是可操作模組），而 HiMem 更偏認知理論驅動（分段策略、再鞏固機制）。兩者可以互補：HiMem 的衝突感知更新填補了 CraniMem 沒有明確處理的記憶矛盾問題，CraniMem 的門控機制則是 HiMem 缺少的噪音過濾層。

## 3. Distilling Feedback into Memory-as-a-Tool

- **arXiv**: 2601.05960
- **Link**: https://arxiv.org/abs/2601.05960
- **Authors**: Victor Gallego et al.
- **Code**: https://github.com/vicgalle/feedback-memory-as-a-tool
- **Data**: https://huggingface.co/datasets/vicgalle/rubric-feedback-bench
- **Venue**: ICLR 2026 Workshop on Memory for LLM-Based Agentic Systems

### 這篇在說什麼

測試時運算（test-time compute）的方法（如 iterative self-correction）效果很好但成本高昂，而且每次對話都要從頭重複推理。這篇提出把反覆修正的過程中的 feedback「蒸餾」成可檢索的指導原則，存入檔案系統形式的記憶，讓模型在未來任務中直接調用，而不是每次從零開始。這樣就把 inference-time reasoning 的成本分攤（amortize）到了記憶系統中。

### 主要貢獻

1. **Memory-as-a-Tool 框架**：記憶不是向量庫，而是 LLM 透過 tool calls 主動管理的檔案系統。讀取靠 `ls` + `read_file`，寫入靠 `write_file` + `edit_file`，模型自己決定什麼時候讀、什麼時候寫、怎麼抽象化。

2. **Rubric Feedback Bench**：42 個精心設計的場景，5 個任務類別，每個類別有 multi-dimensional rubric（3-7 個維度、4-5 個水準、加權評分），用於評估模型從 feedback 中學習的能力。

3. **Continual learning 設定**：不是單次評分，而是讓 agent 在同一 rubric 類別的連續三個任務上逐步改善，測試記憶是否能跨任務累積。

### 方法 / pipeline

1. **生成**：模型對任務 z 產生初始回應 x
2. **評估**：用私有 rubric 的 evaluator LLM 產生 feedback
3. **記憶更新**：模型決定是否更新記憶 M（tool call），把 feedback 抽象化為可重用原則
4. **檢索**：下次任務前，模型先 `ls /memories/` 看有哪些檔案，再 `read_file` 讀相關內容
5. **生成**：帶著檢索到的記憶產生回應

關鍵設計：檔名要語意化（`review_creative_rubric.txt` 而非 `note_1.txt`），抽象化而非記錄原始 feedback。

### 實驗設計

- **Models**: Claude Sonnet 4.5, GPT-5.1, Gemini 3 Pro
- **Baselines**: Zero-shot（無記憶）、Inference-time self-critique（多輪修正但不存記憶）
- **Benchmark**: Rubric Feedback Bench（42 個場景，5 類 rubric）
- **Protocol**: H=3 的 continual learning（同一 rubric 類別的三個相關任務）
- **Results**: Memory-as-a-Tool 在 H=3 後接近 self-critique 的表現，但推理成本大幅降低（只需一次 LLM 呼叫而非多輪）

### かに讀後判斷

這篇跟 HiMem 和 CraniMem 關注的角度不同：HiMem 和 CraniMem 解決的是「長期記憶怎麼組織」，這篇解決的是「推理成本怎麼分攤」。它的記憶設計很輕量（檔案系統 + tool calls），但核心洞見很有力——把 test-time reasoning 的成果存下來，下次直接用，而不是每次從頭來。這跟 agent memory 的「經驗累積」方向一致，但切入點是成本效益而非記憶架構。

**值得看**：Table 1（system prompt）、Appendix A（記憶系統的詳細行為）、Appendix B（rubric 類別摘錄）。開源程式碼和資料集，可直接重現。

## 4. MIRIX: Multi-Agent Memory System for LLM-Based Agents

- **arXiv**: 2507.07957
- **Link**: https://arxiv.org/abs/2507.07957

### 這篇在說什麼

現有 agent 記憶系統有三個根本限制：(1) 扁平單一結構——沒有分類路由到專門記憶類型；(2) 缺乏多模態支援——以文字為中心，無法處理圖像等非文字輸入；(3) 可擴展性差——原始輸入特別是圖像存儲成本太高，沒有有效的抽象層。MIRIX 提出六種記憶類型（Core, Episodic, Semantic, Procedural, Resource, Knowledge Vault）加上多 agent 架構（六個 Memory Manager + Meta Memory Manager + Chat Agent），並在兩個挑戰性基準上驗證。

### 主要貢獻

1. **六類記憶 + 多 agent 管理**：不只是短期/長期記憶，而是六種功能不同的記憶類型，每種有專門的 manager agent。
2. **ScreenshotVQA 基準**：收集 3 位博士生一個月的電腦截圖（5000-20000 張），構建需要深度語境理解的多跳問答。
3. **LOCOMO SOTA**：在長對話基準上達到 85.4%，超越既有方法 8%。
4. **效率**：比 RAG baseline 高 35% 準確率，同時減少 99.9% 存儲需求。

### かに讀後判斷

MIRIX 的六類記憶設計比 HiMem 和 CraniMem 更細粒度，但也更複雜。它的多模態支援（截圖理解）是目前其他 agent memory 工作沒有的。不過，六個 manager agent 的協調成本和延遲可能是實際部署的問題。適合 Morris 關注多模態記憶或實用系統設計時參考，但論文較長，建議先看 Section 2（應用場景）和 Section 4（實驗結果）。
