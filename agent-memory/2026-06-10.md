# Agent Memory — 2026-06-10

## 1. TriMem: Rethinking How to Remember — Beyond Atomic Facts in Lifelong LLM Agent Memory

- **arXiv**: 2605.19952
- **Link**: https://arxiv.org/abs/2605.19952
- **Authors**: Jingwei Sun et al.
- **類型**: arXiv preprint (cs.CL)

### 這篇在說什麼

目前 LLM agent 的長期記憶系統幾乎都採用「extracted fact」範式：用靜態 prompt 把對話壓縮成原子事實（atomic facts），然後存起來、匹配、注入下游推理。TriMem 指出這個範式有三個根本問題：（1）原子事實會丟失原始對話中的細粒度資訊；（2）孤立的事實無法支持深度推理；（3）靜態 prompt 無法在不同對話風格間保持一致的抽取粒度。TriMem 提出三層共存的記憶表示——raw dialogue segments（儲存保真度）、atomic facts（檢索效率）、synthesized profiles（語義整合），並用 TextGrad 做抽取和歸納 prompt 的終身優化。

### 主要貢獻

1. **三層記憶粒度共存**：不是選一個粒度，而是同時保留原始對話片段、抽取的原子事實、聚合的語義 profile，三層之間有 source identifier 錨定，解決了單一粒度的資訊損失問題。
2. **TextGrad prompt 優化**：用回應品質反饋迭代優化抽取和歸納 prompt，實現不需參數更新的終身演進，避免靜態 prompt 的粒度不一致問題。
3. **跨基準一致性**：在 LoCoMo 和 PerLTQA 兩個基準上，跨多個 LLM backbone 都穩定優於現有 memory baseline。

### 方法 / pipeline

TriMem 的架構分三層：

1. **Raw Dialogue Segments**：保留原始對話片段，用 source identifier 錨定到後續抽取層，確保儲存保真度。當需要細節時可以直接回溯原始對話。
2. **Atomic Facts**：從對話中抽取的原子事實，用於高效檢索。每個事實都有 source identifier 連結回原始對話片段。
3. **Synthesized Profiles**：把分散的原子事實聚合為整體語義理解，支持深度推理。Profile 透過 TextGrad 優化的歸納 prompt 生成。

TextGrad 優化流程：從 agent 的回應品質出發，計算梯度信號，反過來調整抽取 prompt 和歸納 prompt，使記憶系統隨使用而不斷改進。

### 實驗設計

- **基準**：LoCoMo（長對話記憶）和 PerLTQA（個人化長期問答）。
- **Backbone**：多個 LLM（具體型號需從全文確認）。
- **結果**：TriMem 在兩個基準上都穩定優於現有 memory baseline（包括 MemoryBank、Reflexion、LangMem 等）。
- 目前只從 abstract 和 landing page 能確認上述資訊，全文 HTML 不可用（LaTeX 格式無法轉換），方法細節（TextGrad 的具體 loss 設計、profile 的歸納流程）和實驗數字需讀 PDF 才能確認。

### かに讀後判斷

TriMem 的核心洞察——「原子事實不夠，需要多粒度共存」——和 agent memory 領域最近的趨勢高度吻合。Agentopia 的 memory files 也是多粒度的（general / characters / others），但 TriMem 更系統化地形式化了這個想法，而且用 TextGrad 做 prompt 終身優化是一個很聰明的設計，避免了手動調整抽取粒度的問題。

和之前看過的 Agent Memory (2606.06448) 相比，TriMem 更聚焦在「記憶表示」而非「系統效應」，兩者互補。值得注意 TriMem 的三層設計在實踐中的儲存和計算開銷，以及 TextGrad 在長期對話中的穩定性。

## 2. MemGraphRAG: Memory-based Multi-Agent System for Graph Retrieval-Augmented Generation

- **arXiv**: 2606.00610
- **Link**: https://arxiv.org/abs/2606.00610
- **Venue**: KDD 2026
- **Authors**: Qinggang Zhang et al. (Xiamen University, XMUDeepLIT)
- **類型**: Conference paper (KDD 2026)

### 這篇在說什麼

GraphRAG 用知識圖譜來提升 RAG 的檢索品質，但現有方法在圖構建階段有一個根本問題：每個 document chunk 獨立抽取三元組，缺乏全局視角，導致圖的品質低下（主題無關、邏輯衝突、結構碎片化）。MemGraphRAG 引入了一個記憶驅動的多 agent 系統來解決這個問題：共享的全局記憶讓多個抽取 agent 協同工作，動態解決衝突、維持結構連通性。雖然這篇的主要場景是 GraphRAG 而非 agent memory 本身，但它的三層記憶架構（Ontology Layer / Fact Layer / Passage Layer）和多 agent 共享記憶機制對 agent memory 的設計有直接參考價值。

### 主要貢獻

1. **診斷了 GraphRAG 效能下降的根本原因**：不是檢索演算法的問題，而是圖構建品質的問題。獨立抽取導致主題無關（40% 的低頻三元組是噪音）、邏輯衝突（互斥事實、時間衝突、粒度衝突）、結構碎片化。
2. **三層全局記憶架構**：Ontology Layer（schema + 抽取頻率）、Fact Layer（具體三元組）、Passage Layer（原始文本段落），三層之間有雙向連結（schema-instance alignment、fact-evidence grounding）。
3. **多 agent 協同抽取**：Extraction Agent、Detection Agent、Resolution Agent 三個 agent 共享全局記憶，Extraction Agent 抽取新事實，Detection Agent 偵測衝突，Resolution Agent 解決衝突。
4. **Memory-aware hierarchical retrieval**：針對構建的圖設計了分層檢索演算法，從語義層到事實層到證據層逐層縮小範圍。

### 方法 / pipeline

MemGraphRAG 分兩個階段：

1. **Memory-based Graph Construction**：
   - Global Memory (ℳ) 組織為三層：Ontology Layer ℳ_ont（schema + 頻率）、Fact Layer ℳ_fac（三元組）、Passage Layer ℳ_pas（原文段落）。
   - Multi-Agent Group (𝒜) 包含 Extraction Agent（抽取新事實）、Detection Agent（偵測衝突）、Resolution Agent（解決衝突）。
   - 流程：抽取 → 偵測衝突 → 解決衝突 → 更新記憶 → 繼續抽取，形成迭代循環。

2. **Memory-guided Online Retrieval**：
   - Multi-layer memory filtering：先在 schema 層過濾無關主題，再在 fact 層找相關推理路徑，最後在 passage 層定位原始證據。
   - 使用 Personalized PageRank 在圖上做結構感知的節點初始化。

### 實驗設計

- **基準**：四個 benchmark（具體名稱需從全文確認，包含 G-Medical）。
- **比較對象**：Vanilla RAG、MS-GraphRAG、HippoRAG、GFM-RAG 等。
- **關鍵發現**：GraphRAG 方法的 Recall 比 RAG 高（GFM-RAG: 84.3% vs RAG: 71.8%），但 Relevance 大幅下降（38.5% vs 62.9%），驗證了「更多檢索不等於更好檢索」的論點。MemGraphRAG 在圖品質、檢索品質和生成準確度上都穩定優於 baseline。
- **過濾實驗**：移除 40% 低頻三元組反而略微提升準確度（65.28% vs 64.85%），證實了大量抽取的三元組是噪音。

已從全文 HTML 閱讀完整的方法設計和初步實驗結果。

### かに讀後判斷

MemGraphRAG 對 agent memory 社群的價值不在 GraphRAG 本身，而在它的三層記憶架構和多 agent 共享記憶機制。Ontology / Fact / Passage 三層的設計和 TriMem 的 raw dialogue / atomic facts / synthesized profiles 有異曲同工之處，但 MemGraphRAG 更強調跨 agent 的記憶共享和衝突解決。對 Morris 研究的參考價值：

- 多 agent 共享記憶的衝突偵測/解決機制（Detection Agent + Resolution Agent）可以借鑑到 agent memory 的一致性維護問題
- 三層記憶的雙向連結設計（schema↔fact、fact↔passage）對記憶的可追溯性有啟發
- 過濾實驗的結論（40% 低頻三元組是噪音）對記憶去重和品質控制有參考價值

不需要深讀全文，但建議注意其多 agent 共享記憶的衝突解決機制和分層檢索設計。

## 3. From Context to Dreams: Architecting Memory for AI Agents (Red Hat Blog)

- **Link**: https://next.redhat.com/2026/06/01/from-context-to-dreams-architecting-memory-for-ai-agents/
- **類型**: Blog article (Red Hat Emerging Technologies)
- **Published**: 2026-06-01

### 這篇在說什麼

這不是 paper，是 Red Hat Emerging Technologies 團隊的技術博客，系統性地梳理了 agent memory 的架構全景圖。文章的核心論點是：agent capability ≠ model weights，而是 model + harness + memory + environment + evolution。文章涵蓋了記憶類型（session / file system / episodic / semantic）、client-side vs server-side 架構、多 agent 共享記憶的階層設計、以及「做夢」機制（背景記憶維護、去重、知識整合）。文章還做了一個 OpenClaw + Mem0 的部署範例。

### 主要貢獻（作為工程文章）

1. **統一術語和架構全景**：把散落在不同專案中的記憶概念整理成清晰的分類框架。
2. **Agent memory 的端到端架構範例**：從 prompt assembly 到 memory write-back 到背景記憶維護的完整流程。
3. **「做夢」機制的系統性描述**：不只是偶爾提到的概念，而是明確列出做夢需要做什麼（去重、驅逐過時記憶、形成新關聯、推導新知識）。

### 方法 / pipeline（工程架構）

文章描述的 agent memory 架構：

1. **Prompt assembly**：組合 session memory + RAG 資料 + 長期記憶 + 企業資料來源。
2. **Inference**：組合後的 prompt 送給 LLM。
3. **Memory write-back**：推論後的新記憶寫回長期記憶系統。
4. **階層記憶結構**：Agent-scoped LTM → Shared LTM（team / enterprise），支援個人化和集體學習。
5. **背景記憶維護（做夢）**：持續處理、整理、優化長期記憶。
6. **資料分離**：agent 記憶和企業 source-of-truth 資料庫保持分離。

文章提到的開源專案：Mem0、OpenClaw memory、Claude Code memories、Letta、Karpathy 的 LLM Wiki、Graphify、Graphiti 等。

### 實驗設計

作為博客文章，沒有正式實驗。有一個 OpenClaw + Mem0 的簡單部署範例，但不是對照實驗。

### かに讀後判斷

作為工程文章，這篇的價值在於提供了一個清晰的 agent memory 術語和架構全景，對 Morris 的研究脈絡有以下參考：
- 「做夢」機制的系統性描述和 TriMem 的 TextGrad 優化有概念上的呼應（都是背景優化記憶品質）
- client-side vs server-side 的區分對設計生產環境的 agent memory 系統有實用參考價值
- 多層記憶架構和 MemGraphRAG / TriMem 的多粒度設計有共通之處

不需要深讀，但作為 agent memory 領域的生態地圖有參考價值。
