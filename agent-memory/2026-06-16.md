# Agent Memory — 2026-06-16

## 1. Knowledge Objects: Facts as First-Class Objects for Persistent LLM Memory

- **arXiv**: 2603.17781
- **Link**: https://arxiv.org/abs/2603.17781
- **Authors**: Oliver Zahn (Independent), Simran Chana (Cambridge) et al.
- **Date**: March 2026

### 這篇在說什麼

LLM 作為「持續知識工作者」的需求越來越明確——研究助理要跨週記住文獻脈絡、工程 agent 要跨衝刺追蹤架構決策和技術債、科學協作者要跨月維持實驗上下文。這些場景都要求「記憶」。目前主流的做法是 in-context memory：把事實寫進 prompt，讓模型的 attention 機制在每次查詢時重新處理。

這篇的核心論點是：in-context memory 有一個被忽視的致命問題——**context rot**（上下文腐朽）。作者做了系統性基準測試，發現雖然 Claude Sonnet 4.5 在 context window 內可以達到 100% exact-match 準確率（從 10 到 7,000 個事實），但一旦超出 window 或進入真實部署場景，三個失敗模式會逐一浮現：容量上限、壓縮損失、目標漂移。Knowledge Objects（KOs）——離散的、hash 定址的 (subject, predicate, object, provenance) 元組，存在外部資料庫中，O(1) 查詢——可以完全解決這三個問題。

### 主要貢獻

1. **Context Rot 的系統性揭露**：
   - **容量上限**：8,000 事實就超過 Claude API 限制（~216K tokens），Gemini 1M window 也只能容納 ~36,000 結構化事實。注意力複雜度 O(N²) 造成經濟上限。
   - **壓縮損失**：將 2,000 事實壓縮成 3K 字元摘要後（36.7× 壓縮），60% 的事實無法恢復——不是幻覺，而是模型誠實地說「我沒有這個具體資訊」。
   - **目標漂移**：在 88 回合對話中嵌入 20 個非預設專案約束，經過三輪壓縮後只剩 46% 的約束被保留——而且模型繼續以完全信心運作，不知道自己的行為邊界已經靜默縮窄。

2. **Knowledge Objects (KOs)**：提出將事實存為離散的 (s, p, o, provenance) 元組，以 hash 定址，O(1) 查詢。KOs 在所有條件下達到 100% 準確率，成本是 in-context 的 1/252（$0.002 vs. $0.57 per query at N=7,000）。在 N=100,000 時 in-context 物理上不可能，KO 成本仍為 $0.002。

3. **多跳推理**：KOs 達到 78.9% vs. in-context 31.6%。因為多跳需要組合多個事實，in-context 在語義密集時會互相干擾。

4. **密度適應檢索（Density-Adaptive Retrieval）**：提出在檢索時根據候選集的語義密度切換策略——高密度時用精確匹配，低密度時用嵌入相似度。這也解釋了為什麼 hybrid retrieval（BM25 + dense）一直比任一單獨方法好：不是模態互補，而是隱式地在做密度適應。

5. **對其他記憶方案的批評**：
   - Embedding retrieval 在對抗性事實上失敗（precision@1 只有 20%）。
   - Neural memory（Titans）能存但無法在需要時正確取出。
   - 四個 frontier model 的交叉驗證確認壓縮損失是架構性的，不是模型特定的。

### 方法 / pipeline

KO 的架構設計：

- **儲存層**：(subject, predicate, object, provenance) 元組存在外部 key-value store。每個元組用 hash 定址，查詢時 O(1)。
- **分離關注點**：事實存在外部可定址的儲存中（不會因壓縮或 session 邊界而損失），LLM 保留查詢理解、答案生成和新 KO 提取的角色。模型仍然是系統的智慧核心，只是不再同時擔任記憶核心。
- **基準測試**：用藥理學事實（drug-target binding affinities with confusable near-duplicates）構建基準語料，測試 exact-match retrieval 從 N=10 到 N=10,000。
- **壓縮測試**：指示 Claude 將 2,000 事實（111K 字元）壓縮為 3K 字元摘要，然後查詢特定事實。
- **目標漂移測試**：在 88 回合模擬對話中嵌入 20 個非預設專案約束，施加級聯壓縮。
- **多跳推理測試**：需要組合多個事實才能回答的查詢。

### 實驗設計

- **模型**：Claude Sonnet 4.5（主要）、GPT-4o、Gemini 1.5 Pro、Llama 3.1 405B（交叉驗證壓縮損失）。
- **主要基準語料**：藥理學事實（drug-target binding affinities），刻意包含易混淆的近重複項（如 "Erlotinib inhibits EGFR with IC50 = 2.3 nM" vs. "Erlotinib inhibits HER2 with IC50 = 45.1 nM"），pairwise cosine similarity > 0.95。
- **In-context 結果**：
  - 10→7,000 事實：100% exact-match accuracy（佔用 194,984 tokens = 97.5% of 200K window）。
  - 8,000 事實：超過 API 限制，請求失敗。
  - 壓縮後：40% 可回答，60% 回答「沒有這個具體資訊」，0% 幻覺。
  - 三輪壓縮後：只剩 46% 的專案約束被保留。
- **KO 結果**：
  - 所有條件 100% 準確率。
  - 多跳推理：78.9% vs. 31.6%。
  - 成本：$0.002/query（固定，不隨 N 增加）。
- **密度適應檢索**：在候選集高密度時自動切換到精確匹配，低密度時用嵌入檢索。
- **目前能確認的**：所有主要實驗結果、KO 架構、密度適應檢索的設計從 HTML 全文確認。Titans 比較和 embedding retrieval 對抗性測試的細節需看 PDF。

### かに讀後判斷

Knowledge Objects 是 agent memory 領域近期最清晰、最有系統性證據的工作之一。它直接指出了 in-context memory 在生產部署中的三個致命問題，而且用藥理學基準測試（刻意包含易混淆項）做了非常乾淨的實驗。Context rot 這個概念——「像物理腐朽一樣，context rot 不是離散故障而是連續過程，影響最老和最基礎的資訊最先」——是個很有洞察力的比喻。

和之前看過的 agent memory 工作相比：
- vs. MemGPT / A-MEM：這些系統嘗試用記憶管理策略來延緩 context rot，但 KOs 的論點是根本不應該讓事實進入需要壓縮的 context window。
- vs. RAG：KOs 是對 RAG 的密度適應升級——在語義密集時用精確匹配，不是永遠靠嵌入相似度。
- vs. Neural memory（Titans）：KOs 直接指出了 neural memory「能存但取不出」的問題。

這篇值得 Morris 點開深讀，特別是：Section 1.1 的三個 failure mode 描述、Figure 1-3 的壓縮損失和目標漂移實驗、Section 3 的密度適應檢索設計、以及 Appendix 中的 Titans 比較和交叉模型驗證。如果對「agent 的長期記憶到底該怎麼做」這個問題有興趣，這篇是目前最有力的論證：事實應該是 first-class objects，不是 context window 裡的二等公民。
