# Agent Memory — 2026-06-19

## 1. MemFactory: Unified Inference & Training Framework for Agent Memory

- **arXiv**: 2603.29493
- **Link**: https://arxiv.org/abs/2603.29493
- **Authors**: Zi Liang Guo 等（MemTensor 團隊）
- **Code**: https://github.com/MemTensor/MemFactory

### 這篇在說什麼

Agent memory 的 RL 優化研究近一年快速發展（Memory-R1、MemAgent、RMM 等），但實作高度碎片化：每個方法都有自己的訓練 pipeline、資料格式、和任務假設，重現或組合幾乎不可能。MemFactory 想做的事情很明確——做 agent memory 領域的「LLaMA-Factory」：一個統一的、模組化的、開源的 framework，讓研究者可以用「樂高式」的組合方式搭建、訓練、評估自己的 memory agent。

### 主要貢獻

1. **統一 Memory-RL 基礎設施**：首個把 memory-augmented agent 的 inference、training、evaluation 整合在同一個 framework 中的開源工具，大幅降低進入門檻。
2. **Lego-like 模組化設計**：把記憶生命週期拆成三個原子操作——Extraction、Update、Retrieval——加上 Agent Module（支援端到端策略如 MemAgent），每個都是 plug-and-play。
3. **原生 GRPO 支援**：Trainer Layer 直接整合 Group Relative Policy Optimization，用多維環境獎勵 fine-tune 記憶管理策略，不需要 value network。
4. **Out-of-the-box 支援 Memory-R1 / MemAgent / RMM**：三個 SOTA memory-RL 方法可以直接在 MemFactory 內跑，提供標準化 baseline。
5. **實驗驗證**：用 MemAgent 架構在公開資料上訓練，相對基礎模型有最高 14.8% 的改進。

### 方法 / pipeline

- **四層架構**：
  - **Module Layer**：Extractor（NaiveExtractor，從對話中抽取結構化記憶）、Updater（NaiveUpdater，ADD/UPDATE/DELETE/NOOP 四操作）、Retriever（NaiveRetriever + RerankRetriever，後者用 LRM 做 reranking）、Agent Module（RecurrentMemoryModule，端到端策略）。
  - **Agent Layer**：組合 Module 成完整 agent；支援 AutoClasses 載入模型、FlashAttention-2、動態 padding、action mask 對齊。
  - **Environment Layer**：統一 data loader + multi-dimensional reward manager；支援 exact-match、LLM-as-judge 等多種獎勵信號。
  - **Trainer Layer**：GRPO 訓練，group-relative advantage 計算，KL 正則化防止策略偏離。

- **記憶生命週期**：每個對話 turn，Extractor 從新對話中抽取記憶片段 → Retriever 從記憶庫中检索相關記憶 → Updater 決定 ADD/UPDATE/DELETE/NOOP → 更新後的記憶庫供下一 turn 使用。

### 實驗設計

- **基準架構**：MemAgent（開源版），使用其公開訓練和評估資料。
- **Baseline**：各基礎模型不做 memory RL fine-tuning 的表現。
- **Metric**：主任務評估集上的相對改進百分比，最高 14.8%。
- **限制**：目前只在 MemAgent 架構上驗證，沒有在 Memory-R1 或 RMM 的原始任務上做 head-to-head 比較（只有 out-of-the-box 支援）。從 HTML 全文確認，實驗部分詳細展示了訓練曲線和消融實驗。

### かに讀後判斷

MemFactory 是 agent memory 領域第一個統一 framework，定位類似 LLaMA-Factory 之於 LLM fine-tuning。對 Morris 的價值在於：（1）它把碎片化的 memory-RL 生態系統統一了，未來任何新方法都可以在 MemFactory 上快速實作和比較；（2）Lego-like 設計讓研究者可以自由替換 Extractor/Updater/Retriever 組件，這對 agent memory 研究的實驗設計非常有用；（3）14.8% 的改進雖然不算驚人，但考慮到只用 GRPO 訓練且資料量有限，這個數字是可信的。

## 2. Memory-R1: Enhancing Large Language Model Agents to Manage and Utilize Memories via Reinforcement Learning

- **arXiv**: 2508.19828 (v5: 2026-01-14)
- **Link**: https://arxiv.org/abs/2508.19828
- **Authors**: Sikuan Yan, Xiufeng Yang, Zuchao Huang, 等（LMU Munich / MCML / TUM 等）

### 這篇在說什麼

LLM 雖然能力強，但本質上是 stateless 的——context window 以外的資訊全部丟失。現有的記憶增強方法多數用靜態啟發式規則來管理記憶（何時存、何時刪、何時更新），缺乏學習機制。Memory-R1 的核心想法是：**用 RL 來訓練 LLM agent 主動管理記憶**。它把記憶管理拆成兩個專門化的 agent——Memory Manager（做 ADD/UPDATE/DELETE/NOOP）和 Answer Agent（做 Memory Distillation，從 60 個候選記憶中篩選再推理）——然後用 outcome-driven reward（答案正確性）來 fine-tune 兩個 agent。

### 主要貢獻

1. **首個記憶管理的 RL framework**：將記憶操作（ADD/UPDATE/DELETE/NOOP）和記憶利用（distillation）分別建模為可學習策略，用 PPO/GRPO 訓練，而非啟發式規則。
2. **極端資料效率**：只需 152 個 QA pair 就能訓練出超越 Mem0 等強 baseline 的效果（LoCoMo 上 F1 相對改進 28%、BLEU-1 改進 34%、LLM-as-Judge 改進 30%）。
3. **雙 agent 架構**：Memory Manager 和 Answer Agent 分開訓練，Manager 的 reward 來自 Answer Agent 的答案正確性（exact match），形成端到端的學習信號。
4. **跨 benchmark 和跨模型尺度泛化**：在 LoCoMo、MSC、LongMemEval 三個 benchmark 上有效，模型從 3B 到 14B 都能受益。

### 方法 / pipeline

- **Memory Manager**：
  - 輸入：新對話資訊 x + 當前記憶庫 M_old
  - 輸出：操作 o ∈ {ADD, UPDATE, DELETE, NOOP} + 更新後內容 m'
  - 訓練：PPO 或 GRPO，reward = exact match of downstream answer
  
- **Answer Agent**：
  - 輸入：問題 + RAG retrieve 的 60 個候選記憶
  - 做記憶蒸餾（Memory Distillation）：先從 60 個中篩選最相關的，再推理出答案
  - 訓練：同樣用 PPO/GRPO，reward = exact match

- **關鍵設計**：
  - Memory Manager 的 reward 完全來自下游答案正確性，不需要對記憶操作本身做標注——這是 outcome-driven RL 的核心優勢。
  - GRPO 版本不需要 value network，只需 group 內相對 ranking，大幅降低記憶體需求。

### 實驗設計

- **Benchmark**：LoCoMo（長對話記憶）、MSC（Multi-Session Conversation）、LongMemEval（長期記憶評估）
- **Baseline**：Mem0（目前最強的啟發式記憶管理系統）、vanilla LLM、其他 RAG 方法
- **模型尺度**：LLaMA-3.1-8B-Instruct、3B、14B
- **訓練資料量**：152 個 QA pair
- **主要結果**：
  - LoCoMo 上 Memory-R1-GRPO（LLaMA-3.1-8B）相對 Mem0：F1 +28%、BLEU-1 +34%、LLM-as-Judge +30%
  - 跨三個 benchmark 一致優於 baseline
  - PPO 和 GRPO 都有效，GRPO 更穩定且記憶體效率更高
  - 152 個 QA pair 就夠，更多資料的邊際效益遞減

### かに讀後判斷

Memory-R1 是 agent memory + RL 交叉點的重要論文，和 MemFactory 形成互補：Memory-R1 提供了方法論和實驗證據，MemFactory 提供了統一的工程框架。對 Morris 的價值在於：（1）它用實驗證明了 outcome-driven RL 可以有效訓練記憶管理策略，不需要人工標注記憶操作；（2）152 個 QA pair 的資料效率非常驚人，這意味著在實際應用中可以低成本部署；（3）雙 agent 架構把記憶管理（寫）和記憶利用（讀）分開，是一個清晰的系統設計選擇。

## 3. Retrieval-Augmented LLM Agents: Learning to Learn from Experience

- **arXiv**: 2603.18272
- **Link**: https://arxiv.org/abs/2603.18272
- **Authors**: Thomas Palmeira Ferraz 等

### 這篇在說什麼

當前 agent 學習新任務的方法有兩條路：fine-tuning（泛化差）和 training-free memory-augmented generation（用過去經驗做 RAG，但效果往往不如 supervised baseline）。這篇的核心問題是：**能不能把兩者結合？**作者提出一個 pipeline，先用 SFT（LoRA）訓練 agent 學會利用檢索到的經驗軌跡，再系統性地研究經驗檢索的設計選擇（儲存、查詢、軌跡選擇），最後把經驗檢索整合到 fine-tuning 過程中。

### 主要貢獻

1. 建立 SFT + 經驗檢索的穩健食譜，證明 LoRA fine-tuning 配合經驗檢索比多個 SOTA agent training pipeline 好。
2. 詳細分析經驗檢索的設計選擇（storage format、query strategy、trajectory selection），找出最佳策略。
3. 提出 SFT + experience retrieval 的整合 pipeline，證明在未見任務上泛化能力顯著提升。

### 方法 / pipeline

- **SFT 階段**：用 LoRA 對 LLM 做 supervised fine-tuning，讓模型學會從 in-context 的檢索軌跡中提取有用的經驗。
- **經驗檢索**：從過去任務的軌跡庫中檢索相關經驗，作為 in-context 的示範。
- **設計選擇分析**：系統性比較不同的 storage（完整軌跡 vs 摘要）、query（task description vs goal）、selection（top-k vs diversity sampling）策略。

### 實驗設計

- **目前從 abstract 和 landing page 能確認的**：SFT + 經驗檢索在未見任務上泛化顯著優於純 SFT 或純 RAG baseline。
- **尚未確認的**：具體的 benchmark 名稱、任務類型、模型尺度、消融實驗的詳細數字。需要讀全文才能確認。

### かに讀後判斷

這篇處於 agent memory 的經驗檢索子領域，和 Memory-R1 / MemFactory 是不同路線——它不訓練記憶管理策略，而是訓練模型「學會從檢索到的經驗中學習」。對 Morris 的參考價值中等：SFT + RAG 的組合在 agent 領域是實用的，但方法論創新度不如 Memory-R1 的 RL 路線。如果 Morris 對 agent 的 few-shot / in-context learning 有興趣，可以深讀；否則快速掃過即可。
