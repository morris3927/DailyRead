# Agent Memory — 2026-06-21

## 1. HORMA: Hierarchical Organize-and-Retrieve Memory Agent

- **arXiv**: 2606.11680
- **Link**: https://arxiv.org/abs/2606.11680
- **Authors**: Hao-Lun Hsu (Duke University), Nikki Lijing Kuang, Boyi Liu, Zhewei Yao, Yuxiong He (Snowflake AI Research)

### 這篇在說什麼

LLM agent 在長任務上的核心問題是 context bottleneck：歷史越長，推理品質越差、成本越高、延遲越大。現有做法要麼是 lossy compression（summarization 不可逆地丟失細節），要麼是 flat semantic retrieval（只做語義相似度匹配，抓不到時間結構和因果依賴）。HORMA 的核心觀點是：memory construction 和 memory retrieval 根本上是不同的功能角色，應該被解耦。Construction 決定經驗如何被抽象和組織，影響是延遲的；Retrieval 決定推理時拿到什麼資訊，直接影響每一步決策。如果你把兩者 joint optimize，sparse task-level reward 會造成嚴重的 credit assignment gap——agent 失敗了，你不知道是 memory 組織不好、retrieval 不準、還是 downstream reasoning 出錯。

HORMA 的解法：把 memory 做成 file-system-like hierarchical structure（目錄+檔案），construction 用 iterative contrastive refinement 來學習組織技能，retrieval 用 RL-trained lightweight agent 來 navigation。Construction 不用 RL optimize（因為 credit assignment 太難），而是用 strong LLM 的 hierarchical reasoning capability 初始化 policy，再用 contrastive analysis（成功 vs 失敗 trajectory）迭代改良。Retrieval 用 RL 訓練，但只用 evidence-grounded retrieval reward（retrieved context 和 ground-truth evidence 的 overlap），跟 downstream task reward decouple。

### 主要貢獻

1. **Memory construction 和 retrieval 解耦**：明確把 working memory 分成兩個 module——Memory Manager M_m（組織）和 Retrieval Agent M_r（導航），各自用不同的 optimization 策略。Construction 用 contrastive skill refinement，Retrieval 用 RL with evidence-grounded reward。

2. **File-system-like hierarchical workspace**：Memory 不是 flat 的 embedding list，而是有目錄結構的 workspace，有 summarized entities 連結到 raw trajectories。Retrieval agent 用 Bash tools 和 terminal actions 在這個 hierarchy 裡導航（cd、ls、cat、select、done）。

3. **Contrastive skill refinement for construction**：不用 RL 訓練 construction，而是用 strong LLM 初始化，然後對比成功和失敗 trajectory 來迭代改良組織策略。區分兩種失敗：missing information（資訊沒被記錄）vs misleading/overloaded context（記錄了但組織不好）。

4. **Evidence-grounded retrieval reward**：Retrieval agent 的 RL reward 是 retrieved context 和 ground-truth evidence 的 overlap，而不是 sparse task-level reward。這 decouple 了 retrieval quality 和 downstream reasoning performance。

5. **強泛化結果**：在 ALFWorld 上，HORMA 在 small 和 large context limits 下都達到更高的 success rate。在 LoCoMo 和 LongMemEval 上，HORMA 只用 3.07%–22.17% 的 baseline token（LoCoMo）和 1.24%–16.19%（LongMemEval）。在 LongMemEval 上的 out-of-distribution generalization 甚至超過所有 baseline（包括沒有 context 限制的）。

### 方法 / pipeline

HORMA 的完整架構：

**Memory Manager M_m（Construction）**：
- 用 strong LLM（GPT-4o）初始化 hierarchical memory structure
- 將 raw trajectory 組織成 file-system-like structure：entity logs、event summaries、state trackers
- Iterative refinement：對比成功和失敗 trajectory，區分 missing information vs misleading context 兩種失敗模式
- 累積可重用的 memory management skills，跨 task transfer 不用從頭學

**Retrieval Agent M_r（Navigation）**：
- Lightweight backbone（Qwen2.5-0.5B/1.5B 或類似小模型）
- 用 RL 訓練，reward 是 evidence-grounded retrieval reward（retrieved context ∩ ground-truth evidence / ground-truth evidence）
- 動作空間：Bash-like commands（cd, ls, cat, select, done）
- select：確認當前 context 足夠，加入最終 context
- done：表示需要更多導航
- 迭代式導航：不是一次檢索，而是多步導航直到找到足夠 context

**Inference**：
- Agent M_θ 在每步收到 (o_t, C_t, q)，其中 C_t 是 M_r 從 workspace ℱ_t 中選出的 context
- π(a_t | o_t, ℱ_t, q) = M_r(C_t | ℱ_t, q) · M_θ(a_t | o_t, C_t, q; P_main)

### 實驗設計

- **Benchmarks**：ALFWorld（interactive household tasks）、LoCoMo（long conversation QA）、LongMemEval-S（long-term memory evaluation）
- **Baselines**：Full History、ReSum、ACON、MemoryBank、Mem0、A-mem、 Reflexion+、Reflexion++
- **Metrics**：Success rate（ALFWorld）、token usage、F1 score（LoCoMo/LongMemEval）
- **主要結果**：
  - ALFWorld：HORMA 在 small context limit 下 success rate 最高，Pareto efficiency（interaction steps vs token usage）最優
  - LoCoMo：HORMA 只用 3.07%–22.17% 的 baseline token，Open-domain F1 顯著高於 baseline
  - LongMemEval-S：HORMA 在 OOD generalization 上超過所有 baseline（包括 full history），Temporal reasoning +4.17 pp
  - Ablation：hierarchical structure 本身（vs flat）貢獻最大，RL-trained retrieval 優於 heuristic retrieval
- **模型規模**：Retrieval agent 用 Qwen2.5-0.5B/1.5B 就能達到很好的效果

### かに讀後判斷

HORMA 是 agent memory 領域近期最重要的工作之一，原因有三：(1) 明確解耦 construction 和 retrieval 是一個概念性進步，避免了 joint RL optimize 的 credit assignment gap；(2) file-system metaphor 是一個非常工程友好且 interpretable 的 memory representation，不像 vector store 那樣是黑盒子；(3) 在三個差異很大的 benchmark（interactive task、long conversation QA、long-term memory）上都有強結果，且 OOD generalization 超過所有 baseline。

跟 CoreMem（同日收錄）的關係：CoreMem 聚焦在 edge-cloud deployment 的 resource efficiency，用 information geometry（Riemannian retrieval + Fisher-guided distillation）解決 hubness 和 compression 問題。HORMA 聚焦在 memory 的組織結構和 navigation，用 hierarchical file-system + RL-trained retrieval 解決 temporal structure 和 causal dependency 問題。兩者互補：CoreMem 解決的是「怎麼在有限資源下檢索和壓縮」，HORMA 解決的是「怎麼組織記憶才能有效導航」。

## 2. CoreMem: Riemannian Retrieval and Fisher-Guided Distillation for Long-Term Memory in Dialogue Agents

- **arXiv**: 2606.18406
- **Link**: https://arxiv.org/abs/2606.18406
- **Authors**: Jiaqi Chen, Yongqin Zeng, Shaoshen Chen, Yijian Zhang, Hai-Tao Zheng (Tsinghua/Peng Cheng Lab), Chunxia Ma, XiuTeng Zhou

### 這篇在說什麼

個人化對話 agent 需要跨多個 session 的長期記憶，但部署在消費級硬體（8 GB VRAM 的 RTX 4060）上時，memory 系統面臨嚴重的資源瓶頸。現有系統（MemGPT、MemoryBank、Mem0）都是為 server-grade hardware 設計的。CoreMem 解決的問題是：在 8 GB VRAM 預算下，如何做高品質的長期記憶檢索和壓縮？

現有做法的三個問題：(1) cosine similarity 在高維空間有嚴重的 hubness 問題——少數 hub memories 主導最近鄰列表，邊緣但語義重要的 tail memories 被淹沒；(2) heuristic compression（如 LLMLingua2、SelectiveContext）沒有理論保證，不提供 KL-divergence bound；(3) retrieval 和 compression 用不同目標優化，造成 cascade failure——檢索到的 facts 在壓縮時丟掉結構性連接詞（如「因為」）。

CoreMem 用 information geometry 把 retrieval 和 compression 統一在同一個理論框架下：retrieval 用 Riemannian geometry（Fisher-Rao metric → Mahalanobis distance），compression 用 Fisher Information Matrix（diagonal FIM → token sensitivity scores → compression-KL tradeoff with explicit bound）。

### 主要貢獻

1. **Riemannian retrieval**：用 locally adaptive Fisher-Rao metric 取代 isotropic cosine similarity，透過 Mahalanobis distance 懲罰 hub memories。用 Woodbury acceleration 達到 O(Ndr) 查詢時間，支援 real-time search。

2. **Fisher-Guided Discrete Token Distillation (FDTD)**：hierarchical sentence-to-token compression，用 diagonal Fisher Information Matrix 的 trace 作為 token sensitivity score，提供 Theorem 1 的 compression error bound：D_KL ≤ O(L² Σ_{m_i=0} S(x_i))。同時有 structural syntax protection（保護句首句尾的 SVO 骨架）。

3. **Triple imperative constraint**：VRAM-friendly（≤ 6 GB for indexing）、time-friendly（sub-100ms per query）、token-friendly（20–30% prompt compression）。三個約束同時滿足。

4. **Empirical gains**：在 LOCOMO 和 LongMemEval-S 上，Open-domain +4.51 pp、Temporal +4.17 pp，全部在 8 GB VRAM 預算內。

### 方法 / pipeline

CoreMem 的 edge-cloud hybrid pipeline：

**Local Edge（≤ 8 GB VRAM）**：
1. Embedding model（~3 GB VRAM）
2. Riemannian retrieval index：L2-normalized embeddings → empirical variance → diagonal covariance D + low-rank SVD correction U_r M_r U_r^⊤ → Woodbury inversion Σ^{-1} → Mahalanobis distance scoring → O(Ndr) per query
3. Residual metric fusion：score = α · norm(sim_cos) + (1-α) · norm(sim_rie)，α = 0.5

**FDTD Compression**：
1. Sentence-level chunking：將 retrieved context 切成 conversational turns 和 sentences
2. For long sentences（> 8 tokens）：保護前 3 和後 3 tokens（SVO 骨架），只在 middle segment 做 token-level pruning
3. Token sensitivity：S(x_i) = ‖∇_{h_i} L ⊙ h_i‖₂ ≈ Tr(I_{H_{ii}} H_i H_i^⊤)，用 single backward pass 計算
4. Greedy sentence selection：根據 post-pruning mean scores 選句子直到 budget B

**Cloud LLM**：只收到 compressed context X̃，減少 API token 成本約 20%

### 實驗設計

- **Benchmarks**：LOCOMO、LongMemEval-S
- **Baselines**：NaiveRAG、MemGPT、MemoryBank、Mem0、A-mem、LLMLingua2、SelectiveContext 等
- **Main results**：
  - Open-domain reasoning：+4.51 pp over best baseline
  - Temporal reasoning：+4.17 pp over best baseline
  - VRAM profiling：< 6 GB for full pipeline
  - Latency：sub-100ms per query
  - API cost saving：~20% reduction in cloud LLM token usage
- **Ablation**：
  - Riemannian vs cosine：Riemannian 在 temporal reasoning 上更強，cosine 在 multi-hop bridge facts 上更強，fusion 最好
  - FDTD vs heuristic compression：FDTD 在 strict token budget 下更穩定，且有理論 bound
  - Structural syntax protection：去掉會導致 fragmented prompts 品質下降

### かに讀後判斷

CoreMem 的理論框架很漂亮——用 information geometry 統一 retrieval 和 compression，而不是各做各的然後祈禱 cascade 不出錯。Riemannian retrieval 解 hubness 和 FDTD 解 compression fragmentation 都是實際問題，而且有 Theorem 1 的 KL bound，不像 heuristic pruning 只能祈禱。

但要注意幾個限制：(1) diagonal Fisher approximation 是 strong assumption，論文承認 full covariance FIM 太貴，但 diagonal 可能 miss cross-dimensional correlations；(2) α = 0.5 的 fusion 是手動設的，沒有自適應機制；(3) edge-cloud 架構假設了特定 deployment pattern（local embedding + cloud generation），不一定適用所有場景。

跟 HORMA（同日收錄）的關係已在上文分析。跟昨天收錄的 All-Mem（2603.19595）的對比：All-Mem 用 Split/Merge/Update 三種非破壞性操作維護 memory topology，CoreMem 用 information geometry 做 retrieval + compression。All-Mem 聚焦在 memory structure 的演進，CoreMem 聚焦在 resource-constrained 環境下的 retrieval 和 compression 品質。
