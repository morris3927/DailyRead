# Agent Memory — 2026-06-23

## 1. GitOfThoughts: Version-Controlled Reasoning and Agent Memory You Can Replay, Diff, and Merge

- **arXiv**: 2606.14470
- **Link**: https://arxiv.org/abs/2606.14470
- **HTML**: https://arxiv.org/html/2606.14470v1
- **Authors**: Pavan C Shekar, Abhishek H S, Aswanth Krishnan (QpiAI, Bengaluru)
- **Subjects**: cs.AI, cs.CL, cs.LG

### 這篇在說什麼

LLM 的推理是暫時的——chain-of-thought 隨 context window 消失，搜索樹剪枝的分支不留記錄，memory buffer 無法 diff、merge 或 audit。程式碼、基礎設施、資料、實驗都有版本控制，推理是唯一沒有的複雜軟體流程。GitOfThoughts 把 agent 的推理樹存成一個 git repository：每個 scored thought 是一個 commit，scores 是 git notes，outcomes 是 tags，retrieval 就是 `git log`。這使得推理可以被 replay、audit、merge。

但更硬的問題是：**記憶到底能不能提升 agent 在新問題上的準確率？** 跨五種 substrate（none、markdown、vector、graph、git）、兩個 benchmark、兩個 model scale、預註冊 replication 的答案是：**在新問題上不行。** 沒有任何記憶格式能穩定幫助新問題，一個看似有前景的早期結果（git +15pp）在預註冊 replication 下崩塌。記憶只在「copyability threshold」以上有用——當 retrieved case 是當前問題的近似複製品（cosine ≳ 0.8），準確率會跳升；低於閾值則什麼都沒有。而且這個增益是答案檢索（answer retrieval），不是方法遷移（method transfer）：4.5× 更大的模型讓近複製品的增益翻倍，但仍然無法從 worked example 提取可遷移的方法。

### 主要貢獻

1. **GitOfThoughts substrate**：把推理樹映射到 git（每個 thought → commit, scores → notes, outcomes → tags），實現零工程成本的 replayability、auditability、mergeability。git 的三路合併讓跨 agent 記憶同步能自動偵測衝突，而非靜默保留矛盾。

2. **H-memory 被否決**：在新問題上，五種記憶 substrate 沒有一種能穩定提升準確率。n=40 時 git 的 +15pp 趨勢在 n=98 預註冊 replication 下崩塌到 +1.0pp。這是負面結果，但論文誠實記錄了 retract 的結果和被否決的假設。

3. **Copyability threshold**：記憶只在工作相似度 ≳ 0.8 時有幫助。增益是答案檢索而非方法遷移。4.5× 更大的模型讓近複製品增益從 +12–13.5pp 提升到 +22.5–28.5pp，但方法遷移帶仍然是零。

4. **H-substrate 被支持**：git 在 auditability、provenance、line-level diff、deterministic replay、mergeable memory 方面提供工程價值，且在準確率上與其他 substrate 打平（成本也低：~15ms/write, ~48ms/read）。

### 方法 / pipeline

GitOfThoughts 的設計是刻意最小化的：

1. **搜索機制**：外層是 depth-1, branching-factor-4 的 tree-of-thoughts；多選題的四個 root children 是四個候選答案。內層是 ReAct loop（max 3 steps），配備 calculator、sympy solver、pulp LP solver。

2. **Git-native memory**：每個問題在獨立的 ephemeral repository 中解決。commit-on-score hook 寫入四個檔案（thought.md, scores.json, trace.jsonl, metadata.json），commit 帶結構化訊息，git note 帶分數，tag 標記結果。主分支累積 session tree，長期 memory branch 儲存跨問題洞察。

3. **Retrieval**：只用 git 原生命令——關鍵字 (--grep)、內容 (-S pickaxe)、結果篩選 (git tag -l 'success_*')、前沿 (git log master..memory)，加權排序 ρ = 0.7·s_comb + 0.2·tag + 0.1·recency。

4. **五種 substrate 對照**：none（無記憶）、markdown（人類可讀的 memory.md）、git（共享 repo + memory branch + git grep）、vector（all-MiniLM-L6-v2 + Chroma）、graph（networkx lesson/concept graph + spread-activation retrieval）。

5. **預註冊 replication**：n=40 的趨勢和 n≈100 的 replication、n=500 的大規模實驗，所有假設在實驗前就 commit 到 git。論文記錄了一個 retract 的結果和一個被否決的假設。

### 實驗設計

- **Benchmark**：GPQA-Diamond（研究生級、「Google-proof」多選題）和 MATH-500
- **模型**：Qwen3.5-9B（主實驗）+ Qwen2.5-7B-Instruct（大規模驗證）+ Qwen2.5-32B（4.5× scale 測試）
- **控制變因**：只替換記憶 substrate，agent 完全相同
- **n=40 探索性結果**：所有 substrate 在 GPQA 的 CI 都包含零；MATH-500 上所有 backend 比無記憶低 2.5–5pp。Git 在 n=40 時顯示 +15pp 趨勢（CI 剛好包含零）
- **n=98 預註冊 replication**：git 崩塌到 +1.0pp [−10.2, +11.2]，substrate 排名完全重排（markdown 從最差變最好，vector 從最好變最差）
- **n=500 大規模**：在 MATH-500 上驗證，所有 substrate 的 CI 都跨零——穩健的 null 結果
- **Copyability threshold**：相似度掃描顯示 cosine ≳ 0.8 以上準確率急升 +12–13.5pp，4.5× 更大模型提升到 +22.5–28.5pp，但方法遷移帶始終為零
- **成本**：git ~15ms/write, ~48ms/read，和 vector index 的 20ms/read 同數量級

### かに讀後判斷

這篇對 agent memory 社群是必讀，原因不是 git substrate 本身（雖然工程上很巧妙），而是 **H-memory 的穩健否決結果和 copyability threshold 的發現**。這直接挑戰了目前 agent memory 領域的主流假設——即跨問題記憶能幫助新問題。論文的結論是：記憶只幫助近複製品的答案檢索，不幫助方法遷移。這和前幾天的 Infini Memory（topic document 管理）和 DCPM（雙歷程認知架構）形成有趣對照——三者都試圖解決「記憶如何幫助 agent」，但 GitOfThoughts 用嚴格的預註冊實驗告訴我們：**在新問題上，不管你用什麼 substrate，記憶都不穩定地幫助。**

git-as-substrate 的價值是 auditability 和 mergeability，不是準確率。這對 agent memory 的工程實踐有重要啟示：選 git 不是為了讓 agent 更聰明，而是為了讓 agent 的推理過程可追溯、可比較、可合併。

## 2. LedgerAgent: Structured State for Policy-Adherent Tool-Calling Agents

- **arXiv**: 2606.20529
- **Link**: https://arxiv.org/abs/2606.20529
- **HTML**: https://arxiv.org/html/2606.20529v1
- **Authors**: Md Nayem Uddin, Amir Saeidi, Eduardo Blanco, Chitta Baral (Arizona State University, University of Arizona)
- **Subjects**: cs.AI, cs.CL
- **Note**: Work in Progress

### 這篇在說什麼

在客服場景中，tool-calling agent 必須在多輪對話中維護任務狀態（相關事實、識別碼、約束條件），同時遵守 domain policy。問題是：現有 agent 把所有資訊放在 prompt 裡，任務狀態是隱式的——agent 可能在前面步驟取得了正確的資訊，但後來決策時卻基於過時、缺失或錯誤的資訊；或者一個語法合法的 tool call 仍然違反了依賴當前任務狀態的 domain policy。

LedgerAgent 在 inference time 加了兩個確定性元件：(1) schema-anchored ledger 把成功的 read-tool 回應存入一個 typed dictionary，(2) policy gate 在環境變更的 tool call 執行前，用 ledger 狀態檢查 policy constraints，阻擋違規操作。不需要 LLM 額外呼叫來建 ledger，也不改模型權重。

### 主要貢獻

1. **識別 state grounding failure mode**：agent 可能取得正確記錄但之後基於過時/缺失/錯誤的狀態做決策。這不是 tool selection 錯誤，而是狀態追蹤失敗。

2. **Schema-anchored ledger + policy gate**：ledger 用 domain schema 把 tool 回應存到 canonical paths（如 orders.1234, products.5678），policy gate 在 environment-changing call 執行前用 ledger 狀態檢查 policy predicates（allow / block with feedback / need more info）。

3. **Observe-not-assume rule**：成功執行 write 後，agent 必須再發 read call 來觀察新狀態，而非假設 write 的結果。這讓 ledger 始終 grounded 在外部系統的實際狀態。

4. **pass^k 改善**：跨四個客服 domain 和混合 open/closed-weight model panel，LedgerAgent 改善了平均 pass^k，尤其在更嚴格的多次一致性指標下改善最大。

### 方法 / pipeline

LedgerAgent 在標準 agent loop 上加了兩個確定性元件：

1. **Ledger L: P → V**：typed dictionary，P 是 canonical schema paths，V 是 tool 回傳值。每個 domain 提供一個 tool path map，把成功的 read-tool 回應路由到 canonical 位置。不需要 LLM 來建 ledger——完全確定性。

2. **Ledger-grounded generation**：每次 model call 前，把完整 ledger block 加到 prompt。每個 entry 顯示 canonical path 和 stored value，讓 model 用 lookup 而非搜尋歷史 transcript。

3. **Policy gate**：在 environment-changing call 執行前，評估 Π(L) → {allow | block(feedback) | need_more_info}。如果違反 policy，返回具體違規規則和衝突狀態。

### 實驗設計

- **Domain**：四個客服場景，來自 τ²-bench 和 τ-Trait
- **Model panel**：混合 open-weight 和 closed-weight 模型
- **Metric**：pass^k（多次獨立試驗的一致性）
- **結果**：LedgerAgent 在多數 domain-model pair 上改善 pass^k，改善最大的場景是需要 environment-changing actions 的任務
- **Ablation**：改善來自 typed ledger 和 policy-gated action 的組合

目前從 HTML 全文能確認：ledger 不需要額外 LLM 呼叫、observe-not-assume 規則的設計理由、policy gate 的三種輸出。具體數字需要看論文的 Table 部分。

### かに讀後判斷

LedgerAgent 的核心洞察很簡單但很實用：**不要讓 agent 在越長越長的 transcript 裡自己找狀態，而是把成功的 read 結果存到一個結構化的 ledger，在 action 執行前用這個 ledger 來檢查 policy。** 這和 GitOfThoughts 形成有趣對照——GitOfThoughts 說跨問題記憶在新問題上不穩定幫助，而 LedgerAgent 的 ledger 是同一次任務內的短期狀態追蹤，完全不同的時間尺度。

對 Morris 的意義：如果做 tool-calling agent 的 harness/policy enforcement，LedgerAgent 的 policy gate 設計可以和 SEB 的 certificate verification pipeline 結合——ledger 提供任務狀態，SEB 提供基礎設施狀態，兩者一起構成完整的狀態感知安全架構。

## 3. Current World Models Lack a Persistent State Core (WRBench)

- **arXiv**: 2606.20545
- **Link**: https://arxiv.org/abs/2606.20545
- **HTML**: https://arxiv.org/html/2606.20545v1
- **Authors**: Jinpeng Lu, Dexu Zhu, Haoyuan Shi, Linghan Cai, Guo Tang, Yinda Chen, Jie Cao, Duyu Tang, Yi Zhang, Yong Dai, Xiaozhu Ju
- **Subjects**: cs.CV
- **Note**: 39 pages, 16 figures

### 這篇在說什麼

這篇嚴格來說是 CV/world model benchmark，但對 agent memory 有重要的概念連結：它指出當前 world model 缺乏 persistent state core——當攝影機轉開後物體應該繼續演化（月亮不管有沒有人看都繼續繞地球轉），但現有模型只是在攝影機回來時恢復目標在離開時的狀態，而非推進在不可觀察期間的事件。這和 agent memory 的「不可觀察狀態追蹤」問題是同一個硬幣的兩面：agent 需要追蹤已經離開觀察範圍的環境狀態，world model 需要在視角轉開時繼續演化世界狀態。

### 主要貢獻

1. **WRBench**：第一個系統性診斷 benchmark，把攝影機移動當作對可觀察性的介入，評估 world model 在視角轉開再轉回後是否維持一致的 world state。

2. **六維診斷鏈**：(i) 攝影機精度、(ii) prompt-camera 對齊、(iii) 視覺完整性、(iv) 可見空間/狀態一致性、(v) 重新觀察支援、(vi) 重新觀察空間/狀態一致性。維度 (vi) 只在 (v) 通過的子集上計算。

3. **人類標定**：2,547 個去重人類標注者判決，在和 benchmark 輸出相同粒度上校準自動評估器。

4. **核心發現**：跨 23 個模型和四種控制範式，當前系統把可觀察世界當作 tracking shot——回來的目標恢復到離開時的狀態而非推進事件。這個失敗在所有控制範式、模型家族、規模增量上都會重現。

### かに讀後判斷

這篇對 agent memory 的直接貢獻是概念性的：它指出了一個 world model 和 agent 都面臨的根本問題——**持久狀態的核心**。和 MemoryWAM（今天的另一篇）相比，WRBench 是診斷工具，指出問題；MemoryWAM 是工程解法，嘗試解決 robotics 場景中的類似問題。但兩者都認同：沒有 persistent state，系統只能在 tracking shot 模式下運作。

因為是 CV 域的論文，不放進今日推薦，但值得了解其對 agent memory 的概念啟示。深讀時看 Figure 1（teaser）和 WRBench 的六維評估鏈。

## 4. MemoryWAM: Efficient World Action Modeling with Persistent Memory

- **arXiv**: 2606.20562
- **Link**: https://arxiv.org/abs/2606.20562
- **HTML**: https://arxiv.org/html/2606.20562v1
- **Authors**: Sizhe Yang, Juncheng Mu, Tianming Wei, Chenhao Lu, Xiaofan Li, Linning Xu, Zhengrong Xue, Zhecheng Yuan, Dahua Lin, Jiangmiao Pang, Huazhe Xu (CUHK, Tsinghua, Zhejiang U)
- **Subjects**: cs.RO

### 這篇在說什麼

MemoryWAM 解決的是 robotics 場景中 world action model 的記憶效率問題：full-history WAM 的推理延遲和 GPU 記憶體隨序列長度線性增長，sliding-window WAM 在非馬可夫環境中遺失長程依賴。MemoryWAM 受認知心理學啟發，設計了 hybrid memory：短期記憶（滑動窗口）、長期 gist token（壓縮歷史）、事件邊界 anchor frame（任務起始狀態）。這使得推理延遲和 GPU 記憶體從 O(N) 降到 O(N/d)，d 是壓縮比（實作中 d=15）。

### 主要貢獻

1. **Hybrid memory 機制**：sliding-window context + gist tokens + anchor frames，保持持久歷史的同時大幅降低 GPU 記憶體和推理延遲。

2. **系統性記憶機制研究**：對 WAM 的記憶機制做 trade-off 分析（推理延遲、GPU 記憶成本、策略效能）。

3. **SOTA on RMBench**：在長程、記憶依賴的 manipulation benchmark 上，比 strong VLA 和 WAM baselines 高 ~70 pp，同時保持計算效率。

### 方法 / pipeline

- **架構**：Mixture-of-Transformers (MoT)，video DiT + action DiT
- **短期記憶**：最近 N_recent 幀的滑動窗口
- **事件邊界記憶**：任務起始的 anchor frame，保留完整 visual tokens
- **Gist 記憶**：每幀 M 個 learnable gist tokens（M=8, vs L=120 visual tokens per frame），壓縮比 d=L/M=15
- **Attention**：action DiT 同時 attend 到短期、anchor、gist 三種記憶
- **KV cache 管理**：推理時 evict 幀的 KV cache 但保留 gist token 的 KV cache

### 實驗設計

- **Benchmark**：RMBench（長程、記憶依賴的 manipulation）
- **比較對象**：VLA baselines + full-history WAM (LingBot-VA) + sliding-window WAM baselines
- **結果**：比只看當前觀察或短期記憶的方法高 ~70 pp，比 LingBot-VA 更好且更快
- **效率**：long-term KV cache 減少 15×，推理延遲顯著降低
- **真實世界實驗**：sim 和 real world 都有改善

### かに讀後判斷

MemoryWAM 是 robotics/embodied AI 領域的論文，核心關切是 robot manipulation 中的長程記憶效率。它和 agent memory 的直接連結在於 hybrid memory 的設計原則——短期窗口 + 長期壓縮 + 事件邊界——這和 DCPM 的認知能力層級、Infini Memory 的 topic document 管理有概念上的呼應。但 MemoryWAM 的 gist token 是在 latent space 操作的，不是文字層面的記憶管理。

不放進今日推薦（偏 robotics），但值得知道。深讀時看 Figure 1（overview）和 Figure 3（attention mask 設計）。
