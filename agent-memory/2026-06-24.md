# Agent Memory — 2026-06-24

## 1. Contextual Reinstatement for Long-term Agentic Memory (RaMem)

- **arXiv**: 2606.22844 | cs.AI, cs.CL
- **Link**: [arXiv HTML](https://arxiv.org/html/2606.22844v1)
- **深度**: 全文 HTML（~25K chars），已讀至 Section 3.4（Context-Preserved Synthesis）

### 這篇在說什麼

長期記憶系統讓 LLM agent 可以跨互動保留經驗，但「取出相關記憶」不等於「這些記憶可以做為當前查詢的有效證據」。作者稱這個失敗模式為 **context collapse**：當經驗被壓縮成可重用片段，來自不同情境的記憶可能因為涉及相同實體或使用者狀態而顯得同樣相關，但實際上只有一個在當前情境下是有效的。

RaMem 的核心 idea 是 **contextual reinstatement**：在取出記憶後，恢復每個記憶片段的原始情境條件，然後用這些條件判斷哪些記憶是當前查詢的有效證據。這不是再加一層 retrieval，而是在 retrieval 之後加一層 validity checking。

這跟昨天的 GitOfThoughts 有直接對話：GitOfThoughts 發現跨問題的記憶幫助不大（copyability threshold），RaMem 則說問題不在於記憶是否能被取出，而在於取出的記憶是否在當前情境下是有效證據。

### 主要貢獻

1. **Context collapse 問題的正式定義**：記憶可以看似相關但屬於錯誤的情境——這不是 retrieval miss，而是 evidence misidentification。例如，「使用者想改晚餐計畫」這個記憶，可能來自上週（已經過時）、昨天（仍有效）、或只是一次性例外。簡單的 relevance retrieval 無法區分。

2. **四階段 pipeline**：
   - (i) **Episodic Memory Anchoring**：每個記憶附上事件時間、提及時間、session span、參與者。
   - (ii) **Recall Condition Induction**：從查詢推導出「需要什麼樣的證據條件」——不只是資訊需求，還有情境需求（什麼時間範圍、誰在場、哪個 session）。
   - (iii) **Validity-Aware Retrieval**：先用情境條件篩選記憶（context-compatible 優先），再用內容相關性取回候選（content-relevant 作為 fallback）。
   - (iv) **Context-Preserved Synthesis**：把選中記憶的結構化情境一起傳給 generator，而不是把記憶壓回純文本。

3. **F1 > 10% 的跨 backbone 改善**：在長期記憶 benchmark 上，RaMem 在多個 backbone 上一致改善，平均 F1 增益超過 10%。

### 方法 / pipeline

RaMem 的 retrieval 不是單純的 semantic search + BM25 fusion。它有一個關鍵的分流：

- 當 recall condition induction 可以成功推導出 grounded conditions（例如：時間範圍、session、參與者），RaMem 用這些條件篩選 context-compatible candidates，然後再融合 content-relevant candidates 作為 fallback。
- 當 recall conditions 無法被 grounded（例如模糊查詢），RaMem 退回純 content retrieval，不強加可能錯誤的情境約束。

時間相容性的計算很直覺：記憶的 session span [s_i^start, s_i^end] 必須與查詢的時間範圍 [t_q^start, t_q^end] 有重疊。可以加 buffer 容忍 event time 和 mention time 的偏移。

最後的 synthesis 階段：不只是把記憶文本丟給 LLM，而是保留結構化的情境資訊（時間、參與者、session），讓 LLM 可以判斷「這個記憶在當前情境下是否有效」。

### 實驗設計

- **Benchmark**：長期記憶 benchmark（具體名稱在全文中，已讀到 Section 3 為止，從 abstract 確認是標準長期記憶評估）。
- **Baselines**：SimpleMem 等強 baseline，RaMem 在 F1 上平均改善 >10%。
- **Context collapse 的實證**：在 context-confusable 子集上，SimpleMem 經常把 context-invalid 的記憶排到 rank 1，而 RaMem 可以區分。
- **跨 backbone 一致性**：在不同 LLM backbone 上都有改善，不是只對特定模型有效。

### かに讀後判斷

這篇是今天 agent memory 領域最重要的論文。Context collapse 是一個真實且未被充分討論的問題：當記憶系統變得更大更長期，不同情境下的相似記憶會越來越多，簡單的 relevance retrieval 會越來越容易把錯誤情境的記憶排在前面。RaMem 的解法（contextual reinstatement）很優雅：不是改 retrieval，而是在 retrieval 之後加一層 validity checking。

和昨天的 GitOfThoughts 互補：GitOfThoughts 發現跨問題的記憶增益有限，RaMem 指出部分原因可能是 context collapse——記憶被取出但不在正確情境中，所以看起來沒用。

建議深讀 Section 3（方法）的細節，特別是 validity-aware retrieval 的數學公式（Eq. 3-4）和 context-preserved synthesis 的實作。Appendix 的 context-confusable 子集分析也值得看。

## 2. Managing Procedural Memory in LLM Agents: Control, Adaptation, and Evaluation (AFTER)

- **arXiv**: 2606.23127 | cs.AI, cs.CL, cs.SE
- **Link**: [arXiv HTML](https://arxiv.org/html/2606.23127v1)
- **深度**: 全文 HTML（~20K chars），已讀至 Section 4.2

### 這篇在說什麼

Procedural memory（程序性記憶）在 LLM agent 上越來越常被用來改善重複任務的表現，但「技能是否可以跨任務、跨角色、跨模型轉移」這個核心問題缺乏系統性評估。AFTER 是一個 382 個真實企業任務的 benchmark，橫跨 6 個職業角色和 22 個技能，專門測量技能的 local improvement、cross-task transfer、cross-role transfer、和 cross-model generalization。

這跟 RaMem 的互補在於：RaMem 關心的是 episodic memory（情境記憶）的 context collapse，AFTER 關心的是 procedural memory（程序性記憶）的 transferability。前者是「記憶是否在當前情境有效」，後者是「技能是否在新的任務/角色/模型下有效」。

### 主要貢獻

1. **AFTER benchmark**：382 任務、6 角色（Data Engineer, Data Scientist, GenAI Engineer, Infra Engineer, Project Manager, SWE）、22 技能、4 種 transfer 設定（local, cross-task, cross-role, cross-model）。

2. **Evolution harness**：一個標準化的 trace 收集、skill 版本化、update 和 transfer 測量框架。Skills 以 SKILL.md 格式存儲，有版本和 lineage tracking。

3. **關鍵實驗結果**：
   - 單輪 refinement 改善 3.7-6.7 points
   - 從多模型 execution trace 演化出的技能達到 73.1% cross-model test accuracy，超過所有 single-model trace source
   - 有些技能可以廣泛轉移（generic skills），有些會 role-specific 過度特化而在轉移時失效

### 方法 / pipeline

- **Static evaluation**：直接把 skill 放入 prompt，不跑 agent loop。三種 skill form：none (∅)、handcrafted (H)、LLM-generated (G)。
- **Evolution**：Collect-Diagnose-Revise-Promote cycle。Reflector 檢查 trace、摘要失敗模式、提出修訂。
- **Transfer 評估**：specificity（source-context improvement）和 generality（transfer under distribution shift）。M1 測部分進度，M2 測完整任務成功。

### 實驗設計

- 13 個模型（GPT 5.4, GPT 5.4 Mini 4, DeepSeek V4 Flash, Nemotron 3 120B, Gemma 4 31B/26B/E4B, Qwen 3.5 系列, GPT-oss-120B/20B）
- Skills 在 weaker models 上改善更大（例如 Gemma 4 E4B 在 GenAI 上 +14.2 points）
- LLM-generated skills (G) 常常超過 handcrafted skills (H)
- Cross-role transfer 有明顯的 over-specialization pattern：DS skills 轉移到 GenAI 好，但轉移到 PM 差

### かに讀後判斷

AFTER 是目前最全面的 procedural memory transfer benchmark。對 agent memory 領域的貢獻是：終於有人系統性地測量「技能轉移」而不是只測「同任務改善」。關鍵發現是技能的 transferability 不是二元的——有些技能可以廣泛轉移（如 sql, validation），有些會 role-specific 過度特化（如 pptx, docx 在 PM 角色上特化後轉移效果差）。

和 RaMem 的對話：episodic memory 需要 contextual reinstatement 來避免 context collapse，procedural memory 需要 diverse training traces 來避免 source-context overfitting。兩者的共同教訓是：記憶的「相關性」不等於「有效性」。

建議深讀 Table 2（static skill valuation 跨模型跨角色）、Section 3（Evolution framework）和 Figure 1（skill evolution landscape）。

## 3. Negative Knowledge as Failure-aware Shared Memory for AutoResearch

- **arXiv**: 2606.21024 | cs.AI
- **Link**: [arXiv HTML](https://arxiv.org/html/2606.21024v1)
- **深度**: 全文 HTML（~20K chars），已讀至 Section 4.4

### 這篇在說什麼

AutoResearch 系統產生很多失敗嘗試，但這些失敗很少成為持久的、可共享的知識資產。作者提出 **negative knowledge memory layer**：一個 curator agent 把每次失敗轉換成一個有界的、類型化的記錄，存入共享 bank；下游 research agent 在提出下一個實驗前，必須明確採納或拒絕這些記錄。

這跟 RaMem 和 AFTER 都有對話：RaMem 說記憶需要 contextual reinstatement 才能當證據用，AFTER 說技能需要 diverse trace 才能轉移，這篇說**失敗也需要結構化**——不是簡單的 self-debug 或 reflection，而是把失敗變成可審計、可轉移的研究物件。

### 主要貢獻

1. **Negative knowledge memory layer**：architecture-agnostic，把失敗嘗試轉成 bounded、typed 的共享記錄。

2. **Bounded failure schema**：每個記錄有失敗層級、範圍、程度、建議行動、風險，使用封閉詞彙表（不是自由文本）。

3. **實證結果**：
   - ScienceAgentBench：一個 negative knowledge record 就把 pass rate 從 31.6% 提升到 36.8%（+5.2pp），deep negative knowledge（三輪失敗蒸餾成一個記錄）達到 47.4%，超過三輪 self-debug 的 44.7%。
   - Negative knowledge records 用更少的 token：比 self-debug 少 28.3%（單輪）和 73.3%（三輪蒸餾）。
   - PDE 系統研究：bank 可以跨任務轉移，甚至跨系統（BKdV → Burgers-NLS）。

4. **Curator-researcher 分離**：curator agent 和 research agent 是不同角色，減少 self-assessment bias。

### 方法 / pipeline

三個設計屬性：
- **Attempt-level**：每個記錄描述一次完整的失敗嘗試
- **Bounded**：遵循 prompt-level 長度和結構限制，整個 bank 可以 inline 傳給 agent
- **Typed**：失敗分類使用封閉詞彙表，curator 必須明確分類而不是自由描述

Workflow：
1. Research agent 執行實驗 → 產生 artifacts（code, logs, traces）
2. Curator agent 把 artifacts 轉成 bounded, typed 記錄 → 存入 shared bank
3. 下游 research agent 讀取 bank → 每個記錄必須明確採納或拒絕，附理由 → 提出新的實驗

### 實驗設計

- **ScienceAgentBench**：deterministic evaluation subset，Claude Sonnet 4.6
  - Base: 31.6%, Retry: 31.6%, Negative Knowledge Retry: 36.8%, Self-debug (3 rounds): 44.7%, Deep NK: 47.4%
  
- **PDE Case Study (BKdV)**：
  - 58 records (15 positive, 43 negative, 7 depth-3 path-closure)
  - 四個條件：Base (no bank), Base+Pos, Base+Neg, Base+Pos+Neg
  - 跨任務轉移有效，跨系統轉移（→ BNLS）部分有效

- **Token efficiency**：NK records 比 self-debug 用更少 token，因為是結構化蒸餾而非原始 feedback

### かに讀後判斷

這篇跟 RaMem 和 AFTER 形成一個有趣的三角：
- RaMem：episodic memory 需要 contextual validity checking
- AFTER：procedural memory 需要 diverse trace 避免過度特化
- 這篇：negative knowledge 需要 bounded schema 和 curator-researcher 分離才能成為可共享資產

三篇的共同主題是：**記憶的結構化程度決定了它的可轉移性和有效性**。Raw reflection 不夠，需要類型化、有界、可審計的結構。

這篇對做 AutoResearch 或 scientific discovery agent 的人特別有價值。Negative knowledge bank 的跨系統轉移（BKdV → BNLS）是 surprising result，值得深讀 Section 4 的 trace analysis。
