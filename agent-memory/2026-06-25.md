# Agent Memory — 2026-06-25

## 1. Don't Ask the LLM to Track Freshness: A Deterministic Recipe for Memory Conflict Resolution

- **arXiv**: 2606.01435
- **Link**: https://arxiv.org/html/2606.01435v1

### 這篇在說什麼

這篇論文處理的是 LLM agent memory 的一個根本但被低估的問題：當同一個 fact 在記憶中有多個矛盾的值時，agent 應該回傳哪一個？這就是 conflict resolution 問題。作者用 MemoryAgentBench (MAB) 的 FactConsolidation 任務做測試場景——事實有編號，反事實的編號更大，agent 被明確告知「越新的事實編號越大」。但所有已發表的記憶系統在這個任務上都大幅失敗：HippoRAG-v2 54%，BM25 48%，Mem0 18%，Zep/Graphiti 只有 7%。多跳版本更慘，22 個系統全部 ≤7%。

作者的發現很直接：瓶頸不在儲存，而在組裝（assembly）。把 LLM 判斷替換成「候選提取 + Python max(serial)」就從 67.2% 跳到 78.0%（gpt-4o-mini），差距隨 context length 放大（6K +8pp → 262K +21pp）。

### 主要貢獻

1. **Assembly bottleneck 的機制性定位**：明確指出 conflict resolution 的瓶頸是 post-retrieval aggregation（組裝），不是 storage（圖、embedding、agentic、typed）。這對整個 memory framework 設計空間是個修正：你在 storage 上做得再精巧，assembly 端用 LLM 判斷就全毀了。
2. **三個 empirical findings**：
   - FC-SH 78.0%（gpt-4o-mini）、94.8%（gpt-4o）
   - FC-MH 30.2%（gpt-4o-mini）、51.5%（gpt-4o），透過 per-hop deterministic freshness extension of Self-Ask
   - 在 matched 262K 比較下，gpt-4o-mini pipeline 比 HippoRAG-v2 多 28pp，比 Zep 多 75pp
3. **LLM 失敗模式的機制分析**：
   - Prior-override：LLM 偏好 training data 的先驗知識而非明確規則
   - Serial-comparison drift：候選數量隨 context 增長時 LLM 追蹤最大編號的能力退化
4. **Cross-benchmark generalization**：在 LongMemEval knowledge-update 上，deterministic max(timestamp) 只和 LLM judgment 打平（57.8% vs 64.4%），因為衝突型別不只是 current-value 還有 Yes/No、historical、aggregation 題。Deterministic aggregation 是 current-value conflict resolution 的正確原語，但要和 question-type-aware handling 組合才能處理更廣的 memory QA。
5. **Reproducibility**：完整開源程式碼（~50 行 orchestration beyond standard BM25 retrieval）。

### 方法 / pipeline

核心 pipeline 很簡潔：

1. **Retrieval**：BM25 TOP_K=10，fact-level chunking。
2. **Candidate extraction**：LLM 從 retrieved chunks 中提取和問題語意匹配的候選值（結構化 JSON 輸出，temperature 0.0）。
3. **Deterministic aggregation**：Python max(serial) 選最新值。

對比 baseline 是 MAB 的 BM25 answer prompt（LLM 判斷 + temperature 0.7 + free-text 輸出）。

Multi-hop 版本（FC-MH）用 Self-Ask 風格的 decomposition：每跳分解子問題，每跳的 conflict 用 per-hop max(serial) 解決，然後串接答案。

這是 whole-pipeline 比較（resolver、prompt、format、temperature 同時變），不是 isolated resolver comparison。

### 實驗設計

- **Dataset**：MemoryAgentBench FactConsolidation（single-hop FC-SH 和 multi-hop FC-MH）
- **Context lengths**：6K, 32K, 64K, 262K
- **Backbones**：gpt-4o-mini, gpt-4o
- **n**：100 per cell，共 2000 evaluations
- **Main results**：
  - FC-SH：78.0%（gpt-4o-mini avg）、94.8%（gpt-4o avg）
  - FC-MH：30.2%（gpt-4o-mini）、51.5%（gpt-4o）
  - LLM-judgment baseline 隨 context 增長退化（75%→61%），deterministic pipeline 不退化（71-82%）
  - Retrieval upper bound：88.5% 的問題被至少一個 pipeline 解決；11.5% 兩個都不行
  - 21% 的問題只有 deterministic pipeline 能解，10.5% 只有 LLM-judgment 能解（方法互補性）
- **LongMemEval cross-check**：max(timestamp) 在 knowledge-update 子集和 LLM judgment 打平（57.8% vs 64.4%，CI 重疊），但對 Yes/No、historical、aggregation 題不適用
- **Ablation**：條件化分析（retrieved vs unretrieved facts）、pipeline 各環節的貢獻拆解

### かに讀後判斷

這篇是 agent memory 領域近期最重要的修正性結果之一。核心論點「瓶頸在 assembly 不在 storage」直接挑戰了整個 memory framework 設計空間——如果你用 LLM 來做 conflict resolution，再精巧的圖/graph/RAG storage 都救不了你。和昨天的 RaMem（context collapse 是 retrieval 之後的 validity checking 問題）呼應：兩篇都在說問題不在記憶存得夠不夠好，而在怎麼用。

值得 Morris 點開。深讀時優先看：(1) §5.4 條件化分析（只看 retrieved facts 的結果），確認 bottleneck 真的在 post-retrieval；(2) §5.7 LongMemEval cross-benchmark 的細節，理解 deterministic aggregation 的適用邊界；(3) whole-pipeline effect 的 caveat——作者明確說這不是 isolated resolver comparison，未來工作要拆解。

## 2. E-mem: Multi-Agent Based Episodic Context Reconstruction for LLM Agent Memory

- **arXiv**: 2601.21714 (v5, June 2026; accepted ICML 2026)
- **Link**: https://arxiv.org/abs/2601.21714

### 這篇在說什麼

E-mem 處理的是目前 agent memory 的一個核心缺陷：主流的記憶預處理範式（embedding, graph, summary 等）把對話歷史壓縮成預定義結構時，會破壞 deep reasoning 所需的上下文完整性——作者稱之為「destructive de-contextualization」。E-mem 的核心主張是從 Memory Preprocessing 轉向 Episodic Context Reconstruction：不要事先壓縮，而是在需要時由多個 assistant agent 重建相關的上下文片段。

### 主要貢獻

1. **Destructive de-contextualization 的診斷**：明確指出主流 memory preprocessing（embedding、graph、summary）在壓縮複雜序列依賴時會切斷 deep reasoning 所需的上下文完整性。
2. **Episodic Context Reconstruction 架構**：異質性階層架構——多個 assistant agent 維護未壓縮的記憶 context，master agent 做全局規劃。Assistant 不是被動檢索，而是在激活的片段內做局部推理，提取 context-aware evidence 後再聚合。
3. **ICML 2026 接受**：代表學術社群對這個方向的認可。

### 方法 / pipeline

E-mem 的架構受生物 engram 啟發：

1. **Multiple assistant agents**：每個 assistant 維護一份未壓縮的記憶 context（episodic segment）。
2. **Master agent**：接收問題，分配給相關的 assistant agents。
3. **Local reasoning within activated segments**：assistant 在自己的 context 內做推理，提取 context-aware evidence。
4. **Aggregation**：master 聚合所有 evidence 形成答案。

這和主流的 retrieve-then-reason 不同——主流是先壓縮再檢索，E-mem 是先激活再推理再聚合。

### 實驗設計

- **Benchmark**：LoCoMo
- **Main result**：F1 超過 54%，超過 state-of-the-art GAM 7.75%
- **Token cost**：減少超過 70%
- 目前從 abstract 和搜尋結果確認到以上數據。完整 ablation、對比系統列表、不同任務類別的細節需要看全文。

### かに讀後判斷

E-mem 的核心洞察和今天的「Don't Ask the LLM to Track Freshness」形成有趣的對比：那篇說 assembly 端要用 deterministic code 不要用 LLM，這篇說 memory 的 context 重建要用多 agent 架構來避免壓縮損失。兩篇都在挑戰「讓 LLM 做所有事」的預設。E-mem 的「不壓縮」策略在 token cost 上反而更省（-70%），這反直覺但合理——因為避免了大量無關壓縮結果的 retrieval 和 re-ranking。

值得 Morris 關注但不必優先深讀。ICML 2026 接受代表品質門檻，但 LoCoMo 單一 benchmark 的驗證寬度需要看全文確認。

## 3. Revolutionizing Long-Term Memory in AI: New Horizons with High-Capacity and High-Speed Storage

- **arXiv**: 2602.16192 | Kioxia Corporation
- **Link**: https://arxiv.org/abs/2602.16192

### 這篇在說什麼

這篇是 Kioxia（記憶體公司）的 position paper，主張當前主流的「extract then store」記憶範式有根本缺陷——提取時已經丟失了對不同任務可能有價值的資訊。作者提倡「store then on-demand extract」：保留原始經驗，在需要時再按任務提取。另外兩個方向是從大量機率性經驗中發現更深洞察，以及透過分享儲存經驗提升收集效率。

### 主要貢獻

1. **對「extract then store」的批判**：明確指出當前主流範式（先提取再儲存）會丟失資訊，因為提取時的判斷標準可能不適用於未來任務。
2. **「store then on-demand extract」範式提案**：保留 raw experience，按需提取。和 E-mem 的「不壓縮」精神相通。
3. **兩個延伸方向**：從大量機率性經驗中發現深層洞察（類似 meta-learning）、透過 sharing stored experiences 提升收集效率。
4. **簡單實驗驗證**：展示了這些方向的直覺有效性。

### 方法 / pipeline

這是 position paper + 簡單實驗，不是系統論文。方法論是：
- 分析 extract-then-store 的資訊損失機制。
- 提出三個替代方向的概念框架。
- 用簡單實驗驗證每個方向的可行性。

### 實驗設計

簡單實驗驗證「store then on-demand extract」的可行性，但從 abstract 來看沒有大規模 benchmark 對比。詳細實驗設計需要看全文。

### かに讀後判斷

這篇作為 position paper 有啟發性（和 E-mem 的「不壓縮」方向一致），但作為 Kioxia 的行銷+研究 paper，深度和嚴謹度可能不及 E-mem 和 Don't Ask the LLM to Track Freshness。對 DailyRead 的價值在於它從硬體產業視角提出記憶範式的反思。Morris 可以略讀，不用優先深讀。重點是「store then on-demand extract」這個概念，和今天的另外兩篇 agent memory 論文形成有趣的呼應。
