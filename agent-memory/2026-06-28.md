## 1. SAGE: A Novelty Gate for Efficient Memory Evolution in Agentic LLMs

- **arXiv**: 2605.30711
- **Link**: https://arxiv.org/abs/2605.30711

### 這篇在說什麼

Agentic LLM 的記憶系統必須持續決定新提取的事實應該加入、合併還是忽略——但現有工作把重點放在檢索和儲存，而不是寫入端的控制。Mem0 對每批候選事實都呼叫 LLM controller 做路由，A-Mem 再加上 note construction 和 neighbor evolution 的 LLM 呼叫——寫入路徑是成本的主要來源。

SAGE 把記憶演化重新框架為新穎度偵測問題：用 von Mises-Fisher (vMF) 分佈在記憶 embedding 的單位超球面上做 kernel density estimation，計算每個候選事實相對於現有記憶的新穎度分數，然後用 adaptive threshold 把明顯新穎的事實路由到 Add、明顯冗餘的到 Noop、只有不確定的才送去 LLM merge——大幅減少昂貴的寫入期推理。

### 主要貢獻

1. **Novelty-detection framing**：把記憶演化從「每個候選事實都要 LLM 判斷」重新框架為「新穎度偵測 + 不確定情況的 LLM 裁決」。這個框架把寫入端控制從全量 LLM 推理變成分層路由。

2. **SAGE gate 設計**：用 vMF 分佈在 𝕊^(d-1) 上做 KDE，計算候選事實相對於記憶庫的密度分數。新穎度低（密度高）→ Noop，新穎度高（密度低）→ Add，中間地帶 → LLM Update。Adaptive threshold 追蹤記憶庫的幾何變化，不需要手動調參。

3. **雙重評估**：
   - 作為完整系統（替代 Mem0 的路由 controller）：在 LoCoMo 上 7/7 open-weight backbone 的 token-F1 勝出 Mem0，GPT-4o-mini 上 add-phase API cost 降低 3.4×，latency 降低 2.5×，judge-score 只有微小差距。
   - 作為 A-Mem 的 drop-in Noop gate：跨五個模型跳過 16–18% 的 LLM 呼叫，token-F1 變化 ≤ 0.5%。

### 方法 / pipeline

SAGE 的核心是一個三路路由器：

- **Embedding**：每個候選事實和每個記憶項都 ℓ2-normalize 到單位超球面 𝕊^(d-1) 上。檢索和路由都在這個角度空間中操作。

- **Novelty scoring**：用 vMF 分佈作為 kernel，在記憶庫上做 KDE。對每個候選事實 c，計算 S(c) = (1/N) Σ_i C_d(κ) exp(κ c·m_i)，其中 κ 是集中度參數，C_d(κ) 是正規化常數。這個分數衡量的是：候選事實周圍有多少記憶支持它——不是只看最近鄰，而是看局部密度。

- **Adaptive threshold**：隨著記憶庫增長和幾何變化，threshold 自動調整。不需要固定閾值。

- **Three-way routing**：
  - S(c) > τ_high（高密度 / 低新穎度）→ Noop：候選已經被現有記憶覆蓋。
  - S(c) < τ_low（低密度 / 高新穎度）→ Add：候選是新資訊。
  - τ_low ≤ S(c) ≤ τ_high → Update：送 LLM 做合併判斷。

- **為什麼 vMF 而不是歐氏 KDE**：因為記憶 embedding 是 ℓ2-normalized 的，語意比較用的是 cosine similarity（= inner product on 𝕊^(d-1)），所以 kernel 也應該在球面上操作。vMF 是方向統計中標準的分佈模型。

### 實驗設計

- **Full system (SAGE replacing Mem0 controller)**：
  - Benchmark: LoCoMo（長對話記憶基準）。
  - Backbone: 7 個 open-weight + GPT-4o-mini。
  - Metric: token-F1（記憶提取品質）、add-phase API cost、add-phase latency、judge score。
  - Results: 7/7 open-weight 上 token-F1 勝出 Mem0；GPT-4o-mini 上 API cost 降低 3.4×、latency 降低 2.5×，judge-score 差距小。
  - LLM call 減少：60–90%（7 個 backbone 中 7 個）。

- **Drop-in Noop gate (on A-Mem)**：
  - 5 個模型，跳過 16–18% LLM calls，token-F1 變化 ≤ 0.5%。

- **Ablation**：作者展示了 vMF density 比 simple cosine similarity nearest-neighbor 更好地捕捉「局部支持」效應——兩個候選可以和最近記憶有相同的 cosine similarity，但一個在密集區域（低新穎度）、一個在稀疏區域（高新穎度）。

### かに讀後判斷

SAGE 是 agent memory 領域一個乾淨且有實際影響的工作。它的核心洞察——寫入端控制是記憶品質和系統效率的槓桿——很重要，因為之前的工作（Mem0、A-Mem）都在寫入端花大量 LLM 推理成本，但沒有考慮先做一個便宜的過濾。

和昨天 TMA-NM（2606.24322）的對比很有趣：TMA-NM 在寫入端做的是安全驗證（origin binding + corroboration），SAGE 在寫入端做的是新穎度過濾。兩者都在解決「寫入端該不該讓這筆記憶進來」的問題，但一個從安全角度、一個從效率角度。如果組合起來，可以先做 SAGE 的新穎度過濾，對需要 LLM 判斷的候選再做 TMA-NM 的安全驗證。

和前幾天的 StructMem（2604.21748）也有間接對話：StructMem 用 hierarchical memory 改善 temporal reasoning 和 multi-hop，SAGE 用 novelty gate 改善寫入效率。兩者互補——SAGE 減少了不必要的寫入，StructMem 改善了已有記憶的組織和檢索。

**值得 Morris 點開**。優先看 §3.2–3.3（novelty detection 到 vMF density estimation 的推導）、§5 的 ablation（vMF vs. nearest-neighbor 的差異）、和 Table 2（LLM call 減少的數據）。如果對 agent memory 的效率問題感興趣，SAGE 是目前最直接的解法。

## 2. Communication Policy Evolution for Proactive LLM Agents

- **arXiv**: 2606.14314
- **Link**: https://arxiv.org/abs/2606.14314

### 這篇在說什麼

LLM agent 和用戶之間永遠有資訊落差：用戶有完整任務意圖，但自然語言無法一次傳達所有約束和偏好。Proactive agent 的現有工作專注於「問什麼」，但忽略了同樣重要的問題：「怎麼問」——用自由文字還是結構化 UI？這篇把這個通道選擇問題形式化為 Communication Policy，並提出 CPE（Communication Policy Evolution），一個通過 rollout 分析和 prompt 層級演化自動發現有效溝通策略的框架。

### 主要貢獻

1. **Communication Policy 形式化**：定義了三種溝通模式——M_text（自由文字）、M_ui（結構化 HTML 表單）、M_hybrid（動態選擇通道）。這不是一個小問題：文字和 UI 有互補優勢——文字促進任務完成，UI 提升回應品質和角色遵從。

2. **Hybrid communication 的實證分析**：跨四個環境和多種用戶 persona，系統性地比較三種模式。文字驅動任務完成，UI 改善回應品質和 persona compliance，hybrid 在大多數設定中達到最佳整體結果——但最優策略依賴於任務結構和 persona。

3. **CPE（Communication Policy Evolution）**：每輪在訓練批次上評估當前策略、讓 LLM 分析 rollout 結果並提出針對性修改、通過兩階段 gate 保證 held-out data 上的單調改善。只用 prompt 層級的優化，不修改模型權重，就達到了所有評估設定中最好的任務完成率。

### 方法 / pipeline

CPE 的演化循環：

1. **Rollout**：在訓練批次上執行當前 communication policy，收集軌跡和結果。
2. **Analysis**：LLM 分析 rollout 結果，識別策略的弱點並提出修改建議。
3. **Edit**：LLM 產生修改後的 policy prompt。
4. **Gate**：兩階段門控——先在訓練資料上檢查改善，再在 held-out 資料上驗證，保證單調改善。

三種溝通模式：
- **M_text**：agent 用 ask_question 發送自由文字詢問。
- **M_ui**：agent 用 generate_ui 產生 HTML 表單讓用戶填寫。
- **M_hybrid**：agent 動態選擇 ask_question 或 generate_ui。

### 實驗設計

- **環境**：四個多步驟任務環境。
- **用戶 persona**：多種用戶類型，模擬不同的專業程度、耐心和溝通風格。
- **模型**：多個 frontier models。
- **設定**：User–Agent（用戶向 agent 溝通）和 Planner–Executor（planner 和 executor 之間溝通）兩個互補設定。
- **主要結果**：
  - 文字和 UI 有互補優勢：文字促進任務完成，UI 改善回應品質和 persona compliance。
  - Hybrid 在大多數設定中最佳，但最優策略依賴任務結構和 persona。
  - CPE 用 prompt 修改（不修改權重）就達到了所有設定中最好的任務完成率。

- **目前從 HTML 前段和 abstract 能確認以上結果**；詳細的 per-environment 和 per-persona breakdown 需要看完整 PDF。

### かに讀後判斷

這篇對 agent memory 和 harness engineering 都有間接相關，但更直接的是它提出了「溝通策略」作為 agent 設計的新維度。和 SAGE 的關係：SAGE 優化的是記憶系統的寫入端，CPE 優化的是 agent 和用戶之間的溝通端——兩者都是在做「路由決策」，只是路由的對象不同（記憶寫入 vs. 溝通通道）。

和 harness engineering 的關係：CPE 的 communication policy 可以看作 harness 的 observation 職責的一部分——agent 如何感知用戶意圖取決於它選擇什麼溝通通道。這和 ActPlane 的 agent-authored policy 有異曲同工之處：agent 自己決定如何互動，然後在 runtime 執行。

**如果對 proactive agent 和溝通策略感興趣，值得快速掃過**。但如果時間有限，優先看 SAGE 和今天的 harness engineering 兩篇。
