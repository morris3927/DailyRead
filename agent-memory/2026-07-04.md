# Agent Memory — 2026-07-04

## 1. HyphaeDB: A Living Knowledge Topology for Agent-First Memory

- **arXiv**: 2606.28781
- **Link**: https://arxiv.org/abs/2606.28781
- **Authors**: (March 2026 submission, detailed author list in full PDF)

### 這篇在說什麼

現有的向量資料庫和 agent memory 框架都把記憶當作被動儲存——agent 寫入、查詢、讀取，儲存層在寫入和讀取之間是惰性的。沒有任何系統讓知識在記憶層本身之間傳播。HyphaeDB 重新詮釋了 HNSW（Hierarchical Navigable Small World）圖——每個現代向量資料庫的核心索引結構——不是作為搜尋優化，而是作為多 agent AI 系統的通訊結構（communication fabric）。在 HyphaeDB 中，agent 是向量空間中的節點（有持續位置），知識透過 gossip protocol 沿著圖的鄰居結構傳播（帶能量衰減），而矛盾檢測、模式結晶、共識形成等湧現行為從拓撲結構、傳播動力學和局部互動規則中自然產生。

### 主要貢獻

1. **HNSW 作為通訊結構**：首次提出將 HNSW 圖拓撲用於多 agent 知識傳播，不是搜尋索引而是通訊網路。Agent 是向量空間中的節點，知識沿語意鄰居關係傳播——語意相關的 agent 先收到知識，不相關的後收到或收不到。這比隨機 gossip 更高效。

2. **Gossip-based 知識傳播 + 能量衰減模型**：每個知識 diff 有初始能量 $E_0 = E_{\text{base}} \cdot \sqrt{s} \cdot \mu(\tau_d)$，其中 $s$ 是顯著性、$\mu(\tau_d)$ 是類型依賴乘數（架構決策廣泛傳播、任務細節局部傳播）。傳播時每跳消耗能量，語意相關性和興趣分數高的路徑優先傳播。傳播算法的關鍵：第 8 行用 HNSW 的語意拓撲選擇鄰居，而非隨機選擇。

3. **多層抽象 + 湧現式晉升**：Layer 0 是密集的局部連接，Layer 1/2 是稀疏的長距連接。知識在 Layer 0 獲得 ≥5 個節點確認且無矛盾後晉升到 Layer 1（區域共識），再在 ≥3 場景無矛盾且顯著性 ≥ 0.8 後晉升到 Layer 2（全局知識）。這不是中心化決策而是湧現的——局部同意晉升為區域同意，再晉升為全局知識。

4. **湧現行為**：四種從拓撲 + 傳播 + 局部規則中自然產生的行為——自動知識路由、矛盾檢測（語意相近的矛盾知識在傳播時碰撞）、模式結晶（局部觀察到的模式透過晉升機制變成全局知識）、共識形成。

5. **PostgreSQL + pgvector 參考實作**：不是純概念提案，有具體的參考實作，並在 Swarm-Driven Development（多 agent 軟體開發方法論）中部署。

### 方法 / pipeline

HyphaeDB 的三個原語：
- **Knowledge nodes**：包含 embedding、content、metadata、salience score、type 的知識單元
- **Topology edges**：HNSW 圖的鄰居關係，同時用於搜尋和傳播
- **Memory diffs**：知識更新的增量表示，帶能量、類型、創建時間

傳播算法（核心）：
1. 收到 diff $\delta$，檢查是否已傳播過（$\mathcal{P}(\delta)$）
2. 投遞到本地（如果此節點是 agent 或 beacon）
3. 找 HNSW 鄰居 $\mathcal{N} = \text{HnswNeighbors}(v, \ell(\delta), K)$
4. 對每個未傳播的鄰居，計算綜合分數 $\sigma = 0.6 \cdot r + 0.3 \cdot \iota + 0.1 \cdot s$（語意相關性 + 興趣 + 顯著性）
5. 如果 $\sigma \geq \sigma_{\min}$ 且剩餘能量 $E(\delta) \geq c$，複製 diff 並衰減能量後繼續傳播
6. 如果滿足晉升條件，創建高層節點並向高層傳播

Anti-entropy：定期的鄰居對狀態比較 + 向量時鐘調解，補 gossip 的概率性傳播。

### 實驗設計

- **參考實作**：PostgreSQL + pgvector，描述了具體的部署場景（Swarm-Driven Development）。
- **理論分析**：基於小世界網路理論（Watts-Strogatz）、epidemic broadcast models（Demers et al.）、群體智能（Reynolds Boids、ACO、stigmergy）。
- **已讀來源**：arXiv HTML 全文前 70%，包含完整的架構、傳播算法、能量模型、層晉升、anti-entropy 和四種湧出行為的描述。參考實作的細節和評估結果在後 30%，需要看完整 PDF。
- **目前能確認的**：架構設計非常新穎（HNSW 作為通訊結構是真正的原創），理論基礎紮實，有參考實作。但沒有看到和大規模多 agent 系統的定量評估對比。
- **不能確認的**：在實際多 agent 工作負載下的效能（延遲、吞吐量、記憶體佔用）、和 Mem0/Letta 等既有系統的直接對比數據。

### かに讀後判斷

HyphaeDB 是 agent memory 領域在 2026 下半年的一個重要原創貢獻。和昨天的 Memory Depth（2606.26806）形成尖銳對比：Memory Depth 問的是「什麼應該持續影響行為」（parametric consolidation vs retrieval），HyphaeDB 問的是「知識如何在 agent 之間流動」（被動儲存 → 主動傳播）。兩者互補：一個處理單 agent 的記憶深度問題，一個處理多 agent 的知識傳播問題。

和 AdMem（2606.06787，今天第二篇）的對比：AdMem 是多 agent 架構（actor + memory + critic），但記憶管理仍是集中式的——memory agent 統一管理寫入、評估、合併、修剪。HyphaeDB 是去中心化的——沒有中心化的 memory agent，知識傳播是透過圖拓撲的局部互動完成的。這是根本性的架構差異。

和 Mem0/Letta 的對比更明顯：Mem0 和 Letta 的記憶都是「agent 寫入 → 向量儲存 → agent 查詢讀取」的被動模式。HyphaeDB 把記憶層變成主動的通訊結構——知識會自己流向需要它的 agent。這是從「database」到「network」的範式轉換。

## 2. AdMem: Advanced Memory for Task-solving Agents

- **arXiv**: 2606.06787
- **Link**: https://arxiv.org/abs/2606.06787
- **Authors**: Runzhe Wang (Princeton), Huilin Lu, Shengjie Liu (Amazon)

### 這篇在說什麼

LLM agent 在長期多回合任務中需要記住、組織和重用知識，但既有的記憶方法主要聚焦於儲存事實資訊（semantic memory），或把程序性記憶簡化為重播過去的成功經驗。這篇提出 AdMem，一個統一的自動記憶框架，整合語意記憶（semantic）、情節記憶（episodic）和程序性記憶（procedural memory），採用雙層設計（short-term + long-term stores），用多 agent 架構（actor + memory + critic）實現自動記憶生成、獎勵標註和自適應檢索。長期記憶透過獎勵驅動的評估、合併和修剪來管理，確保可擴展性和持續改進。

### 主要貢獻

1. **三合一記憶整合**：同時支援 semantic memory（事實知識）、episodic memory（事件序列）和 procedural memory（決策經驗 + 反思），而非只聚焦其中一種。這是對 AWM、MemP 等只做 procedural memory 的系統的改進。

2. **雙層架構**：short-term memory 負責上下文壓縮，long-term memory 負責可擴展的持久儲存，透過獎勵驅動的評估、合併和修剪來管理。這解決了「記憶無限增長」的線上部署問題。

3. **多 agent 架構**：actor agent 負責行動，memory agent 負責記憶管理，critic agent 負責程序性記憶的獎勵標註。Critic 的關鍵創新：不是在任務結束時才標註獎勵，而是在 actor 行動後暫存「半成品記憶」，等觀察到相關結果後再標註獎勵和反思。這解決了程序性記憶的 credit assignment 問題。

4. **線上可擴展性**：長期記憶的合併（相似記憶合併為更高層抽象）和修剪（低獎勵記憶刪除）確保記憶庫不會無限膨脹。這是很多既有系統缺乏的。

### 方法 / pipeline

**Actor Agent Pipeline**：
- 接收觀察 $o_t$，向 memory agent 報告
- Memory agent 生成語意和情節記憶，檢索程序性記憶 $M_t$
- Actor 基於 $(c_t, M_t, M_t')$ 選擇行動 $a_t$，並設定預期結果 $\hat{o}_{t+1}$
- 向 critic 報告半成品記憶 $k = (c_t, a_t, \hat{o}_{t+1}, M_t)$

**Critic Agent Pipeline**：
- 維護記憶佇列 $Q$
- 收到 actor 的半成品記憶後放入佇列
- 收到新的觀察時，檢查佇列中的半成品記憶是否相關
- 相關且所有觀察到齊時，生成獎勵 $r_k \in [0, 1]$ 和反思 $f_k$
- 向 memory agent 報告新的程序性記憶 $(c_k, a_k, f_k)$ 和檢索記憶的獎勵 $(M_k, r_k)$

**Memory Agent**：
- 管理短期和長期記憶庫
- 短期記憶：上下文壓縮，每回合更新
- 長期記憶：獎勵驅動的評估、合併、修剪
- 檢索：基於語意相關性和獎勵分數的加權檢索

### 實驗設計

- **環境**：多種環境（文中提到 various environments，但前半 HTML 沒有完整實驗細節）
- **Baselines**：和 AWM、MemP 等程序性記憶系統對比
- **關鍵發現**：
  - AdMem 在長期多回合任務的穩健性和成功率上優於 baselines
  - Critic agent 的延遲獎勵標註比即時獎勵標註更有效
  - 長期記憶的合併和修剪對可擴展性至關重要
- **已讀來源**：arXiv HTML 全文前半，包含完整的架構描述和算法偽代碼。實驗結果的詳細數據需要看後半。
- **目前能確認的**：架構設計清晰，多 agent 分工合理（actor/memory/critic 的分工解決了程序性記憶的 credit assignment），雙層設計解決了可擴展性。
- **不能確認的**：具體環境的定量結果、合併/修剪的消融實驗、和更多基線的詳細對比。

### かに讀後判斷

AdMem 的定位很明確：它是對當前 agent memory 系統的「只做 retrieval，不做 consolidation」和「只 replay 成功，不學習失敗」兩個限制的回應。Critic agent 的延遲獎勵標註是核心創新——它解決了程序性記憶的 credit assignment 問題，不是在任務結束時才標註，而是在觀察到相關結果後才標註。

和昨天 Memory Depth（2606.26806）的對比：Memory Depth 用 surprise × valence gate 做 parametric consolidation（寫入 LoRA），AdMem 用 critic agent 做 symbolic consolidation（寫入長期記憶庫）。前者是 parametric approach，後者是 symbolic approach。兩者處理的問題相同（什麼應該持續影響行為），但解法根本不同。

和 HyphaeDB 的對比：AdMem 是集中式記憶管理（memory agent 統一管理），HyphaeDB 是去中心式記憶傳播（gossip over HNSW）。兩者互補而非競爭——AdMem 解決單 agent 的記憶管理，HyphaeDB 解決多 agent 的知識流動。理想中的 agent 記憶系統可能需要兩者：每個 agent 內部有 AdMem 式的三合一記憶管理，agent 之間有 HyphaeDB 式的知識傳播。
