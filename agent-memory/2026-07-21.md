# Agent Memory — 2026-07-21

## 1. Do Self-Evolving Agents Forget? Capability Degradation and Preservation in Lifelong LLM Agent Adaptation (2605.09315)

- **arXiv**: 2605.09315
- **Link**: https://arxiv.org/abs/2605.09315
- **Authors**: Ye Yu, Xiaopeng Yuan, Haibo Jin, Heming Liu, Yaoning Yu, Haohan Wang
- **Affiliation**: University of Illinois Urbana-Champaign
- **Submitted**: 2026-05-10

### 這篇在說什麼

這篇問的問題簡單但關鍵：self-evolving agent 在適應新任務時，會不會忘掉已經學會的能力？答案會——而且這不是偶發的，而是一個結構性的現象。作者把 self-evolving agent 的演化路徑分成四個 channel：workflow evolution、skill/tool evolution、model evolution、memory evolution，然後在每個 channel 都觀察到同一個問題：當 agent 的 task distribution 從舊的 D_old 轉移到新的 D_new 時，反覆更新 mutable repository 會破壞之前支撐舊任務的內部結構。作者把這個現象命名為 capability erosion under self-evolution，並提出 Capability-Preserving Evolution (CPE) 作為通用緩解原則——在每次演化更新時加上 retention regularizer，限制更新對舊 capability 的破壞性干擾。

這篇的重要性在於它把一個看似只屬於 catastrophic forgetting（model parameter 層面）的問題，推廣到所有 self-evolution channel：不只是 model weights 會 forget，workflow、skill library、memory store 也都會。這對 DailyRead 之前追蹤的 lifelong agent memory 討論（PlaceMem、Infini Memory、TriMem）有直接影響——如果你的 memory management 沒有考慮 retention，新增 memory 的過程本身就會 erode 之前的能力。

### 主要貢獻

1. **Capability erosion 的系統性識別**：首次在四個 evolution channel（workflow、skill/tool、model、memory）上都觀察到 capability erosion，並證明這不是某個特定 adaptation mechanism 的 artifact，而是 unconstrained self-evolution 的結構性後果。

2. **統一的 interference perspective**：提出一個 local analysis（Proposition 1），顯示 capability erosion 的根源在於 new-task update direction 跟 old-task curvature directions 有 non-zero projection。這意味著更新的大小不是唯一因素——更新方向是否與舊任務的重要方向重疊才是關鍵。

3. **Capability-Preserving Evolution (CPE)**：一個通用穩定化原則，在每個 evolution channel 加入 channel-specific 的 retention regularizer（Ω_wf, Ω_sk, Ω_md, Ω_mem），使更新在改善新任務的同時最小化對舊 capability 的破壞。

4. **Cross-channel 實驗驗證**：在所有四個 channel 上，CPE 都改善了 retained capability stability，同時保持了 adaptation performance。例如 workflow evolution 中，CPE 把 retained simple-task performance 從 41.8% 提升到 52.8%（GPT-5.1），同時 complex-task adaptation 也更強。

### 方法 / pipeline

**Self-evolution 的形式化**：
- 把 self-evolution 建模為 sequential adaptation over task distributions D₁, D₂, ..., D_T
- 每個 stage t，agent 有 capability state R_t（可以是 workflow graph, skill repository, model parameters, memory store）
- Naive self-evolution 只優化當前任務：R_t^naive = argmin L_t(R)
- CPE 加入 retention regularizer：R_t^CPE = argmin L_t(R) + λΩ_t(R, R_{t-1})

**Four evolution channels**：
1. **Workflow evolution**: R_t 是 executable policy graph / prompt program，Ω_wf 限制新 workflow 不要破壞舊 workflow 的執行路徑
2. **Skill/tool evolution**: R_t 是 reusable skill repository，Ω_sk 限制新 skill 的加入不要覆蓋舊 skill 的功能
3. **Model evolution**: R_t 是 model parameters，Ω_md 是 parameter-space retention（類似 EWC 但泛化到 self-evolution setting）
4. **Memory evolution**: R_t 是 external memory store，Ω_mem 限制新 memory entries 不要 overwrite 舊 entries 的 retrieval utility

**Proposition 1 (Curvature mechanism)**：如果 R_{t-1} 是 L_{<t} 的 local minimizer，naive update R_t = R_{t-1} - ηg_t 會使得 L_{<t}(R_t) - L_{<t}(R_{t-1}) = (η²/2)g_t^T H_{<t} g_t + o(η²)，其中 H_{<t} 是 retained objective 的 Hessian。只要 g_t 在 H_{<t} 的正曲率方向有非零投影，erosion 就會發生。

### 實驗設計

論文在四個 evolution channel 各設計了實驗：

- **Workflow evolution**: 在 SWE-bench 和 WebArena 上測試，agent 用 LLM optimize 自己的 workflow，然後在新 task distribution 上再 optimize。CPE 用 workflow retention regularization，在 GPT-5.1 上把 retained simple-task performance 從 41.8% 提升到 52.8%。

- **Skill/tool evolution**: Agent 累積 reusable skills/tools，測試在新 task 來時加入新 skill 是否破壞舊 skill 的表現。CPE 用 skill retention regularization。

- **Model evolution**: 在 continual fine-tuning setting 測試，新 task 的 fine-tuning 是否損害舊 task 的 performance。CPE 的 parameter retention regularization 類似 EWC 但在 self-evolution context。

- **Memory evolution**: Agent 的 external memory store 在新增 entries 時是否損害舊 entries 的 retrieval utility。CPE 用 memory retention regularization。

每個 channel 的實驗都顯示：(1) naive self-evolution 會造成 capability erosion，(2) CPE 能有效緩解 erosion 同時保持 adaptation performance。

### かに讀後判斷

這篇是 agent memory 和 self-evolution 討論裡必讀的一篇。它把 catastrophic forgetting 從 model parameter 層面推廣到所有 self-evolution channel，這直接影響到目前 agent memory 系統的設計。PlaceMem 用 versioned memory capsules 處理 correction/invalidation，TriMem 從 atomic facts 拉到 structural memory，這篇說的是：不管你的 memory 用什麼結構，如果你在新增 memory 時沒有明確考慮 retention，就會 erode 舊 capability。

Proposition 1 的 curvature mechanism 是深讀的重點——它告訴你 erosion 不只是「forgetting」這個直覺概念，而是一個有數學結構的現象：只要 new-task update 在 old-task 的重要方向有投影，erosion 就必然發生。CPE 的 channel-specific regularizer 也值得仔細看，特別是 Ω_mem 怎麼在 memory evolution channel 實作——這跟 DailyRead 之前追蹤的 memory management 討論直接相關。

深讀時優先看：Section 2 的 interference perspective 和 Proposition 1、Section 3 的 CPE formulation、以及每個 channel 的實驗細節（特別是 memory evolution 的 Ω_mem 實作和結果）。

## 2. MemoryCD: Benchmarking Long-Context User Memory of LLM Agents for Lifelong Cross-Domain Personalization (2603.25973)

- **arXiv**: 2603.25973
- **Link**: https://arxiv.org/abs/2603.25973
- **Authors**: Weizhi Zhang 等
- **Published**: Lifelong Agent @ ICLR 2026 (workshop paper)
- **Submitted**: 2026-03-26
- **Depth level**: Abstract + landing page 快速掃描

### 這篇在說什麼

MemoryCD 是一個 user-centric、cross-domain 的 memory benchmark，從 Amazon Review dataset 衍生出 lifelong real-world user behavior。跟之前用 synthetic dialogue 或 scripted persona 的 memory benchmark 不同，MemoryCD 追蹤真實使用者跨年份、跨領域的互動，測試 LLM agent 在單一領域和跨領域設定下的 personalization 能力。它測了 14 個 SOTA LLM + 6 種 memory method baselines 在 12 個領域、4 個 personalization task 上的表現，結論是現有 memory methods 離 user satisfaction 還有很大距離。

### 主要貢獻

1. **第一個大規模 user-centric cross-domain memory benchmark**：不依賴 synthetic data，而是從真實 Amazon Review 的 lifelong user 行為構建。

2. **Multi-faceted evaluation pipeline**：4 個 personalization task（preference prediction, recommendation, review generation, behavior prediction）× 12 個領域 × 14 個 base model × 6 memory methods。

3. **Cross-domain personalization 的首次系統性評估**：不只測單一領域，還測跨領域的 memory transfer 和 personalization。

### 方法 / pipeline

- Benchmark 構建：從 Amazon Review dataset 選取跨年份、跨領域有足夠互動的使用者
- Memory methods：6 種 baseline（包括 simple context, retrieval, summarization 等）
- Evaluation：4 個 personalization task，每個都有對應的 metric

### 實驗設計

目前從 abstract 能確認：
- 14 個 SOTA LLM base models
- 6 memory method baselines
- 4 personalization tasks
- 12 diverse domains
- 結論：existing memory methods are far from user satisfaction in various domains

還看不到每個 memory method 的具體表現差異、cross-domain transfer 的詳細分析、和各 task 的 metric 細節，需要看全文。

### かに讀後判斷

MemoryCD 補了 DailyRead 追蹤的 agent memory benchmark 空白——之前看過的 MemoryCD 跟 PlaceMem、TriMem、Infini Memory 主要是 memory system 設計，benchmark 側面較少。MemoryCD 的 user-centric cross-domain 設計比 synthetic dialogue 更接近真實 lifelong 使用場景，但作為 workshop paper 規模和深度可能有限。如果 Morris 對 memory evaluation 有興趣，值得快速掃過它的 benchmark 設計和主要結果，特別是 cross-domain transfer 的部分。但建議先看 Do Self-Evolving Agents Forget (2605.09315)，那篇的理論貢獻更根本。
