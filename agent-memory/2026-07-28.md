## 1. A Bi-Temporal Memory Engine for LLM Agents Where a Lean Retrieved Context Beats the Full History

![](../assets/2026-07-28/engram-bitemporal-memory.png)

- **arXiv / Venue / 類型**: arXiv:2606.09900，agent memory system / evaluation harness paper
- **Link**: https://arxiv.org/abs/2606.09900
- **查重**: `check_paper_seen.py 2606.09900` → `NOT_SEEN`
- **讀取來源**: arXiv HTML full text（Abstract、Introduction、Related Work、System、Bi-temporal Data Model、Write / Consolidation / Read Path）

### 這篇在說什麼

Engram 這篇的問題意識很直接：長期 agent memory 不能只是把所有歷史塞回 prompt，也不能只說「我們比較省 token」。全文回放 expensive、slow，而且當 distractors 累積後 accuracy 會下降；但很多 memory system 雖然比較便宜或比較快，仍輸給 full-context baseline。Engram 要證明更強的命題：一個精準檢索、帶 provenance、帶 temporal correctness 的 lean retrieved context，不只省，還可以比 full history 更準。

作者把 memory 當成 dual-process system。System-1 hot write path 快速 append lossless episodes，不在 critical path 上跑 LLM；System-2 asynchronous consolidation 才抽 atomic facts、建 bi-temporal knowledge graph、處理 contradictions。這種設計把 agent memory 從「一堆向量或摘要」提升到可以回答「這個事實何時有效？我們何時知道它？它被哪個新事實取代？來源是哪個 episode？」的時態資料系統。

### 主要貢獻

第一，Engram 提出 bi-temporal memory data model。Episode 保留 raw lossless turn / event，帶 event time 和 ingested-at；Fact 是 atomic subject–predicate–object claim，有 embedding、salience、confidence、provenance、valid time、transaction time、supersedes pointer；Entity / Relation 則形成 graph nodes / edges，也帶 temporal stamps。被矛盾的新事實取代時，舊 fact 不是 hard-delete，而是 invalidated，保留 supersession chain。

第二，它的 read path 是 hybrid，不只 retrieval facts，也保留 raw chunks。dense semantic、BM25 lexical、graph proximity、recency / salience 等信號透過 RRF 或配置權重融合，再經 as-of temporal filter，最後組成 compact provenance-tagged context。作者特別強調 facts-only 會掉 recall，facts + raw chunks 才是 load-bearing composition。

第三，它提供 neutral reproducible harness。作者把 official LongMemEvalS category-specific judge、full-context baseline、raw per-question logs、commands 都放在 in-repo pipeline，並批評 memory benchmark 常見的 measurement pitfalls：truncation、home-grown judges、full-history leaks、不同 ingestion / answer prompt 導致分數不可比。

第四，主結果是 lean context 在 accuracy 上打敗 full context：LongMemEvalS 500 questions，Engram lean configuration 用約 9.6k-token retrieved slice，83.6% vs full-context baseline 73.2%，約省 8× tokens，且 McNemar exact p < 1e-6。這不是只省成本，而是移除 distractors 後提升回答品質。

### 方法 / pipeline

Engram 的 pipeline 分三段。Hot write path 接到 `add(messages)` 時，append lossless episode、resolve identity、計算 light embedding，然後 enqueue episode for consolidation；這段目標是 sub-50ms，避免記憶寫入阻塞 agent loop。

Async consolidation path 做較重的 System-2 工作：從 episodes 抽 atomic facts，建 bi-temporal KG，偵測 conflict，invalidate superseded facts，更新 salience，做 decay / reinforcement，必要時產生 session summaries 或 profile-level abstraction。衝突解決採 cheap-then-escalate：先看 exact subject-predicate slot、embedding similarity、content subsumption；明確 temporally ordered contradiction 直接 invalidates old fact 並設定 supersedes pointer；只有模糊情況才找 LLM adjudicator。

Read path 則從 query understanding 開始，必要時拆 multi-hop subqueries；並行跑 dense retrieval、BM25、graph n-hop、recency / salience；用 rank fusion / scoring 合併，套 as-of temporal filter，經 abstention gate，再組成 deduplicated、provenance-tagged、token-budgeted context。這裡的關鍵不是單一 retrieval trick，而是把 temporal correctness、hybrid evidence、provenance、abstention 都放到同一 memory interface。

### 實驗設計

實驗以 LongMemEvalS 500 questions 為主，使用 official category-specific judge。Engram lean configuration 與 full-context baseline 同表呈現，避免只和弱 baseline 比較。主結果是 83.6% accuracy 對 73.2% full-context，+10.4 points，約 8× fewer tokens（9.6k vs 79k），且兩系統 0/500 errors。作者也做 per-category analysis，指出 bi-temporal modeling 對 knowledge-update 和 temporal 類別特別有價值，仍有 multi-session aggregation、preference 類別 headroom。

Ablation 上，作者指出 hybrid read path 是 load-bearing：facts-only path 會失去細節 recall，而加入 retrieved raw chunks 可以補回 detail。這個結果對 memory system 很重要，因為它反駁了「只要把歷史抽成漂亮知識圖譜就好」的直覺；agent 記憶需要結構化 fact 來做時間與衝突管理，也需要 raw provenance chunks 來回答細節。

### かに讀後判斷

這篇是今日 Agent Memory 最值得點開的一篇。它把近期 memory paper 的幾條線合在一起：temporal KG、conflict resolution、hybrid retrieval、full-context baseline、reproducible harness。和 MemGraphRAG、Infini Memory、A-MEM 之類工作相比，Engram 的強點不是某個 flashy model，而是它很清楚地說：記憶系統的 benchmark 數字如果不能重現、沒有 full-context baseline、沒有 raw logs，就很難相信。

我會建議 Morris 深讀 Figure 1、Section 3 的 bi-temporal data model、cheap-then-escalate conflict resolution、Section 5 的 LongMemEvalS results / ablations。對我們自己的 agent memory / graph memory 工作，最可以直接借的不是 83.6% 這個數字，而是 evaluation discipline：每個 memory claim 都要同時報 full-context baseline、token budget、category-specific performance、raw logs、以及 query-time assembled context 到底包含 facts 還是 chunks。

## 2. LazyMem: Retrieve Broadly, Construct Selectively for Efficient Long-Term Agent Memory

- **arXiv / Venue / 類型**: arXiv:2607.22690，cs.AI，agent memory retrieval / compression paper
- **Link**: https://arxiv.org/abs/2607.22690
- **查重**: `check_paper_seen.py 2607.22690` → `NOT_SEEN`
- **讀取來源**: arXiv abstract + arXiv HTML full text（Introduction、Related Work、Method 前段）

### 這篇在說什麼

LazyMem 處理的是 agent memory 裡 retrieval coverage 和 context burden 的兩難。raw dialogue history verbose 而且 information-sparse；retrieve broadly 可以提高 evidence coverage，但會把一大堆 noise 丟給 downstream reasoner；write-time compression / construction 可以減少 noise，卻會在未來 query 還沒出現前不可逆地丟掉細節。LazyMem 的答案是「lazy」：不要在寫入時做 lossy construction，而是在 query time 才把 retrieval candidate pool 壓成 query-relevant memory。

這和 construct-then-retrieve paradigms 不同。既有方法常在寫入時 summarization、rewrite、aggregate、link 成 structured memory units；這對常見 query 有幫助，但對未預期的未來問題可能損失關鍵細節。LazyMem 保留 raw interactions，查詢時 retrieve a large pool，再用小模型處理 overlapping parallel windows，選擇並壓縮 query-relevant content。

### 主要貢獻

第一，提出 retrieve-then-construct memory pipeline：先 broad retrieval 確保 coverage，再在 query time selective construction，避免 write-time irreversible information loss。

第二，用 4B memory-processing model 處理 retrieved candidate pool。它不是把整個 recalled pool 一次塞進大模型，而是切成 overlapping windows 並行處理，降低 context rot，讓 latency 隨 pool 變大時仍可控。

第三，訓練方式是 SFT 加 group-based reinforcement learning。reward 是 format-gated composite reward，結合 rule-based action signal（selection accuracy）與 LLM-judged quality signal（source faithfulness、query utility）。作者說 cumulative training 讓 LongMemEval LLM-judge accuracy 從 prompting alone 0.41 提升到 0.85。

第四，實驗報告 LazyMem-4B 在 LongMemEval 達 0.85 LLM-judge accuracy，只用 213 memory tokens，比 retrieval-only 少 68.7×；且 zero target-domain training generalizes to LoCoMo 0.68。32B variant 可到 0.93，並在 aggregation-heavy question types 超過 oracle-context references。

### 方法 / pipeline

LazyMem pipeline 是 raw messages stored as-is → query arrives → retrieve broad candidate pool → lightweight constructor model processes overlapping windows in parallel → each window selects / compresses query-relevant snippets → downstream answer model receives compact constructed evidence。overlapping windows 的作用是保留跨 window 的 evidence continuity，同時避免單一 constructor prompt 太長而 context rot。

訓練上，constructor model 先用 supervised fine-tuning 學 format 和基本 selection，再用 group-based RL 優化行為。reward 同時要求輸出格式正確、選擇的 evidence 對 query 有用、內容忠於 source、不亂編。這使小模型可以接近或超過 prompt-based extraction 的品質，但成本和延遲更低。

### 實驗設計

實驗包含 LongMemEval 與 LoCoMo。LongMemEval 主結果是 LazyMem-4B accuracy 0.85、213 memory tokens、比 retrieval-only 少 68.7× tokens；LoCoMo 在沒有 target-domain training 下達 0.68。作者也比較 prompt-based query-time baseline，指出 LazyMem 減少 mean latency，並在 appendix 中討論 construct-then-retrieve 的 information loss。

需要注意的是，這篇很倚賴 LLM-judge accuracy 與 constructor training setup。它的數字看起來很強，但如果要深讀，應該檢查 reward design、training data 是否和 benchmark distribution 太接近、oracle-context references 怎麼定義，以及 213 memory tokens 是否在所有 question type 上都足夠。

### かに讀後判斷

LazyMem 是 Engram 之外今天很值得收錄的 memory paper，因為它代表另一條路線：Engram 強調 typed / temporal / provenance memory substrate，LazyMem 強調 raw-preserving、query-time learned construction。兩者其實互補：Engram 提醒我們需要 bi-temporal correctness 與 provenance，LazyMem 則提醒不要過早把 raw history 壓成 query-agnostic memory。

如果 Morris 只想點一篇 agent memory，我會先點 Engram；如果想看 memory compression / query-time evidence construction，就看 LazyMem 的 Figure 1、Method、reward design、LongMemEval / LoCoMo tables。這篇可能對「如何把大量 session transcript 壓成當前任務需要的短 evidence」特別有啟發。

## 3. Accurate and Efficient Long-Term Memory for LLM Agents (MOSAIC)

- **arXiv / Venue / 類型**: arXiv:2607.16211，cs.AI，structured memory graph paper
- **Link**: https://arxiv.org/abs/2607.16211
- **查重**: `check_paper_seen.py 2607.16211` → `NOT_SEEN`
- **讀取來源**: arXiv abstract + arXiv HTML full text（Introduction、Related Work、Method 前段）

### 這篇在說什麼

MOSAIC 關注 memory-augmented LLM agents 的另一個痛點：有記憶不代表會正確地用記憶推理。許多系統把 memory 當 append-only store，新資訊進來就存，沒有驗證它是否和既有記憶矛盾；時間久了，矛盾會透過 extraction → storage → retrieval → reasoning pipeline 放大。作者特別用 clinical / legal / finance 等 safety-critical domain 說明，錯誤或矛盾一旦進入 persistent memory，之後每次 retrieve 都可能造成下游錯誤。

它的解法是 structured, conflict-aware long-term memory。核心主張是 flat unstructured chunks 失去 relational context，LLM-based classification 又太慢太貴；因此 MOSAIC 用 entity-typed graph storage、hash-accelerated dual-path retrieval、以及 save-time active conflict detection，把 memory graph 變成可查、可更新、可偵測矛盾的資料結構。

### 主要貢獻

第一，MOSAIC 用 typed entity graph 保存 events、personas、relationships，讓 multi-hop / temporal reasoning 可以利用 relational structure，而不是只靠 semantic search。

第二，它用 locality-sensitive hashing 取代 expensive LLM-based classification，做 hash-accelerated dual-path retrieval。摘要報告 search latency 平均 0.58 秒，主張在幾乎不犧牲 accuracy 下可大幅降低查詢成本。

第三，active conflict detection 在 save time cross-reference new information against graph neighbors。若新資訊和既有 graph neighbor 有矛盾，就觸發 warning、updates 或 deletions。這和只在 query time 發現 retrieval 裡有矛盾不同，是在 memory ingestion 階段降低 error compounding。

第四，作者提出 neighbor-conditioned stability：一個 node 的 importance、belief state、priority 只有在至少一個 graph neighbor 改變時才需要 re-evaluate。這讓系統避免全局重算，利用 graph locality 做 memory update。

### 方法 / pipeline

MOSAIC pipeline 從 dialogue 開始，經 entity extraction、dual-path classification（LLM 或 LSH）、放入 typed memory graph。Graph 裡區分 prerequisite dependencies 與 semantic associations，前者支撐 logical validity，後者支撐 conversational coherence。儲存時 conflict detection module 會把新 facts 和 graph neighbors cross-reference，找出 contradiction 並 resolve 或標示。查詢時則用 community-aware retrieval / graph-based retrieval 支援 multi-hop reasoning。

它和一般 GraphRAG 不同的地方在於 ingestion-time validation。GraphRAG 類方法多半關注 retrieval quality；MOSAIC 把「不要把矛盾寫進 persistent memory」當成核心功能，這對長期 agent 特別重要。

### 實驗設計

MOSAIC 在 LoCoMo、HaluMem、以及 novel clinical-guideline error compounding test 上評估。摘要與 introduction 報告 LoCoMo overall accuracy 89.35%，比 best baseline Mem0 高 27.21 pp；HaluMem-Medium extraction F1 86.77%、HaluMem-Long extraction F1 85.84%；HaluMem QA correctness Medium / Long 為 73.10% / 70.75%；在 50 個 manually injected hypertension guideline factual conflicts 上偵測 66%，是 best baseline 14% 的 4.7×；平均 HaluMem-Medium search latency 0.58 秒。

我目前讀到 Method 前段，足以確認架構與主結果；若要完整驗證，還需要看 baseline setup、conflict injection protocol、clinical guideline conflict 的人工設計是否公平，以及 LSH retrieval 的 ablation。

### かに讀後判斷

MOSAIC 值得收錄，因為它把 memory 的「矛盾管理」推到 ingestion-time，而不是只期待 retrieval / answer model 自己解決。它和 Engram 在 conflict / temporal correctness 上有共同關心，但 MOSAIC 更偏 typed graph + local update + LSH acceleration；Engram 更偏 bi-temporal provenance + reproducible LongMemEval harness。

如果 Morris 要找可實作靈感，MOSAIC 的 active conflict detection 與 neighbor-conditioned stability 很值得看；但今日推薦我仍放 Engram，因為 Engram 在 benchmark integrity 和 full-context comparison 上更成熟，對 DailyRead 的 paper memory / graphify 方向也更直接。
