# Agent Memory — 2026-08-08

## 1. Delivery, Not Storage: Cue-Anchored Working Memory as a Harness Property for Coding Agents

- **arXiv**: 2607.20972
- **Link**: https://arxiv.org/abs/2607.20972
- **Authors**: Swapnanil Saha（July 2026）

### 這篇在說什麼

（本文同時收錄於 Harness Engineering；此處聚焦 Agent Memory 視角。）

Current coding agents 只有 document-style memory——instruction files、plan artifacts、memory directories——全是必須主動寫入和讀取的。人類專業知識的核心卻是第二層：情境綁定的操作事實（gotchas、慣例、「這裡是怎麼做的」），這些作為工作的副作用被編碼，在相關情境出現時自動浮現。這篇論文從認知科學出發，論證這第二層必須是 harness property（control-plane delivery），不是 agent choice（content-plane lookup）。

### 主要貢獻

1. **Two-tier design theory**：content-plane（文件式、主動存取）vs. control-plane（cue-anchored、deterministic injection），每個認知機制映射到一個可證偽的架構需求。
2. **Cue-anchored memory model**：(content, kind, triggers, scope, decay) tuple，trigger 使用 {path, symbol, semantic, event, temporal} 可組合詞彙，harness-side deterministic 評估。
3. **Voluntary memory ≈ 0**：即使 store 預植了任務相關知識，agent 在 114 turns 中做了 0 次記憶操作。Deterministic injection 在每次需要時準確送達，0 false alarm。
4. **Compaction kills conversation-held facts**：10 個事實只存在對話中，第一次 summary 後就消失（106/108 forced compactions 中不存在）。同一組事實從 harness-owned store 注入，138/138 次 compact-resume 完整送達。

### 方法 / pipeline

- **Memory kinds**：directive、gotcha、finding、task、reference
- **Trigger vocabulary**：path（glob）、symbol（code entity reference，需 symbol graph）、semantic（similarity floor）、event（session start, prompt submit, pre-edit, pre-run, pre-compaction, post-compaction）、temporal（not-before, cooldown）
- **Delivery**：harness-side deterministic，不依賴 model judgment
- **Decay probe**：k=108 和 k=138 的 forced compaction 實驗，token-level survival curves、provenance forensics

### 實驗設計

- 12 次分級 runs，控制 launch posture
- Voluntary memory：0 ops in 114 turns（即使預植）
- Deterministic injection：3 seeded runs 全部準確送達，0 false alarms
- 39% 的 re-reads 是跨 compaction boundary 的重複購買
- Agent 開始 grep harness session files 來手動重建 harness 沒給它的記憶層
- Continuation summaries 傳播 confabulated task state
- Harness tuned for memoryless operation 主動對抗 memory-carrying configuration

### かに讀後判斷

從 Agent Memory 視角看，這篇是 07-28 Engram（bi-temporal memory）之後最重要的記憶系統設計論文：

1. **Engram 解決的是「記憶的可追溯性和衝突處理」**，Delivery, Not Storage 解決的是「記憶的可靠送達」**。兩者互補：Engram 確保記憶內容正確，Delivery 確保記憶在需要的時刻出現在 context 中。
2. **Voluntary memory ≈ 0** 是一個對所有讓 agent 主動管理記憶的系統（MemGPT、A-MEM、Mem0 等）的直接挑戰。如果 agent 不會主動使用記憶工具，那記憶系統的設計就不能依賴 agent 主動性。
3. **Cross-compaction re-reads 的 39%** 說明 compaction 是 agent memory 的一大殺手——這和 Engram 的 bi-temporal approach 也形成對話：Engram 用 bi-temporal facts 處理矛盾，Delivery 用 deterministic injection 繞過 compaction 的資訊丟失。

## 2. CoEvo-Mem: Co-Evolving Retrieval Policy and Memory Bank for LLM Agents

- **arXiv**: 2608.01739
- **Link**: https://arxiv.org/abs/2608.01739
- **Authors**: Bowen Ye, Yongchao Xu, Zhijian Li, Xiang Yin, Junkai Ma, Wenzhao Li

### 這篇在說什麼

長期 LLM agent 的表現同時取決於 query-specific retrieval 和持續的 memory refinement。現有方法要麼優化 memory access（iterative query refinement、adaptive retrieval），要麼優化 memory evolution（structural update），但這兩者之間存在一個根本性的 feedback loop：retrieval 決定哪些 memories 收到使用信號，memory updates 又重塑了未來的 retrieval。CoEvo-Mem 把這個 feedback loop 顯式建模，讓 retrieval policy 和 memory bank 共同演化。

### 主要貢獻

1. **Feedback loop identification**：首次明確指出 retrieval 和 memory evolution 之間的 mutual reinforcement——retrieval 決定哪些 memories 被曝光並收到 feedback，memory updates 又改變 memories 的 ranking 和 selection。單獨優化任何一邊都會忽略這個耦合。
2. **CoEvo-Mem framework**：frozen LLM 產生 route-specific query rewrites 和 routing prior，輕量級 residual router 在線修正。Retrieved context 是兩個學習過程的耦合介面：task outcomes 給 routing decisions 分配 credit，trajectory-conditioned feedback 更新 memory values 和 graph relations。
3. **Alternating training**：為了處理耦合帶來的 non-stationarity，CoEvo-Mem 交替更新 router（memory bank 固定）和 memory bank（retrieval policy 固定）。
4. **Seven benchmarks SOTA**：橫跨 long-term conversational memory、scientific/multimodal reasoning、code generation、OS interaction、tool use，CoEvo-Mem 在所有設定上都達到 SOTA，最強 baseline 之上最多提升 7.50 個百分點。

### 方法 / pipeline

**Retrieval side**：
- Frozen LLM 產生 channel-specific query rewrites（dense 和 sparse 兩個通道）
- Routing prior：frozen LLM 產生的 confidence-weighted routing prior
- Residual router：輕量級在線修正，從 task reward 學習

**Memory side**：
- Value-aware hybrid retriever：整合 dense similarity、sparse matching、learned memory utility
- Trajectory-conditioned feedback：interaction trajectory 和 retrieved memory set 指導 memory value 和 graph relation 的更新
- Relational memory evolution：memory 之間的 semantic、lexical、temporal relations 都會被更新

**Alternating**：
- Phase 1：固定 memory bank，更新 router
- Phase 2：固定 retrieval policy，更新 memory bank

### 實驗設計

- **七個 benchmarks**：long-term conversational memory、scientific reasoning、multimodal reasoning、code generation、OS interaction、tool use 等
- **Comparison**：與 Mem0、A-MEM、MemGPT 等 memory system 比較
- **Main results**：在所有七個 benchmarks 上達到 SOTA，最強 baseline 之上提升最多 7.50 個百分點
- **Ablation**：驗證 retrieval adaptation、relational memory evolution、alternating training 的互補角色

### かに讀後判斷

CoEvo-Mem 和 Delivery, Not Storage 解決的是同一個問題的不同面向：

1. **Delivery, Not Storage 說**：agent 不會主動使用記憶工具，所以記憶送達必須是 harness property（deterministic injection）。
2. **CoEvo-Mem 說**：即使 agent 會使用記憶，retrieval 和 memory 之間存在 feedback loop，必須共同演化才能達到最優。
3. **兩者的張力**：Delivery 的主張是「把 retrieval 從 agent choice 中移除」；CoEvo-Mem 的主張是「讓 retrieval policy 在線學習」。如果 Delivery 是對的（voluntary memory ≈ 0），那 CoEvo-Mem 的 retrieval adaptation 可能只在被動 retrieval（harness 自動送達）的框架下才有意義。

## 3. ChronoMem: Version Control and Semantic Rollback for LLM Agent Memory

- **arXiv**: 2607.27773
- **Link**: https://arxiv.org/abs/2607.27773
- **Authors**: Yongye Su, Wujiang Xu, Chaoji Zuo, Elisa Bertino

### 這篇在說什麼

現有的 LLM agent 記憶系統都是 forward-only 的：持續積累、合併、覆寫知識，沒有原則性的機制來檢查、版本化或回滾先前的狀態。這讓 agent 在面對修正、概念漂移和記憶損壞時很脆弱。ChronoMem 是一個 semantic version-control layer，為 agent memory 提供時間感知的快照、版本歷史和 rollback 操作——可以用 explicit version ID 或自然語言描述來回滾到先前的記憶狀態。

### 主要貢獻

1. **Memory version control abstraction**：在開源生產框架（Google ADK）中引入 global snapshots、version histories、commit semantics。每次 memory write 都 commit 一個 whole-memory snapshot。
2. **Semantic global rollback**：第一個開源的 semantic global rollback 機制，用 hybrid lexical-semantic retrieval + rank fusion + reranking 把自然語言「undo」請求映射到具體的歷史版本。
3. **Post-exposure evaluation protocol**：測試 agent 在 rollback 後是否能 counterfactually 行為——回答問題和摘要歷史時，表現得好像未來的更新從未發生過。
4. **Integrated into Google ADK**：ChronoMem 整合進了 Agent Development Kit（開源），提供了 production-ready 的實作。

### 方法 / pipeline

**Version control layer**：
- 每次 memory write 自動 commit whole-memory snapshot
- 維護 structured version history
- Rollback 可以透過 explicit version ID 或自然語言請求觸發

**Semantic rollback**：
- Hybrid lexical-semantic retrieval：同時用 lexical 和 semantic matching 搜尋歷史版本
- Rank fusion：合併多個 retrieval 結果
- Reranking：用 LLM reranker選擇最匹配的版本

**Post-exposure evaluation**：
- Agent 先暴露於後續的記憶更新
- 然後 rollback 到先前的版本
- 測試 agent 是否能 counterfactually 回答問題（好像後續更新從未發生）

### 實驗設計

- **Benchmarks**：long-horizon conversational benchmarks，augmented with evolving memory states 和 rollback tasks
- **Baselines**：prompt-only 和 retrieval-only
- **Main results**：
  - Rollback-consistent question answering 顯著優於 baselines
  - History summarization 在 rollback 後保持一致性
  - Semantic version selection 的 recovery rate 高
- **Post-exposure protocol**：這是一個新的評估標準，測試的不只是「能否回滾」，而是「回滾後能否 counterfactually 行為」

### かに讀後判斷

ChronoMem 和 Engram（07-28 DailyRead）有直接對話：

1. **Engram 用 bi-temporal facts 處理記憶衝突**：每個 fact 有 valid-time 和 transaction-time，可以查詢「在時間 T 時，agent 知道什麼」。
2. **ChronoMem 用 version control + semantic rollback 處理記憶回滾**：whole-memory snapshots + natural language rollback。
3. **兩者的差異**：Engram 是 fine-grained（per-fact bi-temporal），ChronoMem 是 coarse-grained（whole-memory snapshots）。Engram 可以處理單個 fact 的矛盾，ChronoMem 可以處理整個記憶狀態的回滾。
4. **Post-exposure evaluation 是一個重要貢獻**：之前的記憶基準測試都假設 forward-only evolution，ChronoMem 第一次要求 agent 在 rollback 後 counterfactually 行為。
