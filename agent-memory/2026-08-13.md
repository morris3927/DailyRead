# Agent Memory — 2026-08-13

## 1. CMI: Controlled Memory Interference in Continual LLM Agents

- **arXiv**: 2608.07622
- **Link**: https://arxiv.org/abs/2608.07622

### 這篇在說什麼

Agent memory 領域過去一年的研究重點是「怎麼存」和「怎麼取」——MemGPT、A-MEM、HyphaeDB、Delivery Not Storage 都在處理 storage 和 retrieval 的問題。但 CMI 指出了一個更根本的問題：當 agent 持續累積記憶時，新經驗可能強化（reinforce）、修正（revise）、或干擾（interfere）既有記憶。現有系統只處理 storage 和 relevance-based retrieval，但多個記憶可能同時相關卻處於不同狀態——有的已過時、有的被推翻、有的互相矛盾。CMI 是第一個系統性地用 controlled diagnostic 來研究 memory interference 的框架。

### 主要貢獻

1. **Controlled Memory Interference (CMI) 框架**：一個 controlled diagnostic + data-generation 框架，用來研究 agent memory 在不同記憶關係下的演化行為。CMI 控制 memory 之間的關係類型（reinforcement、revision、interference），測量三個維度：plasticity（agent 能否更新？）、stability（是否保留舊知識？）、poisoning resistance（能否抵抗惡意注入？）。

2. **Interference pathway 分析**：Lexical retrieval 和 Dense retrieval 表現出不同的干擾路徑——這是之前沒有人系統性研究過的。Lexical 干擾偏向 exact match 的覆蓋，Dense 干擾偏向 semantic overlap 的模糊覆蓋。

3. **Interference-aware memory learning**：CMI 不只是診斷工具，它生成的 targeted examples 可以用來做 interference-aware training，改善 agent 區分 valid updates 和 interference-inducing memories 的能力，同時保留原始記憶任務的性能。

### 方法 / pipeline

CMI 的核心設計：

- **Controlled memory evolution**：agent 先學一組初始記憶（target memories），然後遭遇不同類型的新記憶：
  - **Reinforcement**：新記憶支持既有記憶（相同資訊）。
  - **Revision**：新記憶修正既有記憶（更新資訊）。
  - **Interference**：新記憶與既有記憶衝突但權威性較低（應被拒絕）。
  
- **三維度測量**：
  - **Plasticity**：agent 是否成功採納 valid updates？
  - **Stability**：agent 是否保留正確的原始記憶？
  - **Poisoning resistance**：agent 是否拒絕低權威的干擾記憶？

- **Retrieval 模式比較**：同一組記憶演化軌跡，在 Lexical（BM25）和 Dense（embedding similarity）兩種 retrieval 下分別測試。

- **Interference-aware training data**：從 CMI 生成的 targeted examples 用於 fine-tune memory update policy，讓 model 學會區分「什麼該更新」和「什麼是干擾」。

### 實驗設計

目前從 abstract 和 HTML 前段確認到主要結論：
- **Benign accumulation 影響有限**：單純增加記憶量對 plasticity 和 stability 的影響不大。
- **Interference sharply suppresses plasticity**：relationship-specific 的干擾大幅壓低 update plasticity，同時幾乎沒有 stability gain——也就是說，干擾記憶讓 agent 更新能力變差，但不會讓它更好保留舊知識。
- **Lexical vs Dense 的不同干擾路徑**：兩種 retrieval 模式在被干擾的方式上有質性差異。
- **Poisoning 對 update-authority 更敏感**：比起 recency（時間近），poisoning 更受 authority（權威性線索）影響——這對設計記憶系統有直接意義。
- **Interference-aware training 有效**：在改善 update/interference 區分的同時保留原始 task performance。

完整實驗數字、benchmark 規模、和與 baseline memory systems 的比較尚需看全文確認。

### かに讀後判斷

CMI 是 agent memory 領域從「怎麼存取」轉向「怎麼演化」的重要一步。跟之前看過的幾篇放在一起：

- **vs Delivery Not Storage（2607.20972）**：Delivery 說記憶送達是 harness 的責任；CMI 說即使記憶正確送達了，agent 還是要判斷哪些該更新、哪些該拒絕——interference 是第一級公民。
- **vs ChronoMem（2026-08-08）**：ChronoMem 做 version control + semantic rollback；CMI 做的是更根本的 interference diagnosis，告訴你 rollback 的判斷標準應該是什麼。
- **vs SAGE（2605.30711）**：SAGE 用 novelty gate 決定什麼該存；CMI 說光 novelty 不夠，你還要判斷新記憶和舊記憶的關係類型。

對 Morris 來說，CMI 提供了一個非常具體的 diagnostic 工具，可以用來測試任何 agent memory 系統的 interference resilience。建議深讀，特別是 interference pathway 分析和 interference-aware training 的效果。

## 2. MemPrism: Task-Conditioned Relational Memory Views for Long-Horizon Agents

- **arXiv**: 2608.06745
- **Link**: https://arxiv.org/abs/2608.06745

### 這篇在說什麼

長 horizon agent 的記憶系統通常假設相關資訊可以通過 fixed representation 直接被消費。但 MemPrism 指出了 representation mismatch 問題：資訊是相關的，但它的組織方式不適合當前決策。MemPrism 的解法是分離 persistent experience storage 和 decision-time working memory，然後用 task-conditioned relational view 動態構建出適合當前任務的 working memory。

### 主要貢獻

1. **Task-conditioned relational memory view**：把記憶分為 persistent event stream（存所有經驗）和 temporary working-memory view（按當前任務動態構建）。View 的構建由 lightweight view policy 控制，選擇 relation structure、evidence range、outcome condition、granularity。

2. **Deterministic composer + render**：view policy 只決定「看什麼、怎麼看」，composer 和 render 是確定性的，不依賴 LLM 來做 memory 組織。這跟 Delivery Not Storage 的「deterministic injection 勝過 voluntary lookup」路線一致。

3. **Cross-VLM transfer**：學到的 view policy 可以不經額外 adaptation 直接遷移到不同的 VLM 上，說明 task-conditioned relational view 是一種通用的 memory interface。

### 方法 / pipeline

- **Event stream**：所有互動以 event stream 形式持久存儲。
- **View policy**：lightweight policy 網路，輸入當前 task context，輸出 view 參數（relation structure、evidence range、outcome condition、granularity）。
- **Composer**：根據 view policy 的參數，從 event stream 中確定性地選擇和組織相關事實。
- **Render**：把 composer 的輸出格式化為 frozen task policy 可以直接消費的 working-memory view。
- **關鍵設計**：view policy 是可學習的，但 composer 和 render 是確定性的——學的是「看什麼」，不是「怎麼看」。

### 實驗設計

- **Benchmarks**：Long-horizon embodied 和 web-agent benchmarks。
- **主要結果**：MemPrism 在 trajectory 越長時改善越明顯，同時減少 memory token consumption。
- **Transfer**：View policy 在不同 VLM 之間直接遷移，不需額外訓練。
- 目前從 abstract 確認到主要結論；完整實驗規模和 baseline 比較尚需看全文。

### かに讀後判斷

MemPrism 的 task-conditioned view 概念直接回應了 Delivery Not Storage 提出的問題，但用了一個更結構化的方式：不是 harness 直接 inject cue，而是讓一個輕量級 policy 學會「在什麼任務下看什麼記憶」，然後確定性地 render 成 working memory。這是「harness property」和「agent choice」之間的一個有趣中間點。

不過目前只讀到 abstract，對 MemPrism 的完整評估還需要看全文的實驗設計和 baseline 比較。建議先標記，等全文上線後再深讀。

## 3. PMCoder: Coupling Planning with Episodic Memory in LLM Agents for Software Issue Resolution

- **arXiv**: 2608.06811
- **Link**: https://arxiv.org/abs/2608.06811

（此篇同時收錄於 Harness Engineering，此處聚焦 memory 相關內容）

### 這篇在說什麼（memory 視角）

從 agent memory 的角度看 PMCoder，它的核心貢獻是 **plan-conditioned episodic memory retrieval**：episodic memory 不是被動的「存起來需要的時候搜」，而是被當前 plan phase 和 sub-task 主動引導。Memory-derived statistics（edit failure rate、stuck signal）反過來觸發 replanning，形成 plan ↔ memory 的雙向耦合。

### かに讀後判斷（memory 視角）

PMCoder 的 plan-conditioned retrieval 和 MemPrism 的 task-conditioned view 有異曲同工之處——兩者都認為記憶檢索應該由當前任務狀態引導。但 PMCoder 更偏向 coding agent 的具體應用場景，而 MemPrism 更偏向通用框架。PMCoder 的 execution-grounded verification（用 reproduction verdict 而非 self-report）也呼應了 Delivery Not Storage 的「deterministic injection 勝過 voluntary lookup」——在 verification 階段，PMCoder 用執行結果取代 agent 自己的宣告，這是一種 harness-level 的記憶送達保證。
