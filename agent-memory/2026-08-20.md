# Agent Memory — 2026-08-20

今天三篇 NOT_SEEN 的 agent memory 論文從三個不同角度切入長期記憶問題。MEM1 提出 RL-based constant memory 架構，讓 agent 在多輪互動中學會丟棄無關資訊；Harness the Memory 做了第一個系統性的記憶基質橫向評估，發現沒有任何單一基質能在所有情境下勝出；On the Fragility of Self-Improving Agents 揭露記憶型自我改進 agent 的可靠性問題 — 方差大、對任務順序高度敏感、規格不足導致記憶品質低落。

## 1. MEM1: Learning to Synergize Memory and Reasoning for Efficient Long-Horizon Agents

- **arXiv / Venue**: arXiv:2506.15841 (cs.CL, cs.AI, cs.LG)
- **Link**: https://arxiv.org/abs/2506.15841

### 這篇在說什麼

長期互動的 LLM agent 面臨一個根本問題：隨著對話輪次增加，context 不斷膨脹，導致推理成本 O(N²) 增長、超出訓練長度後泛化能力下降、無關資訊稀釋注意力。現有解法（外部記憶模組、摘要器、retriever）和 agent 的推理策略是分開訓練的，無法端到端優化。MEM1 提出了一個很直接的問題：能不能讓 LLM 學會在推理過程中同時做記憶整併，使得記憶使用量始終是常數？

核心洞察是：推理時的 chain-of-thought 不只是「想清楚問題」的工具，它同時也是一種「工作記憶」— 提取關鍵資訊、建立漸進理解的過程。如果把推理和記憶整併統一在同一個表示空間裡，就不需要額外的記憶模組。

### 主要貢獻

1. **Constant-memory agent via RL**：MEM1 是第一個用 end-to-end RL 訓練的 constant-memory agent — 在每一輪互動後，agent 只保留一個 compact internal state `<IS>`，丟棄所有歷史 observation 和 action，context 長度在整個任務中維持近乎常數。

2. **Masked trajectory for policy optimization**：由於 MEM1 的 context 在每輪都會被動態更新（剪掉舊的 IS/query/info，加入新的），傳統 PPO/Reinforce++ 假設線性軌跡不成立。MEM1 提出了 masked trajectory 方法，把多輪的斷裂軌跡縫合成一個邏輯連貫的完整軌跡，用 2D attention mask 確保只計算模型自己生成的 token 的 policy gradient。

3. **Composable task augmentation**：現有 multi-turn 環境都是單目標任務，MEM1 提出了一個簡單但有效的組合增強方法：把現有的單目標 QA dataset 組合成多目標序列（2-objective 到 16-objective），讓訓練和評估更貼近真實的長期互動場景。

4. **強大的 performance-efficiency tradeoff**：MEM1-7B 在 16-objective multi-hop QA 上比 Qwen2.5-14B-Instruct 性能提升 3.5×、記憶使用量降低 3.7×，且能泛化到比訓練更長的互動輪次。

### 方法 / pipeline

**Internal State Update Mechanism**
- 每一輪 t，agent 產生 `<IS_t>`（internal state）、`<query_t>`（環境查詢）或 `<answer_t>`（最終回答）、`<info_t>`（環境回饋）。
- 在下一輪 t+1，agent 將 `(<IS_t>, <query_t>, <info_t>)` 整併成新的 `<IS_(t+1)>`，然後丟棄前一輪的所有 tag。
- 任何時刻，context 中最多保留兩個 `<IS>`、兩個 `<query>`、一個 `<info>`，確保記憶量恆定。

**RL Training**
- 使用 verifiable reward（任務成功得 1，失敗得 0）。
- 關鍵設計：agent 在每輪都被強制丟棄完整歷史，只靠 `<IS>` 攜帶資訊 — 如果學不會有效整併，就無法完成任務。
- Masked trajectory：把各輪的 `(IS, query, info)` tuple 縫合成一個完整軌跡，用 2D attention mask 確保梯度只流過模型自己生成的 token，避免 across-turn information leakage。

**Task Augmentation**
- 從 HotpotQA、MuSiQue 等多跳 QA 資料集構建組合任務：2-objective、4-objective、8-objective、16-objective。
- 每個 objective 可能依賴前一個 objective 的結果（composition），或不依賴（independent）。

### 實驗設計

已從 HTML 全文確認：

- **三個評估領域**：
  - Internal Retrieval QA：HotpotQA 和 MuSiQue，multi-hop 問答
  - Open-domain Web QA：用 WebBrowse 環境，agent 需要上網搜尋
  - Multi-turn Web Shopping：WebShop，agent 需要多輪搜尋和選擇商品

- **Backbone**：Qwen2.5-7B-Instruct（MEM1-7B）和 Qwen2.5-14B-Instruct 作為 baseline

- **主要結果**：
  - MEM1-7B 在 16-objective multi-hop QA 上準確率 78.9%，比 Qwen2.5-14B-Instruct（22.4%）高 3.5×
  - 記憶使用量降低 3.7×（context 長度近似常數 vs. 線性增長）
  - 在 WebShop 上，MEM1-7B 的 reward 也優於 full-context baseline
  - 泛化性：只在 2-objective 上訓練，在 16-objective 上仍然有效

- **Ablation**：
  - 去掉 IS update（即保留完整歷史）：性能提升但記憶線性增長
  - 去掉 RL（只用 SFT）：記憶整併能力顯著下降
  - Task augmentation 的組合數從 2 增加到 16：性能持續提升但邊際遞減

### かに讀後判斷

MEM1 是 agent memory 領域一個非常重要的方向性貢獻。它不是在現有的「外部記憶 + retrieval」範式上做增量改進，而是提出了一個根本不同的架構：讓 agent 學會在推理過程中內化記憶，把推理和記憶整併統一在一個 RL-optimized 的 compact state 中。

和之前讀過的論文比較：
- 和 LycheeMemory V2（8/18）的語意分段建構不同，MEM1 不建構外部記憶紀錄，而是把記憶壓縮到一個 internal state 中 — 一個是 write-path 改進，一個是根本改變記憶的表示方式。
- 和 Harness the Memory（今天的另一篇）互補：Harness the Memory 發現沒有單一記憶基質能在所有情境下勝出，而 MEM1 的 internal state 恰好就是一種新的「activation-compatible」基質。
- 和 On the Fragility of Self-Improving Agents（今天的第三篇）對話：那篇發現記憶型自我改進的可靠性有問題，部分原因就是記憶品質差；MEM1 的 RL-based 整併可能是一個更可靠的記憶建構方式，因為它不是用 LLM 去生成離散的記憶文字，而是學會在 continuous representation 中保留資訊。

值得深讀：Section 3.1 的 internal state update 機制設計、Section 3.2 的 masked trajectory、Figure 3 的 attention mask 設計、以及 Appendix 的泛化實驗（訓練在 2-objective、測試在 16-objective）。

## 2. Harness the Memory: A Holistic Evaluation of Memory Substrates in Memory Agents

- **arXiv / Venue**: arXiv:2608.15008 (cs.CL)
- **Link**: https://arxiv.org/abs/2608.15008

### 這篇在說什麼

長期記憶已經成為 LLM agent 的核心基礎設施，但現有評估嚴重偏斜：62% 的評估集中在兩個對話型 QA 資料集（LoCoMo 和 LongMemEval），81% 只用 GPT 系列 backbone，只有 21% 報告了任何效率指標，沒有任何系統同時達到廣泛覆蓋和完整效率報告。這意味著我們知道哪個系統在特定排行榜上分數最高，但不知道在不同操作情境下哪種記憶基質更合適 — 這正是通用記憶系統需要的路由信號。

Harness the Memory 做了第一個系統性的 controlled harness evaluation：把記憶基質（而非記憶系統）作為唯一實驗變數，在統一的 harness 下評估 11 種方法、7 個基質家族、3 個 backbone、4 個 benchmark、26 個指標。

### 主要貢獻

1. **第一個 holistic harness evaluation**：控制所有其他變數，只改變記憶基質，在統一框架下評估 dense/sparse indices、text records、structural stores、hierarchical stores、refinement-based memories、parametric updates、activation-compatible context 等 7 大類共 11 種方法。

2. **Cross-regime performance-latency analysis**：第一次跨 user-centric（對話 QA）和 agent-centric（決策規劃）情境，繪製每個方法在 performance-latency 平面上的位置，識別哪些基質在哪些情境下被 Pareto 支配。

3. **Retrieval depth 的注意力診斷**：發現 retrieving more entries 幫助 QA 但損害 agentic decisions — 注意力探測顯示，隨著檢索深度增加，模型的注意力從任務上下文轉移到檢索區塊，在 QA 中這恰好是答案所在，但在 agentic tasks 中這會讓模型忽略當前觀察。

4. **Scalability 分析**：refinement memories 在長序列中優雅縮放，structural 和 full-context 基質在長序列中面臨部署限制。

### 方法 / pipeline

**7 大基質家族、11 種方法**

| ID | 家族 | 方法 |
|----|------|------|
| M1 | Flat (dense) | BM25+embedding hybrid retrieval |
| M2 | Flat (sparse) | Sparse retrieval |
| M3 | Text | Text record memory with LLM summarization |
| M4 | Struct | Knowledge graph |
| M5 | Struct | Structured memory (LLM-generated) |
| M6 | Hier | Hierarchical memory (topic-level → detail-level) |
| M8 | Refine | Memory refinement / compression |
| M9 | Weight | Parametric update (fine-tuning) |
| M10 | Act | KV cache management |
| M11 | Act | Activation-based context |

所有方法在相同的互動歷史和 harness 下評估，只改變記憶基質。

**4 個 Benchmark**
- LoCoMo：對話 QA
- LongMemEval-S (LME-S)：長期對話記憶
- MAB (Multi-Session Agent Benchmark)：多輪 agent 問答，含 LRU、TTL、CR 三個子集
- ALFWorld + BigCodeBench-Hard：agent-centric 決策

**26 個指標**
- Performance：P4（LLM-judge score）、各子指標
- Efficiency：per-query latency (E15)、token usage、management cost、compression ratio

### 實驗設計

從 HTML 全文已確認：

**核心發現 1：最優基質在不同情境之間反轉**
- 在 QA 情境（LoCoMo、LME-S、MAB）：structural graph（M5）和 text record（M3）表現最好
- 在 agentic 情境（ALFWorld、BigCodeBench）：refinement memory（M8）和 activation-based（M10）表現最好
- 在 Gemma-4-26B 上的 LoCoMo：M5（structural graph）達到 0.719 P4 score
- 在 Qwen3-32B 上的 MAB-LRU：M10（KV cache）達到 0.810 P4 score

**核心發現 2：Retrieval depth 的雙面效應**
- QA：更多檢索 = 更好（答案是歷史中的事實）
- Agentic：更多檢索 = 更差（注意力從當前觀察轉移到檢索區塊）
- 注意力探測證實：retrieval depth 增加時，attention weight 向檢索區塊偏移

**核心發現 3：Scalability 是另一個路由維度**
- M3（text record）和 M5（structural graph）在長歷史下成本暴增
- M8（refinement）在長序列中優雅縮放
- M10（KV cache）受固定 context window 限制

**設計規則**：Trade read breadth for write depth — 每次查詢檢索更少條目，但在寫入時投入更多資源做蒸餾和結構化。

### かに讀後判斷

這篇是 agent memory 領域近期最需要的評估論文。之前的研究幾乎都是在單一 benchmark 上比較少數幾個系統，缺乏跨情境、跨基質、跨 backbone 的系統性比較。Harness the Memory 的貢獻不是提出新方法，而是提供了選擇記憶基質的實證指南 — 這正是設計通用 agent memory 系統時需要的路由信號。

和 MEM1 的關係：MEM1 的 internal state 屬於這篇分類中的「activation-compatible context」（M10/M11 家族），但 MEM1 更進一步 — 它不是管理 KV cache，而是學會用 RL 來優化一個 compact representation。Harness the Memory 的發現解釋了為什麼 MEM1 的方向是對的：在 agentic 情境中，activation-based 方法表現更好，而 retrieval-based 方法反而因為注意力偏移而損害決策。

和之前讀過的 Agent Memory: Characterization and System Implications（6/4, 2606.06448）比較：那篇是從系統角度做 characterization（10 種系統的行為模式），這篇是從基質角度做 controlled evaluation（7 種基質家族的 performance-efficiency tradeoff）。兩者互補 — 前者告訴你系統怎麼行為，後者告訴你為什麼在不同情境下應該選不同基質。

值得深讀：Table 1 和 Table 2 的完整結果、Section 5.2 的 attention probing 分析、Figure 的 performance-latency landscape。

## 3. On the Fragility of Self-Improving Agents: Variance, Task Order, and Underspecification

- **arXiv / Venue**: arXiv:2608.18066 (cs.AI, cs.CL, cs.LG)
- **Link**: https://arxiv.org/abs/2608.18066

### 這篇在說什麼

記憶型自我改進 agent（memory-based self-improving agents）— 那些從線上任務串流中學習、透過維護文字記憶庫來改進表現的系統 — 近期展現了很大潛力。但這些系統的可靠性問題被嚴重忽視了。Salesforce AI Research 團隊對兩個代表性方法（Agent Workflow Memory 和 ReasoningBank）做了全面重評估，發現：

1. 方差問題：agent 評估本身就有顯著的跨 run 變異，加上自我改進迴圈後方差在 71% 的情況下進一步放大，最好和最差 run 之間可以差 10 個百分點。
2. 任務順序依賴：預設的任務排序隱含了一個 easy-to-hard 課程，這是成功的隱藏前提。一旦隨機打亂任務順序，原本 +1.5% 的改進變成 -4.5% 的退化。
3. 規格不足：手動檢查 agent 產生的記憶，發現環境規格不足（不知道環境只支援瀏覽器不支援程式碼執行）和任務規格不足（模糊的任務描述導致錯誤記憶）是主要問題。

### 主要貢獻

1. **揭示方差放大問題**：第一個系統性量化自我改進 agent 跨 run 方差的研究。發現 71% 的情況下，加入自我改進迴圈會增加方差，有些情況下相對增幅超過 50%。

2. **揭露隱含課程依賴**：證明默認任務排序構成 easy-to-hard 課程，是自我改進成功的隱藏前提。隨機打亂後，性能從改進退化為下降。

3. **Underspecification 診斷和部分緩解**：透過手動檢查記憶，識別出環境規格不足和任務規格不足兩大問題。加入環境回饋和詳細評分標準後，可以關閉 31% 的性能退化，但剩餘的退化說明還有其他未被表徵的因素。

4. **實踐建議**：呼籲自我改進 agent 的評估應該報告多次 run 的結果、在隨機任務順序下做壓力測試、開發人類監督介面來及時糾正「錯誤教訓」。

### 方法 / pipeline

**重評估設計**
- 兩個代表性方法：AWM（Agent Workflow Memory）和 RBank（ReasoningBank）
- 三個 benchmark：WebArena、VisualWebArena、SCUBA
- 兩個評估軸：多次 run 量化方差、隨機打亂任務順序測試課程依賴
- 更強的 baseline：基於 GPT-5-mini，已經和 RBank 報告的 Gemini-2.5-Pro 結果相當

**Underspecification 分析**
- 手動檢查 agent 產生的記憶，分類常見問題
- 環境規格不足：agent 不知道環境的限制（例如瀏覽器環境不支援 API 呼叫），卻在記憶中建議使用 API
- 任務規格不足：模糊的任務描述導致過度思考、誤解、錯誤記憶傳播
- 緩解：加入環境描述到記憶建構 prompt、加入詳細 rubric、修訂 prompt 明確指出環境限制

### 實驗設計

已從 HTML 全文確認：

- **Baseline 強度**：GPT-5-mini baseline 在 WebArena 上已達到 55.3%，和 RBank 報告的 Gemini-2.5-Pro + RBank 的 53.9% 相當。在 VisualWebArena 上達到 54.9%，接近 SOTA 的 54.0%。

- **方差放大**：在 24 個測試組合中，17 個（71%）顯示加入自我改進後方差增加。WebArena GitLab 子集的最好-最差 run 差距從 baseline 的 4.4% 增加到 RBank 的 7.8%。

- **任務順序依賴**：默認排序下 RBank 有 +1.5% 的平均改進（p=0.23，不顯著）；隨機打亂後退化為 -4.5%。

- **Underspecification 緩解**：加入環境回饋和 rubric 後關閉 31% 的性能退化，但仍有顯著殘餘。

- **材料**：WebArena（含 GitLab、Map、CMS 子域）、VisualWebArena、SCUBA（Salesforce 內部 benchmark）

### かに讀後判斷

這篇是對 agent memory 社群的一個重要警示。自我改進 agent 的記憶不是只有「記什麼」的問題，還有「記得可不可靠」的問題。這和 Harness the Memory 的發現形成有趣的對話：

- Harness the Memory 說「沒有單一基質在所有情境下都好」，On the Fragility 則補充說「即使選對了基質，自我改進的記憶品質也不可靠」。
- MEM1 的 RL-based 整併可能是緩解 underspecification 的一條路 — MEM1 不依賴 LLM 生成離散記憶文字，而是學會在 continuous representation 中保留資訊，避免了「生成看似合理但不可執行的記憶」的問題。

和之前讀過的 Self-Harness（6/9, 2606.09498）的關係：Self-Harness 關注的是 harness 本身的自我改進，這篇關注的是記憶型 agent 的可靠性 — 兩者都是「自我改進」但層次不同。
