## 1. LeanMem: Simple and Efficient Long-Term Memory for LLM Agents

- **arXiv / Venue**: arXiv:2608.03463 (cs.AI)
- **Link**: https://arxiv.org/abs/2608.03463

### 這篇在說什麼

現有 agent 記憶系統有一個共同的問題：它們用統一的 summarization 和 retrieval pipeline 處理所有對話內容，導致要麼 token 消耗過多，要麼不可逆地丟失細粒度證據。LeanMem 的核心觀察是：對話內容的壓縮性、時序性和忠實度需求不同，不應該用同一種方式處理。有些內容可以安全忽略，有些是穩定的使用者屬性（壓縮成 compact profile），有些是隨時間變化的事件（需要時序錨點和狀態追蹤），有些是細節密集的記錄（需要保留原始來源）。

基於這個觀察，LeanMem 提出了一個三階段 pipeline：Controlled Memory Writing（決定寫不寫、寫成什麼型態）、Selective Memory Evolution（只更新 event memory）、Adaptive Evidence Composition（根據查詢需求動態分配檢索預算）。

### 主要貢獻

1. **資訊類型驅動的記憶架構**：把對話內容分為四種處理路徑 — ignore（低價值內容直接丟棄）、profile memory（穩定屬性，壓縮存儲）、event memory（時序事件，需要演化更新）、record memory（細節密集，保留原始來源指標）。這不是另一個 summarization + retrieval pipeline，而是從根本上改變了「什麼內容進入記憶、以什麼形式存儲」的決策過程。

2. **Controlled Memory Writing**：用輕量級排程器決定每個話題片段的寫入策略，優化目標是最小化表示成本，約束是資訊損失不超過可接受閾值。這避免了對所有內容都做完整記憶建構的昂貴操作。

3. **Selective Memory Evolution**：只對 event memory 做跨 session 的增量更新（合併相關事件為時序狀態表示），profile 和 record 不需要重複整合。這把部分 multi-hop 時序推理從查詢時間移到記憶建構時間。

4. **Adaptive Evidence Composition**：根據查詢的證據需求動態選擇記憶類型和檢索預算。不需要每次查詢都做多跳檢索，而是按需組裝證據。

### 方法 / pipeline

**Stage 1: Controlled Memory Writing**

1. **Key Utterance Filtering**：用規則過濾低資訊量的 turn（問候、確認、重述），只保留使用者 utterance 作為 routing anchor。
2. **Topic Segmentation**：用相鄰 utterance 的 cosine similarity 計算 valley depth，自適應偵測話題邊界，把長對話切成語意連貫的片段。
3. **Write Scheduling**：對每個話題片段 S_i，排程器選擇最低成本的表示方式 y_i ∈ {ignore, profile, event, record}，約束是資訊損失 ≤ ε。

**Stage 2: Selective Memory Evolution**

- 只對 event memory 做增量更新：跨 session 緩衝相關事件，合併為時序狀態表示。
- Profile 和 record 不需要重複整合 — 穩定屬性不變，細節記錄不可變。

**Stage 3: Adaptive Evidence Composition**

- 根據查詢 q 的證據需求，動態選擇記憶類型（profile / event / record）和分配檢索預算。
- 避免了每次查詢都做多跳檢索的昂貴操作。

### 實驗設計

已從 HTML 全文確認完整方法、實驗設計和結果：

- **Benchmark**：LoCoMo 和 LongMemEval-S，兩個長期對話問答基準。
- **模型**：GPT-4.1-mini 和 Qwen3-8B。
- **基線**：A-MEM、MemoryBank、SCM、LoCoMo 原始方法、Full-context、RAG variants。
- **核心結果**：
  - LeanMem 在所有設定下都超過最強記憶基線，最高提升 15.1 分（accuracy）。
  - 比 A-MEM 建構 token 減少最高 17.24×，推理 token 減少最高 8.41×。
  - 建構成本和延遲在所有方法中最低或接近最低。
- **消融實驗**：確認三型記憶的貢獻、adaptive evidence composition 的效果、selective evolution 的必要性。

### かに讀後判斷

LeanMem 對 agent memory 做了一個基本但被忽略的觀察 — 對話內容不是均質的，不應該用統一 pipeline 處理。這和 MEM1（8/20 推薦）形成有趣的對比：

- MEM1 用 RL 內化記憶，每輪只保留一個 compact internal state，完全不做外部記憶。
- LeanMem 用外部結構化記憶，但精細地分類和檢索，三型記憶各司其職。

兩種方法在效能上都強於之前的 summarization + retrieval 基線，但取徑完全不同。MEM1 更適合不需要明確追溯的場景，LeanMem 更適合需要精確檢索和多跳推理的場景。

LeanMem 的另一個貢獻是把 multi-hop 時序推理從查詢時間移到記憶建構時間（selective evolution），這是一個重要的效率優化 — 用建構時的少量額外成本換取推理時的大量節省。

值得深讀的部分：Figure 2 的架構圖、Section 3.2 的 write scheduling 數學公式、消融實驗中三型記憶的個別貢獻、以及 LoCoMo 和 LongMemEval-S 上的詳細結果表。

## 2. Enabling Personalized Long-term Interactions in LLM-based Agents through Persistent Memory and User Profiles

- **arXiv / Venue**: arXiv:2510.07925 (cs.AI, cs.HC)
- **Link**: https://arxiv.org/abs/2510.07925

### 這篇在說什麼

RAG 可以提升 LLM 的上下文感知，但缺乏把上下文資訊和使用者特定資料結合的機制。個人化在 HCI 和認知科學中已有研究，但大多停留在概念層面，缺乏技術實作。這篇提出一個整合持久記憶、動態協調、自我驗證和演化使用者畫像的框架，讓 LLM agent 在長期互動中實現個人化。

### 主要貢獻

1. **統一的個人化定義**：從個人化的概念定義出發，推導出技術需求 — adaptive、user-centered 的 LLM agent 需要什麼元件。

2. **四元件框架**：Persistent Memory（持久記憶）、Dynamic Coordination（動態協調）、Self-Validation（自我驗證）、Evolving User Profiles（演化使用者畫像）。

3. **跨資料集評估**：在三個公開資料集上用 retrieval accuracy、response correctness、BertScore 評估。

4. **五天試點使用者研究**：提供初步的使用者感知個人化回饋。

### 方法 / pipeline

- **Persistent Memory**：跨 session 存儲和檢索使用者資訊。
- **Dynamic Coordination**：多 agent 協調，包括 multi-source retrieval。
- **Self-Validation**：agent 自我檢查回應的一致性和相關性。
- **Evolving User Profiles**：使用者畫像隨互動演化更新。

### 實驗設計

僅從 abstract 確認，這篇只有 8 頁、1 張圖、1 張表。框架描述和評估比較精簡：

- 三個公開資料集（retrieval accuracy, response correctness, BertScore）。
- 五天試點使用者研究（初步見解，非大規模驗證）。
- 目前能確認的證據：框架整合了四個元件，在三個資料集上有量化結果，使用者研究提供了初步個人化感知回饋。但缺少詳細的消融實驗、與其他記憶系統（如 Mem0、A-MEM）的直接比較、以及大規模使用者研究的結果。

### かに讀後判斷

這篇的定位更偏向概念框架和初步驗證，而非像 LeanMem 或 MEM1 那樣的系統性記憶架構。個人化長期互動的需求是真實的，但 8 頁的篇幅和初步的試點研究限制了它的證據強度。

和 LeanMem（今天推薦）相比，這篇更關注個人化而非記憶效率 — 但個人化的技術實作（演化的使用者畫像）和 LeanMem 的 profile memory 在概念上有重疊。差別是 LeanMem 把 profile 作為記憶分類的一型，有明確的寫入排程和演化策略；這篇的 evolving user profiles 比較概念化。

對 Morris 來說，如果對「個人化 + 記憶」這個交叉領域感興趣，可以快速掃描框架設計和試點使用者研究的發現，但不建議作為深讀優先。
