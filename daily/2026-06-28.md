## 今日推薦點開

### 1. 🎯 ActPlane: Programmable OS-Level Policy Enforcement for Agent Harnesses (2606.25189)
Harness engineering 的系統性突破：讓 agent 自己用 DSL 宣告政策，然後在 OS kernel 用 eBPF + IFC 強制執行。比 tool-call guardrails 多解決 2.0–3.2× 的政策違規（涵蓋間接執行路徑），1.9% end-to-end 開銷。agent-authored + OS-enforced 的設計同時解決語義差距和覆蓋率問題。

### 2. 🧠 SAGE: A Novelty Gate for Efficient Memory Evolution in Agentic LLMs (2605.30711)
把記憶演化重新框架為新穎度偵測問題：用 vMF 分佈在單位超球面上做 KDE，把明顯新穎的 Add、明顯冗餘的 Noop、只有不確定的送 LLM。7/7 open-weight backbone 勝出 Mem0，API cost 降 3.4×，latency 降 2.5×。作為 A-Mem 的 drop-in gate 跳過 16–18% LLM calls，品質幾乎不變。

![](assets/2026-06-28/sage-novelty-gate-memory.png)

### 3. 🗳️ The Model as One Rater Among Several (2606.23042)
不要把 LLM 當政治立場的 oracle，而是當成專家調查裡的一個評分者。9 個模型 panel 的 Krippendorff's α = 0.86，但高可靠性 ≠ 有效性——最大分歧追溯到 referent problem（模型同意事實但對「哪個秩序算作 the regime」有不同解讀）。對 silicon sampling 的效度問題提出了比主流更誠實的方法論。

## Cross-Domain Notes

今天的四個主題圍繞一個共同問題：**誰做決策、在哪裡執行、用什麼標準判斷？**

- **Harness Engineering**：ActPlane 說「讓最接近任務的 agent 寫政策，在 OS kernel 執行」；HarnessAudit 說「不要只看最終輸出，要審計完整軌跡」；Survey 說「agent 品質來自 model × harness × task × evaluation 的交互」。三者都指向同一個結論：runtime 基礎設施設計是效能瓶頸，不是模型能力。
- **Agent Memory**：SAGE 說「寫入端控制是記憶品質和效率的槓桿」，用幾何直覺（vMF 密度）做 cheap routing，只有不確定的才送 LLM。和昨天 TMA-NM 的寫入端安全驗證形成對比：一個管效率、一個管安全，但都在做寫入端路由。
- **Silicon Sampling**：Tayyar（model-as-rater）和 OdysSim（behavioral foundation model）代表了 silicon sampling 的兩個極端——前者把 LLM 當有偏見的測量工具並用 panel 方法管理偏差，後者重新訓練 LLM 讓它更像人。兩者都在回答「如何信任 LLM 的社會/政治判斷」，但策略完全不同。
- **Cross-cutting**：CPE 的溝通策略演化和 SAGE 的記憶路由都是「分層路由」——先做 cheap 判斷，只在不確定時才啟用昂貴的 LLM 推理。ActPlane 的 DSL + eBPF 也是同一個模式：cheap rule 先過濾，只對無法規則化的情況做語義回饋。這是一個值得注意的系統設計模式。
