## Cross-Domain Notes

今天三個 domain 共同指向一個主題：**寫入端的約束和驗證**。

- **Harness Engineering**：Harness-MU 說「治理約束不該交給 LLM 的機率判斷，應該由確定性 runtime hooks 執行」；NOVA 說「程式能跑不代表推薦語義正確，要用 verification cascade 在每個層級攔截」。兩者都在做 harness 層面的寫入端驗證——在錯誤變成持久狀態之前攔截。
- **Agent Memory**：TrustMem 說「記憶更新的每一步都應該被驗證」，MEMPROBE 說「即使任務成功，記憶本身可能很不完整」。這和 Harness-MU 的「確定性 runtime 約束」是同一個精神：不要等到終端結果才發現問題，要在每個中間步驟就檢查。
- **Silicon Sampling**：Group Selection 的演化壓力也是一種寫入端約束——只有高 fitness 的 prompt 能進入下一代，低 fitness 的被淘汰。不是在終端評估整個群體的好壞，而是在每代就做選擇。

跨域模式：**寫入端驗證 > 終端評估**。Harness-MU 的 Gatekeeper、NOVA 的 verification cascade、TrustMem 的 Transition Verifier、Group Selection 的 fitness-based selection——都在做「不要讓錯誤變成持久狀態」。這和昨天的 SAGE（novelty gate 跳過冗餘寫入）和 ActPlane（DSL + eBPF 在 OS kernel 攔截政策違規）形成了一週的主題弧線。
