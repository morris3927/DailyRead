# 2026-05-08 - Harness Engineering

## 今日領域觀察

Harness engineering 目前不像 agent memory 那樣都是 paper。今天的結果更像工程生態掃描：成熟的 LLM benchmark harness、agent eval 的工程文章，以及具體框架的 evaluation harness docs。這個 domain 後續應該明確接受 blog / docs / GitHub repo，並把它們標成 engineering source。

## Items

### 1. EleutherAI lm-evaluation-harness
- Type: framework / GitHub repo
- Source: GitHub
- Link: https://github.com/EleutherAI/lm-evaluation-harness
- What it is: 一個廣泛使用的 LLM evaluation framework，支援大量 benchmark tasks、多種模型 backend 與 CLI/config-based 評估流程。
- Why it matters: 它是「harness」這個詞在 LLM 評估領域最具代表性的基礎設施之一。近期更新也顯示 eval harness 正在往更模組化、backend 分離、config-driven 的方向演進。
- One-line takeaway: 如果要理解 LLM eval harness 的工程基準，lm-evaluation-harness 是必看樣本。
- Read suggestion: 值得收藏。先看 README 與 docs，不一定要讀成 paper。

### 2. Demystifying evals for AI agents
- Type: technical blog / engineering practice
- Source: Anthropic Engineering
- Link: https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents
- What it is: 這篇文章整理 agent eval 的實務設計：task、trial、grader、assertion、transcript / trajectory，以及 multi-turn agent evaluation 為什麼比單輪 LLM evaluation 複雜。
- Why it matters: Harness engineering 不只是在跑 benchmark，而是要記錄 agent 的多步驟行為、工具使用、狀態變化與失敗軌跡。這篇很貼近 production agent 的評估需求。
- One-line takeaway: Agent eval 的核心不是只看最後答案，而是要保存與評估完整 trajectory。
- Read suggestion: 值得細看。這類文章應該納入 DailyRead，因為它比很多 paper 更直接描述工程實務。

### 3. OpenHands Evaluation Harness
- Type: framework docs / engineering guide
- Source: OpenHands Docs
- Link: https://docs.openhands.dev/openhands/usage/developers/evaluation-harness
- What it is: OpenHands 的 evaluation harness 文件，說明如何把自訂 benchmark 接進 OpenHands，並用 CLI、agent class、LLM config 與 runtime 執行評估。
- Why it matters: 這是 agent framework 內部如何設計 evaluation entrypoint 的具體例子。對 harness engineering 來說，docs 本身就有研究價值，因為它呈現工具怎麼被實作與暴露給開發者。
- One-line takeaway: Agent harness 需要把 task、runtime、agent、LLM config 與 grader 串成可重複執行的流程。
- Read suggestion: 略讀。適合看框架設計，不一定每天都要深讀。
