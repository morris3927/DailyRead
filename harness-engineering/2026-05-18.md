# Harness Engineering — 2026-05-18

## 1. General Agent Evaluation

- **arXiv**: 2602.22953
- **Link**: https://arxiv.org/abs/2602.22953
- **Authors**: Elron Bandel, Asaf Yehudai, Lilach Eden, ... Leshem Choshen, ... (IBM Research, MIT)
- **Date**: 2026-02 (v2 updated)
- **Code**: https://www.exgentic.ai

### 這篇在說什麼

這篇要解決的核心問題是：我們目前無法系統性地衡量「agent 架構」如何影響跨不同協議和環境的表現。現有的 eval harness（BrowserGym 只管 web、Harbor 只管 CLI、Inspect 要手動 per-benchmark wiring）都限制在單一協議或單一領域，導致一個根本問題——沒有人能回答「如果我換一個 agent 架構（從 tool-calling 換成 code-generation），在同一個 benchmark 上表現會差多少？」這個問題對 harness engineering 極為重要，因為 harness 的設計決策（protocol choice、tool interface、memory integration）直接影響 agent 能力邊界。

研究動機：agent 領域快速碎片化，每個團隊用不同的 agent 架構和 backbone model，但沒有統一的 eval 環境能分離「架構貢獻」和「模型貢獻」。這導致我們不知道某個能力的提升是來自更好的 harness 還是更好的 LLM。

### 主要貢獻

1. **Unified Protocol**：一個 benchmark-agent 中介協議，把現有的 agent interface（CLI、tool-calling API、MCP）和 benchmark interface 橋接起來。Unified Protocol 用 canonical task/context/actions 表示法，讓任何 benchmark 可以被任何 agent 架構存取，反之亦然。這是解決 cross-protocol eval 問題的基礎建設。

2. **Exgentic Evaluation Harness**：實作 Unified Protocol 的 eval harness，可以把任何 benchmark 表面化（surface）給任何 general-purpose agent 和 backbone model，不需要 per-benchmark 的手動接線。這跟 AHE（2604.25850，之前深讀過）互補：AHE 是自動演化 harness，Exgentic 是讓 harness 能跨架構比較。

3. **Open General Agent Leaderboard**：第一個公開的通用 agent 排行榜，5 agent 架構 × 5 backbone LLMs × 6 benchmarks 的完整因子實驗，總 eval 成本 $20K。這是目前唯一能分離 agent architecture effect 和 backbone model effect 的公開資源。

### 方法 / pipeline

Exgentic 的技術設計圍繞三個 gap：

- **Framework Gap**：現有 harness 要麼固定 protocol class（BrowserGym = web, Harbor = CLI），要麼要手動 wiring（Inspect）。Exgentic 的 Unified Protocol 用一個 canonical representation 把 benchmark 的 task description、context、available actions 標準化，然後透過 protocol adapter 把這個 canonical form 轉成各 agent 原生 interface。

- **Benchmark Gap**：現有 benchmarks 假設 agent 有 domain-specific 知識和手動整合 glue。Exgentic 透過 Unified Protocol 的 canonical task/context/actions 暴露機制，讓 benchmark 不再隱含「你知道這是什麼環境」的假設。

- **Evaluation Pipeline**：每個 (agent, model, benchmark) 組合跑完整 eval→ 記錄 binary success rate → 排行榜排序。全因子設計（5×5×6 = 150 cells）讓我們可以分解 variance 到 architecture、model、benchmark 三個因子。

### 實驗設計

- **Benchmarks**：6 個，跨軟體工程、客服、深度研究、個人助理。
- **Agent Architectures**：tool-calling、MCP、code-generation、CLI，以及混合型。
- **Backbone Models**：3 closed-source（包括 frontier models）+ 2 open-weight。
- **Cost**：$20K 總 eval 成本。
- **Main Findings**：
  - (i) General agents 可以適應所有測試領域而不需 per-domain customization。
  - (ii) Agent architecture choice 在同一個 model 內可以造成高達 12pp 的差異，但 backbone model choice 整體影響更大。
  - (iii) 在 6 個 benchmark 中有 4 個，top general agents 跟 leading domain-specific agents 表現無統計差異。
  - (iv) Open-weight models 出現「generality sinks」——在特定架構或 benchmark 上系統性崩潰，frontier closed-source models 沒有這個問題。
  - (v) 行為失敗分析顯示不同架構有特徵性的錯誤 signature，aggregate scoring 無法區分。

### かに讀後判斷

這篇是 harness engineering 領域今年最重要的基礎建設論文之一。它跟之前深讀的 AHE（2604.25850）形成有趣的對照：AHE 問的是「如何自動演化 harness 讓它更好」，General Agent Evaluation 問的是「如何讓不同 harness 之間的比較公平」。兩者合在一起構成了 harness engineering 的 eval→optimize 閉環。12pp 的 architecture effect 和 generality sinks 的發現也直接影響實踐——如果你在選擇 agent 架構，12pp 的差異意味著架構選擇比很多微調手段影響更大。

值得 Morris 點開深讀。優先看 Table 2（Leaderboard 全因子結果）、Section 4（Unified Protocol 設計）、以及 generality sinks 的行為分析——這些是判斷 harness 設計如何影響 agent 可靠性的核心證據。

## 2. Efficient Benchmarking of AI Agents

- **arXiv**: 2603.23749
- **Link**: https://arxiv.org/abs/2603.23749
- **Authors**: Franck Stéphane Ndzomga et al.
- **Date**: 2026-03-24

### 這篇在說什麼

這篇的研究問題是：agent eval 很貴（Holistic Agent Leaderboard 跑一次 $40K），能不能用更少的 task 來維持可靠的排行榜？跟 static LM benchmark 不同的是，agent eval 有「scaffold-driven distribution shift」——同一個 model 換一個 harness（scaffold）表現就變了，這使得 benchmark reduction 的泛化性要求更嚴格。

作者發現一個關鍵不對稱性：在 distribution shift 下，絕對分數預測很快退化，但排名預測（rank-order）保持穩定。利用這個不對稱性，他們提出一個簡單的 optimization-free 協議：只跑歷史通過率在 30–70% 的 task，這是 IRT（Item Response Theory）啟發的中等難度篩選。

### 主要貢獻

1. **Ranking-Score Asymmetry 發現**：scaffold shift 和 temporal shift 下，Spearman ρ（排名）保持穩定，但 R²（分數預測）快速退化。這意味著 leaderboard 的核心功能（誰比誰好）可以在 shift 下保持，但精確分數不行。

2. **Mid-Range Difficulty Filter（MR）**：只保留歷史 pass rate 30–70% 的 task。IRT 啟發：接近 50% pass rate 的 task 對 latent agent ability 的區別力最強。這是 deterministic、optimization-free 的規則。

3. **跨 shift 的穩健性驗證**：8 benchmarks、33 scaffolds、70+ model configs，5 個 shift protocol 的 nested cross-validation。MR 在所有 shift 下排名穩健度最高，而 random sampling 和 greedy selection 在 shift 下變異很大。

### 方法 / pipeline

- **問題建模**：Agent eval 的 cost 來自每個 task 需要完整的 agent loop（tool use、multi-step reasoning、environment interaction）。Benchmark reduction 的目標是用 subset of tasks 維持 ranking fidelity。

- **MR Filter**：
  1. 收集歷史 eval 結果，計算每個 task 的 pass rate。
  2. 篩選 pass rate ∈ [0.3, 0.7] 的 task。
  3. 用這個 subset 跑新 agent，計算 ranking。
  4. 與 full-benchmark ranking 比較，計算 Spearman ρ。

- **Baselines**：random sampling、greedy selection（選最 informative task）、stratified sampling、extreme-difficulty filter。

- **Evaluation Protocols**：5 個 increasing distributional shift 層級，用 nested cross-validation 避免 data leakage。

### 實驗設計

- **Benchmarks**：8 個 agent benchmarks。
- **Scaffolds**：33 個 agent scaffold/framework。
- **Models**：70+ model configurations。
- **Key Result**：MR 減少 44–70% 的 task 數量，Spearman ρ 保持高水準。
- **Comparison**：Random sampling 跨 seed 變異大，greedy selection 在 distribution shift 下過擬合歷史數據，MR 最穩健。
- **Practical Implication**：日常 leaderboard eval 可以用 reduced task suite，只在 initialization、drift monitoring、重大能力變化時跑 full benchmark。

### かに讀後判斷

這篇直接回應 agent eval 的成本問題，跟 General Agent Evaluation（2602.22953）互補：後者解決「怎麼公平比較」，這篇解決「怎麼便宜比較」。MR filter 的 IRT 啟發很優雅，且不依賴任何 optimization，可以直接嵌入現有 eval pipeline。44–70% 的成本削減加上穩健的 ranking fidelity，使得頻繁 eval（例如 CI/CD 中的 regression test）變得可行。

值得收藏。如果 Morris 要在日常 harness eval 流程中加入成本控制，優先看 Section 3（MR protocol）和 Figure 1（ranking vs. score 的 asymmetry）。
