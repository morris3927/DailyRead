# Harness Engineering — 2026-05-19

## 1. Harness Engineering as Categorical Architecture

- **arXiv**: 2605.12239
- **Link**: https://arxiv.org/abs/2605.12239
- **類型**: arXiv (cs.PL, cs.AI, math.CT)

### 這篇在說什麼

這篇要回答的問題是：harness engineering 目前是 ad hoc 的——沒有形式化理論可以規範 harness 的組合（composition）、性質保持（preservation of properties under compilation）、跨框架的系統性比較。作者提出的主張是：範疇論的 Architecture triple (G, Know, Φ) 可以精確地形式化 harness 的結構保證。

這填補的洞很明確：harness engineering 從實務出發（LangChain、AHE 等），但一直缺乏形式化基礎。當你說「一個 harness 保證了某個性質」，這句話的精確意義是什麼？當你把一個 harness 從 LangGraph 編譯到 Swarms，那個保證還在嗎？這篇給出了一個具體的答案：structural guarantees 是 Know-level certificates，保證的保持是 structural replay（編譯器檢查 identity 和 verifier replay，不是 output-layer correctness）。

### 主要貢獻

1. **建立了 harness externalization 四大支柱跟 categorical Architecture triple 的對應**：Memory ↔ coalgebraic state、Skills ↔ operad-composed objects、Protocols ↔ syntactic wiring G、Harness ↔ Architecture itself。這不是隱喻式的對應，而是精確的數學對應。

2. **提出 certificate-preservation 作為編譯的正確性標準**：不是「編譯後行為一樣」，而是「編譯後 certificate 的 theorem identity、parameters、和 replayable evidence 都被保持」。這是一個比行為等價更弱但更有用的標準。

3. **五個 compiler functors 的參考實作**：Swarms、DeerFlow、Ralph、Scion、LangGraph，每個都保持三個 named certificate types。LangGraph compiler 用 per-stage method，提供 LangGraph-native observability。

4. **End-to-end escalation 實驗**：用兩個模型、一個 task 展示 quality-based escalation control path 是 model-parametric 的——也就是說，escalation 的結構保證不依賴特定模型。

### 方法 / pipeline

理論框架：ArchAgents 的 Architecture triple (G, Know, Φ)，其中 G 是 syntactic wiring（模組、port、有向邊構成的圖）、Know 是 structural properties/invariants/certificates、Φ 是 deployment map（抽象能力 slot 到具體 model/tool 實作的對應）。

Certificate preservation：一個 compiler f: A → B 如果要保持 certificate，需要把每個 source certificate 的 theorem、parameters、和 replayable evidence 帶到 target 的 Know structure 中。

實作：四個 configuration compiler（Swarms, DeerFlow, Ralph, Scion）+ 一個 per-stage compiler（LangGraph），每個都保持三個 named certificate types（integrity gates、quality-based escalation、supported convergence checks）。

LangGraph 特別之處：每個 stage 變成一個 node，用跟 native runtime 一樣的 per-stage method，所以保持 certificate 的同時提供 LangGraph-native observability，不需要重新實作 harness logic。

### 實驗設計

主要實驗是 end-to-end escalation experiment：
- 兩個模型（一個主模型、一個 escalation 模型）
- 一個 task
- 展示 quality-based escalation control path 是 model-parametric 的

從 HTML 前段能確認的是：compiler functors 的實作細節、certificate preservation 的檢查方式、LangGraph per-stage compiler 的設計。詳細的實驗數據（成功率、latency、各 certificate 的具體檢查結果）需要看全文的 Section 6。

這篇的實驗設計相對輕量——一個 two-model, one-task 的實驗主要用來驗證 model-parametric 性質，不是大規模基準測試。這跟 Meta-Harness（今天的另一篇）的多 benchmark 評估形成對比。

### かに讀後判斷

這篇在 harness engineering 領域中是非常獨特的存在——它是第一篇嘗試用形式化理論（範疇論）來定義 harness 的結構保證和編譯正確性的工作。對 Morris 來說，如果你在思考 harness 的 formal foundation，這篇是必讀。

跟之前的 AHE（觀測驅動的自動演化）和 Meta-Harness（外迴圈搜尋）比起來，這篇走的是完全不同的路線：AHE 和 Meta-Harness 是「讓電腦自動找好的 harness」，這篇是「定義什麼叫『好的 harness』和『好的 harness 編譯』」。兩者是互補的——形式化標準可以作為自動搜尋的 constraint。

值得深讀的部分：
- Section 3 的 formal correspondence——四大支柱到 triple 的精確對應
- Section 4 的 certificate-preservation 機制——integrity gates、quality-based escalation、convergence checks 的具體定義
- Section 6 的 escalation experiment 細節
- Discussion 中關於 limitation 的部分——model-parametric 在多大程度上可以被推廣？

## 2. Meta-Harness: End-to-End Optimization of Model Harnesses

- **arXiv**: 2603.28052
- **Link**: https://arxiv.org/abs/2603.28052
- **類型**: arXiv (cs.AI)
- **Authors**: Yoonho Lee, Omar Khattab (MIT), Chelsea Finn (Stanford)

### 這篇在說什麼

這篇要解決的問題是：harness（模型周圍的程式碼——決定存什麼、取什麼、給模型看什麼）目前幾乎都是手工設計的，而既有的 text optimizer（用來自動改進文字/程式碼的方法）不適合 harness engineering，因為它們把反饋壓縮得太厲害——要嘛只看當前候選、要嘛只看 scalar score、要嘛限制反饋為短模板或摘要。

Meta-Harness 的核心想法是：讓一個 agentic proposer 存取一個 filesystem，filesystem 裡放了所有先前候選 harness 的原始碼、執行軌跡、和分數。Proposer 不是從壓縮過的摘要來學習，而是直接看原始資料，自己決定要看什麼、改什麼。這讓 Meta-Harness 可以處理遠超過既有 text optimizer 能處理的診斷資訊量（單次評估最多 10M tokens，比既有方法的最大 feedback budget 大三個數量級）。

### 主要貢獻

1. **提出 harness optimization 問題的新正規化**：不是「改 prompt」而是「搜尋 harness 程式碼」，而且用 agentic proposer + filesystem 替代壓縮反饋。

2. **三個 benchmark 上的強結果**：
   - Online text classification：比 ACE（SOTA context management system）好 7.7 points，同時用 4x 更少 context tokens
   - Retrieval-augmented math reasoning：單一 discovered harness 在 200 道 IMO-level 題目上跨 5 個 held-out 模型平均進步 4.7 points
   - Agentic coding（TerminalBench-2）：超越所有 reported Claude Haiku 4.5 harnesses，包括 Terminus-KIRA

3. **雙冪律衰減的發現**：improvement frequency ∼ 1/iteration、improvement magnitude ∼ 1/improvement count，這意味著 harness 搜尋的收益遞減是可以預測的。

4. **Width vs depth 的分析**：width（平行嘗試多個候選）提升平行性和多樣性，但 depth（在同一候選上持續迭代）對困難改進仍然關鍵。

### 方法 / pipeline

Meta-Harness 的搜尋迴圈：
1. Agentic proposer 讀取 filesystem，filesystem 包含所有先前候選的 source code、execution traces、scores
2. Proposer 提出一個新的 harness（修改程式碼）
3. 評估新 harness 在 evaluation tasks 上的表現
4. 將所有 logs（proposed code、reasoning traces、evaluation scores）存入 filesystem 的一個新目錄
5. 重複

Proposer 是 coding agent（不是 raw LLM），因為經驗量很快就超過 context limit，所以 proposer 需要選擇性地檢視原始檔案（用 grep、cat 等標準開發工具），而不是一次性把所有歷史塞進一個 prompt。實際上 proposer 每次迭代讀取 median 82 個檔案、參考超過 20 個先前候選。

關鍵設計：expose full history through filesystem，而不是透過壓縮的 per-candidate summary。

### 實驗設計

三個 evaluation domains：

**Online text classification**：
- 比較對象：ACE（Agentic Context Engineering）、TTT-Discover、OpenEvolve
- Meta-Harness 用 4 次評估就達到次佳方法的最終表現
- 最終比 ACE 好 7.7 points，同時用 4x 更少 context tokens

**Retrieval-augmented math reasoning**：
- 200 道 IMO-level 問題
- 單一 discovered harness 在 5 個 held-out 模型上平均進步 4.7 points
- 說明 discovered harness 有跨模型泛化能力

**Agentic coding（TerminalBench-2）**：
- 超越所有 reported Claude Haiku 4.5 harnesses
- 包括 Terminus-KIRA（之前最強的 hand-engineered baseline）

**分析性發現**：
- 雙冪律衰減：improvement frequency ∼ 1/iteration、magnitude ∼ 1/improvement count
- Width 幫助平行性和多樣性、depth 對困難改進關鍵

### かに讀後判斷

這篇是 harness engineering 領域的重要實務進展。作者團隊（MIT + Stanford）的份量也夠。跟前幾天的 AHE 相比，AHE 是從「觀測驅動」的角度自動演化 harness，Meta-Harness 是從「搜尋」的角度——用 agentic proposer 在 harness 程式碼空間裡搜尋。兩者互補：AHE 強調 observability（component、experience、decision 三層可觀測性），Meta-Harness 強調 full-history access（filesystem 暴露所有先前候選的原始資料）。

跟今天的 Categorical Architecture 那篇放在一起看，三篇形成了 harness engineering 的三個層次：
- Categorical Architecture：形式化定義「什麼是好的 harness 編譯」
- AHE：從觀測驅動的角度自動演化 harness
- Meta-Harness：從搜尋的角度自動最佳化 harness
