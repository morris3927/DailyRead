# Harness Engineering — 2026-05-20

## 1. VeRO: An Evaluation Harness for Agents to Optimize Agents

- **arXiv**: 2602.22480
- **Link**: https://arxiv.org/abs/2602.22480
- **Authors**: Varun Ursekar et al. (Scale AI)
- **Venue**: Accepted to ICML 2026
- **Versions**: v1 (Feb 25, 2026), v2 (May 1, 2026), v3 (May 11, 2026)
- **Code**: https://github.com/scaleapi/vero

### 這篇在說什麼

隨著 coding agent 越來越多地被用來改進其他 agent（agent optimization：透過 edit-execute-evaluate 循環迭代改進目標 agent），社群缺乏系統性的理解和可重複的評估基礎設施。Agent optimization 和傳統軟體工程不同：目標 agent 交織了確定性程式碼和隨機 LLM completions，需要同時捕捉中間推理和下游執行結果。VeRO（Versioning, Rewards, and Observations）就是為了填補這個缺口而提出的——它提供了一個可重複的評估 harness，包含版本化 agent snapshots、預算控制評估、結構化執行 traces，以及一套目標 agent 和任務的 benchmark suite。

### 主要貢獻

1. **VeRO Harness**：一個評估環境（Figure 1），提供版本化快照（每次修改都是一個 Git commit，可回滾、可比 diff）、預算執行（n_ℰ ≤ B，防止 optimizer 透過額外計算取得優勢）、權限控制（限制搜索空間，防止 trivial solutions 如升級模型）、以及結構化執行 traces。

2. **Agent Optimization Benchmark**：一個標準化的目標 agent、任務和評估程序套件，覆蓋數學推理（GAIA, GPQA, SimpleQA）、工具使用（TAU-Bench）和多步驟 QA（FACTS），附帶參考評估程序。

3. **三個實證發現**：
   - (a) 無論是簡單還是複雜的目標 agent，都可以被有意義地優化。
   - (b) Optimizer instructions 對方差和跨任務泛化有強烈影響。
   - (c) 當前 optimizers 默認集中在 prompt 修改，修改的多樣性和影響力有限。

### 方法 / pipeline

VeRO 將 agent optimization 形式化為一個優化問題：

- **Target agent task** 𝒯 = (ℐ, 𝒪, ℰ)：輸入空間、輸出空間（包含最終回應和執行 trace）、評估函數。
- **Optimization task**：在預算 B 內找到最大化 held-out performance 的 agent 𝐀*。
- **Optimizer** S：coding agent，在每一步 t 產生更新的 agent implementation 𝐀_{t+1} = S(f({𝐀ᵢ, τᵢ}ᵢ₌₀ᵗ), C)，其中 τ 是評估 traces，f 是 observation function（控制 optimizer 看到多少歷史），C 是額外 context。

VeRO 的三個核心設計目標：
1. **Controlled comparison**：不同 optimizer 在完全相同的資源和環境條件下運行。
2. **Informative feedback**：optimizer 收到結構化信號指導搜索。
3. **Post-hoc interpretability**：優化軌跡可以完全恢復和分析。

六個具體要求：Versioning、Budget enforcement、Permission control、Reproducible execution、Structured feedback、Interpretability。

### 實驗設計

- **Target agents**：多個不同複雜度的 baseline agent（數學推理、工具使用、多步驟 QA）。
- **Optimizer**：多種 coding agent 配置，比較不同 instructions 和觀察函數。
- **Benchmark tasks**：GAIA, GPQA, SimpleQA, TAU-Bench, FACTS。
- **主要結果**：
  - 無版本控制時，optimizers 經常無法完成優化 run 或產生不可重複的結果。
  - Optimizer instructions 的選擇顯著影響結果方差和跨任務泛化。
  - 當前 optimizers 主要做 prompt 修改（占比最高），對程式碼結構、工具邏輯的修改較少。
- **Metric**：Lift（相對於 baseline 的改進量），在 held-out test set 上評估。
- **Ablation**：對 observation function f 的設計進行了系統性 ablation（是否看過去版本、是否看完整 traces、是否看 aggregate metrics）。

### かに讀後判斷

VeRO 是 harness engineering 領域的重要基礎設施論文。它和之前 DailyRead 收錄的 Meta-Harness (2603.28052) 以及 AHE (2604.25850) 形成了一個完整的光譜：

- **Meta-Harness**：用 agentic proposer 搜索 harness 程式碼，關注「如何自動找到更好的 harness」。
- **AHE**：用 observability-driven closed-loop 自動演化 coding-agent harness，關注「harness 如何在生產中自我改進」。
- **VeRO**：用標準化評估 harness 來衡量「誰在優化 agent、效果如何」，關注「如何公平、可重複地比較 optimizers」。

三篇的關係是：Meta-Harness 和 AHE 是 optimizer，VeRO 是評估 optimizer 的基礎設施。VeRO 被接收至 ICML 2026，且代碼開源，這增加了它的可信度和可重複性。

對 Morris 來說，這篇的價值在於：
1. 它形式化了 agent optimization 問題（Section 3.1 的 𝒯, 𝒫, 𝐀 定義），為整個 harness engineering 領域提供了統一的問題表述。
2. 三個實證發現（尤其是 optimizers 默認集中在 prompt 修改）對理解當前 coding agent 的能力邊界很重要。
3. 開源代碼可以直接用來測試自己的 optimizer。

建議深讀時優先看 Section 3.1（形式化問題定義）、Figure 1（系統架構）、Table 的 optimizer 比較結果和 ablation。
