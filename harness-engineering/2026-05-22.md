# Harness Engineering — 2026-05-22

## 1. TEBench: Evaluating LLMs on Tibetan Language Understanding and Cultural Awareness

- **arXiv**: 2605.06125
- **Link**: https://arxiv.org/abs/2605.06125
- **全文來源**: arXiv HTML (完整讀取)

### 這篇在說什麼

TEBench 是一個針對 LLM 在藏語理解和文化認知方面的基準測試。這不是一個典型的 harness engineering paper，而是屬於 benchmark 建構——在 DailyRead 的分類中，benchmark 設計和評估框架都歸在 harness engineering 底下，因為它們都是「如何評估和約束 agent」的基礎設施。

作者的核心觀察是：主流 LLM 在低資源語言（特別是藏語）上的表現遠不如在高資源語言上的表現，而且現有的多語言基準對藏語的覆蓋非常有限。TEBench 填補這個空白，提供了一個覆蓋語言理解和文化認知兩個維度的系統性評估。

### 主要貢獻

1. **雙維度基準設計**：TEBench 不只測語言理解（翻譯、QA、文本分類），還測文化認知（藏傳佛教概念、藏族社會習俗、歷史地理），這對低資源語言的 LLM 評估非常重要，因為語言能力不等於文化理解。

2. **多層次評估協議**：從基礎詞彙到高級推理，從通用語言能力到文化專門知識，分層測試。這種分層設計可以精確定位 LLM 在哪個層次出了問題。

3. **對主流 LLM 的系統性評估**：測試了 GPT-4、Claude、Gemini 等模型在藏語上的表現，結果顯示即使是最強模型在文化認知維度上也顯著弱於語言理解維度。

### 方法 / pipeline

TEBench 的建構流程：

1. **語料收集**：從藏文佛教典籍、藏族歷史文獻、現代藏語教材等來源收集原始語料。
2. **題目設計**：分兩大維度——語言理解（閱讀理解、翻譯、語法判斷）和文化認知（宗教概念、社會習俗、歷史地理）。
3. **評估協議**：使用標準化的 prompt 模板和評分規則，確保不同 LLM 之間的可比性。
4. **基線模型**：GPT-4、Claude、Gemini 等主流模型作為基線。

### 實驗設計

- **測試集規模**：覆蓋藏語的多個語域（宗教、日常、學術、新聞）。
- **Metric**：準確率、BLEU、文化認知正確率。
- **主要發現**：主流 LLM 在藏語語言理解上表現中等（可做基本翻譯但推理弱），在文化認知上表現差（對藏傳佛教概念和藏族社會結構的理解非常有限）。
- **目前能確認的**：全文已讀，基準設計清晰。但作為 harness engineering 的貢獻，TEBench 更偏向「基準建構」而非「agent harness」——它評估的是 LLM 的語言和文化能力，而不是 agent 的行為約束或 workflow 管理。

### かに讀後判斷

**不推薦作為今日重點點開。** TEBench 做得不錯，但它更屬於「低資源語言基準」而非「agent harness」。對 DailyRead 的 harness engineering 分類來說，它的相關性偏低。如果你對低資源語言 LLM 評估有興趣，值得一看；但如果聚焦在 agent harness / eval / workflow engineering，這篇不太相關。
