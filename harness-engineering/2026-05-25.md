# Harness Engineering — 2026-05-25

## 1. SkillGenBench: Benchmarking Skill Generation Pipelines for LLM Agents

- **arXiv**: 2605.18693
- **Link**: https://arxiv.org/abs/2605.18693
- **Authors**: Yifan Zhou, Zhentao Zhang, Ziming Cheng, Shuo Zhang et al. (SJTU, XJTU, NUS, QuantaAlpha, THU, SUFE, NTU, PKU, UCAS)
- **Code**: https://github.com/QuantaAlpha/SkillGenBench

### 這篇在說什麼

隨著 agent 系統越來越依賴可重用的 skill（打包好的程序性知識 artifact），核心挑戰已經不只是「agent 能不能用提供的 skill」，而是「一個 pipeline 能不能從 repository 和 document 生成正確、可重用、可執行的 skill」。現有基準要麼測的是「提供的 skill 能不能提升下游執行」，要麼測的是「agent 能不能從原始上下文解決 end task」，但沒有把 skill 生成本身獨立出來評估。

SkillGenBench 把 generator 本身作為評估對象：給定原始語料，generator 產生標準化的 skill artifact，然後在固定的 harness 下執行，用統一的評估協議打分。它覆蓋兩個生成模式（task-conditioned 和 task-agnostic）和兩種程序性知識來源（repository-grounded 和 document-grounded），建立了一個可重現的 testbed 來研究 skill generation 作為獨立的研究問題。

### 主要貢獻

1. **首個獨立評估 skill generation pipeline 的基準**：不像 SkillsBench 測的是「提供的 skill 好不好用」，SkillGenBench 直接測的是「生成的 skill 好不好」，把生成品質從下游整合選擇中解耦出來。

2. **Task-agnostic 設定**：generator 在不知道下游任務的情況下，一次性從語料中蒸餾出一個可重用的 skill library，然後在隱藏的下游任務上測試。這測量的是抽象品質和跨任務重用能力，而不是 task-specific 的生成能力。

3. **雙來源覆蓋**：repository-grounded（程序散布在程式碼、配置、腳本中）和 document-grounded（程序和約束散布在長文本中），測試 generator 從不同結構的來源中提取程序性知識的能力。

4. **系統性失敗模式分析**：實驗顯示 repository-grounded 和 document-grounded 有截然不同的失敗模式——程式碼來源的困難在於隱含的工作流和分散的依賴，文件來源的困難在於約束的整合和條件分支的推理。

### 方法 / pipeline

SkillGenBench 的基準建構管線分五個階段：

1. **知識圖譜建構**：從原始語料中提取實體-關係三元組、社群摘要，覆蓋輸入 schema、domain 規則、輸出格式、驗證標準。
2. **場景生成**：從知識圖譜生成候選場景（code development, workflow execution, rule-grounded reasoning 等）。
3. **任務和測試用例生成**：每個場景產生任務規格和測試用例（normal, edge, adversarial inputs），經過自我反思細化。
4. **無 skill 任務驗證**：排除不需要程序性提取就能解決的任務（corpus-free pass rate ≥20%）或太簡單的任務（with-corpus pass rate ≥50%）。
5. **有 skill 任務驗證**：用迭代優化的 reference skill 驗證任務可解性。

每個基準項目是一個容器化環境，包含五個組件：source materials、task specification、skill interface、executor、evaluation protocol。

兩個生成設定：
- **Task-conditioned**：generator 看到 task spec，只生成與該任務相關的 skill
- **Task-agnostic**：generator 不看 task spec，一次蒸餾整個 skill library，然後在隱藏任務上測試

### 實驗設計

- **基準規模**：187 個任務，跨 repository-grounded 和 document-grounded 兩種來源，涵蓋多個任務領域
- **評估協議**：以確定性執行為基礎（deterministic execution-based checks），輔以相似性和 judge-based 信號做診斷
- **Generator 家族**：跨多個 skill-generation 方法（直接生成、知識圖譜輔助、迭代優化等）和多個 backbone model
- **關鍵發現**：
  - Task-agnostic skill distillation 明顯比 task-conditioned 更困難
  - Repository-grounded 和 document-grounded 有不同的失敗模式
  - 大部分 generator 在 task-agnostic 設定下產生不穩定或有負面轉移的 skill
  - 從全文 HTML 已讀到完整的基準建構方法和初步實驗結果

### かに讀後判斷

SkillGenBench 填補了 harness engineering 領域一個重要的空白——現有基準測的是 skill 的使用效果，不是 skill 的生成品質。Task-agnostic 設定特別有價值，因為它測量的是「一次蒸餾，多次重用」的能力，這正是真實部署中需要的。

和 5/24 的 AHE 對比：AHE 測的是「harness 的演化能不能改善 agent 表現」，SkillGenBench 測的是「skill 的生成能不能產生可重用的程序性知識」。兩者是同一個「agent 能力基礎設施」問題的不同面向——AHE 關注 harness 的可觀測性和演化，SkillGenBench 關注 skill 的生成品質和抽象能力。

不過需要注意：SkillGenBench 目前只測了 skill 的生成和執行，沒有測 skill 在長期使用中的維護和更新。另外，repository-grounded 和 document-grounded 的任務分佈可能偏斜，需要在深讀時確認。深讀優先看 Section 3（基準建構管線）、Section 4（實驗結果和失敗模式分析）、以及 Table 1（與現有基準的比較）。

## 2. RealUserSim: Bridging the Reality Gap in Agent Benchmarking via Grounded User Simulation

- **arXiv**: 2605.20204
- **Link**: https://arxiv.org/abs/2605.20204
- **Authors**: Ming Zhu, Juntao Tan, Rithesh Murthy et al. (Salesforce AI Research)

### 這篇在說什麼

LLM 模擬用戶是 agent 端到端評估的主要機制，但模擬用戶是真實人類的糟糕代理。作者識別出兩個根因：（1）**Formalism Ceiling**——不加約束的 LLM 默認產生語法正確、標點完整、冗長的文字，不管目標用戶的實際風格，風格匹配率只有 6-8%；（2）**Directive Amplification**——手工設計的行為指令（如「你是一個生氣的客戶」）被模型超解讀成不自然的行為極端，而且不同模擬器模型之間差異巨大，讓基準分數不可比較。

RealUserSim 從 14,000+ 真實人類-LLM 對話（WildChat）中提取 7,275 個可執行的行為 profile，用這些 profile 來 grounding 模擬器。PT3 基準（600 個對話，71+ 領域，anti-leakage 控制）顯示 grounded simulation 將匹配率從 24.2% 提升到 45.3%。在 τ-bench 上，grounded simulation 作為真實壓力測試，暴露了三個合作模擬器看不到的失敗機制（平均 -3.2% 到 -3.5% 任務成功率下降）。

### 主要貢獻

1. **首個從真實行為數據 grounding 的用戶模擬框架**：從 WildChat 提取 7,275 個可執行行為 profile，每個包含人口統計摘要和語言風格定義，取代合成或虛構的 persona。

2. **Executable Persona Manual**：每個用戶的 profile 包含最多 15 個「Command + Example」對，直接約束模擬器的行為——不是抽象描述（如「informal writer」），而是具體指令加真實引用。

3. **PT3 fidelity benchmark**：Paired Trajectory Turing Test，五個維度（Persona & Affective Traits, Interaction & Data Flow, Pacing & Action Sequencing, Linguistic Style & Mechanics, Tech Competency & Knowledge），帶 anti-leakage 清理，600 個對話跨 71+ 領域。

4. **Formalism Ceiling 和 Directive Amplification 的系統性分析**：無 grounding 時風格匹配率 6-8%（Formalism Ceiling）；加了手工指令後，不同模型產生截然不同的行為，讓基準不可比較（Directive Amplification）。

5. **Grounded simulation 作為真實壓力測試**：在 τ-bench 上暴露三個合作模擬器看不到的失敗機制，平均 -3.2% 到 -3.5% 任務成功率下降。

### 方法 / pipeline

**Profile 建構管線**：
1. 從 WildChat-4.8M 篩選 21,637 個多輪（≥3 turns）英文 GPT-4o 對話，7,311 個唯一用戶
2. GPT-4o 分析每個用戶的對話歷史，產生 Executable Persona Manual（最多 15 個 Command + Example 對）
3. 人口統計屬性提取：GPT-4o 從對話中提取明確自述 + 混合推論管線預測缺失欄位
4. 合併為 7,275 個統一 profile

**PT3 評估**：
- 對每個真實對話，提取問題描述和解決條件
- 合成對話：simulator 根據 profile 與 GPT-4o agent 互動
- LLM judge 盲比真實 vs. 合成對話，五維度打分
- Anti-leakage：測試對話中的例子從 profile 中移除

**Agent 評估**：
- τ-bench（Airline 50 任務 + Retail 114 任務）
- GPT-4.1 作為 agent
- 6 個模擬器模型
- 三個條件：Original（帶行為指令）、No Persona（移除指令）、Real Persona（注入 WildChat profile）

### 實驗設計

**PT3 結果**：
- 整體匹配率：Baseline 24.2% → With Profile 45.3%（+21.1 pp）
- 四個風格維度都有提升：Persona & Affective +31.8 pp, Interaction & Data Flow +28.3 pp, Pacing & Action Sequencing +25.5 pp, Linguistic Style & Mechanics +20.0 pp
- Tech Competency 不受 profile 影響（93.3% → 93.1%），確認 profile 建模的是溝通風格而非領域知識
- Formalism Ceiling：無 grounding 時風格維度匹配率 6-8%

**Agent 評估結果**：
- Grounded simulation 作為壓力測試：暴露三個合作模擬器看不到的失敗機制
- 平均 -3.2% 到 -3.5% 任務成功率下降
- Directive Amplification：手工指令讓不同模型產生截然不同的行為

### かに讀後判斷

RealUserSim 是 harness engineering 和 silicon sampling 的交叉點：它同時解決了「agent 評估中模擬用戶不真實」的問題和「silicon sampling 中行為異質性不足」的問題。Formalism Ceiling（6-8% 風格匹配率）的發現對整個 LLM-as-user-simulator 研究社群是一記重擊——大部分用 LLM 當用戶模擬器的工作，其模擬用戶跟真實用戶的風格幾乎沒有匹配。

和 silicon sampling 領域的對話：RealUserSim 的 profile grounding 方法和 Calibrated Value Personas (2605.16193) 有相似的直覺——從真實數據中提取行為特徵來 grounding 模擬。但 RealUserSim 更偏工程/評估，而 Calibrated Value Personas 更偏社會科學模擬。兩者的核心問題是一樣的：如何讓 LLM 模擬的行為更像真實人類。

和 harness engineering 的對話：RealUserSim 直接挑戰了現有 agent 基準（τ-bench 等）的用戶模擬方式，指出合作模擬器隱藏了真實的失敗模式。這和 AHE 的可觀測性論述互補——AHE 說的是 harness 設計影響 agent 表現，RealUserSim 說的是用戶模擬方式影響我們能看到什麼樣的失敗。
