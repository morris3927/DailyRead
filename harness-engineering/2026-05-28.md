# Harness Engineering — 2026-05-28

## 1. The Necessity of a Unified Framework for LLM Agentic Capabilities Evaluation

- **arXiv**: 2602.03238
- **Link**: https://arxiv.org/abs/2602.03238
- **Authors**: Pengyu Zhu, Li Sun, Philip S. Yu, Sen Su (Beijing University of Posts and Telecommunications, University of Illinois Chicago, Chongqing University of Posts and Telecommunications)
- **Submitted**: 2026-02-03, v2 updated 2026-05-26

### 這篇在說什麼

這篇論文要解決的問題非常直接：現在的 LLM agent benchmark 評估結果根本不可比。同一個 LLM 在同一個 benchmark 上，換一個 harness（system prompt、tool interface、memory 實作、parser）就可以跑出完全不同的分數。這不是小問題——當你看到「模型 A 在 SWE-bench 上 50%，模型 B 在 SWE-bench 上 45%」時，你不知道這個差距是來自模型能力，還是來自 harness 的選擇。

作者稱這為「identification problem」：observed score = agentic capability + harness compatibility + environment drift + evaluator conventions。目前沒有任何標準化方式把後三個因素控制住，所以報告的數字根本無法做跨模型歸因。Holistic Agent Leaderboard 的經驗數據也證實了這一點：同一個 LLM 在同一個 benchmark 下不同 harness 可以產生顯著不同的分數。

### 主要貢獻

1. **精確定位 identification problem**：把 agent benchmark score 的方差來源拆成三層——LLM 本身、harness 層（prompting, memory, tool invocation）、execution environment。後兩者是目前不可控的混淆因子。
2. **區分 evaluation-time 和 deployment-time**：這是一個重要的概念區分。在 evaluation time，我們需要標準化 harness 來做公平的模型比較；在 deployment time，harness 創新是應該鼓勵的（Claude Code、Codex 的 harness 創新是產品優勢，不是作弊）。兩者回答不同的問題：前者是「哪個 LLM 在固定 harness 下更強」，後者是「哪個 agent product 端到端更強」。
3. **提出什麼該標準化、什麼不該**：應該標準化的——LLM inference API、system prompt template、memory management protocol、tool interface specification、evaluation environment。不應該標準化的——benchmark-specific task content、task-specific tools。
4. **Versioning-based governance model**：提出用語意化版本號（semver）管理 spec 的演進，讓標準可以隨時間更新但不破壞可比性。
5. **Migration case studies**：展示了從現有碎片化評估遷移到統一框架的可行性。

### 方法 / pipeline

這是一篇 position paper + framework proposal，不是一個實驗系統。核心方法是分析性的：

1. **方差來源分析**（Section 2）：逐項分析 harness 的各個組件（system prompt、memory management、tool invocation、parser、environment）如何引入獨立於 LLM 能力的方差。用 Holistic Agent Leaderboard 的數據做實證支持。
2. **Standardization proposal**（Section 3-4）：
   - **Standardized Agent Stack**：固定 LLM inference、system prompt、memory protocol、tool interface。
   - **What to freeze vs. what to leave open**：freeze non-LLM components, preserve task content and task-specific tools。
   - **Versioning governance**：spec 的 major/minor/patch 版本控制，類似開源項目的 semver。
3. **Addressing objections**（Section 5）：回應了五個主要的反對意見——「標準化會扼殺創新」、「現有努力已經夠了」、「production agent 不需要這個」、「MCP 等協議層面的標準化就夠了」、「ecological validity 問題」。

### 實驗設計

這篇沒有傳統意義上的實驗。它的「實驗」是 migration case studies——展示現有 benchmark 可以如何遷移到統一框架下。具體的數據來自 Holistic Agent Leaderboard 的跨 harness 比較結果。

但論文引用了很強的實證支持：
- Holistic Agent Leaderboard 顯示同一個 LLM 在同一個 benchmark 上不同 harness 下分數差異顯著
- τ-bench、Terminal-Bench、Harbor 等的經驗數據
- MCP 協議作為 tool invocation 標準化的先例

**目前能確認的**：identification problem 的分析很紮實，migration case studies 展示了可行性。**目前看不到的**：統一框架的完整實作和在大規模 benchmark 上的驗證結果——論文是 position paper，不是 system paper。

### かに讀後判斷

這篇和之前 DailyRead 看過的幾篇 harness 工程論文有直接的對話關係：

- **vs. "Code as Agent Harness" (2605.18747)**：那篇說 code 是 harness 的 operational substrate，這篇說 harness 的非 LLM 部分應該在 evaluation time 被標準化。兩者互補——一個定義了 harness 是什麼，另一個定義了怎麼控制它。
- **vs. AHE (2604.25850)**：AHE 用 observability-driven 自動演化 harness，這篇說在 evaluation time 你應該凍結 harness。不矛盾——AHE 優化的是 deployment-time harness，這篇要求的是 evaluation-time 的 controlled comparison。
- **vs. "The Last Harness You'll Ever Build" (2604.21003)**：那篇說 harness 可以被 meta-optimized，這篇說 optimization 結果不應該污染模型間的公平比較。

這篇的定位很清楚：它不是要做另一個 benchmark，而是要做「benchmark 的基礎設施」。對 Morris 來說，如果你在做 agent evaluation，這篇提供了為什麼 harness 標準化重要的理論基礎。值得點開看 Section 2（variance analysis）和 Section 4（what to standardize / what not to）。

## 2. Beyond Static Responses: Multi-Agent LLM Systems as a New Paradigm for Social Science Research

- **arXiv**: 2506.01839
- **Link**: https://arxiv.org/abs/2506.01839
- **Authors**: Jennifer Haase (Weizenbaum Institute, HU Berlin), Sebastian Pokutta (TU Berlin, Zuse Institute Berlin)
- **Submitted**: 2025-06-02, v3 updated 2026-05-18

### 這篇在說什麼

這篇論文提出一個六層分類框架，把 LLM-based 系統從「靜態工具」到「複雜適應系統」做了一個完整的譜系劃分。核心論點是：目前社會科學對 LLM 的使用大多停留在 Level 0（LLM-as-Tool）和 Level 1（LLM-as-Role），但 LLM 技術的發展已經讓更高層次的 agentic 系統成為可能，這些系統可以帶來質變性的社會模擬能力。

這篇被放在 harness engineering domain 的原因：它雖然主要討論社會科學應用，但其分類框架對理解 agent harness 的複雜度分級有直接幫助——Level 3+ 的 agent 系統需要 memory、environment interface、strategic coordination，這些正是 harness engineering 要解決的問題。

### 主要貢獻

1. **Six-tier framework**：Level 0 (LLM-as-Tool) → Level 1 (LLM-as-Role) → Level 2 (Agent-like LLM) → Level 3 (LLM-based Agents) → Level 4 (Multi-Agent Systems) → Level 5 (Complex Adaptive Systems)。每層有明確的功能閾值（memory → autonomy → coordination → learning）。
2. **OODA loop 對齊**：把六層框架和 OODA (Observe-Orient-Decide-Act) loop 對齊，提供決策論視角。
3. **Methodological 和 ethical challenges**：對每一層的 reproducibility、ethical oversight、emergent bias 風險做了系統性分析。
4. **Living document 承諾**：作者明確說這是一份「living document」，會隨領域發展持續更新。

### 方法 / pipeline

這是一篇 framework/survey paper，核心方法是概念分析和文獻綜述：

- 把現有 LLM-based 社會科學應用按六層框架分類
- 每層對應一個功能閾值：Level 0-1 無 memory / 短期 memory，Level 2 有 task-oriented reasoning + multi-step planning，Level 3 有 comprehensive memory + environment interface + strategic coordination，Level 4 有 multi-agent interaction，Level 5 有 self-organization + norm formation + institutional change
- 對每層舉出代表性系統和實證例子

### 實驗設計

這篇沒有實驗。它是概念框架論文，用大量文獻引用和系統分類來支撐論點。目前能確認的是框架的邏輯完整性和文獻覆蓋度，無法確認的是框架的實證有效性——沒有任何實驗驗證這個六層分類是否真的對應到不同的系統行為模式。

### かに讀後判斷

這篇的價值不在於實驗結果（它沒有），而在於分類框架。對 harness engineering 的意義：它提供了一個判斷你的 agent harness 需要多複雜的參考框架——如果你的系統在 Level 2+，你就需要 structured memory；如果在 Level 3+，你需要 environment interface + strategic coordination；如果在 Level 4+，你需要 multi-agent orchestration。

這篇也和 silicon sampling/social simulation domain 高度相關（Level 4-5 正是 social simulation 的範疇），所以今天也出現在 silicon-sampling-social-simulation 的 domain note 中。
