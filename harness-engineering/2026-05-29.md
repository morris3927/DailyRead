# Harness Engineering — 2026-05-29

## 1. HASP: Harnessing LLM Agents with Skill Programs

- **arXiv**: 2605.17734
- **Link**: https://arxiv.org/abs/2605.17734
- **Authors**: Hongjun Liu, Yifei Ming, Shafiq Joty, Chen Zhao (NYU, Salesforce AI Research)
- **Submitted**: 2026-05-18

### 這篇在說什麼

HASP 要解決的核心問題是：現在的 LLM agent 從過去經驗中提取的 skill，幾乎都只以 textual guidance 形式存在——prompt 裡的 advice、reflection 裡的 lesson、skill library 裡的自然語言描述。這些 textual skills 是 advisory 的：它們說「你應該避免重複搜尋」或「記得先驗證再下結論」，但沒有明確的機制決定什麼時候觸發、怎麼修改下一步行動。模型可以忽略它們，也經常忽略它們。

HASP 的解法是把 skill 從 passive text 升級為 executable Program Functions (PFs)。每個 PF 是一個 state–action intervention function：給定當前 agent state 和 candidate next action，PF 判斷要不要 intervene，如果要，就修改 action 或注入 corrective context。這把 skill 從「建議」變成「執行檔」——可以被觸發、可以修改 agent loop 的決策、可以留下結構化記錄用於後續訓練。

在 harness engineering 的脈絡裡，HASP 是一個非常具體的 harness 設計範例：它定義了一個外部的 skill intervention layer，環繞在 base policy 之外，可以在 inference time、post-training、self-improvement 三個階段分別作用。這和之前 DailyRead 看過的 AHE (2604.25850) 的 observability-driven harness evolution 是同一個方向的兩個面向：AHE 用 observability 來演化 harness 本身，HASP 用 executable skill programs 來控制 agent loop。

### 主要貢獻

1. **Skills as executable state–action intervention functions**：這是這篇最核心的概念貢獻。PF 有 should_activate（什麼時候觸發）和 intervene（怎麼修改）兩個部分，不再是 free-form text。這讓 skill 變成可以被驗證、可以被訓練、可以演化的模組化元件。

2. **三階段模組化設計**：同一套 PF interface 可以在 inference time 直接 intervene（不動 model weights）、在 post-training 時提供 structured supervision（PF-corrected trajectories → SFT / rejection sampling / on-policy distillation）、在 self-improvement 時演化 skill library（failure patterns → candidate PFs → validation → admission）。這個設計讓 HASP 的三個使用模式共享同一個 PF abstraction，而不是三個獨立的系統。

3. **PF-guided rejection sampling**：HASP-Evolve + RS 是主要的訓練 recipe。和標準 rejection sampling 只看 final task success 不同，HASP 的 trajectory scoring 同時考慮 task success 和 PF-derived intervention quality：Score(τ) = β₁·TaskSuccess(τ) + β₂·A(τ)，其中 A(τ) = T⁻¹Σ(λ_t·t_t + λ_m·m_t + λ_q·q_t + λ_o·o_t)。四個信號分別是 intervention timing、mode、correctness、outcome。權重設為 (0.15, 0.10, 0.25, 0.50)，outcome 最重要。

4. **實證結果強**：Web-search reasoning 上，inference-time PFs alone 就比 ReAct Agent 提升 25%；加上 post-training 和 controlled evolution 後比 Search-R1 提升 30.4%。Math reasoning 上，closed-loop RS 達到 45.4%。Coding上，teacher-augmented PF intervention 達到 68.7% pass@1，PF-based training 提升到 69.9%。

### 方法 / pipeline

HASP 的 agent loop 流程：

1. **Base policy proposes action**：π_θ 提出下一個 action a_t^orig
2. **Harness retrieves relevant PFs**：從 skill library M 中根據當前 state s_t 取回候選 PFs R(s_t) ⊆ M
3. **PF activation check**：每個 PF 的 should_activate 判斷是否要在當前 state 和 proposed action 上觸發
4. **Intervention**：觸發的 PFs 透過 intervention operator Γ 修改 action 或注入 context：(ã_t, c_t, κ_t) = Γ(s_t, a_t^orig, R(s_t))
5. **Execution**：執行修改後的 action ã_t，得到 observation o_{t+1}
6. **Record**：每個 PF activation 產生結構化記錄 e_t = (s_t, a_t^orig, ã_t, c_t, κ_t, Δ_t)

PF initialization：從 training pool 的 failure cases 中歸納 recurring failure–repair patterns（例如 premature finalization、entity confusion），每個 pattern 變成一個 candidate PF，必須通過 syntax、interface、mock-execution validation 才能進入 library。

三種使用模式：
- **Inference-time PF intervention**：PFs 直接在 agent loop 中觸發，不動 model weights
- **Post-training**：PF-corrected trajectories 提供 structured supervision（SFT、rejection sampling、on-policy distillation）
- **Self-improvement**：failure patterns → candidate PFs → validation → library update

### 實驗設計

**Tasks**：
- Web-search reasoning（3 個 multi-hop QA benchmarks）
- Math reasoning（GSM8K, MATH）
- Coding（HumanEval, MBPP）

**Baselines**：
- Training-free: ReAct Agent (multi-loop), Reflexion, ExpeL, SKILL0
- Training-based: Search-R1, ReSearch, SimpleRL-reason, General-Reasoner, P-GRPO

**Models**：Qwen2.5-7B-Instruct, Qwen2.5-3B-Instruct

**Main results**（web-search reasoning, avg accuracy）：
- ReAct Agent: 40.8%
- HASP (PF-only, inference-time): 51.0% (+25% relative)
- HASP (PF + auxiliary teacher): 56.2%
- Search-R1: 47.8%
- HASP-Evolve + RS (rejection sampling): 60.3% (+30.4% relative over Search-R1)
- SFT variant: 52.8%
- OPD variant: 62.5%

**Math reasoning**（GSM8K + MATH）：
- Base Qwen2.5-7B: 78.2% / 26.8%
- HASP-Evolve + RS: 79.5% / 45.4%

**Coding**（avg pass@1）：
- Base: 66.8%
- Teacher-augmented PF: 68.7%
- PF-based training: 69.9%

**Ablation**：
- PF activation timing: 大部分 PFs 在 task 的前半段觸發（corrective intervention 集中在 early steps）
- Skill internalization: SFT 可以讓 student 部分學到 PF 的 correction pattern，但 rejection sampling 更穩定
- Library evolution stability: 沒有 controlled selection 的 library evolution 會引入 noise，有 teacher review 的 stable evolution 效果最好

### かに讀後判斷

這篇是 harness engineering 領域目前最具體的「skill 從 text 變成 code」的實作。和之前看的幾篇對照：

- **vs. AHE (2604.25850)**：AHE 用 observability signals 來演化整個 harness（tool schemas, system prompts, etc.），HASP 用 PFs 來演化 skill library。AHE 演化的是環境，HASP 演化的是 agent 的行為知識。兩者互補——AHE 管的是「agent 在什麼環境裡運作」，HASP 管的是「agent 知道什麼 and 何時知道要修正」。
- **vs. "The Last Harness You'll Ever Build" (2604.21003)**：那篇的 Meta-Evolution Loop 和 HASP 的 skill evolution 有概念上的相似，但 The Last Harness 演化的是 harness blueprint，HASP 演化的是 skill library。層次不同。
- **vs. "Code as Agent Harness" (2605.18747)**：Code as Harness 說 code 是 harness 的 substrate，HASP 把這個 substrate 用在 skill programs 上——PF 就是一段 code，在 agent loop 的特定狀態被觸發和執行。這是 code-as-harness 的一個非常具體的應用實例。

值得 Morris 點開嗎？非常值得。這篇是目前 harness engineering 領域裡少數有完整方法、完整實驗、完整 ablation 的 paper。重點看 Section 3（HASP framework）、Table 2（main results）、Figure 3（PF trigger and intervention analysis）。如果你對 agent 的 self-improvement 機制感興趣，Section 3.3（self-improvement with controlled evolution）也值得細讀。

## 2. From Model Scaling to System Scaling: Scaling the Harness in Agentic AI

- **arXiv**: 2605.26112
- **Link**: https://arxiv.org/abs/2605.26112
- **Authors**: Shangding Gu et al. (UC Berkeley, SafeRL Lab)
- **Submitted**: 2026-05-25

### 這篇在說什麼

這篇論文提出了一個 framing shift：agentic AI 的下一個 bottleneck 不只是 model scaling（更大的模型、更多的資料、更強的 post-training），而是 system scaling——即 harness 的設計、評估和優化。作者把 agent harness 定義為六個互動組件的系統：reasoning substrate (ℛ)、memory store (ℳ)、context constructor (𝒞)、skill-routing layer (𝒮)、orchestration loop (𝒪)、verification-and-governance layer (𝒢)。Agent performance 是這六個組件的函數 𝒫_H = Φ(ℛ, ℳ, 𝒞, 𝒮, 𝒪, 𝒢)，model scaling 主要改善 ℛ，system scaling 改善 ℳ, 𝒞, 𝒮, 𝒪, 𝒢。

這個 framing 直接回應了 DailyRead 之前看過的幾篇 harness 論文的核心觀察：同一個 LLM 在同一個 benchmark 上換 harness 就跑出不同分數、SWE-agent 只靠 redesigning agent-computer interface 就大幅提升 accuracy。作者認為這些不是「implementation details」，而是 first-class design variables。

### 主要貢獻

1. **System-scaling framing**：把 agent performance 拆成六個組件的函數，並明確論證 model scaling 是 necessary but not sufficient——once models reach a sufficient capability threshold, additional gains increasingly depend on system design。這不是一個新觀察（SWE-agent、τ-bench 都暗示過），但這是第一次被系統性地框架化。

2. **三個 core bottlenecks 的深入分析**：
   - **Context governance**：不是 context window size 的問題，而是 what to retrieve, compress, order, refresh, trust, and keep active at each step。Attention dilution over long inputs（Lost in the Middle）、evidence preference for start/end of context 都是 context governance failure 的具體表現。
   - **Trustworthy memory**：Memory 不只是 storage。Precision（存什麼）、durability（存多久）、retrievability（怎麼找到）、verifiability（怎麼確認沒有被污染或 drift）四個維度。Memory poisoning、semantic drift、stale information 都是 memory governance failure。
   - **Dynamic skill routing**：不僅是「有沒有 tools/subagents」，而是「怎麼 dispatch the right tool/subagent at the right time」。Multi-agent coordination failures、uncertainty sharing、delegation quality 都是 skill routing 的問題。

3. **Harness-level evaluation agenda**：超越 one-shot task success，量測 trajectory quality、memory hygiene、context efficiency、communication fidelity、verification cost、safe evolution over time。這和之前 DailyRead 看過的 identification problem paper (2602.03238) 直接對齊——兩者都在說目前的 evaluation 看不到 harness 的影響。

4. **CheetahClaws**：一個 Python-native reference harness，和 Claude Code、OpenClaw 做具體比較，讓 harness-level design choices 變得 explicit。CheetahClaws 是一個可重現的 baseline，讓不同 harness 設計的比較有共同的 reference point。

### 方法 / pipeline

這是一篇 framework + position paper，但也包含實際系統比較。核心方法是：

1. **概念框架**（Section 3）：定義 agent harness 的六個組件，解釋每個組件的 factorization（例如 ℳ = (precision, durability, retrievability, verifiability)，𝒞 = (relevance, compactness, traceability, refresh policy)）。
2. **Bottleneck 分析**（Section 4）：逐一分析 context governance、trustworthy memory、dynamic skill routing 三個核心 bottleneck，引用經驗數據支撐。
3. **Evaluation agenda**（Section 5）：提出 harness-level benchmarks 應該量測的六個維度。
4. **System comparison**（Section 3.1）：把 Claude Code、OpenClaw、CheetahClaws 作為三個 harness 實例，逐一分析它們在六個組件上的設計選擇。

作者特別強調：這個框架是 conceptual organization，不是 quantitative model。Φ 沒有 closed form，六個 factors 不是 orthogonal 的。但每個 factor 都是一個獨立的 intervention point——「你可以關掉 𝒢，同樣的 ℛ 和 𝒞 就會跑出明顯不同的 agent」。

### 實驗設計

這篇沒有傳統實驗，但有系統比較：

- **Claude Code**：subagent-based architecture, hybrid context strategy（persistent project guidance up front + just-in-time retrieval via glob/grep），tool dispatch for codebase navigation，verification through bash execution。
- **OpenClaw**：plugin-based architecture, session-bound memory, dynamic skill routing, multi-turn orchestration。
- **CheetahClaws**：Python-native reference harness，明確的六組件設計，可作為 reproducible baseline。

作者明確聲明 paper 仍在 active development（"This manuscript is under active development"），所以目前看到的比較更多是定性的架構分析而非定量 benchmark 結果。

**目前能確認的**：框架的邏輯完整性、六個組件的 intervention point 分析、和現有系統的定性對齊。
**目前看不到的**：CheetahClaws 在具體 benchmark 上的定量結果、六個組件之間的交互效應分析、framework 的預測力驗證。

### かに讀後判斷

這篇是 harness engineering 領域的「systematization of experience」paper——它把目前社群已經在做但還沒有統一語言的東西，用一個清晰框架說出來。和之前看的幾篇對照：

- **vs. "Code as Agent Harness" (2605.18747)**：那篇說 code 是 harness 的 substrate，這篇把 harness 拆成六個組件並說每個都是 first-class design variable。互補——一個定義 medium，另一個定義 architecture。
- **vs. AHE (2604.25850)**：AHE 是這篇框架中 𝒪 和 𝒢 的具體實作方法——用 observability signals 來演化 orchestration 和 verification。這篇提供的是 AHE 的理論定位。
- **vs. HASP (2605.17734)**：HASP 是這篇框架中 𝒮（skill routing）的具體實作——PFs 就是 skill programs 的 routing 和 intervention 機制。
- **vs. identification problem paper (2602.03238)**：那篇說 evaluation 時應該 freeze harness，這篇說 harness 本身就是一個應該被評估的 first-class object。兩者完全一致——你應該在 controlled harness 下評估 model，但也應該把 harness 作為獨立變量來評估。

值得 Morris 點開嗎？如果你對 harness engineering 的整體框架感興趣，這篇是目前最完整的 overview。重點看 Section 3（六組件框架）、Section 4（三個 bottleneck）、Table comparing Claude Code / OpenClaw / CheetahClaws。但要注意這篇還在 active development，定量結果可能還不完整。
