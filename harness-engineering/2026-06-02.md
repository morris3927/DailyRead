# Harness Engineering — 2026-06-02

## 1. SkillsBench: Benchmarking How Well Agent Skills Work Across Diverse Tasks

- **arXiv**: 2602.12670
- **Authors**: Xiangyi Li, Wenbo Chen, Yimin Liu, Shenghan Zheng, Xiaokun Chen, Yifeng He, Yubo Li, Bingran You, Haotian Shen, Jiankai Sun, Shuyi Wang, Binxu Li, Qunhong Zeng, Di Wang, Xuandong Zhao, Yuanli Wang, Roey Ben Chaim, Zonglin Di, Yipeng Gao, Junwei He, et al.
- **Venue**: arXiv preprint (v3: March 2026)
- **Link**: https://arxiv.org/abs/2602.12670

### 這篇在說什麼

SkillsBench 是第一個系統性評估「Agent Skills」（結構化程序知識包）對 LLM agent 實際表現影響的 benchmark。過去的 agent 評估聚焦在模型能力本身，但越來越多 agent 系統使用 Skills（即結構化的操作指南、最佳實踐文檔、工具使用說明）來增強 agent。問題是：這些 Skills 到底有沒有用？在什麼情境下有用？在什麼情境下反而有害？SkillsBench 正是為了回答這個問題而設計。

### 主要貢獻

1. **首個 Skill-as-variable 的系統性 benchmark**：86 tasks × 11 domains，每個 task 配有 curated Skills，在三種條件下評估：no Skills、curated Skills、self-generated Skills。7 個 agent-model configurations，7,308 trajectories。

2. **量化 Skill 效果的不均勻性**：curated Skills 平均提升 16.2pp，但 domain 差異極大——Healthcare +51.9pp vs Software Engineering +4.5pp。16/84 tasks 甚至出現負面影響（Skill 反而降低表現）。

3. **Self-generated Skills 的失敗**：模型自己生成的 Skills 平均沒有正面效果，顯示模型「消費知識的能力」遠高於「生成知識的能力」。這對「讓 agent 自己學會 skill」的路線構成挑戰。

4. **聚焦 vs 全面的取捨**：包含 2-3 個模組的聚焦 Skills 表現優於全面文檔，暗示過多的程序知識反而造成認知負擔。

5. **小模型 + Skills ≈ 大模型**：較小的模型搭配 Skills 可以匹配較大模型不使用 Skills 的表現，為成本優化的 harness 設計提供實證基礎。

### 方法 / pipeline

- **Benchmark 設計**：86 tasks 橫跨 11 domains（Software Engineering, Data Science, Healthcare, Finance, Legal, Creative Writing, Education, Customer Service, Research, Marketing, Project Management）。
- **Skills 類型**：
  - No Skills：純模型，無額外知識。
  - Curated Skills：人工編寫的結構化程序知識包。
  - Self-generated Skills：模型自己生成的 Skills。
- **Agent-model configurations**：7 種（不同模型 + 不同規模）。
- **Verification**：確定性 verifiers（每個 task 有明確的對錯判斷標準）。
- **總 trajectories**：7,308。

### 實驗設計

- **主要結果**：
  - Curated Skills 平均 +16.2pp，但分布極度不均勻。
  - Healthcare +51.9pp（最大的 domain 提升），Software Engineering +4.5pp（最小）。
  - 16/84 tasks 有負面影響（curated Skills 反而降低表現）。
  - Self-generated Skills：平均無正面效果。
  - 聚焦 Skills（2-3 模組）> 全面文檔。
  - 小模型 + Skills ≈ 大模型 no Skills。

### かに讀後判斷

這篇對 harness engineering 有直接且實用的貢獻。過去一年 harness engineering 的討論多聚焦在 harness 架構本身（如 Harness-Bench 2605.27922），但 SkillsBench 把視角轉向 harness 中注入的知識內容——「你給 agent 什麼 skill」和「你怎麼給」一樣重要。

幾個核心洞察特別值得注意：
1. **Skill 的效果高度 domain-dependent**：Healthcare +51.9pp vs Software Engineering +4.5pp 的差距，暗示 harness 設計不能假設「有 skill 就好」，必須按 domain 評估。
2. **Self-generated Skills 的失敗**：這直接挑戰了「讓 agent 自己寫 skill → 用 skill」的遞迴改進路線。模型可以消費但不能可靠生成程序知識。
3. **小模型 + Skills ≈ 大模型**：這是 cost-aware harness 設計的重要實證基礎。

和 Harness-Bench（2605.27922）的關係：Harness-Bench 把 harness 當成變項，SkillsBench 把 Skills 當成變項，兩者互補地回答了「agent 的表現有多少來自 harness、多少來自 skill、多少來自模型本身」。

## 2. Engineering Reasoning and Instruction (ERI) Benchmark

- **arXiv**: 2603.02239
- **Authors**: M.Z. Naser, Ahmad Bani Awwad, Zoie McCreery, Radwa Eissa, Ahmad Naser, Gianluca Cusatis, Andrew Metcalf, Kapil Madathil, Jamal Abdalla, Venkatesh Kodur, Mohammad Reza Saeb
- **Venue**: arXiv preprint (February 2026)
- **Link**: https://arxiv.org/abs/2603.02239

### 這篇在說什麼

ERI（Engineering Reasoning and Instruction）是一個 taxonomy-driven 的工程推理基準資料集，用來訓練和評估工程領域的 LLM 和 agent。不同於一般的 coding benchmark，ERI 涵蓋九個工程領域（土木、機械、電機、化工、環境、航太、材料、消防、工業工程），55 個子領域，搭配七種意圖類型和三個難度層級，共 57,750 筆記錄。

### 主要貢獻

1. **跨工程領域的 taxonomy-driven 基準**：9 領域 × 55 子領域 × 7 intent types × 3 difficulty tiers = 57,750 筆。這是目前工程推理領域最全面的覆蓋。

2. **三層效能結構**：7 個 LLM 測試結果顯示統計顯著的三層結構——frontier models（GPT-5, Claude Sonnet 4, DeepSeek V3.1）平均 > 4.30/5.00，mid-tier 和 small models 效能遞減且在 graduate-level 問題上退化更快。

3. **收斂驗證協議**：用 cross-provider independence + multi-judge averaging + frontier-model agreement analysis 將幻覺風險經驗性上界定在 1.7%。

### 方法 / pipeline

- 57,750 筆記錄帶有 field/subdomain/type/difficulty metadata 和 solution formatting。
- Taxonomy 規格 + 驗證腳本 + evaluation harness 公開釋出。
- 七種意圖類型：definition, explanation, calculation, comparison, design/synthesis, troubleshooting, code-related。
- 三個難度層級：undergraduate, graduate, professional。

### 實驗設計

目前僅從 abstract 能確認 7 個 LLM 的三層效能結構和 1.7% 幻覺上界。具體的領域間差異、意圖類型分析、以及 evaluation harness 的設計需要看全文。

### かに讀後判斷

ERI 的定位和 SkillsBench 不同——ERI 評估的是「模型本身在工程推理上的能力」，而非「skill/harness 如何影響表現」。但 ERI 的 evaluation harness 設計（taxonomy specs + validation scripts + reproducible comparison）對 harness engineering 社群有參考價值：它提供了一個可複用的評估框架，而這正是 Harness-Bench 和 SkillsBench 都需要的基礎設施。

值得注意的是 ERI 的三層效能結構和 Harness-Bench 的核心發現形成呼應：模型能力不是單一維度，而是有明顯的階層結構。如果 model × harness × skill 的交互作用是 harness engineering 的核心研究問題，那 ERI 提供了 model 層面的基線。
