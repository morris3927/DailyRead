# Harness Engineering — 2026-06-09

## 1. AutoHarness: Improving LLM Agents by Automatically Synthesizing a Code Harness

- **arXiv**: 2603.03329
- **Link**: https://arxiv.org/abs/2603.03329
- **Authors**: Xinghua Lou, Miguel Lázaro-Gredilla, Antoine Dedieu, Carter Wendelken, Wolfgang Lehrach, Kevin P. Murphy (Google DeepMind)

### 這篇在說什麼

LLM 作為 agent 時，常會輸出環境不允許的動作——Kaggle GameArena 棋類比賽中 Gemini-2.5-Flash 有 78% 的輸局是因為下了違規棋步。傳統做法是手寫 harness 來過濾違規動作，但每個新環境都要重新手寫，既脆弱又費工。AutoHarness 提出了一個核心洞見：讓 LLM 自己寫自己的 harness。更具體地說，用 Gemini-2.5-Flash 少量回合的迭代式程式碼精修，從環境回饋中自動合成出合法動作過濾器，甚至整個策略程式碼。

### 主要貢獻

1. **提出 code-as-harness 框架**：不再手寫 harness，而是讓同一個小模型自動合成 harness 程式碼。harness 可以是 action verifier（過濾違規動作）、action filter（產生合法動作集後讓 LLM 排序）、或完整的 code-as-policy（完全用程式碼決策，不需 LLM 推理）。

2. **在 145 個 TextArena 遊戲上達成 100% 合法動作率**：訓練平均只需要 14.5 次迭代，其中 19/32 遊戲在 10 次以內就收斂。

3. **小模型 + auto harness 超越大模型**：Gemini-2.5-Flash + harness 在 2P 遊戲中對 Gemini-2.5-Pro 贏了 9/16 場（勝率 56.3% vs 38.2%）；在 1P 遊戲中平均 reward 0.745 vs Pro 的 0.707。

4. **Harness-as-Policy 可超越 GPT-5.2-High**：完全用程式碼策略的版本在 16 個 1P 遊戲上拿到比 Gemini-2.5-Pro 和 GPT-5.2-High 更高的平均 reward。

### 方法 / pipeline

AutoHarness 的核心是一個 Thompson sampling 搜尋流程：

1. **樹狀搜尋 + Thompson sampling**：維護多個 harness 程式碼假說，用 Thompson sampling 決定下一個要精修的節點，啟發式值是合法動作準確率。

2. **迭代精修**：每次迭代在 10 個平行環境中 roll out 至多 1000 步，收集最多 5 個失敗步驟，送給 Critic 整合錯誤訊息，再由 Refiner（同一個 LLM）產生改良後的程式碼。

3. **三種 harness 模式**：
   - **harness-as-action-verifier**：LLM 提議動作，`is_legal_action()` 驗證，違規則重試
   - **harness-as-action-filter**：`propose_action()` 產生合法動作集，LLM 從中排序
   - **harness-as-policy**：程式碼直接決策，完全不需要 LLM

4. **訓練設定**：用 Gemini-2.5-Flash 作為 base model，TextArena 的 145 個遊戲（去掉 9 個自由文本遊戲），刻意移除觀察字串中的「Available Moves」提示，讓問題更貼近真實場景。

### 實驗設計

- **Dataset**: TextArena 145 個遊戲（1P 和 2P），評估聚焦 16 個 1P + 16 個 2P 遊戲
- **Baseline**: Gemini-2.5-Flash（無 harness）、Gemini-2.5-Pro、GPT-5.2 (no thinking)、GPT-5.2-High
- **Metrics**: 合法動作率、2P 遊戲勝率、1P 遊戲平均 reward
- **Main results**:
  - 合法動作率：145 個遊戲全部達到 100%（測試 rollout 長度 1000、10 個 seed）
  - 2P 對 Pro：贏 9/16 場，整體勝率 56.3% vs 38.2%
  - 1P reward：0.745 vs Pro 的 0.707 vs Flash 的 0.673
  - Harness-as-Policy：平均 reward 超過 GPT-5.2-High
- **Ablation**: 論文附錄有生成 harness 程式碼的範例、不同遊戲的收斂曲線（Fig. 2）

### かに讀後判斷

這是目前 harness engineering 領域最直接的實驗驗證之一：不是概念框架，而是用小模型自己寫 harness，然後小模型 + harness 打贏大模型。這跟之前讀過的 Code as Agent Harness（2605.18747）和 Effective Harness Engineering for Algorithm Discovery（2605.15221）形成有趣的對話——前者提出 harness 應該是可執行、可驗證的程式碼，後者在演算法探索中展示了 harness 的約束效果，而 AutoHarness 則把這推向極端：harness 不只是約束，它可以直接取代 LLM 的決策角色。

**值得深讀**：Fig. 2（收斂曲線）、Appendix D（生成的 harness 程式碼範例）、Section 4.3（harness-as-policy 的細節與限制）。這篇建議 Morris 點開全文，特別是附錄中的 harness 程式碼範例非常有參考價值。
