# Harness Engineering — 2026-06-16

## 1. Self-Harness: Harnesses That Improve Themselves

- **arXiv**: 2606.09498
- **Link**: https://arxiv.org/abs/2606.09498
- **Authors**: Hangfan Zhang, Shao Zhang, Kangcong Li, Chen Zhang, Yang Chen, Yiqun Zhang, Lei Bai, Shuyue Hu (Shanghai AI Lab)

### 這篇在說什麼

目前 agent 的 harness（系統提示、工具定義、runtime 機制、驗證規則、錯誤恢復流程等）主要靠人類工程師手動設計。問題是：不同模型有不同的行為模式、工具使用習慣、錯誤傾向和 prompt 敏感度，一個模型的好 harness 到另一個模型可能就不適用。隨著新模型不斷推出，為每個模型手動調 harness 越來越不可行。之前有 Meta-Harness 之類的做法——用更強的外部模型來幫弱模型改 harness——但這需要一個更強的模型可用，成本高且不一定適合 frontier model。

Self-Harness 問的是：一個 LLM agent 能不能自己改進自己正在用的 harness？不是靠外部更強的模型，而是靠分析自己的失敗模式來提出修改。

### 主要貢獻

1. **新範式：Self-Harness**：agent 在固定模型權重下，透過分析自己的執行痕跡來改進 harness。這不是改模型、改回應策略或改記憶——是改「模型周圍的腳手架」。

2. **三階段迭代迴圈**：Weakness Mining（從失敗的執行痕跡中聚類出反覆出現的失敗模式）→ Harness Proposal（根據失敗模式，模型以 proposer 角色提出多樣但最小的修改）→ Proposal Validation（回歸測試，只有不造成退步的修改才被接受）。整個迴圈中模型權重和評估器不變，只有 harness 在改。

3. **跨模型一致性提升**：在 Terminal-Bench-2.0 上，三個不同家族的模型（MiniMax M2.5, Qwen3.5-35B-A3B, GLM-5）都有一致提升。Held-out pass rate 從 40.5%→61.9%（MiniMax）、23.8%→38.1%（Qwen）、42.9%→57.1%（GLM）。相對提升最高達 138%。

4. **模型特定修改**：定性分析顯示 Self-Harness 不是簡單加長 prompt 或加通用指令，而是針對每個模型的反覆失敗模式提出具體修改——MiniMax 的修改鼓勵提早建立輸出檔案、更好地處理結構化工具輸出；Qwen 的修改專注於預先檢查依賴、避免重複失敗命令、打破無限探索循環；GLM 的修改幫助跨 shell 命令保持環境設定、更快從探索轉到實作。

### 方法 / pipeline

Self-Harness 的正式定義和演算法流程：

- **Harness h**：非參數的腳手架（提示、工具、記憶/狀態管理機制等），不改模型權重，但決定了模型如何觀察任務、採取行動、呼叫工具和產出結果。
- **每輪迭代**：
  1. 用目前 harness h_t 在 held-in split D_in 上跑，收集執行痕跡。
  2. 從失敗痕跡中聚類出 verifier-grounded failure patterns（不是看表面症狀，而是看 verifier 揭露的終端失敗原因、與此原因相關的 agent 行為、以及該行為在 trace 中的因果位置）。
  3. 用同一個模型（在 proposer 角色下）根據 failure patterns 提出 K 個多樣但最小的候選修改。
  4. 對每個候選修改做回歸測試：在 D_in 和 D_held-out 上都跑，只有同時滿足「held-in 不退步」、「held-out 不退步」、「至少一個有正向提升」三個條件的才被接受。
  5. 被接受的修改合併成 h_{t+1}；如果沒有任何修改被接受，保持 h_t 不變。

關鍵設計：修改必須是「bounded edit」（有界修改），不是重寫整個 harness；Proposal 的多樣性透過 K 個 parallel proposals 保證；regression test 確保不會改壞。

### 實驗設計

- **Benchmark**：Terminal-Bench-2.0（軟體工程任務）。
- **初始 harness**：一個最小的 harness（只有基本指令）。
- **模型**：MiniMax M2.5, Qwen3.5-35B-A3B, GLM-5（三個不同家族）。
- **主要結果**：
  - Held-in: 43.0%→50.0% (MiniMax), 15.1%→36.0% (Qwen), 47.7%→57.0% (GLM)
  - Held-out: 40.5%→61.9% (MiniMax), 23.8%→38.1% (Qwen), 42.9%→57.1% (GLM)
  - 絕對提升最大 21.4 百分點，相對提升最高 138%。
- **定性分析**：不同模型的 harness 修改不同，證實了模型特定性。有趣的是 Self-Harness 還能引入更結構性的修改（如 subagent 分解和 middleware 建立），超越了局部修補。
- **目前能確認的**：方法、演算法、主要結果表格已從 HTML 全文確認。Ablation 和消融實驗的細節需看 PDF。

### かに讀後判斷

Self-Harness 是 harness engineering 領域近期最重要的工作之一。之前我們看過的 harness 相關工作主要是靜態設計（人類工程）或外部優化（Meta-Harness），Self-Harness 第一次提出「agent 自己改自己的 harness」這個範式，而且實驗結果很紮實——三個不同家族的模型都有一致提升。

這篇和之前看過的 Meta-Harness（2605.00197, mentioned_daily 2026-05-27）形成直接對比：Meta-Harness 用更強的模型改弱模型的 harness，Self-Harness 則讓模型自己來。兩者各有優劣——Self-Harness 不需要更強的外部模型，但可能受限於模型本身的改進能力。

值得 Morris 點開深讀，特別是：Figure 2 的迴圈概覽、Algorithm 1 的完整演算法、Section 4 的定性分析案例（不同模型的 harness 修改差異）、以及 Appendix 中的 regression test 細節。

## 2. Agents' Last Exam (ALE): A Benchmark for Long-Horizon, Economically Valuable Tasks

- **arXiv**: 2606.05405
- **Link**: https://arxiv.org/abs/2606.05405
- **Authors**: Yiyou Sun, Xinyang Han, Weichen Zhang et al., Dawn Song (UC Berkeley, 250+ contributors)

### 這篇在說什麼

現有的 agent benchmark 大多測的是抽象能力（數學、程式競賽），但 AI 在這些 benchmark 上的勝利沒有轉化成經濟面上的實際影響。ALE 問的是：如果我們要衡量 AI 能不能做真正有經濟價值的專業工作，我們需要什麼樣的 benchmark？

ALE 的答案是：長視野、真實專業工作流程、可驗證結果的 benchmark。它和 250+ 產業專家合作，依據 O*NET / SOC 2018 職業分類，建立了涵蓋 55 個子領域、13 個產業叢集、1000+ 任務實例的 benchmark。目前最強配置（Codex with GPT-5.5）在最難的 tier 上平均 pass rate 低於 1%。

### 主要貢獻

1. **廣度與深度兼具的產業覆蓋**：13 個產業叢集、55 個子領域，從金融、法律到電機工程、製造業，每個子領域都有非零覆蓋。比之前任何一個 agent benchmark 的產業覆蓋都廣。

2. **真實工作流程的採集流程**：不是編造合成情境，而是讓專家提交他們實際完成過的專案。經過五階段品管（招募→提交→初審→工程實作→同儕審查），確保真實性、複雜性和可驗證性。

3. **可驗證的評估**：異質化輸出（檔案、試算表、媒體、報告、設計、模型）透過 deliverable-based 或 milestone-based 的自動化評分來處理，不需要人類裁判。

4. **防汙染策略**：只公開 1490 個任務中的 150 個（~10%），其餘為私有池；私有任務會定期輪替到公開集，維持評估面的乾淨。

5. **目前結果顯示巨大差距**：最強配置在 Terminal-Bench 上達 82%，但在 ALE 最簡單的 tier 上也低於 50%，最難的 tier 低於 10%；主流 agent 在最難 tier 的 pass rate 接近 0%。

### 方法 / pipeline

ALE 的評估管線有三個解耦的組件：

1. **Task Specification**（main.py）：定義 load()、start()、evaluate() 三個生命週期函數。load() 宣告任務和運算需求；start() 將 VM 環境設為確定性初始狀態；evaluate() 在 [0,1] 區間評分。

2. **Agent**（harness + model）：只接收任務描述和 metadata，在 action loop 中透過截圖、shell 輸出、滑鼠鍵盤、檔案編輯、API 呼叫與環境互動，直到終止。

3. **Environment**：遠端 VM，標準化四目錄佈局（input/、output/、workspace/、reference/），預裝目標軟體。

關鍵設計：task specification 和 agent 和環境都是可替換的。任何 harness+model 組合都可以跑，task 可以替換，環境可以是 Linux 或 Windows VM。

### 實驗設計

- **規模**：1,490 個任務實例（150 公開、1,017 私有、323 待 QC）。
- **Taxonomy**：55 子領域 × 13 產業叢集，依據 O*NET/SOC 2018。
- **難度分層**：依 expert-estimated completion time 分為多個 tier。
- **目前結果**：最強配置（Codex + GPT-5.5）最簡 tier < 50%，最難 tier < 10%。大多數主流 agent 在最難 tier 接近 0%。
- **跨 benchmark 比較**：Figure 3 將 16 個現有 benchmark 的領域映射到 ALE 的 55 子領域座標系上，顯示 ALE 填補了大量既有 benchmark 的覆蓋空白。
- **目前能確認的**：benchmark 設計原則、taxonomy、建構流程、評估管線架構、主要結果已從 HTML 全文確認。具體任務實例和每個子領域的詳細分數需看 PDF。

### かに讀後判斷

ALE 是 harness engineering / agent evaluation 領域的一個里程碑級 benchmark。它填補了一個重要空白：現有 benchmark（SWE-bench、Terminal-Bench、OSWorld 等）要麼只測 CLI、要麼只測 GUI、要麼領域太窄。ALE 把 GUI + CLI + 長視野 + 真實專業工作 + 可驗證評分全部結合在一起，而且結果顯示目前最強的 agent 也離「經濟上有用」還很遠。

這篇和之前看過的 Terminal-Bench（Self-Harness 用的基準）直接互補：Terminal-Bench 測的是軟體工程能力，ALE 測的是跨產業的通用專業能力。ALE 的設計也對 harness engineering 有直接影響——因為每個 task 需要 GUI+CLI 混合能力，harness 的設計空間比純 CLI 環境大得多。

值得注意但不需要今天深讀——如果你對「agent benchmark 的下一步」有興趣，可以之後看 Figure 3 的跨 benchmark 比較和 Appendix B 的建構流程細節。
