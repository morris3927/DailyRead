# Harness Engineering — 2026-06-18

## 1. Stop Comparing LLM Agents Without Disclosing the Harness

- **arXiv**: 2605.23950
- **類型**: arXiv preprint / Position paper (cs.AI, cs.SE)
- **Link**: https://arxiv.org/abs/2605.23950

### 這篇在說什麼

這是一篇 position paper，核心論點是：在長程任務（long-horizon tasks）中，當比較的模型能力相近時，agent 的執行 harness（管控 context 建構、tool 互動、orchestration、verification 的基礎設施層）對效能的決定性，往往比模型本身更強。作者提出 Binding Constraint Thesis：在 frontier model 區間，效能方差主要由 harness configuration 而非 model choice 主導，而目前的評估協議系統性地把 harness 層的增益錯誤歸因為模型改進。

這篇補的洞在 harness engineering 領域是根本性的：之前的工作（AHE、Harness-Bench、Layer-Isolated Test Harness）都在回答「如何改善或測量 harness」，但這篇回答的是「為什麼不披露 harness 就無法比較 agent」。它把一個實務觀察提升到控制理論的正式框架——harness 是閉環系統的 controller，LLM 是 open-loop 的 stochastic policy，穩定性、context drift、control lag 都是 controller 性質而非 model 性質。

### 主要貢獻

1. **Binding Constraint Thesis 的形式化**：把 harness 定義為閉環系統的 controller 𝒞_H，把 LLM 定義為 open-loop stochastic policy π_θ。在這個框架下，穩定性（stability）、context drift、control lag 都是 harness 性質，不是 model 性質。這給了 harness engineering 一個正式的理論基礎，而不只是工程實務觀察。

2. **實證證據：harness variance 超過 model variance**：引用了多個 benchmark 數據——Terminal-Bench 2 同模型換 harness 從 69.7% 到 77.0%；HAL 報告單一模型在不同 scaffold 下高達 48 個百分點的差距；第三方監測報告 GPT-5 有 11 個百分點的 scaffold-only variation，Kimi K2 Thinking 有 15 個百分點。這些數據清楚顯示：harness 帶來的效能變異可以遠超模型替換。

3. **Harness-aware evaluation framework**：提出兩種評估協議——locked-harness protocol（所有模型用同一 harness）和 factorial protocol（把 harness 當成 controlled factor 來做變異數分解）。同時提出 harness disclosure standard，要求 benchmark 回報必須包含 harness 規格。

4. **控制理論視角的三層分析**：把 agent 執行重新框架為離散時間閉環動態系統，指出 model 升級可以降低異常事件的基率，但異常發生後的回應完全由 harness controller 決定，模型升級不會改善這部分。

### 方法 / pipeline

這篇是 position paper，實證部分來自：

- **Control-theoretic formalization**：把 agent 執行建模為 closed-loop dynamical system。State s_t 由 context window 和 persistent memory 組成；model 是 stochastic policy π_θ(·|c(s_t))；harness 是 controller 𝒞_H，從 (s_t, a_t, o_t) 更新到 s_{t+1}。這個形式化讓「harness 為什麼重要」有了數學基礎——open-loop policy 不自帶回饋路徑，所有 feedback 都是 harness 的性質。

- **Published benchmark evidence**：從 SWE-bench Pro、Terminal-Bench 2、HAL leaderboard、第三方監測數據中提取 harness variance 的實例。

- **Controlled variance decomposition**：對 Var(B(M,H)) 做變異數分解，分成 model variance (MV)、harness variance (HV)、和 interaction variance。當 HV ≫ MV 時，benchmark score 不能歸因於 model。

### 實驗設計

作為 position paper，這篇沒有獨立的實驗，而是系統性整理了既有 benchmark 的 harness variance 證據：

- **SWE-bench Pro**：同一模型（Claude Opus 4.5），SEAL scaffold 45.9% vs. Claude Code 55.4%
- **SWE-bench Pro model ordering flip**：加一個 search subagent（WarpGrep）就翻轉 MiniMax 2.5 和 Claude Opus 4.6 的排名
- **HAL Leaderboard**：SWE-bench Verified Mini 上單一模型在不同 scaffold 下最高差 48 個百分點
- **第三方監測**：GPT-5 有 11pp scaffold-only variation，Kimi K2 Thinking 有 15pp
- **Terminal-Bench 2**：AHE 十輪迭代從 69.7% 到 77.0%（同模型）

這些數據從多個獨立來源一致指向同一結論：在 frontier model 區間，harness variance ≫ model variance。

### かに讀後判斷

這篇是 harness engineering 領域目前最強的理論 position paper。它不是在說「harness 很重要」（這大家都知道），而是在說「當你不披露 harness 時，leaderboard 比較根本無效」。這個論點比之前讀過的 AHE（自動演化 harness）、Harness-Bench（測量 harness effects）、Layer-Isolated Test Harness（per-layer CI）都更根本——那些是工程解法，這篇是認識論挑戰。

**值得 Morris 點開嗎？** 非常值得。這篇的 control-theoretic formalization 和 variance decomposition 公式提供了分析 harness 工程的數學工具，對 Morris 的 harness engineering 研究方向有直接的理論貢獻。深讀時優先看：Section 3 的 variance decomposition 數學細節、Section 4 的 harness disclosure standard 具體規格、以及 appendix 中對「locked-harness vs. factorial protocol」的比較分析。這篇跟之前讀的 AHE 和 Harness-Bench 形成完整的「理論-測量-自動化」三角關係。

## 2. A Unified Framework for the Evaluation of LLM Agentic Capabilities

- **arXiv**: 2605.27898
- **類型**: arXiv preprint (cs.AI)
- **Link**: https://arxiv.org/abs/2605.27898

### 這篇在說什麼

這篇提出一個統一框架來公平評估 LLM agent 的 agentic capability，核心問題是：各 benchmark 各自包裝了不同的 harness 實作，導致跨 benchmark 的分數無法直接比較。作者設計了統一的 instruction–tool–environment 配置格式、固定 ReAct-style agent 架構、可控沙箱、和離線模式（用 curated snapshot 取代 volatile live environment），把 7 個主流 benchmark 整合到 24 個 domain，跑了 400K+ rollouts。

### 主要貢獻

1. **統一配置格式**：把各 benchmark 的 task/tool/environment 規格標準化為 instruction–tool–environment 格式，讓 agent 在統一架構下跑。
2. **統一效率指標 + 失敗歸因分類**：不只是 task success rate，還加了資源消耗指標和 decision-/execution-level failure attribution。
3. **大規模實證**：400K+ rollouts 跨越 single-agent、multi-agent、safety-critical 場景。

### 方法 / pipeline

- 統一配置系統把不同 benchmark 的 task 轉成標準格式
- 固定 ReAct-style agent scaffold
- 可控沙箱 + 離線模式（curated snapshot）
- 統一評估指標：task success + resource consumption + failure attribution

### 實驗設計

7 個 benchmark、24 個 domain、400K+ rollouts。目前從 abstract 能確認有 large-scale empirical analysis，但具體的 benchmark 名單、模型列表、以及 harness 分離效果的數據需要看全文。

### かに讀後判斷

這篇跟 Stop Comparing LLM Agents Without Disclosing the Harness (2605.23950) 是同一天的兩篇互補工作——2605.23950 提出問題和理論框架，2605.27898 提出工程解法。但這篇更偏工程整合，理論深度不如 2605.23950。對 Morris 的研究方向來說，2605.23950 更值得深讀，這篇作為背景參考即可。目前僅從 abstract 層級快速掃描，需要看全文才能確認統一架構的具體設計是否真的能分離 harness 效果。
