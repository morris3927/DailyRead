# Harness Engineering — 2026-06-19

## 1. WildClawBench: A Benchmark for Real-World, Long-Horizon Agent Evaluation

- **arXiv**: 2605.10912
- **Link**: https://arxiv.org/abs/2605.10912
- **Authors**: Shuangrui Ding, Xuanlang Dai, Long Xing, 等（Shanghai AI Laboratory / InternLM 團隊）
- **Code**: https://github.com/internlm/WildClawBench

### 這篇在說什麼

當前 agent benchmark 有四個系統性缺口：多數仰賴合成沙盒而非真實 runtime、任務偏短（< 1 分鐘）、只測少量 mock API 而非真實工具鏈、只用最終答案檢查而不追蹤執行軌跡。WildClawBench 直接處理這四個缺口：它用 60 個人工撰寫的雙語（中英文）多模態任務，跑在真實 CLI harness（OpenClaw / Claude Code / Codex / Hermes Agent）上，每個任務平均 8 分鐘牆鐘時間、20+ 工具呼叫，並且用混合驗證（rule-based + environment state audit + LLM/VLM judge）。這篇的核心問題是：**在真實部署環境中，frontier agent 到底能不能完成長程多步驟任務？**

### 主要貢獻

1. **Native-runtime 評估**：任務跑在 Docker 容器中的真實 CLI agent harness 上，不是 mock API 或合成沙盒。這意味著 agent 必須面對真實的 shell、browser、file system、email client 等工具，而非被簡化的替代品。
2. **Harness 效應量化**：同一模型在不同 harness 下差異可達 18 分（例如 MiMo V2 Pro 在 Claude Code vs Hermes Agent）。這直接回應了 Harness-Bench 和 PawBench 的核心觀點——agent 能力必須在 model × harness 層級報告。
3. **混合驗證方法**：不是只看最終答案是否正確，而是結合 deterministic checks、environment state auditing、和 LLM/VLM judge 的語義驗證，後者只在 rule-based 無法決定時才調用。
4. **60 個跨領域任務**：productivity flow、code intelligence、social interaction、search & retrieval、creative synthesis、safety alignment 六類，包含 26 個原生多模態任務。雙語設計（36 英 + 24 中）也是獨特之處。

### 方法 / pipeline

- **任務設計流程**：四階段——Task authoring → Reference answer construction → Task filtering（pilot score vector 差距 ≥ 0.2 才保留 + 人工審查）→ Refinement。
- **Harness 配置**：支援 OpenClaw、Claude Code、Codex、Hermes Agent 四種 harness，透過統一 OpenRouter endpoint 存取模型，tool schema 和 system prompt 在同一 harness 內保持一致。
- **Grading pipeline**：每個任務有對應的 executable grading function，回傳 per-criterion 和 aggregate 分數。Ground truth 和 grading-only 資源在 agent process 結束後才 mount，防止洩漏。
- **模型測試**：19 個 frontier model（6 proprietary + 13 open-source），時間預算 300-1200 秒。

### 實驗設計

- **Dataset**：60 個人工撰寫任務，6 類別，雙語。
- **Baseline/Benchmark 比較**：與 AgentBench、GAIA、τ-bench、SWE-bench、WebArena、OSWorld 等做軸向比較（Table 1），WildClawBench 是唯一同時滿足 cross-modal、auditable、native runtime、bilingual、reproducible 的 benchmark。
- **主要結果**：
  - 最強模型 Claude Opus 4.7 在 OpenClaw harness 下僅達 62.2%，其餘全部 < 60%。
  - 切換 harness 可讓單一模型分數變動高達 18 分。
  - 多模態任務普遍比純文字任務差（GPT 5.4: 40.2% vs 58.0%；Claude Opus 4.7: 58.5% vs 65.0%）。
  - 19 個模型分數範圍 19.3%-62.2%，遠未飽和。
- **Ablation**：分析了 time budget 和 skills 對表現的影響，但全文中詳細 ablation 表我僅從 abstract 和前半段確認。

### かに讀後判斷

WildClawBench 是 2026 年 harness engineering 領域的重要 benchmark 論文，直接延續了 Harness-Bench（2605.27922）和 PawBench 的「harness 效應」論點，但走了一條不同路線：不是測 harness 本身的差異，而是**在多個 harness 上跑同一批真實世界長程任務**，從而證明 harness 選擇是不可忽略的變數。對 Morris 來說，這篇的價值在於：（1）它是少數同時測試 OpenClaw 的 benchmark 論文；（2）它用實驗證明了 harness 效應不是邊際現象——18 分的差距是巨大的；（3）60 個任務的雙語設計和混合驗證方法有工程參考價值。
