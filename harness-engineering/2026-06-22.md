# Harness Engineering — 2026-06-22

## 1. ABA: Auto Benchmark Audit — Automated Issue Detection for LLM Benchmarks

- **arXiv**: 2605.26079
- **Link**: https://arxiv.org/abs/2605.26079
- **Authors**: Federico Bianchi, Shang Zhu, Fan Nie, Yongchan Kwon, Bhuwan Dhingra, James Zou (Duke / Together AI / Stanford)

### 這篇在說什麼

現代 AI benchmark 的複雜度已經超出傳統驗證方法的能力範圍。Benchmark task 由領域專家撰寫，但專家恰好最不可能把自己的隱含假設講清楚——他們把關鍵背景視為理所當然，留下不完整的環境規格、模糊的任務描述、和脆弱的評分邏輯。這些問題不是壞意，而是複雜度的自然副產物。

ABA 提出一個 agentic framework 來系統性地審計 individual benchmark task，找出三類問題：（1）Instruction — 提示語無法唯一決定評分標準所要求的答案；（2）Environment — 容器缺少提示語所假設的資源；（3）Evaluation — 評分 harness 拒絕了正確遵循提示語的解答。這不只是「找 bug」——而是把 benchmark 當成需要持續維護的活文件。

### 主要貢獻

1. **Benchmark-agnostic agentic auditing pipeline**：ABA 用一個 deterministic evidence collector 把不同格式的 benchmark artifacts（目錄結構、JSON task_patch、(instruction, gold_answer) pair 等）統一成一個 manifest，然後用 Auditor Agent 依 issue category 和 severity scale 審計。支援 static audit（直接分析 artifacts）和 trajectory audit（重播 agent 執行軌跡）兩種模式。
2. **大規模審計實證**：橫跨 168 個 benchmark、九個領域、超過三萬個 task，發現 **25.7% 的 task 有 critical issues**（ambiguous task design、execution environment conflicts、incorrect ground truths 等）。
3. **實際影響驗證**：過濾掉有問題的 task 後，SWE-bench Verified 和 Terminal-Bench 2 的平均效能分別提升 **9.9%** 和 **9.6%**，且模型排名會改變。這說明有問題的 task 不只是「雜訊」，而是會系統性地扭曲能力評估。

### 方法 / Pipeline

ABA 的 pipeline 分三步：

1. **Evidence Collector Agent**：下載 benchmark 的 repository、dataset、和（若有）agent trajectories。解析各種 heterogeneous 格式為一個統一的 manifest（file paths + metadata）。
2. **Auditor Agent**：對每個 task，根據 issue categories（instruction ambiguity, environment conflict, evaluation brittleness 等）和 severity scale 進行審計。產出 structured findings，每項 finding 引用具體的 file path 和行號。
3. **Report Generation**：彙整所有 findings 為結構化報告，包含 suggested fixes。

關鍵設計：ABA 是 benchmark-agnostic 的——它不依賴特定 benchmark 的格式或評分邏輯，而是透過 evidence collector 的 manifest schema 來抽象化差異。這讓它可以同時審計 SWE-bench（patch-based）、Terminal-Bench（container-based）、HLE/GPQA（static QA）等截然不同的 benchmark。

### 實驗設計

- **規模**: 168 benchmarks、九個領域、30,000+ tasks。
- **驗證方式**: 
  - Upstream PRs：向 benchmark 原作者提交 PR 修復發現的問題，獲得接受。
  - Independent human review：領域專家逐一驗證 ABA 的 findings。
- **Impact 測試**: 在 SWE-bench Verified 和 Terminal-Bench 2 上，比較過濾前後的 model ranking 和平均效能。
  - SWE-bench Verified: 平均 +9.9%
  - Terminal-Bench 2: 平均 +9.6%
  - 模型排名發生變化。
- **已讀來源**: arXiv HTML 全文（Sections 1–2 完整讀取；Section 3 之後的詳細實驗、per-domain breakdown、具體 finding 範例需要 PDF 確認）。

### かに讀後判斷

ABA 直接對 harness engineering 的「評估基礎設施」開刀——不是改 agent，而是審計評估 agent 的工具本身。這和 DeployBench（同日候選）互補：DeployBench 測的是「agent 能不能部署 research artifact」，ABA 測的是「benchmark 本身可不可信」。

25.7% 的 task 有 critical issues 是一個驚人的數字，但更重要的洞察是「過濾後模型排名會改變」——這意味著我們目前在用的 benchmark 排行榜很可能被系統性偏差扭曲。對 Morris 的 harness engineering 追蹤來說，ABA 是一個必須關注的方向：如果連 SWE-bench 和 Terminal-Bench 這種高品質 benchmark 都有這麼多問題，那自建 harness 時的品質保證就更重要了。

值得深讀。優先看 Section 3（具體 finding 的分類與範例）、Section 4（impact 測試的完整數據）、和 Appendix（per-domain 審計結果）。

## 2. DeployBench: Benchmarking LLM Agents for Research Artifact Deployment

- **arXiv**: 2606.05238
- **Link**: https://arxiv.org/abs/2606.05238
- **Authors**: Yuanli Wang, Yaoyao Qian, Yue Zhang, Hanhan Zhou, Jindan Huang, Tianfu Fu, Qiuyang Mang, Huanzhi Mao, Wenhao Chai, Wendong Fan, Liqiang Jing
- **類型**: arXiv preprint（僅 abstract 層級快速掃描，HTML 版本不可用）

### 這篇在說什麼

LLM agent 在 software engineering 和 ML research 任務上進展很快，但這些進展通常假設已經有一個可運行的環境。對於伴隨論文發布的 research artifact，從乾淨機器設定環境仍然是一個主要瓶頸。現有的環境設定 benchmark 沒有覆蓋 research artifact deployment 的完整範圍——多語言 toolchain、system-level dependencies（GPU/CUDA、kernel 配置）、和 legacy artifact 相容性。

DeployBench 提出一個跨領域的 51 個 deployment task benchmark，涵蓋 AI/ML、computer systems、和 scientific computing，每個 task 都有一個 hidden pipeline 執行論文指定的實驗並檢查輸出。

### 主要貢獻

1. **Multi-domain deployment benchmark**: 51 個 task 跨 AI/ML、computer systems、scientific computing，覆蓋多語言 toolchain、GPU/CUDA 依賴、legacy 相容性等真實部署挑戰。
2. **Hidden verification pipeline**: 每個 task 都有論文原實驗的 ground truth 輸出作為驗證基準，而非只檢查「環境能跑起來」。
3. **Completion-judgment problem 的發現**: 4 個 SOTA LLM 搭配 OpenHands 的 pass rate 只有 7.8%–51.0%，其中 97/154 個失敗是 agent 自行終止的「self-stop」——agent 的 pre-finish check 驗證了一個比論文要求更弱或不同的目標。

### 方法 / Pipeline

（僅 abstract 層級快速掃描，無法確認具體 pipeline 細節。）

從 abstract 可推測：每個 task 包含一個 research artifact 的 repository 和/或 Docker image，agent 需要從乾淨環境部署並執行指定實驗。Evaluation 透過 hidden pipeline 比對 agent 輸出和 ground truth。

### 實驗設計

（僅 abstract 層級快速掃描，以下為 abstract 可確認的範圍。）

- **4 個 SOTA LLM** + OpenHands agent framework
- **Pass rate 範圍**: 7.8%–51.0%
- **主要失敗模式**: completion-judgment problem（97/154 失敗是 agent-terminated self-stop）
- **缺乏資訊**: 無法確認具體是哪些模型、詳細的 task 分類、ablation 設計。

### かに讀後判斷

DeployBench 的「completion-judgment problem」是一個很有洞察力的發現——agent 不是不能部署，而是部署完後自己判斷「夠了」的標準和論文要求的不同。這和 harness engineering 的關聯在於：agent 的 self-evaluation 能力是 harness 設計的重要一環，而 DeployBench 顯示目前的 agent 在這方面有系統性缺陷。

但因為只讀到 abstract，無法確認方法細節和實驗深度。建議 Morris 在深讀時優先看 Section 3（task construction 和 verification pipeline）和 Section 4（失敗模式分類的詳細統計）。如果對 SWE-bench 和 Terminal-Bench 的部署場景有興趣，這篇值得跟進。

## 3. Agent-ValueBench: A Comprehensive Benchmark for Evaluating Agent Values

- **arXiv**: 2605.10365
- **Link**: https://arxiv.org/abs/2605.10365
- **Authors**: Haonan Dong et al.
- **類型**: arXiv preprint（僅 abstract 層級快速掃描）

### 這篇在說什麼

現有 value benchmark 只評估 LLM 的價值觀，但 agent 的價值觀和底層 LLM 不同——agentic modality 引入了 dataset-level、evaluation-level、和 system-level 的挑戰。Agent-ValueBench 是第一個專門評估 agent 價值觀的 benchmark，包含 394 個可執行環境、16 個領域、4,335 個 value-conflict task，覆蓋 28 個價值體系和 332 個維度。每個 task 都有心理學家逐案策劃，並提供兩個 pole-aligned golden trajectories 和 trajectory-level rubric-based judge。

### 主要貢獻

1. **Agent value benchmark 的首個系統性工作**：證明 agent 價值觀和 LLM 價值觀不同，且 agentic modality 帶來 text-only protocol 沒有的挑戰。
2. **End-to-end synthesis pipeline**：自動生成 + 心理學家逐案策劃的混合流程。
3. **Three concerted findings**：(a) Value Tide — 跨模型價值觀趨同的潮流下有可解讀的逆流；(b) harness pull 非疊加地影響價值觀；(c) 嵌入 skill 的 steering 比單純 prompt steering 更有效——暗示 agent alignment 的槓桿正從 model alignment 轉向 harness alignment 和 skill steering。

### 方法 / Pipeline

（僅 abstract 層級快速掃描，無法確認具體 pipeline 細節。）

從 abstract 可推測：每個 task 是一個 value-conflict 情境，agent 在 harness 中執行，產出 trajectory，由 rubric-based judge 評分。14 個模型 + 4 個 harness 的組合測試。

### 實驗設計

（僅 abstract 層級快速掃描。）

- 14 frontier models × 4 harnesses
- 394 environments, 16 domains, 4,335 tasks
- 28 value systems, 332 dimensions
- Three main findings about value tide, harness pull, skill steering

### かに讀後判斷

Agent-ValueBench 的「harness pull」和「skill steering」發現對 harness engineering 很相關——它實證了 harness 本身就是 alignment 的槓桿，這和 Morris 追蹤的 harness 工程方向直接呼應。但因為只讀到 abstract，無法確認方法細節和實驗嚴謹度。建議深讀時看 Section 3（task synthesis pipeline）、Section 4（harness pull 的實驗設計）、和 Section 5（value tide 的量化分析）。
