# Harness Engineering — 2026-06-25

## 1. HarnessX: A Composable, Adaptive, and Evolvable Agent Harness Foundry

- **arXiv**: 2606.14249 | Darwin Agent Team
- **Link**: https://arxiv.org/html/2606.14249v1

### 這篇在說什麼

HarnessX 處理的是 agent harness 領域最核心的工程問題：harness 是手刻的、靜態的、各組件糾纏在一起的，每次換模型或換任務都要重寫，而且執行時產生的 trace 從未被系統性地回收改進 harness 本身。這不是一篇只提概念框架的論文——它實際建了一個 foundry，可以把 harness 當成 first-class object 來組合、適應、演化，然後在五個 benchmark 上驗證。

研究問題的核心是：agent 的進步能不能不只靠 model scaling？能不能從 harness 端系統性地拿回效能？答案是 +14.5% 平均增益，最弱模型在 ALFWorld 上拿到 +44.0%。

### 主要貢獻

1. **Harness Composition via substitution algebra**：把 harness 正式化為 typed processor 組成的 first-class object，每個 processor 依附於 lifecycle hook，用 nine-dimensional taxonomy 覆蓋全部行為空間，用 substitution algebra 做型別安全的 per-task 組合和替換。這比之前所有 harness framework 都更精確地定義了「組合」的語義。
2. **AEGIS：trace-driven multi-agent evolution engine**：把 harness 適應框架為 RL 問題的符號空間映射（operational mirror），明確指出 reward hacking、catastrophic forgetting、under-exploration 這些 RL 病理在 harness evolution 中的對應物，然後用 Digester → Planner → Evolver → Critic 四階段 pipeline + deterministic gating 來處理。這是目前 harness 領域最完整的 self-evolution 設計。
3. **Harness-Model Co-Evolution**：harness 進化產生的 trajectory 同時作為 model RL training 的 signal（Cross-Harness GRPO），打破 harness-only adaptation 的 scaffolding ceiling 和 model-only RL 的 training-signal ceiling。這是之前 Self-Harness 和 AHE 都沒做到的。
4. **Inverse scaling pattern**：越弱的 model 從 harness evolution 受益越大（Qwen3.5-9B 在 ALFWorld +44.0%，Sonnet 4.6 只有 +11.2%），暗示 harness 補的是 model 自身無法校正的行為缺口。

### 方法 / pipeline

HarnessX 是三層架構：

1. **Composition layer**：harness 由 typed processors 組成，每個 processor 對應一個 lifecycle hook（context, tools, skills, control, memory 五大類 × 數個子類），用 substitution algebra 做 type-safe 的組合替換。九維 taxonomy 涵蓋 full behavioral space。
2. **Adaptation layer (AEGIS)**：
   - Digester：壓縮執行 trace 成結構化失敗報告。
   - Planner：根據失敗報告規劃 harness 修改方案。
   - Evolver：生成候選修改（prompt, tool, memory, control policy 四類）。
   - Critic：用 regression test 評估修改效果，只合併通過的改動。
   - Operational mirror：把 harness adaptation 映射到 RL 問題空間，使 RL 的病理（reward hacking 等）有對應的 design risk 和應對策略。
   - Variant isolation：optional 的 ensemble routing 策略，避免 cross-task interference。
3. **Co-Evolution layer**：harness evolution + model RL 交錯進行，共享 replay buffer。Cross-Harness GRPO 讓 model 從連續 harness 版本的策略中學習。

### 實驗設計

- **Benchmarks**：ALFWorld, GAIA, WebShop, τ³-Bench, SWE-bench Verified（5 個）
- **Models**：Claude Sonnet 4.6, GPT-5.4, Qwen3.5-9B（3 個 task-agent families）
- **Evolution rounds**：最多 15 輪
- **主要結果**：
  - 平均絕對增益 +14.5%（15 個 model-benchmark configurations）
  - 單一配置最高 +44.0%（ALFWorld / Qwen3.5-9B）
  - 15 個配置中 14 個改善
  - τ³-Bench 近天花板 baseline 只拿到 +1.1%
  - Heterogeneous task set（GAIA）上 single-harness evolution 會停滯，variant isolation ablation 恢復穩定改善（+13.6%）
  - Co-evolution 比 harness-only evolution 再多 +4.7%
- **Ablation**：evolution strategy 比較、meta-agent effectiveness、variant isolation、failure analysis 都有完整展開。
- 完整程式碼承諾開源但尚未釋出。

### かに讀後判斷

這是目前 harness engineering 領域最完整、最系統性的工作。和之前 Self-Harness（2606.09498，自動識別弱點並修改 harness）相比，HarnessX 把 harness 當成可組合的 typed object 來管理、把 evolution 映射到 RL 問題來處理 pathology、還加了 harness-model co-evolution，三個層次都超越了 Self-Harness 的單純 weakness-mining + proposal + validation 循環。和 AHE（agentic harness engineering，2604.25850）的 observability-driven 相比，HarnessX 的 operational mirror 更明確地把 RL pathology 映射過來。

值得 Morris 點開，深讀時優先看：(1) §3 substitution algebra 的型別定義和九維 taxonomy，(2) §4 AEGIS 的 four-stage pipeline 細節和 operational mirror 的具體映射，(3) §6 GAIA 上 variant isolation 的 ablation 數據，(4) §6.5 co-evolution 的 +4.7% 是怎麼量出來的。

## 2. Harness Engineering for Physical AI: Robot Middleware Is the Harness Layer

- **arXiv**: 2606.09416 | Middleware 2026 Big Ideas track
- **Link**: https://arxiv.org/html/2606.09416v1

### 這篇在說什麼

這篇把 harness 的概念從 software agent 延伸到 Physical AI（機器人）。目前 language agent 領域開始把 harness 定義為 model 外部的治理層，但機器人領域還沒有採用這個框架。作者論證 robot middleware（ROS 2 等）就是 Physical AI 的 harness layer，但它缺少 AI model 的 enforcement 機制。

### 主要貢獻

1. **定位 relocation**：把 harness 概念從 software agent 的 tool-call boundary 延伸到 Physical AI 的 control-computing-communication 三軸同時介入。software harness 在 tool-call 邊界隔離非確定性；Physical AI harness 必須在控制迴路內部處理非確定性。
2. **三個 enforcement function**：Projection（每個 output 在發射時閘門檢查）、Isolation（限制 model 的執行和傳輸 slot）、Transfer（檢查失敗時 fallback 到驗證過的 baseline）。目前這三個功能在各 deployed robot 系統中都是手寫應用層代碼。
3. **ROS 2 Harness Profile**：一個 deployment artifact，攜帶 AI model 的 output region、inference budget、operating regime 宣告，讓 middleware（跨 ROS 2, DDS, Zenoh）執行。

### 方法 / pipeline

這是一篇 position / Big Ideas paper，提出框架而非實驗系統。方法論是概念分析 + 既有的 middleware 抽象能力的盤點：
- 分析 software harness（tool-call boundary mediation）和 Physical AI harness 的差異（control + computing + communication 三軸同時）。
- 盤點 ROS 2 / DDS / Zenoh 已經提供的 mediation 抽象（QoS, scheduling, discovery）。
- 定義三個 Physical AI harness 必須新增的 enforcement function。
- 用 ROS 2 Harness Profile 概念示範宣告式整合。

### 實驗設計

無正式實驗。這是 Big Ideas track submission，目前只有框架提案和概念論證。作者承認是「relocation of the question」而非 finished system。

### かに讀後判斷

這篇對 harness engineering 領域的意義是把疆域從 software agent 拓展到 Physical AI，論點清晰：software harness 在 tool-call boundary 隔離非確定性就夠了，但 Physical AI 的 learned model 在 control loop 內部製造非確定性，所以 isolation boundary 要同時覆蓋 control、computing、communication 三軸。不過目前只是概念提案，沒有實驗驗證。對 Morris 來說，這篇值得知道但不一定要深讀——框架有啟發性，但距離實作還遠。和昨天的 harness 定義論文（2606.10106）互補：那篇定義什麼是 harness，這篇定義 Physical AI 的 harness 介面要長在哪裡。
