# Harness Engineering — 2026-07-03

## 1. Recursive Agent Harnesses

- **arXiv**: 2606.13643
- **Link**: https://arxiv.org/abs/2606.13643
- **Authors**: Sahil Sen, Kevin Paul, Vamse Kumar Subbiah (PwC US)

### 這篇在說什麼

Recursive Language Models（RLM）證明了遞迴 model call 是長上下文推理的有效策略，但遞迴單位是裸 model call——沒有工具、沒有檔案系統、沒有規劃。同時，production coding agent 已經在寫會 spawn subagent 的程式碼（Anthropic dynamic workflows）。這篇命名並評估兩者之間的模式：Recursive Agent Harness（RAH），遞迴單位是完整 agent harness（filesystem + code execution + planning），而非裸 model call。核心問題：當遞迴單位從 model call 升級為 full harness 時，效能增益有多少？

### 主要貢獻

1. **命名並定義 harness recursion**：遞迴單位是 full agent harness 而非裸 model call。這不是全新的 primitive（code-as-action、subagent spawning 都是既有概念），但命名並系統評估這個模式是新的。
2. **受控評估**：backbone 固定為 GPT-5，匹配 Codex 和 RLM baselines，增益歸因於 harness 而非 model。Oolong-Synthetic 199 samples × 13 context-length buckets（1K–4M tokens），Codex baseline 71.75% → RAH 81.36%。
3. **Code-execution spawning 打破 per-turn cap**：JSON tool-call spawning 受限於 API 的 per-turn parallel tool-call budget，code-execution spawning 用 shell script 在 subprocess 中執行，並行度由 workload 決定而非 provider protocol。
4. **模型差異**：Claude Sonnet 4.5 + RAH 達到 89.77%，顯示 harness 效應跨模型存在但強度不同。

### 方法 / pipeline

- **RAH 架構**：parent agent 接收完整任務 → 檢查文件判斷工作量 → 兩條 spawning 路徑：
  - **JSON tool-call spawning**：1–5 entries 的子任務，用結構化 function call，受 per-turn cap 限制。
  - **Code-execution spawning**：大量 entries，parent 寫一個 Python script，用 `asyncio.gather` 並行 spawn 所有 subagent harnesses，透過 shell tool 執行。
- **Subagent 架構**：每個 subagent 是完整的 agent harness，有 read_file、write_file、ls、glob、grep、execute、web search，加上 planning step。隔離的 workspace，不存取 parent context 或 peer subagents。
- **結果彙總**：subagents 寫入共享 output file，parent 讀取彙總。
- **遞迴性**：每個 subagent 有相同的 spawning capability，深度由 configurable depth limit 控制。

### 實驗設計

- **Benchmark**：Oolong-Synthetic，199 個 samples，13 個 context-length buckets（1K 到 4M tokens）。
- **Baselines**：Codex coding agent baseline（71.75%）、RLM baseline（64.38%）。
- **固定 backbone**：GPT-5，匹配 Codex 和 RLM baselines，排除 model 差異。
- **主要結果**：RAH（GPT-5）= 81.36%，RAH（Claude Sonnet 4.5）= 89.77%。增益在所有 context-length buckets 上一致，包括 4M tokens。
- **Ablation**：code-execution path vs JSON tool-call path 的自動選擇基於 entry count。
- **實作**：基於 LangChain agent framework，但聲稱 approach 是 language-agnostic 的。

### かに讀後判斷

這篇直接命名並評估了一個已經在 production 中出現的模式（Anthropic dynamic workflows 是同一件事）。受控評估是核心價值：backbone 固定下 +10 個百分點的增益清楚歸因於 harness。對 harness engineering 的啟示：遞迴不只是在 model call 層面，也可以在 full agent 層面，而且 code-as-action 的 spawning 比 JSON tool-call spawning 更具擴展性。值得深讀 Section 3（RAH 架構細節）和 Table 2（per-bucket 結果）。和前幾天的 TUA-Bench 互補：TUA-Bench 暴露了 terminal agent 的弱點，RAH 展示了一種解決長上下文工作的 harness 設計。

## 2. Agent Skill Evaluation and Evolution: Frameworks and Benchmarks (Survey)

- **arXiv**: 2606.11435
- **Link**: https://arxiv.org/abs/2606.11435
- **Authors**: Kexin Ding, Yang Zhou, Can Jin, Feng Tong, Mu Zhou, Dimitris N. Metaxas (Rutgers, UNC Charlotte)

### 這篇在說什麼

Agent skill 正在從手寫建立走向自動化、評估驅動的演化。這篇 survey 系統性地整理 skill evolution 和 evaluation 的地景。核心論點：隨著 skill library 規模成長，缺乏 robust evaluation framework 已成為關鍵瓶頸，而從孤立 skill creation 到 evaluation-driven skill evolution 是一個正在發生的範式轉移。

### 主要貢獻

1. **四種演化範式分類**：execution feedback（單次執行的步級信號）、trajectory distillation（多次執行的序列級模式）、compression & augmentation（library 層級的結構優化）、reinforcement learning（task 層級的 reward 傳播）。
2. **六類 skill-centric benchmark 分析**：識別結構缺口、trade-off、metric richness 問題。
3. **開放方向**：generalizable、efficient、verifiably safe 的 skill ecosystem。

### 方法 / pipeline

Survey 的組織方式：
- **Skill 定義**：$\mathcal{S} = (C, \pi, T, \mathcal{R})$，其中 C 是條件、π 是執行策略、T 是終止準則、$\mathcal{R}$ 是可重用介面。
- **Evolution strategies**：每種範式下列舉代表性系統（SkillForge、CoEvoSkills、SPARK、Trace2Skill、SkillNet、SkillX、D2Skill 等），分析信號來源、學習粒度、優缺點。
- **Benchmarks**：六類，分析覆蓋範圍缺口。

### 實驗設計

這是一篇 survey，沒有新的實驗。主要分析來自對現有系統和 benchmark 的系統性比較。Table 1 列出四種演化範式的代表系統。Appendix C 分析 evolution 和 benchmark 的對齊。

### かに讀後判斷

作為 harness engineering 的參考材料，這篇 survey 的價值在於提供了 skill evaluation 和 evolution 的系統性地圖。四種演化範式的分類對理解 harness 如何自動改進自己的 skill 有幫助。但 survey 的深度取決於引用論文的品質——目前從 HTML 前段能確認的是分類框架和部分系統描述，具體 benchmark 分析和開放方向需要看全文。如果 Morris 對 skill evolution 的自動化有興趣，Section 3 的四種範式對比和 Appendix C 的 benchmark-evolution 對齊分析最值得深讀。
