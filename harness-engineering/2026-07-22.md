# Harness Engineering — 2026-07-22

## 1. MemoHarness: Agent Harnesses That Learn from Experience (2607.14159)

- **arXiv**: 2607.14159
- **Link**: https://arxiv.org/abs/2607.14159
- **Authors**: Wenjie Wang, Han Bao, Yuchen Ma, Xiaonan Luo, Yi Nian, Haomin Zhuang, Zheyuan Liu, Yue Zhao, Xiangliang Zhang (University of Notre Dame, LMU Munich, USC)

### 這篇在說什麼

Harness engineering 社群已經形成共識：agent harness（prompt 建構、tool 介面、decoding 參數、orchestration 拓撲、memory 管理、output handling）對 agent 表現的影響可以差幾十個百分點。但目前的自動 harness 優化方法大多只改 prompt 或 pipeline，而不是把整個 harness 當成一個可編輯的控制層來系統性地搜尋和調適。MemoHarness 要解決的是：**能不能讓 harness 從自己的執行經驗中學習，在 test time 不需要 label 或額外搜尋的情況下，針對每個新 case 調適？**

這填補的是 Self-Harness (2606.09498) 和 Harness Handbook (2607.13285) 之後的下一塊：Self-Harness 做的是無監督迭代改良固定 harness；Handbook 做的是讓 harness 可讀、可導航；MemoHarness 做的是讓 harness 有記憶，能從過去成功和失敗中學到什麼 dimension 該改、什麼 pattern 值得保留。

### 主要貢獻

1. **六維度 harness 分解**：把 harness 沿 inference 時序分解為六個可編輯控制面——context, tool, generation, orchestration, memory, output——讓搜尋變成結構化的六維度編輯，而不是在單一 opaque prompt 上搜尋。

2. **雙層 experience bank**：搜尋過程中不只記 scalar score，還記 per-case diagnosis（哪個 dimension 失敗了、為什麼）和跨 case 的 global patterns（哪種 case 特徵配哪種 harness 調整有效）。這讓每次搜尋迭代是診斷性的，不是只看分數。

3. **Test-time case adaptation**：test time 不用 label、不用 feedback、不用新搜尋，直接從 experience bank 檢索相似 case 和相關 pattern，把 global harness W* 映射成 case-specific harness W(x_j)。correctness-first ranking rule 確保搜尋不會 drift 到便宜但錯誤的配置。

4. **選擇性 transfer**：學到的 harness 在 unseen evaluation suites 和不同 base model 上顯示選擇性正向 transfer——某些 suite 改善、某些持平，但不是全面泛化，作者也坦誠指出更大規模的研究和更細的 component ablation 是必要的。

### 方法 / pipeline

MemoHarness 分兩個 phase：

**Phase A: Training-time Search**
1. 在 labeled search cases 上跑 guided search，搜尋六維 harness space W = W^(1) × ... × W^(6)。
2. 每個 candidate harness W 被執行，得到 prediction + trajectory + diagnostics。
3. Per-case execution entry 記錄：case 特徵、harness 配置、configuration delta、success/failure、primary failure dimension、secondary dimensions、自然語言分析。
4. 每 N 次迭代，distillation operator 從 failure cluster 提取 global patterns。
5. Search policy π 根據 experience bank 決定下一步搜尋方向。

**Phase B: Test-time Case Adaptation**
1. 收到 unlabeled test case x_j^test。
2. 從 experience bank 檢索相似 cases 和相關 global patterns。
3. 把 global harness W* 映射成 case-specific harness W(x_j)。
4. 執行 W(x_j) 產生最終預測 ŷ_j。

correctness-first rule：primary reward 決定排名，cost 只在 tiebreaker 時使用。

### 實驗設計

- **Benchmarks**：shell-agent benchmark (主要)、code generation、analytical reasoning。
- **Base model**：多個模型家族（從論文描述推斷至少包含不同大小的模型）。
- **Baselines**：fixed harness configurations（最強 baseline 0.722）。
- **Main result**：MemoHarness 在 shell-agent benchmark 上達到 0.806（vs. 最強 fixed harness 0.722），同時在 dollar cost 上相對於最強商業 baselines 有競爭力（retrieved context 有 cacheability）。
- **Cross-dataset transfer**：在 unseen evaluation suites 上有選擇性改善。
- **Cross-model transfer**：在 held-out base models 上平均 task success 提升 +0.098。
- **Limitation**：作者明確說明更大的規模和更細的 ablation 是 future work。

### かに讀後判斷

MemoHarness 是 harness engineering 領域目前最完整的「harness optimization + case adaptation」框架。它回應了 Rethinking Harness Evaluation (2607.12227) 提出的問題：自動 harness evolution 的 evaluation 可能 conflating genuine improvement 和 test-time scaling。MemoHarness 用 correctness-first ranking + 結構化搜尋 + case adaptation 的方式，給了一個具體方案——但它的 evaluation protocol 是否真的避免了那篇 paper 指出的問題，需要仔細看。

跟 Harness Handbook (2607.13285) 的關係也很直接：Handbook 做的是讓 harness 可讀、可導航、可編輯（人類和 coding agent 都能用）；MemoHarness 做的是讓 harness 有記憶、能自動從經驗學到該改什麼。兩者互補——Handbook 幫你找到要改哪裡，MemoHarness 幫你自動學到該改什麼。

## 2. Copy-on-Write Scoring: Application-Specific Agent Evaluations (2607.14336)

- **arXiv / Venue**: 2607.14336, accepted at ICML 2026 Second Workshop on Agents in the Wild
- **Link**: https://arxiv.org/abs/2607.14336
- **Authors**: Joanna Roy et al. (trail-ml)

### 這篇在說什麼

Agent evaluation 目前有個具體的工程缺口：benchmark 的 construct validity 對 application-specific workflow 太低，而 replica evaluation environment 又貴又容易 drift。這篇提出 CoW Scoring，利用 PostgreSQL 的 Copy-on-Write 機制直接在真實應用環境裡隔離 agent 的 database writes，讓你不用建 replica 就能量測 agent 在真實 workflow 上的表現。

### 主要貢獻

1. **CoW Scoring framework**：用 PostgreSQL COW 機制在 transaction 層級隔離 agent writes，產生 session-level 和 operation-level 的 granular scores。
2. **Application-level evaluation without replica**：直接在生產環境的資料庫上跑 agent，但 agent 的寫入不影響真實資料。
3. **Demonstrated on Plane (open-source project management)**：在真實開源軟體上展示，分析找出了 tool surface 的具體問題，修正後在受影響的模型上有可量測的改善。

### 方法 / pipeline

核心工程思路很直覺：在 PostgreSQL 裡，用 COW（分支一個 snapshot）讓 agent 的 database session 在隔離的 snapshot 上操作。Agent 完成後，比對 agent 的 writes 和預期結果，得到 per-operation 的成功/失敗判定。整個過程不需要 replica environment，也不需要人工 judge。

### 實驗設計

- **Platform**: Plane（開源專案管理平台）。
- **Evaluation**: agent 在 Plane 上執行一系列 workflow tasks（create project, add issue, assign 等等），CoW Scoring 量化每個 database write operation 的成敗。
- **Analysis**: 找出 tool surface 的具體問題（例如某個 API endpoint 的 schema 不清楚），修正後重新評估，受影響模型的表現有改善。

### かに讀後判斷

這篇直接回應了 harness engineering 裡一個長期的工程痛點：你改完 harness 之後，怎麼知道改好了？benchmark 太泛、replica 太貴。CoW Scoring 提供了一個務實的 middle ground。跟 MemoHarness 的 case adaptation 互補：MemoHarness 學到哪些 harness dimension 該改，CoW Scoring 告訴你改了之後在真實 app 上是否真的變好。
