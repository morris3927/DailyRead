# Harness Engineering — 2026-08-18

今天唯一 NOT_SEEN 的 harness engineering 候選是 SWE-Touch。這篇把 coding agent 評估從「agent 獨自工作」推進到「使用者在 shared workspace 中修改程式碼」的場景，直接挑戰現有 harness 假設 agent 在孤立環境中運作的前提。

## 1. SWE-Touch: Benchmarking Coding Agents When Users Touch the Code

- **arXiv / Venue**: arXiv:2608.02499v1 (cs.SE, cs.AI, cs.CL)
- **Link**: https://arxiv.org/abs/2608.02499
- **Code**: https://github.com/Trae1ounG/SWE-Touch

### 這篇在說什麼

目前主流的 coding agent benchmark（SWE-bench 系列、Terminal-Bench 等）都假設 agent 在一個靜態的、不受干擾的 repository 中工作 — agent 收到任務描述、拿到初始 codebase、完成後用 test 打分。但真實的軟體開發不是這樣的：使用者和 agent 共享同一個 workspace，使用者可能會在 agent 工作期間查看、修改、甚至覆寫程式碼。作者分析了 SWE-chat 資料，發現 59.0% 的真實 session 中包含使用者對 repository 的修改。

SWE-Touch 填補了這個缺口：它不只是加一個 user message（那是現有 interactive benchmark 做的事），而是在 agent 工作期間注入一個合理的、但與任務完成衝突的程式碼修改（Counter-Edit），強迫 agent 在共享 workspace 中維持 state awareness。

### 主要貢獻

1. **從 message-only interaction 推進到 shared-workspace interaction**：SWE-Touch 是第一個在 coding agent 評估中加入使用者 code edit 的框架，而不只是 user message。

2. **Counter-Edit 注入框架**：設計了一個系統化的流程來產生和驗證 Counter-Edit — 從多個 agent trajectory 中挖掘 task-critical region，用獨立的 User Patch Generator 產生局部合理但與任務衝突的修改，並驗證修改既不能單獨解決任務，也不能被忽略。

3. **State awareness 的實證發現**：9 個模型在 SWE-bench Verified 上的 Counter-Edit 導致平均 resolve rate 下降 7.7 個百分點；63.3% 的失敗案例保留了使用者衝突程式碼。開源模型在互動條件下的退化尤其嚴重。

### 方法 / pipeline

SWE-Touch 的構造和評估流程：

1. **Region Mining**：從多個 agent 的 autonomous trajectory 中挖掘 task-critical code region，確保注入點是 agent 真正會接觸到的位置。

2. **User Patch Generator**：用獨立的模型產生 Counter-Edit — 一個局部的、看起來合理的修改，但會與任務完成衝突。每個 edit 都經過驗證：
   - Counter-Edit 本身不能解決任務（$V^F(R^{-})=0$）
   - 正確 patch 能解決任務（$V^F(R^{\star})=1$）
   - Counter-Edit + 正確 patch 合併後仍不能解決任務（$V^F(R^{-\star})=0$）

3. **Region-Triggered Delivery**：在評估期間，當 agent 的 action scope 與 Counter-Edit region 重疊時，注入 Counter-Edit 並附帶 contextual user message。最多嘗試 K=3 次。

4. **Dual Container Architecture**：分離 edit container（agent 工作區）和 test container（評估區），允許 agent 持續編輯同時 evaluation runtime 獨立取樣 workspace state。

5. **Evaluation on SWE-bench Verified (200 tasks)、SWE-Bench Pro (25 tasks)、DeepSWE (25 tasks)**：三個 benchmark 涵蓋從短到長的 horizon。

### 實驗設計

已從 HTML 全文確認到：

- **9 個模型**：包括 Claude 系列、GPT 系列、開源模型等。
- **SWE-bench Verified (200 tasks)**：Counter-Edit 降低平均 resolve rate 7.7 個百分點。模型間退化幅度從 1.3 到 16.5 pp 不等，且嚴重重新排列了模型排名。
- **SWE-Bench Pro 和 DeepSWE**：退化持續存在，證明問題不限於短 horizon 任務。
- **Trajectory 分析**：63.3% 的失敗 run 保留了使用者的衝突程式碼。失敗模式包括：
  - 完全沒注意到外部修改
  - 保留了衝突程式碼但未重新檢查
  - 替換了衝突程式碼但未用測試驗證修正後的行為
- **開源模型退化更嚴重**：在 static benchmark 上競爭力強的開源模型在互動條件下退化幅度更大，暗示 leaderboard 最佳化不等於 shared-workspace 魯棒性。

### かに讀後判斷

SWE-Touch 是 harness engineering 領域一個重要的方向性貢獻。它直接挑戰了現有 coding agent benchmark 的基本假設：agent 在孤立環境中工作。59% 的真實 session 包含使用者 code edit，這個數字本身就說明了問題的嚴重性。

和前幾天的 harness 論文比較：
- 8/8 的 LoopsBench (2608.00267) 把評估從 harness engineering 推向 loop engineering — 關注 agent 在長 horizon 中的執行順序和 regression。
- 8/13 的 Harness-IF (2608.11727) 把 instruction following 拆到不同的 instruction surfaces，用 AP-Acc 區分真實遵守和默認行為。
- SWE-Touch 則把評估從「agent 獨自工作」推向「shared workspace collaboration」— 關注 agent 是否能維持 state awareness。

三篇合在一起看，harness engineering 正在從三個方向逼近同一個問題：coding agent 的評估不能只看最終結果，還要看過程中的行為品質（loop engineering）、規則遵守（instruction surfaces）、和狀態感知（shared workspace）。
