# Silicon Sampling / Social Simulation — 2026-05-18

## 1. discourse_simulator: LLM-Agent-based Social Simulation for Attitude Diffusion

- **arXiv**: 2604.03898
- **Link**: https://arxiv.org/abs/2604.03898
- **Authors**: Deepak John Reji et al.
- **Date**: 2026-04-04

### 這篇在說什麼

這篇要解決的問題是：傳統 agent-based model（ABM）用固定規則更新態度，無法生成自然語言、無法考量時事事件對輿論的影響；而現有的 LLM agent swarm 框架又把模擬當成 prediction black box，缺乏社會科學理論檢驗的認識論基礎。discourse_simulator 企圖在兩者之間開一條路：用 LLM 生成貼文、判讀意見、模擬態度擴散，同時把它定位為「theory-testing instrument」而非預測工具，這在 silicon sampling 領域是少見的認識論清晰定位。

研究動機源自一個觀察：社會事件（抗議、政策爭議、醜聞）對輿論的影響很難用固定 rule 的 ABM 捕捉，因為同樣的事件在不同時間點、不同資訊環境下會產生完全不同的社會反應。LLM 可以理解事件的語意並產生相應反應，這使得事件驅動的態度模擬成為可能。

### 主要貢獻

1. **discourse_simulator 開源框架**：結合 LLM 與 agent-based modeling 的 Python 套件，agents 放在小世界網路拓撲中，搭配 live news retrieval 系統，可以將真實事件時序注入模擬。這是目前 silicon sampling 領域少數直接提供「事件驅動 + 時序」能力的開源工具。

2. **多維度社會學信念結構**：每個 agent 不只持有一個標量態度，而是擁有多維度信念結構（例如對移民議題的經濟、文化、安全等多個面向的態度），LLM 在生成貼文和更新態度時會考量這些維度的交互作用，而非單純用一個 rule 把標量推向鄰居平均值。

3. **理論檢驗定位（epistemological stance）**：作者明確區分 discourse_simulator 與其他 LLM Agent Swarm 框架的差異——後者把模擬當作 prediction black box，discourse_simulator 則視其為 theory-testing instrument。這意味著模擬的價值不在於「預測正確」，而在於能否檢驗特定社會學理論的假設（例如：資訊繭房是否加劇極化？事件衝擊的衰減速率是否符合理論預測？）。

### 方法 / pipeline

discourse_simulator 的架構由幾個核心模組構成：

- **Agent 模組**：每個 agent 有 demographic profile、多維度信念結構、以及一組 LLM prompt template。Agent 的態度表示不是單一標量，而是一個向量，每個維度對應一個議題面向。LLM 負責生成社交貼文（模擬發文行為）和判讀他人貼文的意見（模擬態度更新）。

- **小世界網路拓撲**：Agents 排列在 Watts-Strogatz 小世界網路上，控制重連率可以調節資訊繭房程度。

- **Live News Retrieval**：模擬過程中可以注入真實新聞事件。系統會在指定時間點從新聞來源取得相關報導，這些事件會影響 agent 的態度更新——LLM 讀到新聞後會調整自己的信念結構，然後在下一輪生成貼文時反映出態度變化。

- **態度擴散機制**：Agent 在每一輪先閱讀鄰居的貼文（由 LLM 判讀語意與態度方向），然後結合自己的信念結構和最近接觸到的資訊，用 LLM 更新態度向量。這取代了傳統 ABM 的固定意見更新規則（如 DeGroot model 或 bounded confidence model）。

- **Python 套件**：包裝成 `discourse-sim`，可 pip install，輸入參數包含 agent 數量、網路拓撲參數、LLM model、事件時序等。

### 實驗設計

作者展示了一個 case study：模擬 2025 年 4 月 26 日 Dublin 反移民遊行前後 15 天的輿論動態，N=100 agents。

- **Dataset / Scenario**：真實事件時序（Dublin anti-immigration march），agent 的初始態度分佈基於社會調查數據。
- **Evaluation**：目前從 abstract 和框架描述能確認到的是，論文展示了模擬輸出（態度分佈隨時間的變化、極化指標），但尚未看到系統性的 ground truth comparison 或 quantified validation（例如與真實民意調查數據的相關性）。
- **目前能確認到的證據**：框架可行性 demo、態度隨事件的合理變化趨勢、開源可用性。還看不到的是：與真實民意數據的定量對齊、跨事件場景的泛化性、與傳統 ABM baseline 的比較。

### かに讀後判斷

discourse_simulator 是近期 silicon sampling 領域少數把「事件驅動 + 多維度信念 + theory-testing」三件事同時做好的框架。它跟之前讀過的 Silicon Society Cookbook（2605.00197）互補：Cookbook 在分析設計空間的幾何結構，discourse_simulator 則提供了一個可直接操作的具體工具，讓研究者可以在這個設計空間裡跑實驗。跟「AI Agents Alone Are Not Sufficient」（2603.00113）的關聯也很直接——那篇批評 LLM agent 模擬缺乏 environment-agent co-dynamics 的建模，discourse_simulator 的 live news retrieval 和事件驅動更新就是在嘗試捕捉這種共動態。

值得 Morris 點開深讀。優先看 Section 3（框架架構）和 case study 的態度分佈圖，以及附錄的 prompt template 設計——這些是判斷「theory-testing instrument」是否真的比 prediction black box 更有社會科學價值的關鍵。

## 2. PolicySim: An LLM-Based Agent Social Simulation Sandbox for Proactive Policy Optimization

- **Venue**: ACM Web Conference 2026 (WWW'26)
- **arXiv**: 2603.19649
- **Link**: https://arxiv.org/abs/2603.19649
- **Authors**: Renhong Huang et al.
- **Date**: 2026-03-20

### 這篇在說什麼

這篇的研究問題是：平台干預政策（推薦系統、內容過濾、曝光控制）可能在部署後產生意想不到的負面效果（加劇同溫層、極化、削弱立場多樣性），但現有的 A/B testing 是「reactive」的——先部署再觀察後果，風險辨識既延遲又昂貴。PolicySim 主張應該用 LLM 社會模擬做「proactive」的政策預評估，在部署前就能看到政策的可能影響。

這填補的缺口很明確：既有的 LLM 社會模擬框架不會顯式建模平台干預政策，agent 設計過度依賴 prompt engineering 而非真實行為建模，且缺乏把模擬回饋用來優化實際政策的機制。PolicySim 三個都處理了。

### 主要貢獻

1. **雙向動態建模**：PolicySim 同時建模「用戶行為→平台干預」和「平台干預→用戶行為」的雙向回饋。這超越了一般 LLM 社會模擬只看 agent-agent messaging 的模式。

2. **User Agent Module（SFT + DPO）**：用 supervised fine-tuning 和 direct preference optimization 訓練社交媒體 agent，使其行為對齊特定平台的真實用戶數據，而非純 prompt engineering。這是 silicon sampling 領域少見的「從真實數據學行為」做法。

3. **Adaptive Intervention Module（Contextual Bandit + Message Passing）**：干預模組用 contextual bandit 捕捉動態網路結構，結合 message passing 在圖上傳播資訊，讓干預策略能根據當前網路狀態自適應調整。

### 方法 / pipeline

PolicySim 由兩個核心模組構成：

- **User Agent Module**：每個 agent 代表一個社群平台用戶。先從平台真實數據收集用戶行為（貼文、互動、立場），然後用 SFT 訓練 LLM 模仿用戶的發文模式，再用 DPO 增強用戶意圖的區別性（distinctiveness）。這使得 agent 不只是「平均用戶」，而是能再現不同用戶群體的行為差異。

- **Adaptive Intervention Module**：用 contextual bandit 建模平台的干預決策（如推薦哪些內容、過濾哪些貼文）。Bandit 的 context 包括當前網路狀態和用戶行為特徵，message passing 層在圖上聚合鄰居資訊，讓 bandit 能考慮網路結構的動態變化。干預模組的回饋會影響下一輪用戶 agent 看到的內容，形成閉環。

- **Simulation Loop**：每個時間步，user agents 根據當前看到的內容和干預生成行為→ intervention module 觀察網路狀態並做出干預決策→ 干預影響下一輪 agent 的資訊環境→ 循環。

### 實驗設計

- **Benchmark / Dataset**：模擬社群平台生態系統，但論文沒有明確說明是否使用公開資料集或專有資料。從全文 HTML 可以確認的是，作者在 micro-level（個別用戶行為對齊）和 macro-level（整體輿論動態）兩個層次驗證模擬的準確性。
- **Baseline**：目前能確認到與 A/B testing 做對比，以及與純 prompt-engineering agent 的比較，但詳細 baseline 列表需要看全文。
- **Metric**：micro-level 用用戶行為分佈的對齊度，macro-level 用極化指標、立場多樣性等。
- **Main Result**：PolicySim 在 micro 和 macro 層次都能準確模擬平台生態，並能支持有效的干預政策優化。
- **目前能確認的**：SFT+DPO 訓練有效提升行為真實性、contextual bandit 能捕捉動態網路結構、閉環模擬比開環更能反映干預效果。還看不到的：訓練數據規模與來源、具體量化結果、跨平台泛化性。

### かに讀後判斷

PolicySim 的核心價值在於把「platform intervention」從 LLM 社會模擬的背景搬到了前景，並用 SFT+DPO 取代純 prompt engineering 來建模用戶行為。這跟之前讀的「AI Agents Alone Are Not Sufficient」（2603.00113）的批評直接對話——那篇說 role-playing plausibility ≠ behavioral validity，PolicySim 的 SFT+DPO 正是在嘗試解決這個問題。跟 discourse_simulator（2604.03898）互補：discourse_simulator 走「theory-testing instrument」路線，PolicySim 走「proactive policy sandbox」路線，兩者都是 silicon sampling 從「能不能模擬」走向「模擬有什麼用」的重要步驟。
